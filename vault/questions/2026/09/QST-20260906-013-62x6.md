## Original

가시성이 갑자기 떨어지고, 작업이 끝까지 완결되지 않는 경우가 생기기 시작한것같다. 테스트를 jade에서 해서 그런가?

## Notes

### 2026-09-06T10:00:26+09:00 answer (agent: lead:claude-fable-5-1, by nicehugepark)

`[2026-09-06 10:00:26 KST - 타치코마]`

021 은 **끝났습니다** — 방금 done 으로 닫았습니다. 코드는 09:43 에 커밋·push 됐고(`4a6844b`) 화면은 그때부터 쓸 수 있었습니다. 그 커밋의 전체 테스트는 09:45 에 jade 에서 통과했는데(원격 96초 통과 + 이 기계 몫 통과), 타치코마가 그 결과를 기다리는 감시를 걸어 두고는 **결과 줄을 놓치고** 다른 요청(022·023)을 처리하느라 상태를 안 닫았습니다. 답답하게 한 것은 타치코마의 진행 관리이지 작업 자체가 아니었습니다.

**가시성이 떨어진 원인 — jade 때문은 아닙니다.** jade 의 테스트는 매번 100초 안에 끝났습니다. 원인은 셋이고 전부 타치코마 쪽입니다.
1. 작업을 마치고도 「전체 테스트 결과를 보고 닫겠다」며 상태를 in-progress 로 남겨 두는 버릇 — 화면에는 진행 중으로 보이고, 결과가 와도 바로 안 닫았습니다.
2. 결과를 기다리는 감시가 시한을 넘기거나 옛 파일을 읽어 결과를 놓친 경우가 오늘 세 번 있었습니다.
3. 동기화(sync)가 문서 커밋을 즉시 얹으면서 타치코마의 코드 커밋이 두 번 밀려 다시 시도해야 했습니다.

고치는 방식: 코드가 커밋·push 되고 표적 테스트가 통과한 시점에 **곧바로 done 으로 닫고**, 전체 테스트는 그 뒤 배경에서 돌아 붉으면 별도 요청으로 세웁니다(이미 그렇게 설계된 「붉음 라쳇」이 지켜 줍니다). 지금부터 그렇게 합니다. 현재 나무의 전체 테스트는 배경에서 다시 돌고 있고, 결과가 실패일 때만 보고하겠습니다.
