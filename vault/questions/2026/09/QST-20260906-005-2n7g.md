## Original

배포 문제를 다시 이야기해보자. export ignore는 뭐지? gitignore와 다른가? 그러면 깃헙 동기화는 못하게되나?

## Notes

### 2026-09-06T16:51:11+09:00 answer (agent: lead:claude-fable-5-1, by nicehugepark)

`[2026-09-06 16:51:11 KST - 타치코마]`

둘은 다른 것이고, export-ignore 는 GitHub 동기화에 아무 영향이 없습니다.

**.gitignore 는 「git 에 넣지 않는다」입니다.** 여기에 적힌 파일은 추적되지 않으므로 commit 에도, GitHub 에도 올라가지 않습니다. 지금 state/ 와 index/ 가 이 경우입니다.

**export-ignore 는 「git 에는 넣되, 내보낼 때만 뺀다」입니다.** `.gitattributes` 파일에 `vault/ export-ignore` 처럼 적으면, 그 경로는 평소처럼 commit 되고 push 되고 GitHub 에 그대로 있습니다. 다만 `git archive` 로 배포용 묶음(tar·zip)을 만들 때만 빠집니다. GitHub 의 「Download ZIP」과 릴리스 페이지의 소스 묶음도 `git archive` 를 쓰므로 같은 규칙을 따릅니다.

정리하면 이렇습니다.

| | .gitignore | export-ignore |
|---|---|---|
| 추적·commit | 안 됨 | 됨 |
| GitHub 동기화 | 안 올라감 | 올라감 |
| 배포 묶음(archive) | 없음 | 빠짐 |

**그래서 vault 에는 export-ignore 가 맞습니다.** vault 는 여러 머신이 GitHub 로 동기화해야 하는 데이터라 .gitignore 에 넣을 수 없고, 배포 묶음에는 넣을 이유가 없습니다. export-ignore 는 정확히 그 둘을 동시에 만족합니다. 동기화는 지금과 똑같이 돌고, 달라지는 것은 태그에서 만든 배포 묶음의 내용뿐입니다.

한 가지 한계는 있습니다. export-ignore 는 묶음에만 작용하므로, 누군가 저장소를 `git clone` 하면 vault 까지 전부 받습니다. 비공개 저장소이니 clone 은 허가된 사람만 하고, 외부에 나가는 것은 태그로 만든 묶음이라는 전제에서 이 방식이 성립합니다. clone 자체에서 문서를 빼려면 앞서 반려한 저장소 분리로 가야 합니다.
