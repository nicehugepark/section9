WSL 리드가 맡긴 첫 검증(REQ-20260907-079-62x6)을 마쳐 회신했고, 그 사이에 주신 질문에 답합니다.

**검증 결과.** 실제 Safari, 폭 1440 에서 넷 중 셋은 통과입니다. Docs 목록 숫자는 Board 를 20초 다녀와도 그대로였고, 빈 오른쪽 판은 「골라 주세요」 안내가 서고 문서를 열면 그 문서가 섭니다. Graph 탭은 노드가 그려지고 API 도 200 입니다. 프로젝트 필터 하나는 확인하지 못했습니다. 목록을 펼치려면 클릭이 필요한데 이 맥에서 자동화 도구에 그 권한이 없습니다. 캡처 5장은 요청 문서에 첨부해 push 했습니다.

**Safari 에서 켜 주시면 도움이 되는 설정.** 지금은 창을 열고 화면을 찍는 것만 되고, 클릭·값 읽기·오류 확인이 안 됩니다. 아래 순서대로 켜 주시면 됩니다. 어느 창에서든 하실 수 있고 명령을 칠 일은 없습니다.

1. **Safari ▸ 설정(⌘,) ▸ 고급** 에서 맨 아래 「**웹 개발자용 기능 보기**」를 켭니다. 그래야 다음 단계의 「개발자」 탭이 나타납니다.
2. **Safari ▸ 설정 ▸ 개발자** 탭에서 둘을 켭니다.
   - 「**원격 자동화 허용**」: safaridriver 로 클릭·입력·스크린샷을 자동으로 할 수 있게 됩니다.
   - 「**Apple 이벤트의 JavaScript 허용**」: 페이지 안의 값(뷰포트 크기, select 의 항목 문구, 오류 유무)을 읽을 수 있게 됩니다.
3. **시스템 설정 ▸ 개인정보 보호 및 보안 ▸ 손쉬운 사용** 에서 **터미널**(또는 Claude 를 띄운 앱)을 켭니다. 이것이 없으면 자동화 도구가 클릭과 키 입력을 보낼 수 없습니다. 첫 시도 때 허용 여부를 묻는 창이 뜨면 「허용」을 누르셔도 됩니다.

셋을 켜신 뒤 「켰다」고 한 줄만 주시면, 못 본 프로젝트 필터 항목을 바로 다시 확인하겠습니다. 하지 말아야 할 것은 하나뿐입니다. 「Apple 이벤트의 JavaScript 허용」은 신뢰하는 스크립트만 실행되는 이 맥에서만 켜 두시고, 다른 사람이 쓰는 맥에는 켜지 않는 편이 안전합니다.
