두 질문에 답합니다.

**011 은 문서 정리가 아닙니다.** 말씀하신 그대로 「하네스 기본 시스템이 그 원격 머신을 몰라야 한다」를 코드에 적용한 것입니다 — `tests/p5_live.py` 의 **코드 기본값** `key="jade"` 세 곳, 시험 데이터 여섯 곳, 주석 열세 곳을 걷어냈고(`df16918`), 두 번째 컴퓨터의 이름은 이제 `--key` → `S9_TEST_REMOTE` → `state/test-remote`(기계 상태) 에서만 옵니다. 그리고 이 기계의 비밀 이름이 `bin/·tests/·harness/·web/` 에 다시 들어오면 붉어지는 시험(`test_no_secret_names`, 값은 읽지 않음)과 `CONTEXT.md` 의 저장소 정책 한 줄을 두었습니다. 요청 문서(vault)의 경위는 그대로입니다 — 그건 괜찮다고 하신 자리입니다. 011 은 done 으로 닫았습니다.

**표적 시험이 이 기계에서 도는 이유** — 지금 원격으로 가는 것은 **전체 실행**뿐입니다(손으로 치든 commit 뒤 배경이든). 표적·스모크·커밋 문의 시험은 **아직 commit 하지 않은 작업 나무**를 재는 자리라 이 기계에서 돕니다 — 원격은 commit 된 것만 받아 돌기 때문입니다(refs/ci 로 sha 를 보냅니다). 화면의 「표적 테스트 1/5건」이 그것입니다. 「모두 jade 에서」로 만들려면 미커밋 변경을 patch 로 실어 원격에서 돌리고 원격이 없으면 로컬로 물러나는 설계가 필요해 REQ-20260906-013-62x6(M) 으로 세워 두었습니다 — 착수하라 하시면 합니다.

곁가지: 두 머신 실측 장면 5-d 가 세 번 중 두 번 어긋나(간헐) 규약대로 격리해 REQ-20260906-012-62x6 로 따로 세웠고, 이 기계 sync 의 간헐 실패(「Cannot rebase onto multiple branches」 — fetch 둘이 겹쳐 FETCH_HEAD 를 겹쳐 쓰는 경합)는 뿌리를 고쳐 `67129c2`·`e38421e` 로 넣었습니다. 그 커밋의 전체 실행이 jade 에서 도는 중입니다.
