## Original

대시보드 포트가 9909에서 사용중이면 9910이 되는데 9909가 정리되면 다시 9909가되는게 아니라 무조건 1씩 증가해 9911이 되는건가? 9909가 비게되면 9909로 돌아오면 안되나?

## Notes

### 2026-09-08T18:54:59+09:00 answer (agent: lead:claude-fable-5-1, by nicehugepark)

`[2026-09-08 18:54:59 KST - 타치코마]`

**답: 1씩 올라가는 설계가 아니고, 물으신 대로 「9909 가 비면 돌아오지 않던」 결함이 맞습니다 — 고쳐서 commit 24f0f833 으로 push 했습니다 (REQ-20260908-064-62x6).**

무엇이 어떻게 되어 있었나:
- 옮길 때는 9910~9949 에서 **첫 빈 포트**를 고릅니다. 오늘 9911 이 된 것은 그 순간 9910 이 bind 되지 않았기 때문이지, 9910 다음 차례라서가 아닙니다.
- 옮긴 사실은 `state/port.auto` 로 남겨 다음 기동에서 되돌아오게 되어 있었는데, 조건이 「9909 에 **내 서버가 답할 때**」뿐이라 9909 가 그냥 비어 있으면 돌아오지 않았습니다.
- 오늘은 그보다 먼저 다른 결함이 겹쳤습니다: 18:21 에 세션 시작 훅이 serve 를 `--port-auto` 없이 띄워 9911 이 **사람이 정한 포트**(`state/port.pinned`)로 굳었습니다. 그 상태면 되돌리는 장치 어느 것도 손을 못 댑니다.

고친 것:
1. 훅(s9-audit-session)과 s9-install 이 serve 를 띄울 때 `--port-auto` 를 달아 기계가 읽은 포트를 못박지 않습니다.
2. 자동으로 옮긴 뒤 다음 기동에서 9909 가 비어 있으면 9909 로 돌아옵니다. 단, 옮겨 앉은 포트에 내 서버가 아직 살아 있으면 그대로 둡니다 — 돌아오면 대시보드가 둘이 됩니다.
3. 이 머신의 잘못된 `port.pinned` 는 지웠습니다.

지금 9911 의 서버는 살아 있어 그대로입니다. 9909 로 돌리려면 순서대로:

```
cd ~/section9
bin/s9 serve --stop      # 감시자를 먼저 물리고 서버를 내린다 (state/port.auto 를 잊는다)
bin/s9 code              # 다음 기동이 9909 부터 다시 잰다 → "대시보드 기동: http://127.0.0.1:9909/"
```

주의: `--stop` 없이 서버만 죽이면 감시자가 같은 포트(9911)로 되살립니다.
