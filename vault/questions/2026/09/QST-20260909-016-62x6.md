## Original

needs_on 기능은 완전 나 개인 하나만을 위한 기능인거같은데.. 맞아?

## Notes

### 2026-09-09T19:13:22+09:00 answer (agent: lead:claude-opus-5, by nicehugepark)

`[2026-09-09 19:13:22 KST - 타치코마]`

**쓰임은 개인적이고, 설계는 아닙니다.** 재 본 값입니다:

| 잰 것 | 값 |
|---|---|
| `needs_os` 를 쓴 요청 | 20건 — **전부 macOS**, 19건이 오늘 하루 안 |
| 코드가 아는 것 | 판 이름 넷(`Linux`·`macOS`·`Windows`·`WSL`)뿐. 장치 이름은 한 글자도 없음 |
| 화면 손잡이 | 없음 (guide.html 설명 한 줄이 전부) |
| 안 쓰는 설치가 치르는 값 | 0 — 필드가 비면 검사가 그냥 지나감 |

**개인적인 쪽**: 값이 나오려면 **한 vault 를 OS 가 다른 기계 여럿이 나눠 써야** 합니다. 지금 그런 설치는 이 집(WSL + 맥미니) 하나뿐이고, 그래서 20건이 전부 macOS 입니다. 기계가 하나인 사람에게는 평생 안 쓰이는 필드입니다.

**개인적이지 않은 쪽**: 이 기능이 아는 것은 **판**이지 **장치**가 아닙니다. 그게 갈림길입니다 — 만약 `needs_machine: Seongjinui-Macmini` 였다면 그건 이 집만의 것이고 CONTEXT.md 가 금지한 것(「개인 장치의 이름은 코드 밖에 둔다」)에 정확히 걸립니다. OS 로 적었기 때문에 Windows 전용 설치 스크립트를 고치는 사람, 리눅스에서만 나는 경로 문제를 쫓는 사람이 같은 값을 받습니다. Safari/WebKit 검증은 맥이 아니면 못 하는 대표적인 일이고, 그건 이 집만의 사정이 아닙니다.

리드 판정: **남겨 둘 값은 합니다.** 다만 지금 모양은 축이 하나(OS)뿐이라, 같은 꼴의 다른 제약(GPU 있는 기계·사내망 안·특정 브라우저)이 생기면 축을 늘리기보다 「이 요청은 어떤 자리에서만 된다」로 한 단계 올리는 게 맞습니다. 지금 필요한 일은 아니니 요청으로 세우지는 않았습니다 — 필요하시면 세우겠습니다.
