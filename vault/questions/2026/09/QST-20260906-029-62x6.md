질문 문서(QST)에 대해 확인한 사실부터 말씀드립니다.

**갱신 장치는 있습니다 — 다만 절반만 있습니다.**

QST 는 상태 전이가 없습니다. `status: published` 로 고정이고, 대신 「답했는가」를 본문의 answer/response 라벨 노트 유무에서 **파생**시킵니다(DOC-20260826-011-62x6 의 결정). 상태와 노트가 어긋나 「답했는데 미답」이라는 두 번째 진실이 생기는 것을 막으려고 일부러 그렇게 뒀습니다.

지금 있는 것:
- `s9 ls --unanswered` — 미답 질문만 뽑습니다
- Docs 탭 — 미답 질문이 목록 맨 앞에 서고, 타입 띠에 남은 장수가 뜹니다
- 문서 뷰어 — 미답이면 그 사실을 한 번 더 말합니다

**없는 것 — 지적하신 「방치」의 실체입니다:**
- **워처가 없습니다.** 요청은 반려·승인 메모에 워처가 붙어 30초마다 스캔하고 무인 세션을 스폰하지만, 미답 질문은 아무도 집지 않습니다.
- **훅 주입이 없습니다.** `s9 digest` 와 `s9 next` 어디에도 질문이 나오지 않습니다. 세션이 새로 떠도 미답 질문은 리드 눈에 안 보입니다.
- **Board 탭에 없습니다.** 일이 흐르는 화면에는 요청만 있고 질문은 Docs 탭으로 들어가야만 보입니다.

실측: 지금 미답이 **6장**입니다 (8/27 두 장, 8/29, 8/30, 9/2, 그리고 방금 하신 이 질문). 191장 중 184장은 답이 붙어 있으니 답 자체는 기록되고 있고, 새는 곳은 **답이 안 붙은 채 잊히는 경로** 하나입니다.

고칠 방향은 셋이 있고, 어느 것을 택하실지가 갈립니다:

| | 하는 일 | 값 |
|---|---|---|
| A. 훅 주입 | 세션 시작·`s9 next` 에 미답 질문 N장을 띄운다 | 작고 확실 — 리드가 보면 답한다 |
| B. 워처 | 유예를 넘긴 미답 질문에 무인 세션을 스폰한다 | 요청과 대칭 — 사람 발화와 무관하게 진행 |
| C. Board 노출 | 미답 질문을 작업 흐름 화면에 세운다 | 사람이 직접 본다 |

타치코마는 **A + C** 를 권합니다. B(워처)는 질문에 붙이면 무인 세션이 사람 대신 답을 지어낼 위험이 있습니다 — 질문 중에는 「이거 왜 이래?」처럼 사람의 화면을 봐야만 답할 수 있는 것이 섞여 있고(실제로 미답 6장 중 3장이 그렇습니다), 그걸 무인이 답하면 잘못된 답이 문서에 남습니다.

지금 에이전트·스킬 화면 개선(REQ-091)과 태블릿 반응형(REQ-20260906-092-62x6) 둘이 병행 중입니다. 어느 조합으로 갈지 정해 주시면 요청으로 세워 착수하겠습니다.
