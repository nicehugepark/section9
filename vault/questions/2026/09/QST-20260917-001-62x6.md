● API Error: Can't reach the API server — check your internet or DNS (EAI_AGAIN) 
이 오류는 왜 발생하는거지?

## Notes

### 2026-09-17T10:51:53+09:00 answer (agent: lead:claude-opus-5, by nicehugepark)

`[2026-09-17 10:51:53 KST - 타치코마]`

`EAI_AGAIN` 은 DNS 이름 풀이가 **일시적으로 실패**했다는 신호입니다 — API 서버가 죽은 것도, 인증이 틀린 것도 아니고, `api.anthropic.com` 이라는 이름을 IP 로 바꾸는 단계에서 응답을 못 받은 것입니다(getaddrinfo 의 EAI_AGAIN = "try again").

지금 이 컴퓨터에서 실측한 것:

- `/etc/resolv.conf` 의 nameserver 는 `8.8.8.8` · `164.124.101.2` (WSL 이 자동 생성한 파일)
- `api.anthropic.com` → `2607:6bc0::10` 로 풀립니다
- 접속도 됩니다 (dns 0.046초, connect 0.054초)

즉 **지금은 정상**이고, 07:42 무렵의 그 오류는 지나간 일시 장애였습니다. WSL2 에서 이 오류가 나는 흔한 원인 셋입니다:

1. **호스트가 절전·최대 절전에서 깨어난 직후** — WSL 의 가상 네트워크가 다시 붙기 전 몇 초~몇 분 동안 DNS 패킷이 나가지 못합니다. 이 세션이 밤새 30분 간격으로 idle 상태로 떠 있었으니 가장 유력합니다.
2. **VPN·회사망 전환** — nameserver 가 바뀌었는데 `/etc/resolv.conf` 가 옛 값을 들고 있는 상태.
3. **업스트림 DNS 순간 무응답** — `8.8.8.8` 로 나가는 UDP 53 이 잠깐 막히면 그대로 EAI_AGAIN 입니다.

다시 나면 순서대로 보시면 됩니다: `getent hosts api.anthropic.com` (이름이 풀리는가) → `ping -c1 8.8.8.8` (밖으로 나가는가) → 둘 다 실패면 PowerShell 에서 `wsl --shutdown` 후 재진입. 재발이 잦으면 `/etc/wsl.conf` 에 `[network] generateResolvConf=false` 를 넣고 `/etc/resolv.conf` 를 직접 고정하는 것이 뿌리 처방입니다 — 다만 지금은 정상이라 손댈 자리가 없습니다.

끊긴 자리는 이어서 계속합니다 — 이어받을 작업은 없고, 수신 대기 상태입니다.
