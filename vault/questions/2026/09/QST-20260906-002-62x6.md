## Original

jade 머신에서 s9 code를 실행했다. ssh 로 접근을해서 대시보드를 확인할수는 없는 상태이고. 이제 테스트는 jade 머신에서만 테스트를 실행하고 문서, 소스코드 등은 깃헙으로 실시간 동기화 되기를 기대하는데 어때?

## Notes

### 2026-09-06T00:43:45+09:00 answer (agent: lead:claude-fable-5-1, by nicehugepark)

`[2026-09-06 00:43:45 KST - lead]`

제가 틀렸습니다. jade 는 비밀 `jade` 로 이미 닿고 있고(이번 라운드의 원격 시험도 전부 그 길로 갔습니다), ssh 별칭은 필요 없습니다. 별칭을 물은 이유는 git 이 `ssh://` 주소를 쓸 때 호스트 이름을 따로 받기 때문이었는데, 방금 올린 검토(REQ-20260906-001-62x6)대로 가면 그마저 필요 없습니다 — 두 머신이 함께 볼 저장소는 GitHub 의 section9 `main` 자체이기 때문입니다. 0902-037 의 사유에서 별칭 요구를 지웠습니다.

**제안에 대한 판정 (REQ-20260906-001-62x6, 확인 대기로 올렸습니다)**

- **시험을 jade 에서만** — 이미 그렇게 돌고 있습니다. `state/test-remote = jade` 라 전체 실행은 손으로 치든 commit 뒤 배경이든 jade 로 갑니다(95초). 이 머신에 남는 것은 커밋 문의 스모크·표적 실행뿐인데, 그것은 **아직 commit 하지 않은 작업 나무**를 재는 자리라 원격이 대신할 수 없습니다(원격은 commit 된 것만 돕니다). 수초라 그대로 두는 것이 맞습니다.
- **문서·소스의 GitHub 실시간 동기화** — 기계는 이미 있습니다(`s9 sync` remote 모드: 문서 이벤트마다 commit → pull → push, 대시보드 안의 60초 루프, 문서 병합 드라이버). 다만 지금은 인스턴스 전용이라 이 저장소에는 **꺼져** 있습니다. 켜는 길은 뿌리에 `.s9-sync`(내용 `remote`) 한 파일을 commit 하는 것이고, jade 는 pull 만으로 물려받습니다. 동기화되는 것은 문서(vault·users·projects)이고 소스는 지금처럼 사람이 commit 하되 그 commit 이 양쪽에 실립니다.
- **위험** — 문서 노트 하나가 main 커밋 하나가 됩니다(이 저장소의 main 직접 push 정책과는 맞습니다). 네트워크 실패 뒤 60초는 쉬면서 「sync: local」이라고 말하는 낱말 혼동이 있습니다.
- **덤** — 켜면 그것이 곧 0902-037 「두 머신 실측」의 무대가 됩니다.

대시보드 카드에서 **승인**하시면 제가 켜고 두 머신 실측까지 이어서 밟습니다. **반려**면 지금처럼 사람이 commit·push 합니다.

**jade 대시보드를 이 화면에서 보는 법** (ssh 포트 전달, 비밀은 치환으로만):
1. 이 기계의 터미널에서, 어느 디렉토리든:
   `~/section9/bin/s9 secret run -- sh -c '{{secret:jade}} -N -L 9919:127.0.0.1:9909'`
   — 아무 출력 없이 붙어 있는 것이 정상입니다(끊으려면 Ctrl+C).
2. 브라우저에서 `http://127.0.0.1:9919` — 이 기계의 9909 와 겹치지 않게 9919 를 씁니다.
