## Original

.s9-sync 파일은 왜 따로 존재하는거야 루트디렉토리에? config에 있어야하는거 아니야?

## Notes

### 2026-09-14T01:14:03+09:00 answer (agent: lead:claude-fable-5-1, by nicehugepark)

`[2026-09-14 01:14:03 KST - 타치코마]`

이유는 셋입니다 — 설계 판단이지 우연은 아닙니다.

1. **저장소의 속성이라 저장소와 함께 다녀야 합니다.** `.s9-sync` 는 git 이 track 하는 파일이라 GitHub 에 이었다가 두 번째 컴퓨터에서 clone 하면 그 컴퓨터도 같은 모드(local/remote)로 시작합니다. 컴퓨터마다 다른 것은 `state/`(track 안 함), 사람마다 다른 것은 `users/<이름>/config` 에 있고, 이건 그 둘이 아니라 「이 저장소 전체」의 값이라 셋째 자리가 필요했습니다.
2. **파일의 존재 자체가 뜻입니다.** 「있다 = 여기는 문서를 track 하는 인스턴스다, 없다 = 코드 저장소를 그냥 clone 한 것이다(git 쓰기를 절대 하지 않는다)」. 그래서 어떤 설정도 읽지 않고 파일 하나 있나 보는 것으로 판정하고, 내용 한 줄(`local` / `remote`)이 모드입니다. `.gitattributes`·`.gitignore` 처럼 루트의 점파일 관례를 따른 것입니다.
3. 저장소 수준의 설정 파일이 따로 없습니다 — `s9 config` 는 컴퓨터 간 설정 이동 명령이고, 저장소 자체의 설정은 지금 이 마커 하나뿐입니다.

바꾸고 싶으시면 길은 있습니다: 루트에 저장소 설정 파일 하나(예: `.s9/config` 또는 `s9.toml`)를 두고 sync 모드를 그 안의 값으로 옮기는 것 — 다만 「존재 = 인스턴스」 판정과 옛 저장소 호환(마커 없는 clone 을 인스턴스로 오인하지 않기)을 같이 옮겨야 해서 0.9.0 뒤의 요청감입니다. 원하시면 요청으로 세우겠습니다.
