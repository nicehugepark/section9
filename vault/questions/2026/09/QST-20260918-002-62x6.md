**가이드가 맞고 배포판이 틀렸습니다.** `section9.cmd` 는 사라진 게 아니라 0.9.1 에 들어 있던 적이 없습니다.

그리고 **제가 틀렸습니다** — 처음에 판만 올리고 끝낸 것은 수습이었습니다. 지적받고 근원까지 갔습니다.

**본질** — 태그 `v0.9.1` 은 9/14 에 땄고, 두 번 눌러 시작하는 파일 셋은 9/15 에 들어왔습니다(commit `2f4602b01`·`b8b8fb394`). 그 뒤 나흘간 코드 commit 147 개가 태그 뒤에 쌓이는 동안 VERSION 은 0.9.1 그대로였고, 가이드는 그 판에 없는 절차를 적었습니다. 진짜 문제는 **배포판과 저장소의 거리가 어느 화면에도 없었다**는 것입니다 — 검출기가 사용자였습니다.

**근원 해결** — 판 낼 때를 사람 기억에서 뺐습니다. `s9 doctor` 가 거리를 셉니다:

```
✓ 배포: 나간 판 v0.9.2 · 뒤로 코드 commit 1개 · 0일
```

선(commit 20개 또는 7일)을 넘으면 「받는 사람은 이 코드를 못 받는다」로 경고합니다. 9/15 그날부터 이 줄이 화면에 있었을 겁니다.

**재발 방지** — 두 겹입니다. `test_release_drift.py` 13건(거리) · `test_release_guide_match.py` 6건(가이드가 이름 댄 파일이 그 판에 있나). 후자만으로는 이름을 대지 않는 변화를 못 잡아서 앞엣것을 더했습니다.

**실물 확인** — 릴리스에서 받은 zip 을 Windows 에서 **실제로 실행**했습니다. `sha256` 대조 OK, cmd.exe 로 `section9.cmd` dry run → exit 0, 저장소·훅·바로 가기·대시보드까지. 뒤처리(서버 내리기·임시 폴더)도 했습니다.
