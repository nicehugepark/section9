세션을 껐다켜거나 시크릿 관련 기능들이 다 완료된걸로 아는데 왜 볼 수가 없지?

007 재작업을 마치고 판정 대기로 올렸습니다.

**원인은 문구가 아니라 길이 둘이었다는 것입니다.**

```
보드 카드의 ✓ 승인    data-approve  →  승인 창 ("승인하기")
문서 화면의 ✓ 승인    data-trans    →  일반 이동 창 ("상태 옮기기")
```

반려만 두 길이 한 함수를 쓰고 있었고 **승인은 갈라져 있었습니다.** 그래서 같은 버튼이 어느 화면에서 눌리느냐에 따라 다른 창을 띄웠습니다. 문구만 맞추면 또 갈립니다 — 판정이 두 벌이면 한 벌만 고쳐지니까요.

**판정을 `judgeAct` 한 함수로 모았습니다.** 행동의 이름은 어디서 왔는가로 정해집니다 — `review` 에서 나가는 것만 판정입니다. `in-progress → done` 은 일을 끝낸 것이지 승인이 아니라 그대로 "상태 옮기기"입니다.

**맥락을 챙기라는 말에 해당하는 부분이 하나 더 있었습니다 — 끌어 옮기기입니다.** 그 길만 창 없이 `drag 이동` 으로 적혔고, 결과가 둘이었습니다: **반려에 사유가 필수라는 규칙이 이 길로만 비껴갔고**(끌어 놓으면 사유 없이 반려), 같은 행동이 History 에 세 가지 말로 남았습니다. 이제 review 에서 끌어 내면 버튼과 같은 창이 뜹니다.

그리고 `RVLABEL` 의 `⏸ 보류` 를 걷어냈습니다. 상태머신이 `review → blocked` 를 주지 않아 **한 번도 그려진 적 없는 이름표**였습니다.

`judge_dialog` 18/18(계약 2건 추가) · `goto_dispatch` 4/4 · 전체 1358건 중 실패 2건은 `test_instance_init` 인데, 이 worktree에서 `s9 instance init` 이 `main` 가지를 못 찾아 나는 **환경 실패**입니다. 제 변경은 `web/index.html` 과 테스트 두 파일뿐이라 그 테스트가 읽는 것을 건드리지 않습니다. worktree 도입의 부작용이라 따로 잡아야 합니다.

**두 가지는 못 했습니다.** worktree 사본을 띄워 눈으로 보려 했는데 서버 기동이 권한에 막혔고, `file://` 로는 화면이 API 를 기다려 비어 나옵니다 — 창의 생김새는 건드리지 않았고 이미 승인받은 명세를 그대로 씁니다만, 제가 직접 보지 못한 건 사실입니다. 그리고 **worktree 안에서 `git add`·`git commit` 도 막혀** 변경이 작업 트리에만 있습니다. worktree를 거두기 전에 커밋해야 사라지지 않습니다.
