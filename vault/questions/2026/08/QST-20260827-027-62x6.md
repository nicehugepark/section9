### 지식 문서를 선행으로 잡은 것 — 아무도 안 막았다

**전수로 세어 보니 딱 1건이었고, 방금 거뒀다.** 원인은 명확하다. `--blocked-by` 는 **자기 참조·존재 여부·대기 순환** 세 가지를 검사하는데, **"그것이 완료될 수 있는 문서인가"는 안 봤다.** 21:08 에 무인 작업자가 자기가 쓴 지식 문서를 선행으로 걸었고, 세 검사를 전부 통과했다.

지식의 종착 상태는 `published` 다 — **완료되는 개념이 없다.** 그러니 영원히 안 풀리는 대기가 된다. 보드엔 "막혀 있다"고 뜨는데 풀 방법이 없다.

**경계에서 막았다.** 요청이 아닌 것을 선행으로 걸면 거부하고 이유를 말한다 — "완료되는 문서가 아니라 영원히 안 풀리는 대기가 된다, 관계를 남기려면 `--relates` 를 써라". `relates`·`parent`·`derived_from` 은 그대로다 — 지식과 요청을 잇는 건 정상이고 권장된다. **막는 건 대기뿐이다.** 이미 걸린 과거 것은 `s9 linkcheck` 가 잡는다.

### 강제 푸시 금지는 어떻게 걸렸나

**이 하네스의 문서가 그렇게 하라고 안내한다.** `docs/09` · `docs/guide.md` 가 "서버측 최종 게이트 — CODEOWNERS + branch protection(PR 필수 + Code Owners 리뷰 필수)" 을 설정하라고 하고, `.github/CODEOWNERS` 도 리포에 있다. 8월 24일에 그 안내대로 거신 것으로 보인다.

**코드오너인데 왜 안 되나** — 코드오너는 *리뷰 승인* 권한이지 *강제 푸시* 권한이 아니다. 둘은 다른 항목이다:

```
required_pull_request_reviews   승인 1건·코드오너 리뷰   ← enforce_admins:false 라 관리자는 통과
allow_force_pushes: false       강제 푸시 금지            ← 이건 관리자도 예외 없다
```

그래서 20:21 의 **일반** 푸시는 통과했고, 지금 **강제** 푸시만 막힌다. 그 항목만 잠깐 켜면 된다 — **"풀어도 된다"만 하시면** 켜고→푸시→끄고, 끈 것까지 확인해 보고하겠다.

### worktree — 동기화에는 도움이 안 된다. 다른 데 도움이 된다

worktree는 **한 클론에 작업 디렉토리를 여러 개** 두는 것이다. 원격·푸시·풀과는 무관하니 **머신 간 동기화도, 여럿이 쓰는 것도 나아지지 않는다** — 각자 자기 클론을 쓰니까.

**대신 오늘 실제로 다친 자리에는 정확히 맞는다.** 무인 작업자들이 같은 작업 트리를 동시에 고쳐서, 제가 `git add -A` 로 커밋할 때 남의 미완성 파일을 쓸어 담았다. 워커마다 worktree를 주면 그 충돌이 **구조적으로** 사라진다 — 지금은 "리드가 조심한다"로 버티고 있고, 오늘 그게 안 됐다.

별건으로 등록해 두겠다. 지금 도는 designer 와 워커들이 `web/index.html` 을 만지고 있어서 바로 손대긴 위험하다.
