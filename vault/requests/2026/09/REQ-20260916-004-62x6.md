### TDD 시나리오 (작업자 권한 목록의 범용 실행기)

봉투가 「명령 이름」으로 정해졌는데 그 명령 하나(s9)가 범용 실행기를 품고 있었다.
고침은 둘: ① 봉투를 하위명령 단위로 세운다, ② s9-git-gate 가 `s9 secret run` 을
「인자를 다시 실행하는 명령」으로 본다.

- [ ] N1 정상 — 작업자 봉투에 s9 하위명령이 줄마다 서고, 작업자가 쓰는 것
      (show·status·note·last·claim·commit·shot·worktree)이 전부 들어 있다
- [ ] N2 정상 — 봉투 어느 줄도 임의 실행기를 허용하지 않는다 (secret·tunnel·
      code·resume·config·user·account·env·uninstall·instance·github·release·
      reset·purge 는 봉투 밖)
- [ ] B1 경계 — 등록된 하위명령 77개 전부가 허용/거부 둘 중 한쪽에 분류돼 있다
      (새 하위명령을 더하면 분류할 때까지 시험이 실패한다)
- [ ] B2 경계 — 봉투에 명령 이름 통짜 줄(`Bash(<s9>:*)`)이 없다
- [ ] F1 실패 — 적용 모드 봉투에 목적지가 자유로운 복사(`Bash(cp <ROOT>/web/:*)`)가 없다
- [ ] F2 실패 — `s9 secret run -- sh -c "<작업 트리 되돌림>"` 이 s9-git-gate 에 막힌다(exit 2)
- [ ] R1 회귀 — 글은 여전히 지나간다: 노트 본문에 그 이름들이 적혀 있어도 통과한다
      (REQ-20260902-003-62x6 의 사고가 되살아나지 않는다)
- [ ] R2 회귀 — `timeout 60 bash -c "<작업 트리 되돌림>"` 도 막힌다
- [ ] R3 회귀 — 무인 세션(S9_AUTO_RESUME)에서 `S9_GIT_OK=1` 우회가 듣지 않고,
      사람 세션에서는 그대로 지나간다
- [ ] R4 회귀 — 기존 봉투 계약 유지: Read·Glob·Grep · 적용 모드=acceptEdits ·
      gh 는 따로 켜는 스위치 · worktree 워커의 git 손
