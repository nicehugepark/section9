### 고친 것 (commit 263bd04cf, 가지 wt/w-916-004-62x6)

**근원**: 권한 목록을 「명령 이름」으로 정했는데 그 명령 하나(s9)가 범용 실행기를
품고 있었다. `s9 secret run -- <명령…>`(bin/s9.py:9020~9045)은 치환한 argv 를
그대로 subprocess 로 넘긴다 — 적용 모드가 꺼진 「읽기 전용」 자리에서도 무엇이든
실행됐다. 증상(secret run)만 막으면 같은 자리가 또 난다: `s9 code -- <claude 인자>`
와 `s9 resume <sid> -p <프롬프트>` 는 제 권한을 스스로 고른 새 세션을 띄우고,
`s9 config apply --with-permissions` 와 `s9 user config <사람> auto_resume_apply on`
은 다음 작업자의 권한을 바꾼다. 그래서 목록 자체를 하위명령 단위로 세웠다.

1. **bin/s9.py** — `WORKER_ALLOWED_SUBCOMMANDS`(63) / `WORKER_DENIED_SUBCOMMANDS`(14)
   와 `worker_s9_tools()`. 뺀 14: 인자를 다시 실행하는 것(secret·tunnel·code·resume),
   권한을 바꾸는 것(config·user·account·env·uninstall), 바깥에 만드는 것
   (instance·github·release), 되돌릴 수 없는 것(reset·purge). 등록된 하위명령
   77개 전부가 둘 중 한쪽에 있는지 시험이 본다 — 새 하위명령은 분류할 때까지 실패한다.
2. **bin/s9.py** — 적용 모드의 `Bash(cp <ROOT>/web/:*)` 를 걷었다. 출처만 web/ 으로
   묶고 목적지가 자유라 만든 파일을 `~/.claude/settings.json` 같은 바깥 자리로 옮길
   수 있었다. 워크스페이스 안을 고치는 손은 acceptEdits 의 Write·Edit 이 주고, 그쪽은
   작업 디렉터리 밖을 건드릴 때 사람에게 묻는다.
   `Bash(python3 tests/:*)` 는 남겼다 — 고칠 수 있고 tests/ 를 돌릴 수 있으면 그 둘을
   이어 무엇이든 실행할 수 있다는 사실을 gh 항목과 같은 자리에 솔직히 적어 뒀다.
   경계는 기본 권한 목록이고, 적용 모드는 사람이 알고 켜는 스위치다.
3. **bin/s9-git-gate** (H5) — 「그 글자를 누가 받느냐」의 받는 자를 첫 낱말 하나가
   아니라 토막의 머리에서 읽는다(`receives_commands`). `bin/s9 secret run -- sh -c
   "<파괴 명령>"` 이 이제 막힌다. 앞선 따옴표 안의 글이 다음 따옴표의 소유자로 읽히지
   않게 지운 사본에서 읽으므로, 이 결함을 문서로 남기는 노트 명령은 그대로 지나간다.
   INTERP 이름 끝을 `$` 로 못박고(shred·shutdown 오판정) timeout·stdbuf·setsid·
   nice·flock·doas 를 더했다. 무인 세션(S9_AUTO_RESUME)에서는 `S9_GIT_OK=1` 우회가
   듣지 않는다 — 훅은 사람의 Bash 와 모델의 Bash 를 구별하지 못한다.

**안 한 것**: `s9 secret run` 자체를 무인 세션에서 거부하는 갈래(보안 점검의 ①)는
두지 않았다. 원격 전체 테스트(tests/remote_run.py)와 `s9 tunnel` 이 그 하위명령을
**코드로** 부르고, 그 호출은 작업자 세션 안에서 일어난다 — 환경변수로 막으면 원격
테스트가 함께 죽는다. 권한 목록은 모델이 **치는** 명령만 제약하므로 코드 호출은
그대로 살아 있고, 경계는 목록 하나로 선다.

**검증**: test_worker_envelope(신규 6항목) · test_git_gate(g11~g14 추가) ·
test_auto_resume_gate · test_wake_effect · test_worker_worktree ·
test_worker_gh_envelope — 27건 통과. 전체 테스트 4129건 중 실패 5건은 전부 web/ 과
parent_nudge 로 이 변경과 닿지 않아 REQ-20260916-011-62x6 로 갈라 두었다.
