### TDD 시나리오 — clone 한 자리의 git 신원

대상은 `ensure_identity` 를 `ensure_repo` 밖으로 꺼내 `s9 code` 가 언제나 부르게 하는
일입니다(부모 REQ-20260921-004-62x6 의 1단계). 임시 신원의 사다리(2단계)와 doctor
문구(3단계)는 이 요청의 몫이 아닙니다.

### 정상
- [x] N1. 신원이 없는 컴퓨터에서 clone 한 자리(.git 은 있고 로컬 신원은 없다)에
  `ensure_identity` 를 부르면 저장소 로컬에 임시 신원이 서고 `set=True` 입니다.
- [x] N2. 그 자리에서 실제로 commit 이 섭니다 — 신원 부재로 거부되지 않습니다.
- [x] N3. clone 한 자리에서 `bin/s9 code --no-open` 을 돌리면(exit 0) 로컬 신원이 서고
  doctor 의 「git 이름」 판정이 critical(✗) 이 아닙니다.

### 경계
- [x] B1. 전역(~/.gitconfig)에 신원이 있으면 아무것도 쓰지 않습니다 — `set=False`,
  `scope=global`, 로컬은 비어 있습니다.
- [x] B2. 이 저장소 로컬에 이미 값이 있으면 덮지 않습니다 — `set=False`, `scope=local`.
  지금의 `git config <키>` 는 전역과 로컬을 한 값으로 읽어 이 둘을 가르지 못합니다.
- [x] B3. `.git` 이 없는 자리는 `skipped=no-repo` 입니다 — 전역 설정에는 손대지 않습니다.

### 실패
- [x] F1. git 실행 파일이 없으면 예외를 밖으로 내지 않고 `error` 한 줄을 돌려줍니다.

### 회귀
- [x] R1. `ensure_repo` 의 기존 갈래는 그대로입니다 — 전역 신원이 있는 자리의 `did` 에
  identity 가 없습니다(test_firstrun U2).
- [x] R2. 압축을 푼 자리의 첫 실행은 그대로 임시 신원을 세웁니다(test_firstrun N1).
