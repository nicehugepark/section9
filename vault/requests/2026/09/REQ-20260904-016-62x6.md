## Original

devops-engineer·security-engineer 판정(REQ-20260904-013).

지금: 0.60 기록만 → **비어 있음** → 0.90 무인 `doctor --recover --yes`.
오늘 실측 p90 이 84%, 낮 천장 90% — 그 선은 이상 신호가 아니라 평시 분포의
꼬리 안이다. 사다리의 유일한 중간 칸이 「남을 죽인다」였기 때문에 그것을 60%로
내렸다가 아홉 번을 죽였다(REQ-20260902-066). **중간 칸은 파괴적일 필요가 없다.**

다시 놓을 층:

    0.60          기록만
    0.75 + 오름    화면 배너 — 사람이 처음 보는 자리 (지금 화면에 아무것도 없다)
    0.85  5분 지속  파괴 없는 선제 회수 (--fix)
    0.90          여섯 조건 AND

여섯 조건: 비율 · **기울기**(0.85 이상 분 표본 연속 5개, 하락 없음) · 귀속(중계
독식) · `--fix` 선행 실패 · **조용함**(live 세션·클레임된 in-progress 없음) ·
예산(시간당 1·하루 3). 기본값은 off 유지.

화면에 띄울 숫자는 퍼센트가 아니라 **ETA** 다 — 실측 시간당 2,670이면 어느
시점에서든 여섯 시간이 안 남는다. 재료는 이미 있다(metrics_sample 의
sys.win_bound, 1분 주기·7일 보관). 읽는 쪽만 없다. 표본에 최다 점유자
(pid·이름·개수)를 5분 주기로 더해야 사후에 「중계였나 사용자 앱이었나」를 묻는다.

**켜기 전에 REQ-20260903-003 의 3,873표본에 그 조건을 겹쳐 몇 번 발동했을지
세어 보라 — 세어 보지 않은 문턱은 다시 60%가 된다.**

종료 도구 자체의 방어선(security): CLSID 게이트 승격(지금은 이름 한 글자로
판정한다) · kill 직전 재검증 + 프롬프트 타임아웃(지금은 확인 프롬프트가
TOCTOU 창을 무한대로 벌린다) · taskkill 절대경로 · 폭발 반경 사전 계측 ·
실패 원인 기록 · 발동 예산 · 감사 로그.

### TDD — 사다리의 중간 칸 (코드 착수 전)

자리는 `port_guard_tick`(bin/s9) 하나다. 지금 사다리: 0.60 기록 → (비어 있음)
→ 0.90 무인 `--recover --yes`. 오늘 p90 이 84% 라 그 선은 평시의 꼬리 안이다.

#### 정상
- [ ] L1. 0.75 이상이고 **오르는 중**(최근 표본 대비 +)이면 verdict 에
      `banner` 와 **ETA**(시간당 증가분으로 16,384 까지 남은 시간)가 실린다 —
      화면이 그릴 재료. 퍼센트가 아니라 시간을 준다.
- [ ] L2. 0.85 이상이 **5분 지속**(연속 5틱, 하락 없음)이면 파괴 없는 회수
      `_doctor("--fix")` 를 부르고 `action="fix"` 를 적는다. 사람도 남도 안 죽인다.
- [ ] L3. 0.90 이상이어도 **여섯 조건이 전부 참**일 때만 `--recover --yes` 다:
      비율 ≥0.90 · 기울기(연속 5표본 ≥0.85, 하락 없음) · 귀속(최다 점유자가
      중계) · `--fix` 를 이미 돌렸고 안 들었다 · 조용함(live 세션 0 · 클레임된
      in-progress 0) · 예산(시간당 1 · 하루 3).

#### 실패 적발 (오늘의 사고 모양)
- [ ] F1. 0.90 을 **한 표본** 넘은 것만으로는 안 죽인다 — 오늘 낮 천장 90% 가
      한 번 스쳤다고 처형되지 않는다.
- [ ] F2. 일하는 중(live 세션 있음)에는 0.95 여도 안 죽인다 — 사람의 연결을 끊는
      자리에 사람이 있다.
- [ ] F3. 최다 점유자가 사용자 앱(chrome 등)이면 안 죽인다 — 기존 P2 그대로.
- [ ] F4. `--fix` 를 아직 안 돌렸으면 `--recover` 로 못 간다 — 무해한 칸을 건너뛰지
      않는다.
- [ ] F5. 예산을 다 썼으면 기록만 하고 세운다.

#### 경계
- [ ] B1. 하락이 한 번이라도 끼면 지속 카운터가 0 으로 돌아간다.
- [ ] B2. 표본이 5개 미만이면(방금 뜬 서버) 기울기 판정을 「모른다」로 두고 죽이지
      않는다 — 모르면 안 죽인다.
- [ ] B3. 자동 발동(fix·recover)은 전부 guard 로그와 verdict 에 **왜**(어느 조건이
      참이었나)를 남긴다 — 다음에 아홉 번이 나면 각각의 이유가 있어야 한다.

#### 회귀
- [ ] R1. 기존 port_guard 시험(P2 사용자 앱 불가침·49% 침묵·67% watch·매 틱 sweep)
      그대로 초록.
- [ ] R2. 3,873표본(REQ-20260903-003-62x6)에 새 조건을 겹쳐 세어 본다 — 어제·오늘
      하루에 **0.90 처형이 몇 번 발동했을지**. 세어 보지 않은 문턱은 다시 60% 다.

화면 배너(0.75 + 오름) 자체는 designer·ux-writer·tech-writer·translator 몫이라
파생으로 뗀다 — 여기서는 verdict 에 재료(banner·eta)를 싣는 데까지다.
