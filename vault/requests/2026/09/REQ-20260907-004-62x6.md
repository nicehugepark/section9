### 원인 (reflog 실측 11:53)

카탈로그 항목이 문서보다 낡은 이유는 `git pull --rebase` 가 되풀이 실패하는 동안 **rebase 의 첫 걸음(`checkout @{u}`)이 옛 문서를 작업 트리에 잠깐 올려놓고**, 그 순간의 post-checkout 훅이 카탈로그를 옛 문서로 다시 지은 것이다. 이어지는 pick 이 충돌해 `rebase --abort` 가 작업 트리는 되돌리지만 카탈로그는 되돌리지 않는다.

- reflog: 10:36 이후 매 sync 마다 `rebase (start): checkout @{u}`(8f385a7, 맥미니 commit) → `rebase (pick): fc3011a(098)` → `rebase (abort)` 가 되풀이됐다(11:50:50·11:51:43·11:51:47·11:52:24·11:52:48·11:52:51 …).
- 카탈로그 파일 mtime 11:50:50 = 그 rebase 시작 시각, 문서 mtime 11:50:51 = abort 의 되돌림. 카탈로그의 094 항목은 `updated 10:26:20` — 8f385a7 시점의 문서 상태다.
- 같은 이유로 헤더의 「서버가 옛 코드로 실행 중」 경고도 떴다(checkout 이 bin/s9 의 mtime 을 바꾼다).

즉 두 결함이다: ① sync 의 rebase 가 충돌로 막혀 10:34 이후 code commit 다섯이 push 되지 않았다 ② rebase 의 임시 checkout 이 카탈로그 재생성을 촉발하고 abort 가 그것을 되돌리지 않는다.
