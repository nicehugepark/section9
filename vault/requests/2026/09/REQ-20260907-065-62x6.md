## Original

주인 지적 2026-09-07 19:35: 「나무는 뭘 말하는거야. 또 용어가 회귀됐나?」

**회귀다.** 「나무」는 git 의 **tree** — 한 커밋에 담긴 파일 전체(commit tree) 또는 지금 작업 중인 파일들(working tree) — 를 옮겨 쓴 것이다. 규약 2조 ③ 이 「작업 나무」를 이름 붙여 금지하는 바로 그 직역이고, 검사 표(`BANNED_TERMS`)에 그 항목이 있다. 그런데 표가 「작업 나무」 네 글자만 잡아 「돈 나무」「옛 나무」「지금 나무가 성한가」「나무 지문」은 전부 빠져나갔다.

## 같은 글자, 다른 뜻 셋 — 갈라서 다뤄야 한다
1. git tree → **tree** (남의 도구의 이름은 그대로) 또는 사실 그대로(「커밋된 파일 전체」).
2. `tests/test_port_pool.py:46·57`·`tests/test_human_reasons.py:68` 의 「구문 나무(AST)」 → **AST**.
3. `web/app/project.js:180` 「사람을 **나무라는** 말」 — 우리말 동사 나무라다. **직역이 아니다. 건드리지 않는다.** 검사 표를 넓힐 때 이것을 잡으면 안 된다(색 문맥 예외와 같은 결).
4. `harness/common/PROTOCOL.md:70` — 규칙이 그 말을 예로 든 자리. 그대로 둔다.

- AST(`test_port_pool.py`·`test_human_reasons.py` 의 「구문 나무」) → **AST**.
- 우리말 동사 **나무라다**(`web/app/project.js:180` 「사람을 나무라는 말」)는 **건드리지 않았다** — 직역이 아니다. 규약이 그 말을 예로 든 자리(PROTOCOL.md:70)도 그대로.

### 재발 방지 — 검사 표를 넓혔다
`BANNED_TERMS` 에 낱개 「나무 → tree」를 더했다. 표 자신이 걸리지 않게 왼쪽 글자는 이스케이프로 적었다(REQ-20260907-059-62x6 에서 배운 것 — 일괄 치환이 표를 ("키","키") 로 만들었던 자리). `banned_terms_in` 은 바로 뒤 글자가 「라」면 건너뛴다 — 나무라다는 잡지 않는다.

실측: 「원격은 commit 된 나무를 돈다」→ 경고 1건 · 「사람을 나무라는 말이었다」→ 없음 · 「commit 된 tree 를 돈다」→ 없음. no_metaphors·banned_terms·screen_lexicon·test_budget 30건 통과, 소스 글자 계약 62 그대로.
