구현 — 명령을 짓는 자리를 둘로 모으고 서버의 OS 를 따르게 했다

**뿌리**: 화면과 서버가 s9 명령을 **글자로 박아** 두었다. 네이티브 Windows 에는 PATH 에 s9 가 없어 그 글자를 붙여 넣으면 실행되지 않는다 — 안내가 안내가 아니게 된다.

**고친 것**
- `bin/s9.py` `s9_cmd(rest)`: os_platform() 이 Windows 면 `bin\\s9 …`, 아니면 `s9 …`. 알림 줄의 명령 넷(미등록 계정·서버 옛 코드·동기화·진단)이 이것을 지난다.

| `section9` | 그대로 | `section9` (소문자) | 제품 이름이자 `cd ~/section9` 로 치는 폴더 이름. 「섹션9」·`Section9`·`SECTION9` 전부 반려 — 저장소와 경로가 소문자다. |

| 이름 | **조건부** | 「이름」 — 성의 짝일 때만 | 한국어에서 「이름」 단독은 전체 이름(박성진)으로 읽힌다. 지금 화면은 **첫 물음에서 id 를 「이름」이라 부르고** 마지막 물음에서 given name 을 또 「이름」이라 부른다. 낱말을 바꿀 자리가 아니라 **id 자리에서 「이름」을 빼야** 이 낱말이 산다. |
| `full name` | **내림** | (화면에 세우지 않는다) | 사람이 칠 명령이 없다 — 치는 것은 `--first-name`·`--last-name` 뿐이고 `full` 은 코드가 만들어 내는 값이다. 성·이름을 물어 놓고 그 합에 또 이름을 붙일 까닭이 없다. 가리켜야 하면 「성과 이름」 또는 예시(「홍길동」). 「전체 이름」·「풀네임」도 반려. |

### 처방 — 「이름」을 한 자리에만 둔다

이 화면에 이름은 **둘뿐**이다. 셋으로 보이는 것은 라벨 탓이다.

1. **id** — 폴더 이름이 되고 경로·명령에 들어가는 값. 영문·숫자와 `.` `_` `-`.
2. **부르는 이름** — 화면 카드에 뜨는 이름. 성·이름으로 묻는다.

그러니 ① 첫 물음의 라벨을 「이름」에서 `id` 로 바꾸고 ② 두 번째 물음의 「한글 이름은 표시 이름에 둔다」를 「한글 이름은 뒤에서 성·이름으로 따로 묻습니다」로 바꾼다 — **약속한 자리의 이름과 실제 자리의 이름이 같아야** 한다. 지금은 「표시 이름」을 약속하고 「성/이름」을 묻는다.

### 몇 낱말로 알려 줄 수 있는가 — 할 수 있다, 「왜 다른가」가 아니라 「어디에 쓰이나」로

「식별자와 표시명은 다르다」는 몇 낱말로 못 준다. **「id 는 폴더 이름이 됩니다」는 된다** — 사람이 나중에 실제로 보게 될 자리를 가리키기 때문이다. 지금 문안의 「폴더 이름이 되는 id」가 이 화면에서 가장 잘 된 부분이고, 그 말을 첫 물음으로 올리면 따로 설명할 것이 없어진다. 반대로 「표시 이름」은 **가리킬 자리가 없어서**(처음 켠 사람은 카드를 아직 못 봤다) 몇 낱말로 못 알려 준다 — 그래서 내린다.

### 판정 요약

지금 말의 결함은 낱말이 아니라 **구조**였다. 한 물음에 ① 상황 ② 규칙 ③ 기본값 ④ 출처

머리말로 올렸다. 규칙은 물음에 한 번, 오류에는 예시만 — 같은 문장을 두 번 쓰지 않는다.

고친 것 여섯:
1. 해라체를 전부 존댓말로 (…습니다 / …주세요). s9-design R1 과 규약 「말과 태도」 1조.
2. 변수 뒤 조사를 없앴다 — 「박성진」 는 → 「박성진」 — 이 이름은 …. 이름이 무엇이든 맞는다.
   (더 나은 길: 받침을 보고 은/는을 고르는 josa 헬퍼. 지금은 헬퍼 없이도 맞는 어순으로 썼다.)
3. 대시·괄호로 이어 붙인 한 문장을 끊어, 줄바꿈을 코드가 정하게 했다(터미널 폭 64칸 기준).
4. 「영문·숫자와 . _ - 만」 규칙은 물음에 한 번. 오류는 규칙 대신 **예시**를 준다.
5. 「id」는 첫 등장에서 한 줄로 정의하고 끝까지 그 말만 쓴다. 「표시 이름」은 화면 문구에서
   뺐다 — 그 자리를 「화면에 보일 이름」으로 풀고, `--display` 는 명령 예시에만 남긴다.
6. 터미널에 백틱(`)이 글자 그대로 찍히고 있었다. 명령은 백틱 대신 **들여쓴 제 줄**에 둔다
   — 그래야 마우스로 끌어 복사해도 따옴표가 안 섞인다.

### A. id 물음 — 이 컴퓨터의 계정 이름을 id 로 쓸 수 있을 때 (지금의 1번)

```
◌ 이 컴퓨터에서 section9 을 처음 켰습니다.
  이 컴퓨터를 쓰는 사람을 등록합니다.

  먼저 id 를 정합니다 — 기록이 쌓일 폴더 이름입니다.
  영문·숫자와 . _ - 만 쓸 수 있습니다.
  이미 등록된 사람이 있습니다: nicehugepark
  다른 컴퓨터에서 쓰던 이름이면 그 이름을 그대로 적으세요.

◌ id (Enter = sjpark1 · 이 컴퓨터의 계정 이름):
```

왜 이렇게 — 물음 줄에는 **지금 칠 것 하나**만 남긴다. 「등록돼 있지 않다」는 상황 보고는
머리말로 올렸다. 기본값 옆의 출처(`· 이 컴퓨터의 계정 이름`)는 주인이 물었던
「모든 사람에게 내 계정이 뜨는 거냐」에 그 자리에서 답하는 줄이라 그대로 살렸고, 대시를
가운뎃점으로 바꿔 괄호 안에서 두 토막으로 읽히게 했다. 「이미 있는 이름」은 무엇에 쓰는지를
말하지 않으면 정보가 아니라 잡음이다 — 「그대로 적으세요」 한 줄이 그 이름의 용도다
(attach 라는 말을 화면에 쓰지 않고 attach 를 시키는 길이다).
※ 등록된 사람이 없으면 그 두 줄(「이미 등록된 사람…」·「다른 컴퓨터에서…」)은 빼고 찍는다.

### B. id 물음 — 계정 이름을 id 로 쓸 수 없을 때 (지금의 2번)

```
◌ 이 컴퓨터에서 section9 을 처음 켰습니다.
  이 컴퓨터를 쓰는 사람을 등록합니다.

  이 컴퓨터의 계정 이름은 「박성진」입니다.
  id 는 기록이 쌓일 폴더 이름이라 한글은 쓸 수 없습니다.
  영문·숫자와 . _ - 로 쓸 id 를 정해 주세요.
  한글 이름은 다음 물음에서 따로 받습니다.

◌ id:
```

왜 이렇게 — 사람이 처음 만나는 말이 「당신 이름은 쓸 수 없다」이면 거부로 읽힌다. 그래서
차례를 **사실 → 까닭 → 할 일 → 안심** 넷으로 세웠다. 「폴더 이름이라」가 까닭이고,
「한글 이름은 다음 물음에서 따로 받습니다」가 안심이다 — 이 한 줄이 없으면 사람은 제 이름을
못 쓰는 줄 알고 아무 영문이나 친다. 「표시 이름에 둔다」는 내부 필드 이름이라 뺐다.
「박성진」입니다 — 조사 대신 「입니다」로 받아, 이름이 무엇으로 끝나도 문장이 맞는다.

### C. id 오류 (지금의 OUT 줄)

```

  영문·숫자와 . _ - 로 다시 적어 주세요.
  예: sungjin · sj.park · park-sj
  한글 이름은 다음 물음에서 따로 받습니다.
```

왜 이렇게 — 오류의 세 몫(무엇이 안 됐나 / 왜 / 지금 할 일)을 한 줄씩 나눴다. 물음에서
규칙을 이미 읽은 사람에게 규칙을 그대로 되풀이하는 것이 지금의 결함이라, 오류가 더하는
것은 **예시**다(규칙보다 예가 강하다). 예 셋은 한 사람 이름을 세 방식으로 적어, 붙여
쓰기·점·붙임표가 다 된다는 것을 규칙 문장 없이 보여 준다. 마지막 줄은 A 경로로 들어와
한글을 친 사람에게는 처음 듣는 말이고, B 경로로 들어온 사람에게는 되짚는 말이다 —
규칙이 아니라 안심이라 되풀이해도 잡음이 되지 않는다.
※ 세 번 되풀이되는 것이 길면, 두 번째부터는 첫 두 줄만 찍는 갈래도 된다(리드 판단).
