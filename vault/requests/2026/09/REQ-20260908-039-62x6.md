## Original

주인 2026-09-08 14:01: 「vault에서 section9 프로젝트의 문서들을 다 가져가는건 싫은데 말이지... 아무것도 없이 깨끗하게 시작하는 방법은 없나?」

지금: `s9 instance init` 이 이 저장소를 통째로 clone 한다. vault/ 는 track 이라 **문서 2,344개가 그대로 따라가고**, git 이력에도 남는다.

**긴장의 핵심**: 지금의 업그레이드 길이 `git merge upstream/main` 이라 **이력을 공유해야** 한다. 그런데 이력을 공유하면 upstream 의 vault 문서가 따라오고, 지운다 해도 이력에는 남는다.

푸는 길 둘.
1. **새 이력 + 파일 단위 업그레이드**: 인스턴스는 코드와 빈 데이터 뼈대만 담은 **한 커밋**으로 시작한다(이력 없음). 업그레이드는 merge 가 아니라 upstream 의 **코드 경로만** 파일로 덮어쓴다(fetch 뒤 그 경로만 꺼내 commit). vault 를 건드리지 않으므로 문서가 되돌아오지 않고, 인스턴스가 코어를 고치지 않는다는 규율과도 맞는다.
2. **얕은 clone + 문서 삭제**: 이력을 얕게 가져오고 vault 를 지운 커밋으로 시작. 이력은 짧지만 merge 업그레이드가 얕은 저장소에서 지저분해진다.

리드 권고는 1번이다. 확인할 것: 무엇을 코드로 보고 무엇을 데이터로 볼지 목록을 한 곳에 두고(지금 `INSTANCE_TRACK_GITIGNORE` 옆), 업그레이드를 **실제로 한 바퀴 돌려** 확인한다 — 만들고, upstream 에 변화를 주고, 받아 보는 것까지.
