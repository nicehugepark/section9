commit 1ff9420a3 · 5faebe61a. 내가 만든 결함이고, 뿌리는 「캡처에는 알파가 없다」는 것이다.

19:0x 에 래스터 아이콘을 다시 구우면서 넷을 다 바탕색(#141518) 위에 찍었다. 그래서
favicon.ico 가 RGBA 에서 RGB 로 바뀌었고, 탭과 북마크 줄은 제 바탕색 위에 그림을
얹으므로 렌즈가 검은 사각형을 달고 앉았다. 옛 favicon.ico 는 RGBA 였다.

**고친 법**: 같은 그림을 흰 바탕과 검은 바탕에 각각 찍어 알파를 되돌린다.

    검은 바탕 B = C·a      흰 바탕 W = C·a + 255·(1−a)
    a = 1 − (W−B)/255  ·  C = B/a

합성이 source-over 인 한 근사가 아니라 정확하다. favicon.ico 의 16·32·48 은
투명으로, 앱 아이콘 셋은 종전대로 불투명으로 굽는다 — 홈 화면·앱 목록은 투명을
제 맘대로 메우므로 그쪽은 바탕이 있는 것이 맞고 옛 파일도 그랬다.

**그리고 한 번 더 물릴 뻔한 자리**: 주소의 지문을 favicon.svg 하나에만 달아 두었다.
.ico 를 고쳐도 주소가 그대로면 북마크는 옛 그림을 쥔다. link 셋이 각각 제 파일의
지문을 달게 했다(favicon.ico?v=834c9b43 · apple-touch-icon.png?v=77137321).

**확인한 것**: 새 favicon.ico 의 세 장이 전부 colortype 6(RGBA)이고, 32px 의 네
모서리 알파가 0, 렌즈 가운데가 255 다. 앱 아이콘 셋은 colortype 2(불투명) 그대로다.
시험 E9 가 그 차이를 지키고 E7 이 지문 셋을 지킨다.

### 2026-09-18T20:39:21+09:00 response (agent: lead:claude-opus-5, by nicehugepark)

검은 네모가 실제로 걷혔는지 화소로 확인했다 (맥에서)

16px 탭 아이콘을 눈으로 보는 것보다 **화소를 읽는 쪽이 확실해서** 그렇게 했다.
favicon.ico 안의 PNG 세 장을 직접 풀어(zlib·언필터) 알파를 읽었다:

  16x16 : 네 귀퉁이 알파 0 · 가운데 알파 255
  32x32 : 네 귀퉁이 알파 0 · 가운데 알파 255
  48x48 : 네 귀퉁이 알파 0 · 가운데 알파 255

즉 **뒤가 비어 있고 렌즈만 찍혀 있다.** RGBA 이기만 한 것이 아니라 실제로 투명이다
(RGBA 로 굽고 모서리를 검게 칠해 두는 자리를 가르려고 귀퉁이까지 읽었다).

앱 아이콘 셋은 goal 대로 **불투명 그대로**다 — apple-touch-icon(180) · icon-192 ·
icon-512 가 모두 colortype 2(RGB)다. 홈 화면이 투명을 제멋대로 칠하는 자리라 이쪽은
불투명이 맞다.

goal 의 셋째(시험이 그 차이를 지킨다)도 이미 서 있다 — `tests/test_mark_eyes.py` 의
E9 가 「favicon.ico 세 장은 RGBA 에 모서리가 비어 있고 앱 아이콘 셋은 불투명」을 재고,
여기서 9건 통과한다. brand_assets · brand_mark 도 통과.

확인 포인트의 북마크 쪽 단서(「안 바뀌면 북마크를 지웠다 다시 담아 보라」)는 파일이
아니라 브라우저가 쥔 사본의 문제라, 파일이 옳은 지금은 그 안내로 충분하다.
