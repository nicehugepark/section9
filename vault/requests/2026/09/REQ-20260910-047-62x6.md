### 재현됐다 — 리드가 잰 46.9px 은 잘리지 않는 쪽의 상자다 (designer)

**결함은 살아 있다. 기본 스킨·기본 밀도·창 1280·1366·1440 에서 라벨이 잘린다.**
리드가 잰 `.lincap` 46.9px 은 언제나 46.9px 이다 — 그 상자는 `flex:none` 이라
줄지 않기 때문이다. 잘리는 것은 그 상자가 아니라 **부모 칩(`.lin`)의
`overflow:hidden` 을 통과해 보이는 부분**이다. DOC-20260910-001-62x6 이 적은 함정의
반대편이고(거기서는 상자가 안 겹치는데 잉크가 겹쳤다), 여기서는 **상자가 온전한데
잉크가 반 글자**다. 상자를 재면 영원히 안 보인다.

**실측** (실서버 9909 · 기본 밀도 · 보이는 폭 = 칩 클립 상자 ∩ 라벨 상자):

| 스킨 | 창 | 카드 안쪽 | 칩 폭 | 라벨 보이는 폭 | 값 보이는 폭 |
|---|---|---|---|---|---|
| ledger | 1280 | 177 | 14.9 | **14.9** / 46.9 | 0 |
| ledger | 1366 | 191 | 29.2 | **29.2** / 46.9 | 0 |
| ledger | 1440 | 203 | 41.6 | **41.6** / 46.9 (5.3px 깎임) | 0 |
| soft | 1440 | 163 | 0 | **0** / 46.9 | 0 |

| ledger | 1920 | 283 | 91.7 | 46.9 (온전) | 40.8 (온전) |

원래 노트의 「5.3px」은 **깎인 양**이다(46.9−41.6). 리드가 잰 그 창(1440)이
바로 그 자리다. 배율 1.25 캡처를 5배로 확대해 눈으로도 봤다 — 「만든 사」 뒤에
「람」의 왼쪽 반쪽이 남는다(첫 그림). 값(「타치코마」)은 한 화소도 안 보인다.

### 고친 것 — 줄이지 않고 뺀다 (web/css/board.css)

```
@container (max-width:243px){ .card .m.mwho>.lin{display:none} }
```

문턱은 잰 값에서 온다: 배지(맡은 사람) 87.8 + 틈 10 + **계보 77.3** + 틈 10 +
프로젝트 9ch 58 = 243.1. 계보 77.3 = 라벨 46.9 + 라벨 오른여백 4 + 값 26.4
(두 글자 20.4 + 말줄임 6). 값이 그보다 짧으면 「만든 사람 …」이 되어 아무것도
말하지 않는다 — `.proj` 의 9ch 바닥과 같은 자다(REQ-20260909-064-62x6).
`.card{container-type:inline-size}` 는 이미 있던 것을 그대로 쓴다(id 줄의 176px
문턱이 쓰는 그 컨테이너). 근거는 CSS 주석에 수식째 적었다.

**빠진 사실은 사라지지 않는다** — 문서 머리의 계보 줄이 온전히 말하고, 칩이
빠진 자리는 프로젝트 이름이 받는다. 칩이 서는 조건 자체가 좁다(만든 사람 ≠
맡은 사람이거나 사람이 아닌 것이 만들었을 때만).

### 대안 셋을 재 봤다
- ㉠ **채택**: 문턱을 넘으면 칩을 통째로 뺀다. 순수 CSS · 선례 있음 · 계약 불변.
  약점: 문턱이 잰 값이라 계정 이름이 지금(12자)보다 훨씬 길면 배지가 넓어져
  다시 잘릴 수 있다. 그때도 **덜 보이는 쪽으로** 틀리게 문턱에 여유를 뒀다.
- ㉡ 칩 전체 말줄임 → 「만…」. REQ-20260910-009 이 이미 반려한 것.
- ㉢ 라벨에 바닥(min-width) → 칩이 상자를 넘어 이웃 잉크 위에 찍히거나,
  줄을 자르면 프로젝트 이름이 대신 반 글자가 된다. DOC-20260910-001-62x6 이 금한 짝.
- ㉣ `.lin` 에 `flex:1` + 컨테이너 질의로 **남는 폭**을 직접 재기 — 배지 길이에
  영향받지 않는 유일한 순수 CSS 안이지만, 칩이 남는 폭을 다 먹어 프로젝트가
  카드 오른끝으로 밀린다(18장 전부 모양이 바뀐다). 이번 크기(S)의 일이 아니다.
