### 2026-09-06T20:49:37+09:00 response (agent: sub:designer, by nicehugepark)

프로젝트 범위를 「프로젝트마다 한 묶음」에서 **한 묶음 + 고르는 칸**으로 바꿨다. 고친 자리는 `web/app/settings.js` 의 `showRoster()` 와 `web/css/density.css` 한 줄이다. 서버 API 는 그대로 — `/api/roster` 가 이미 모든 프로젝트 행을 준다.

**구조** — 「내 것」 / 「프로젝트」 / 「공용」 세 묶음은 그대로고, 가운데 묶음만 이렇게 선다:

    프로젝트
    고른 프로젝트에서만 씁니다
    [ Section9 하네스 시스템 (section9) ▾ ]
      에이전트 1 · release-captain …
      스킬 1 · vault-rules …
      [ 이름 ] [+ 에이전트 추가] [+ 스킬 추가]

**기본 선택은 셋 중 먼저 맞는 것**: ① 이 화면에서 마지막으로 고른 것 ② 헤더의 프로젝트 필터가 좁혀 둔 프로젝트 ③ 목록의 첫 프로젝트. 어떤 slug 도 코드에 적지 않는다 — 기본 프로젝트도 여럿 중 하나일 뿐이다. 칸의 출처는 `window.__projects` ∪ `/api/roster` 의 project 행이고, 같은 slug 가 두 번 들어와도 옵션은 하나다.

**대안 비교**
- (A) 채택 — 한 묶음 + select. 결정이 하나로 모이고(어느 프로젝트를 고칠 것인가), 프로젝트가 10개여도 판 길이가 그대로다. 되돌리기: 칸을 다시 바꾸면 끝(파괴적 조작 없음).
- (B) 프로젝트마다 묶음(현행) — 전부 한눈에 보이지만 N배로 길어지고, 스크롤이 곧 탐색이 된다. 주인의 반려 사유 그대로.
- (C) 왼쪽 설정 목록에 프로젝트를 펼침 — 화면 이동이 한 번 더 늘고, 「설정 항목」과 「데이터」가 같은 자리에 섞인다. 프로젝트가 늘어날수록 설정 목록이 오염된다.

**세부 판단**
- 칸은 새 부품을 만들지 않고 이 제품의 `.uf` select 문법 그대로다(`#as-user` 와 같은 짝: 위에 `.path` 설명 줄, 아래 칸). 색면·띠 없음.
- 프로젝트가 하나뿐이어도 칸은 보인다 — 늘어날 자리라는 것을 화면이 말해야 한다.
- 아무것도 없는 프로젝트 옵션에는 ` · 없음` 을 붙인다. 고르기 전에 어디에 무엇이 있는지 보이면 빈 판을 열어 보는 걸음이 없어진다. (대안: 옵션마다 `에이전트 N·스킬 M` 을 붙이는 안 — 고르는 칸이 표 노릇을 하게 되어 뺐다.)
- 다른 프로젝트로 옮기면 펼쳐 둔 항목은 접는다 — 이 목록의 것이 아니다.

**검증** — 이 저장소에는 프로젝트가 하나뿐이라 갈리는 것을 눈으로 볼 수 없어, 실브라우저(Windows Chrome + CDP)에서 `/api/roster` 응답과 `window.__projects` 만 화면 쪽에서 갈아 끼워 두 프로젝트 상태를 만들고 **실키보드로** 칸을 바꿨다(저장소 데이터는 건드리지 않았다). section9 → `release-captain`·`vault-rules`, demo-portal → `form-auditor` 로 목록과 추가 칸 대상이 함께 갈렸다. 캡처 셋: ① 실제 저장소 1440 ② 두 프로젝트 1440 ③ 바꾼 뒤 768 태블릿.

**리드에게 넘기는 것 둘**
1. 회귀 시험을 하나 세울 자리가 있다 — 「`showRoster` 절에 프로젝트 slug 가 문자열로 박히지 않는다」. 이번 예산 안에서는 지정 시험 넷만 돌렸다(모두 OK).
2. 칸의 라벨이 프로젝트 등록명을 그대로 쓰는데, 이 저장소의 등록명이 `Section9 하네스 시스템` 이라 화면에 「하네스」가 뜬다. 헤더 프로젝트 필터도 같은 이름을 쓰므로 화면 코드가 아니라 **프로젝트 표시명(`s9 project set section9 --name …`)** 을 고칠 일이다.
