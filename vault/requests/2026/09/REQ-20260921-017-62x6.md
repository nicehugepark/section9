### 2026-09-21T12:17:38+09:00 response (agent: lead:claude-opus-5, by nicehugepark)

commit 의 이름 칸에는 **그 사람의 이름**이 서게 했습니다. 판정과 까닭을 남깁니다.

### 판정 — 이름입니다(id 가 아닙니다)
- 이 제품은 이미 그 물음에 답해 두었습니다(REQ-20260915-032-62x6): **기계가 읽는 자리에는 id, 사람이 읽는 자리에는 이름**입니다. `git log` 와 GitHub 의 commit 목록은 사람이 읽는 자리입니다. 화면이 「박성진」이라 부르는 사람이 commit 에서는 `nicehugepark` 으로 서면 같은 사람이 자리마다 다른 이름이 됩니다.
- GitHub 이 commit 을 계정에 잇는 것은 이름이 아니라 **메일**입니다. 이름을 사람의 글자로 두어도 이어짐은 그대로이고, 사다리의 메일 칸은 손대지 않았습니다.
- 원문이 든 반대 근거(「GitHub 은 로마자가 관례라 한글 이름이 어색하다」)는 버리지 않고 자리를 주었습니다 — 프로필의 `display` 에 제 로마자 표기를 적으면 그 글자가 이깁니다. 도구가 로마자를 짐작해 짓지는 않습니다(같은 문서의 규칙). 새 설정은 만들지 않았습니다.

### 고친 자리
- `bin/s9_firstrun.py`: `person_full_name(프로필)` 을 세우고 `pick_identity` 의 이름 사다리를 넷으로 폈습니다 — 이름 → github → section9 의 id → 계정. 임시 칸은 `s9 <계정>` 그대로입니다(`s9 doctor` 가 그 모양으로 「우리가 넣은 값」을 가릅니다).
- `commit_name()`: 꺾쇠·줄바꿈·제어문자가 든 이름은 손보지 않고 **버리고 다음 칸으로** 내려갑니다. `이름 <메일>` 줄이 깨지는 자리이고, 사람이 쓴 글자를 도구가 고치면 그 사람이 정하지 않은 표기가 이력에 박힙니다.
- `bin/s9.py` 의 `user_full_name` 이 그 함수를 지납니다 — 이름을 짓는 자리는 하나입니다. 규칙이 `s9_firstrun` 쪽에 있는 까닭은 그 모듈이 `s9.py` 를 실어 읽을 수 없기 때문입니다(서로 부르는 모양이 됩니다). 규칙을 두 벌로 두면 화면의 이름과 commit 의 이름이 갈립니다.
- `_firstrun_module()` 은 한 번 실어 두고 다시 씁니다 — 사람 수만큼 불리는 자리(`user_names`)가 생겨, 부를 때마다 파일을 읽어 실행하면 목록 한 번이 파일 읽기 여러 번이 됩니다.
- `s9 code` 의 안내 한 줄이 메일만이 아니라 **이름 바꾸는 명령도** 함께 말합니다.
