버린 프로젝트의 열람·되돌리기 — 격리 vault 실측 시나리오 (tests/test_trash_project_access.py).

boss(admin) 가 만든 프로젝트 `shop` 에 mem 이 contributor 로, gone 이 만료된 옛
멤버로 있다. outsider 는 남이다. 계약은 하나다 — **버리는 일이 보이는 범위를
바꾸지 않는다.** 넓히면 삭제가 격리를 우회하는 열람 경로가 되고, 좁히면 멤버가
자기 프로젝트를 되돌릴 수 없다.

- [x] S1 정상(기준선) — 프로젝트가 살아 있으면 버린 요청은 멤버에게 보이고 남에게는 안 보인다
- [x] S2 실패 재현 — 버린 프로젝트 문서가 그 명부의 활성 멤버에게 보인다
- [x] S3 경계 — 남과 **만료된 옛 멤버**는 버린 프로젝트를 못 본다 (넓히지 않는다)
- [x] S4 실패 재현(진짜 반경) — 프로젝트를 버려도 그 프로젝트의 문서는 멤버에게 그대로 보인다: 버린 것도, **살아 있는 것도**
- [x] S5 실패 재현 — 멤버가 되돌리면 원래 자리로 가고 등록부가 그 slug 를 다시 안다
- [x] S6 경계 — 남은 restore 도 purge 도 못 한다 (되돌릴 수 없는 쪽이 더 비싸다)
- [x] S7 회귀 — 휴지통 행이 판정이 보는 원 필드(slug·creator_raw·assignee)를 싣는다
- [x] S8 회귀 — 판정이 .trash 를 보게 됐다고 **등록부까지** 보지는 않는다 (버린 프로젝트가 목록에 다시 서면 버린 일이 무효)
