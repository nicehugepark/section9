## Original

사용자가 20:20 에 리드가 알려 준 절차를 그대로 밟다가 부딪혔다:

    $ ~/section9/bin/s9 metrics report --at now
    Traceback (most recent call last):
      File "bin/s9", line 18206, in cmd_metrics
        base = datetime.datetime.fromisoformat(at)
    ValueError

결함은 둘이다.
① `--at` 이 ISO 문자열만 받는다. 사람이 "지금"을 가리키려고 가장 먼저 치는 낱말이 now 인데 그것이 안 통한다. (--at 을 아예 빼면 지금이 되지만, 알려 준 절차가 --at now 였고 그 절차를 리드가 확인 없이 냈다.)
② 못 알아들은 입력에 **트레이스백으로 답한다**. 계기는 사고가 났을 때 쓰는 도구다 — 그 자리에서 파이썬 스택을 읽게 하면 도구가 사고를 하나 더 만든다.

받아들일 형식: now/지금 · HH:MM(오늘) · HH:MM:SS · ISO 전체. 그 밖은 한 줄로 형식을 알려 준다.

### 고친 것과, 그 김에 드러난 것

`_metrics_at(at, now=None)` 하나가 `--at` 이 받는 말을 정한다: `now`·`지금`·
`현재` · `20:19` · `20:19:30` · ISO(시간대 있든 없든). 못 알아들으면 ValueError
를 올리고, CLI 가 그것을 **받아들이는 형식 한 줄**로 옮겨 종료코드 2 로 끝낸다.

`--at` 도움말도 고쳤다 — 전에는 "(ISO, 기본 지금)" 이라 now 를 못 받는다는
사실이 화면에 없었다.

**곁가지 하나**: 처음 고칠 때 `return 2` 로 두었는데 종료코드가 0 이었다.
`main()` 이 `args.fn(args)` 의 반환을 보지 않는다 — 이 저장소의 관행은
`sys.exit()` 이다. 시험(F3)이 그 자리를 잡았다.

**실측** — 사용자가 부딪힌 그 명령이 이제 답한다:
```
$ bin/s9 metrics report --at 19:30
창 2026-09-02T19:20:00+09:00 ~ 19:40:00 — 표본 40
판정: 회선 — 대조군·이름 풀이까지 함께 죽었다
  실패 api 23 · 대조군 23 · 이름 23
```
