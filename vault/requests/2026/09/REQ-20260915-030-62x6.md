### 2026-09-15T16:12:39+09:00 response (agent: sub:backend-developer, by nicehugepark)

첫 실행이 id 다음에 성·이름을 묻는다 (커밋은 리드의 몫).

**묻는 자리**: bin/s9.py 의 first_run_person_name(ask, out, tries, profile) — 성 먼저,
이름 다음으로 묻고 (이름, 성) 을 돌려준다. 비우면 ('', '') 로 건너뛰고 등록은 그대로
간다 — 이름이 없다고 등록이 끊기지 않는다. 줄바꿈·제어문자가 든 답은 그 자리에서
까닭을 말하고 되묻는다. profile 을 주면 이미 부를 이름이 있는 사람에게는 묻지 않는다
(두 번째 컴퓨터의 attach).

**부르는 자리**: cmd_code 의 first_run_identity 바로 뒤. id 가 정해진 뒤에만 묻고
(skip 이면 묻지 않는다), 등록 subprocess 가 끝난 다음 do_user_update 로 이름을 앉힌다 —
add 로 들어오든 attach 로 들어오든 쓰기는 한 벌(do_user_update)이다. 저장에 실패하면
등록을 되돌리지 않고 다시 적을 한 줄(s9 user update … --last-name … --first-name …)만
찍는다.

한계: 실제 첫 실행(TTY 대화)은 이 컴퓨터에 이미 계정이 등록돼 있어 끝까지 재현하지
못했다 — ask/out 을 주입해 함수 단위로 검증했고, 부르는 자리는 읽기로 확인했다.
새 컴퓨터의 첫 실행 확인은 사람 쪽에서 한 번 필요하다.
