'on'/'off' 로 명시돼 있으면 그것, 없으면 파생 기본값(jira_site 가 있거나 Jira 를 이은
프로젝트가 하나라도 있으면 True).

- [ ] S1. 정상 — config 에 jira_enabled=on 이면 jira_state(user)['enabled'] 가 True, off 면 False (파생 조건과 무관하게 명시가 이긴다).
- [ ] S2. 회귀 — 명시가 없고 jira_site 가 있으면 True; 명시도 site 도 없지만 Jira 를 이은 프로젝트가 있으면 True (이미 쓰던 사람이 이 변경으로 꺼지지 않는다).
- [ ] S3. 경계 — 아무것도 없는 사용자는 False, jira_state('') 도 enabled 키를 bool 로 준다.
- [ ] S4. 실패 경로 — 담당(user)이 off 인 요청은 jira_export_wanted(meta) 가 (None, '…꺼져 있다…') 를 준다.
- [ ] S5. 예외 — 같은 요청도 manual=True(s9 jira create)면 막지 않는다(까닭 '').
- [ ] S6. 경계 — meta 의 user 가 비면 종전대로 동작한다(스위치가 막지 않는다).
- [ ] S7. 실패 경로 — jira_pull_targets() 가 꺼진 사용자의 요청을 대상에서 뺀다(user 가 빈 문서는 남는다).
- [ ] S8. 회귀 — 기존 tests/test_jira_settings.py · tests/test_jira_content.py 가 그대로 통과한다.
