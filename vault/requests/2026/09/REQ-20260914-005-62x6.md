1) bin/s9.py sync_resolve — fetch 뒤 refs/stash 의 꼭대기를 재고(stash_before), rebase 루프가 끝난 자리에서 _sync_reclaim_autostash(stash_before) 를 부른다. 이미 저장소에 있는 그 함수를 그대로 쓴다(가지의 _sync_stash_top·_sync_restore_stored_autostash 는 같은 자리를 다르게 고친 것이라 옮기지 않았다). rebase 가 returncode 0 으로 끝나도 되돌리기만 실패하면 autostash 가 보관함에 남는 그 기제다.

2) bin/s9-doctor sync_info/sync_verdict — git stash list 에서 줄 끝이 autostash 인 것을 세어 autostash 로 싣고, orphan 이 없으면 warn 으로 올리며 git stash list · git stash apply · git stash drop 을 함께 적는다.

3) 덧붙여 고친 것 — orphan(critical) 줄이 이기면 이미 쌓인 건수가 그 뒤에 가려졌다. 이 머신에서 실제로 그랬다: orphan 파일은 1건인데 보관함의 autostash 는 8건이었고 화면에는 「1건」만 떴다. 그래서 stuck 이 orphan 보다 많으면 critical 줄에도 「보관함에는 autostash 가 N건 있다」를 붙이고 조언에 나머지를 보는 법을 적었다. 이것이 없으면 요청의 목적(이미 쌓인 것을 사람에게 보인다)이 이 머신에서 그대로 안 이뤄진다.
