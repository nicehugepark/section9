### 디자인 전수 점검 — ⏸ 에서 시작해 체계로 (designer)

실측: Playwright chromium/webkit, 1440x1000, 배율 1·1.25, 스킨 6종(ledger·calm·glass·terminal·grid·cobalt) × 탭 5종(Board·Docs·Audit·Settings·Projects). 확대 캡처 4·5배.

### 1. ⏸ 버튼의 진단 — 왜 못생겼나

**한 줄: ⏸ 는 제 모양이 틀린 것이 아니라, 손잡이 사전이 없는 줄에 혼자 손잡이 규칙을 지키고 서 있어서 이물로 읽힌다.**

id 줄(`.card .id`)을 5배로 떠서 잰 것(첨부 1·2):

| 원소 | 그리는 법 | 획/잉크 | 색 | 상자 |
|---|---|---|---|---|
| 점(livedot) | SVG 원 | 1.5px 테 | `--dot-live` | 7x7 |
| id 글자 | mono 10px | 글자 획 ~1px | `--faint` #9096a0 | 텍스트 |
| **⏸** | **SVG 채움** | **막대 3px x 2, 면 42px²** | **`--muted` #5c6470** | **과녁 27x27 / 그림 13x13** |
| ⏱ | **폰트 코드포인트 U+23F1** | 외곽선 ~1px | `--c-inprogress` #b45309 | 글자 |
| 경과 글자 | mono 10px | ~1px | `--c-inprogress` | 텍스트 |

여섯 가지 병이 한 자리에 겹쳐 있다.

1. **잉크 농도가 이웃의 3~4배다.** ⏸ 의 잉크는 3x7 막대 둘 = 42px² 의 **채운 면**이다. 같은 줄의 mono 10px 글자 한 자는 잉크가 8~12px² 이고 전부 **획**이다. 게다가 색이 `--muted`(#5c6470, 대비 5.97:1)로 이웃 id 글자 `--faint`(#9096a0, 3.01:1)보다 진하다. **줄에서 가장 조용해야 할 자리에 줄에서 가장 진한 덩어리가 있다** — 위계가 뒤집혔다.
2. **모양이 정사각형이라 재생기 글리프로 안 읽힌다.** 막대 3 + 틈 1 + 막대 3 = 가로 7, 세로 7. 잉크의 86%가 채워진 정사각이다. 재생기의 ⏸ 는 보통 막대 폭:높이가 1:3~1:3.5 인데 여기는 1:2.33 이라 막대가 아니라 **슬래브** 두 장이다. 사람 눈에는 두 막대가 아니라 네모난 덩어리 하나로 들어온다.
3. **모양 사전이 충돌한다.** 이 제품의 점 어휘(s9-design 「일곱 얼굴」)에서 **사각은 「멎은 것」의 모양**이다(▫ 멈춤 · ▪ 죽음 · ⊟ 사람이 중단해 둠). 그런데 **행위** 버튼인 ⏸ 가 같은 12px 줄에서 사각 덩어리로 서 있다. 상태의 알파벳과 행위의 알파벳이 같은 모양을 쓴다.
4. **이웃 마크와 그리는 법이 다르다.** ⏱ 는 SVG 가 아니라 **폰트 글리프**(`board.css:418 .elapsed::before{content:"⏱ "}`)다. 윈도우에서는 Segoe UI Symbol 의 가는 외곽선 시계, **맥·iPad Safari 에서는 컬러 이모지**로 나온다(WebKit 에서도 같은 코드포인트 확인). 손으로 격자에 맞춘 13px SVG 와 OS 가 그려 주는 글자가 1em 거리에 나란히 선다.
5. **과녁이 줄을 뚫는다.** 과녁 27px, 줄 높이 12px(1em). ledger·terminal·grid 에서 버튼은 줄 위아래로 **각각 7.5px 씩 넘쳐** 제목/카드 모서리 위에 보이지 않게 얹힌다. calm·glass·cobalt 에서는 반대로 **줄이 두 줄로 접힌다**(실측 rowH 12 → 24~26). 즉 **⏸ 가 있으면 카드의 줄 수가 달라진다** — 손잡이가 리듬을 바꾼다.
6. **배율에서 흔들린다.** 막대 3px · 틈 1px 은 배율 1.25 에서 3.75/1.25 화소가 되어 반올림이 좌우로 갈린다 — 확대 캡처에서 **왼 막대와 오른 막대의 폭·농도가 눈에 띄게 다르다**(첨부 4). 배율 1 에서는 딱딱한 한 덩어리, 1.25 에서는 두께가 다른 막대 둘. 같은 그림이 두 얼굴이다.

**그런데 이 버튼은 네 번(REQ-20260830-042-62x6/043, 20260831-006/019)에 걸쳐 그림 안쪽 기하만 고쳐 왔다.** viewBox 눈금·거울 대칭 잔차·mask 반올림까지 화면에서 가장 정밀하게 다듬은 원소다. 문제는 **그 정밀함이 전부 그림 안에서 끝났고, 줄과의 관계는 한 번도 재지 않았다**는 것이다. 그리고 결정적으로 — **이 줄에서 과녁·모서리·시각 피드백을 가진 손잡이는 ⏸ 하나뿐이다**(아래 2절). 규칙을 지키는 것이 혼자면 그것이 튄다. **⏸ 를 다섯 번째로 다시 그리는 것은 답이 아니다. 없는 손잡이 사전을 만들고 그 안에 앉히는 것이 답이다.**

### 2. 전수 실측 — 체계의 병

### ① 손잡이 사전이 없다 (가장 큰 병)
Board·Docs·Audit·Settings·Projects 다섯 탭의 모든 `button/a/select/input/summary` 를 실측했다. 손잡이 **높이 16종**이 공존한다:

`11 · 12 · 13 · 13 · 15 · 18 · 18 · 19 · 19.5 · 22 · 23 · 27 · 27 · 32 · 33 · 37` (px)

글자 크기 **7종**(9.5·10·10.5·11·11.5·12.5·13), 모서리 **3종**(0 · 10px · 999px)이 같은 화면에 있다. 예: 탭 68.9x**33**(r999, 13px) / 필터 select 124x**37**(r10) / 검색 input 190x**27**(r0) / `s9 serve --restart` 158x**23**(r0) / 닫기 28.9x**19** / ⏸ 27x**27**(r999) / 이어 말하기 55.9x**12** / 「더 보기」 37.9x**11** / 프로젝트 새로 105x**15**(r999) / Docs 종류 띠 78.5x**19.5**(9.5px).

**44x44 를 넘는 손잡이는 하나도 없다.** s9-design 7절이 스스로 정한 최소치인데 최대가 37px 이고, 최소는 **11px** 이다. iPad Safari 가 실제 사용처인 제품에서 11px 과녁은 못 누른다.

### ② 색이 아니라 대비가 문제다 — `--faint` 로 읽는 글자를 칠했다
`--faint` #9096a0 는 흰 판 위 **대비 3.01:1**. 본문 최소 4.5:1 에 못 미치고, 쓰인 자리는 전부 **10~10.5px**(큰 글자 예외도 못 받는다). 전 탭에서 나온다:
- Board 카드: `만든 사람` (라벨인데 안 읽힌다)
- Docs 목록: `DOC-20260909-002-62x6` 등 문서 id 전부
- Settings 왼쪽 레일: **모든 둘째 줄**(`고치던 파일 8개`·`Jira · 준비 4/4`·`등록·역할·시점 미리보기`) — 그 줄이 레일의 정보 절반이다
- Projects 카드: `멤버 1 · 열린 요청 9 · 마지막 활동 방금` — 카드의 유일한 데이터

REQ-20260907-011-62x6 designer #5 가 이미 「`--faint` 는 글자에 쓰지 않는다」고 못박았고, 전 화면이 어긴다.

### ③ 스킨이 자리와 부품을 바꾼다 (규칙 1 위반)
- **id 줄이 카드 아래에서 위로 옮겨 간다**: calm 은 `[data-skin="calm"] .card>.deedrow{order:3}` 로 맨 아래, grid 는 카드 **맨 위**. 같은 사실이 스킨마다 다른 자리에 선다.
- **calm 만 사람 이름에 동그란 머리글자 표를 붙인다**(초록 원 안의 `N`). 다른 스킨은 `@nicehugepark` 글자다. 같은 뜻에 부품이 둘이다.
- **한 줄 ↔ 두 줄**: 위 1-⑤. ledger/terminal/grid 는 한 줄, calm/glass/cobalt 는 두 줄.

### ④ 상태의 얼굴은 대체로 한 사전이다 (여기는 건강하다)
빈 상태는 어디서나 점선 상자 + 두 줄(무엇이 없나 / 무엇을 하면 되나)로 같다 — Board 빈 칸(`착수를 기다리는 요청 없음 / 새로 들어온 요청이 이 칸에 놓입니다`), Docs 빈 판(`← 왼쪽 목록에서 문서를 골라 주세요 / …`). **이 축은 손댈 것이 없다.**
다만 **상태 이름의 표기가 탭마다 다르다**: Board 는 칸 이름 + 점, Docs 는 오른쪽 정렬 mono 대문자 색 글자(`DONE`·`IN-PROGRESS`), Audit 는 `.cdot` 사각 + mono 대문자. 같은 값에 표기가 셋이다.

### ⑤ 표(Audit) — 규칙 8 을 세 열에만 적용했다
`종류`·`남긴 사람`·`세션` 은 첫 행만 적고 접었는데, **`시각` 열은 접지 않아 `2026-09-10` 이 20행 내리 똑같이 반복**된다. 결과: 왼쪽 90px 이 같은 글자로 채워지고, 정작 다른 값(시:분)은 그 뒤에 묻힌다. 그리고 세 열이 19행 연속 비어 있어 표가 「접힌 것」이 아니라 **「빠진 것」**으로 읽힌다. `내용` 열은 18행이 같은 문장(`서브에이전트 중간보고 생략 (NN자)`)이고 전부 링크 파랑이라, 화면에서 가장 큰 색 덩어리가 아무것도 구분해 주지 않는 문장이다.

### ⑥ Settings — 상주 안내문과 남의 위젯
- 세 개의 select 가 **브라우저 기본 위젯**이다(r10px, OS 화살표). ledger 는 라운드 0·그림자 0 인데 여기만 남의 모양이고, **스킨을 아무리 바꿔도 이 셋은 안 따라온다.** 맥 Safari 에서는 또 다르게 그려진다.
- 맨 아래 `skin은 모양과 배치, tone은 색, density는 여백을 바꿉니다…` 는 바로 위 라벨(`SKIN — 모양과 배치`)을 그대로 되풀이한다. s9-design 「표 위의 안내문은 상주하지 않는다」.
- `가이드 열기` 만 레일에서 혼자 강조색이고 둘째 줄에 **파일 경로 `/guide.html`** 이 노출된다(ux-writer R5).
- 판 폭 1030px 에 300px 컨트롤 셋 — 헤어라인이 남는 700px 을 가로질러 빈 자리를 강조한다.

### 3. 고칠 것 — 우선순위와 묶음

### 지금 당장 아픈 것 5 (각각 한 파일·한 값 수준)

**P1. ⏸/▶ 의 잉크를 줄에 맞춘다** (`web/app/card.js` GLYPH_PAUSE/PLAY, `web/css/actions.css`)
