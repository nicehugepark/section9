### 1. ⏸ 버튼의 진단 — 왜 못생겼나

**한 줄: ⏸ 는 제 모양이 틀린 것이 아니라, 손잡이 사전이 없는 줄에 혼자 손잡이 규칙을 지키고 서 있어서 이물로 읽힌다.**

id 줄(`.card .id`)을 5배로 떠서 잰 것(첨부 1·2):

| 원소 | 그리는 법 | 획/잉크 | 색 | 상자 |
|---|---|---|---|---|
| 점(livedot) | SVG 원 | 1.5px 테 | `--dot-live` | 7x7 |
| id 글자 | mono 10px | 글자 획 ~1px | `--faint` #9096a0 | 텍스트 |
| **⏸** | **SVG 채움** | **막대 3px x 2, 면 42px²** | **`--muted` #5c6470** | **과녁 27x27 / 그림 13x13** |
| ⏱ | **폰트 코드포인트 U+23F1** | 외곽선 ~1px | `--c-inprogress` #b45309 | 글자 |
| 경과 글자 | mono 10px | ~1px | `--c-inprogress` | 텍스트 |

여섯 가지 병이 한 자리에 겹쳐 있다.

1. **잉크 농도가 이웃의 3~4배다.** ⏸ 의 잉크는 3x7 막대 둘 = 42px² 의 **채운 면**이다. 같은 줄의 mono 10px 글자 한 자는 잉크가 8~12px² 이고 전부 **획**이다. 게다가 색이 `--muted`(#5c6470, 대비 5.97:1)로 이웃 id 글자 `--faint`(#9096a0, 3.01:1)보다 진하다. **줄에서 가장 조용해야 할 자리에 줄에서 가장 진한 덩어리가 있다** — 위계가 뒤집혔다.
2. **모양이 정사각형이라 재생기 글리프로 안 읽힌다.** 막대 3 + 틈 1 + 막대 3 = 가로 7, 세로 7. 잉크의 86%가 채워진 정사각이다. 재생기의 ⏸ 는 보통 막대 폭:높이가 1:3~1:3.5 인데 여기는 1:2.33 이라 막대가 아니라 **슬래브** 두 장이다. 사람 눈에는 두 막대가 아니라 네모난 덩어리 하나로 들어온다.
3. **모양 사전이 충돌한다.** 이 제품의 점 어휘(s9-design 「일곱 얼굴」)에서 **사각은 「멎은 것」의 모양**이다(▫ 멈춤 · ▪ 죽음 · ⊟ 사람이 중단해 둠). 그런데 **행위** 버튼인 ⏸ 가 같은 12px 줄에서 사각 덩어리로 서 있다. 상태의 알파벳과 행위의 알파벳이 같은 모양을 쓴다.
4. **이웃 마크와 그리는 법이 다르다.** ⏱ 는 SVG 가 아니라 **폰트 글리프**(`board.css:418 .elapsed::before{content:"⏱ "}`)다. 윈도우에서는 Segoe UI Symbol 의 가는 외곽선 시계, **맥·iPad Safari 에서는 컬러 이모지**로 나온다(WebKit 에서도 같은 코드포인트 확인). 손으로 격자에 맞춘 13px SVG 와 OS 가 그려 주는 글자가 1em 거리에 나란히 선다.
5. **과녁이 줄을 뚫는다.** 과녁 27px, 줄 높이 12px(1em). ledger·terminal·grid 에서 버튼은 줄 위아래로 **각각 7.5px 씩 넘쳐** 제목/카드 모서리 위에 보이지 않게 얹힌다. calm·glass·cobalt 에서는 반대로 **줄이 두 줄로 접힌다**(실측 rowH 12 → 24~26). 즉 **⏸ 가 있으면 카드의 줄 수가 달라진다** — 손잡이가 리듬을 바꾼다.
6. **배율에서 흔들린다.** 막대 3px · 틈 1px 은 배율 1.25 에서 3.75/1.25 화소가 되어 반올림이 좌우로 갈린다 — 확대 캡처에서 **왼 막대와 오른 막대의 폭·농도가 눈에 띄게 다르다**(첨부 4). 배율 1 에서는 딱딱한 한 덩어리, 1.25 에서는 두께가 다른 막대 둘. 같은 그림이 두 얼굴이다.

**그런데 이 버튼은 네 번(REQ-20260830-042-62x6/043, 20260831-006/019)에 걸쳐 그림 안쪽 기하만 고쳐 왔다.** viewBox 눈금·거울 대칭 잔차·mask 반올림까지 화면에서 가장 정밀하게 다듬은 원소다. 문제는 **그 정밀함이 전부 그림 안에서 끝났고, 줄과의 관계는 한 번도 재지 않았다**는 것이다. 그리고 결정적으로 — **이 줄에서 과녁·모서리·시각 피드백을 가진 손잡이는 ⏸ 하나뿐이다**(아래 2절). 규칙을 지키는 것이 혼자면 그것이 튄다. **⏸ 를 다섯 번째로 다시 그리는 것은 답이 아니다. 없는 손잡이 사전을 만들고 그 안에 앉히는 것이 답이다.**

### 2. 전수 실측 — 체계의 병

### ① 손잡이 사전이 없다 (가장 큰 병)
Board·Docs·Audit·Settings·Projects 다섯 탭의 모든 `button/a/select/input/summary` 를 실측했다. 손잡이 **높이 16종**이 공존한다:

`11 · 12 · 13 · 13 · 15 · 18 · 18 · 19 · 19.5 · 22 · 23 · 27 · 27 · 32 · 33 · 37` (px)

글자 크기 **7종**(9.5·10·10.5·11·11.5·12.5·13), 모서리 **3종**(0 · 10px · 999px)이 같은 화면에 있다. 예: 탭 68.9x**33**(r999, 13px) / 필터 select 124x**37**(r10) / 검색 input 190x**27**(r0) / `s9 serve --restart` 158x**23**(r0) / 닫기 28.9x**19** / ⏸ 27x**27**(r999) / 이어 말하기 55.9x**12** / 「더 보기」 37.9x**11** / 프로젝트 새로 105x**15**(r999) / Docs 종류 띠 78.5x**19.5**(9.5px).

**44x44 를 넘는 손잡이는 하나도 없다.** s9-design 7절이 스스로 정한 최소치인데 최대가 37px 이고, 최소는 **11px** 이다. iPad Safari 가 실제 사용처인 제품에서 11px 과녁은 못 누른다.

### ② 색이 아니라 대비가 문제다 — `--faint` 로 읽는 글자를 칠했다
`--faint` #9096a0 는 흰 판 위 **대비 3.01:1**. 본문 최소 4.5:1 에 못 미치고, 쓰인 자리는 전부 **10~10.5px**(큰 글자 예외도 못 받는다). 전 탭에서 나온다:
- Board 카드: `만든 사람` (라벨인데 안 읽힌다)
- Docs 목록: `DOC-20260909-002-62x6` 등 문서 id 전부
- Settings 왼쪽 레일: **모든 둘째 줄**(`고치던 파일 8개`·`Jira · 준비 4/4`·`등록·역할·시점 미리보기`) — 그 줄이 레일의 정보 절반이다
- Projects 카드: `멤버 1 · 열린 요청 9 · 마지막 활동 방금` — 카드의 유일한 데이터

REQ-20260907-011-62x6 designer #5 가 이미 「`--faint` 는 글자에 쓰지 않는다」고 못박았고, 전 화면이 어긴다.

### ③ 스킨이 자리와 부품을 바꾼다 (규칙 1 위반)
- **id 줄이 카드 아래에서 위로 옮겨 간다**: calm 은 `[data-skin="calm"] .card>.deedrow{order:3}` 로 맨 아래, grid 는 카드 **맨 위**. 같은 사실이 스킨마다 다른 자리에 선다.
- **calm 만 사람 이름에 동그란 머리글자 표를 붙인다**(초록 원 안의 `N`). 다른 스킨은 `@nicehugepark` 글자다. 같은 뜻에 부품이 둘이다.
- **한 줄 ↔ 두 줄**: 위 1-⑤. ledger/terminal/grid 는 한 줄, calm/glass/cobalt 는 두 줄.

### ④ 상태의 얼굴은 대체로 한 사전이다 (여기는 건강하다)
빈 상태는 어디서나 점선 상자 + 두 줄(무엇이 없나 / 무엇을 하면 되나)로 같다 — Board 빈 칸(`착수를 기다리는 요청 없음 / 새로 들어온 요청이 이 칸에 놓입니다`), Docs 빈 판(`← 왼쪽 목록에서 문서를 골라 주세요 / …`). **이 축은 손댈 것이 없다.**
다만 **상태 이름의 표기가 탭마다 다르다**: Board 는 칸 이름 + 점, Docs 는 오른쪽 정렬 mono 대문자 색 글자(`DONE`·`IN-PROGRESS`), Audit 는 `.cdot` 사각 + mono 대문자. 같은 값에 표기가 셋이다.

### ⑤ 표(Audit) — 규칙 8 을 세 열에만 적용했다
`종류`·`남긴 사람`·`세션` 은 첫 행만 적고 접었는데, **`시각` 열은 접지 않아 `2026-09-10` 이 20행 내리 똑같이 반복**된다. 결과: 왼쪽 90px 이 같은 글자로 채워지고, 정작 다른 값(시:분)은 그 뒤에 묻힌다. 그리고 세 열이 19행 연속 비어 있어 표가 「접힌 것」이 아니라 **「빠진 것」**으로 읽힌다. `내용` 열은 18행이 같은 문장(`서브에이전트 중간보고 생략 (NN자)`)이고 전부 링크 파랑이라, 화면에서 가장 큰 색 덩어리가 아무것도 구분해 주지 않는 문장이다.

### ⑥ Settings — 상주 안내문과 남의 위젯
- 세 개의 select 가 **브라우저 기본 위젯**이다(r10px, OS 화살표). ledger 는 라운드 0·그림자 0 인데 여기만 남의 모양이고, **스킨을 아무리 바꿔도 이 셋은 안 따라온다.** 맥 Safari 에서는 또 다르게 그려진다.
- 맨 아래 `skin은 모양과 배치, tone은 색, density는 여백을 바꿉니다…` 는 바로 위 라벨(`SKIN — 모양과 배치`)을 그대로 되풀이한다. s9-design 「표 위의 안내문은 상주하지 않는다」.
- `가이드 열기` 만 레일에서 혼자 강조색이고 둘째 줄에 **파일 경로 `/guide.html`** 이 노출된다(ux-writer R5).
- 판 폭 1030px 에 300px 컨트롤 셋 — 헤어라인이 남는 700px 을 가로질러 빈 자리를 강조한다.

### 3. 고칠 것 — 우선순위와 묶음

### 지금 당장 아픈 것 5 (각각 한 파일·한 값 수준)

**P1. ⏸/▶ 의 잉크를 줄에 맞춘다** (`web/app/card.js` GLYPH_PAUSE/PLAY, `web/css/actions.css`)
- 그림 상자 13x13 · 과녁 27px · 격자 정수는 **그대로 둔다**(네 번 걸려 맞춘 값이다).
- 잉크만 바꾼다: 막대 **3px → 2px**, 틈 **1px → 2px**, 높이 **7px → 9px**(y 2..11). 잉크 면적 42px² → **36px²**, 비율 1:4.5 로 재생기 글리프가 된다. 틈 2px 은 배율 1.25 에서 2.5화소라 어느 쪽으로 반올림돼도 **살아남는다**(지금 1px 은 1.25화소라 사라진다).
- ▶ 도 같은 눈금으로: `M4 2 L11.5 6.5 L4 11 Z` → 정수만 쓰려면 `M4 2 L11 6.5 L4 11 Z` 유지하되 채움을 `fill-opacity` 로 낮추지 말고 **폭을 줄인다**(면적을 ⏸ 과 ±10% 안에 맞춘다 — 두 얼굴이 같은 무게여야 상태 배타가 성립한다).
- 색을 `--muted` → **`--faint`** 로 내린다. 같은 줄의 id 글자와 같은 층에 선다. 진해지는 것은 hover 때만.

**P2. ⏱ 를 폰트 글리프에서 SVG 마크로 옮긴다** (`board.css:418`)
`content:"⏱ "` 를 없애고, ⏸ 와 **같은 13x13 격자·1.5px 획**의 시계 SVG 로 바꾼다. 이유 둘: ① 맥·iPad Safari 에서 컬러 이모지로 나와 계기판 언어가 깨진다 ② 획 두께를 OS 가 정하니 ⏸ 와 절대 안 맞는다. 대안으로 **마크를 아예 없애고 `15m 39s` 글자만 두는 것**도 성립한다(경과 시간에 시계 그림은 정보를 더하지 않는다) — 이쪽이 줄을 더 조용하게 만들고 구현도 한 줄이다. **권장: 없애는 쪽.**

**P3. id 줄의 줄 수를 스킨 사이에서 잠근다** (`board.css .card .id`, `calm.css`·`skins.css`)
- `.card .id{min-height:20px; flex-wrap:nowrap}` 로 못박고, 넘치면 접는 것은 **id 글자**(`text-overflow:ellipsis`)이지 손잡이가 아니다.
- 27px 과녁이 12px 줄을 뚫는 것은 그대로 두되(칠은 13px 원 안이라 안 보인다), 줄 높이를 **20px** 로 올려 넘침을 위아래 3.5px 로 줄인다. 4의 배수라 비정수 배율에서 갈리지 않는다.

**P4. `--faint` 를 읽는 글자에서 걷는다** (`tokens.css` + 5개 파일의 `color:var(--faint)`)
- 새 토큰 **`--quiet:#6e7583`**(흰 판 대비 **4.69:1**, AA 통과) 을 세우고, 위 ②의 네 자리(카드 `만든 사람`·Docs id·Settings 레일 둘째 줄·Projects 메타)를 `--quiet` 로 옮긴다.
- `--faint` 는 **선·자리 표시·placeholder 전용**으로 남긴다.

**P5. Audit 의 시각 열도 접는다** (`web/app/audit.js`)
날짜가 앞 행과 같으면 날짜를 접고 시:분만 남긴다(`2026-09-10 08:46` → `08:46`). 접는 방식은 규칙 8 그대로 1px 상자 + `clip-path:inset(50%)` 라 복사·화면낭독기는 온전한 값을 갖는다. 덤으로 시각 열이 130px → 60px 로 줄어 본문 열이 앞당겨진다.

### 체계로 고칠 것 3 (여러 파일·회귀 시험 동반)

**S1. 손잡이 사전을 세운다 — 세 크기 x 세 종류** (새 `web/css/control.css`, 전 파일이 참조)
지금 16종인 높이를 **3종**으로 잠근다. 과녁과 칠은 따로다(s9-design 7절).

| 급 | 과녁(높이) | 글자 | 쓰는 자리 |
|---|---|---|---|
| `--ctl-lg` | **36px** | 13px | 탭 · 필터 · 검색 · 판 머리의 주 손잡이 |
| `--ctl-md` | **28px** | 11.5px | 카드/문서의 행위 버튼(⏸ ▶ ✓승인 ↺반려) · 「더 보기」 |
| `--ctl-sm` | **20px** | 10.5px | 줄 안의 글자 손잡이(이어 말하기 · 프로젝트 · 우선순위 · Jira 키) |

- **글자 손잡이도 과녁을 갖는다**: 지금 11~15px 인 것들에 `padding-block` 으로 20px 을 채운다(칠은 글자에만 — `background-clip:content-box`, ⏸ 가 이미 쓰는 그 처방이다).
- 모서리는 **스킨이 정한다**(ledger 0 / calm·glass 999px). 크기는 **스킨이 못 바꾼다**.
- 회귀: `tests/test_wake_handle.py` 에 「모든 손잡이 높이는 20·28·36 중 하나」 한 건을 더한다. 이 시험 하나가 16종이 다시 늘어나는 것을 막는다.
- 이것이 P1 보다 크지만, **P1 만 하면 ⏸ 는 다음 번에 또 반려된다** — 이번 반려의 진짜 뿌리다.

**S2. 마크 사전을 세운다 — 13x13 격자 · 획 1.5px · 전부 SVG** (`web/app/marks.js` 새 파일)
지금 화면의 마크는 출처가 넷이다: 손 SVG(⏸ ▶), 폰트 코드포인트(⏱ ▲ ↻ ← ▸ ×), `.cdot` 사각, `.livedot` SVG. 한 사전으로 모은다.
- **좌표는 13칸 = 13화소** (⏸ 가 이미 확립한 눈금).
- **획은 1.5px 단일**, 채운 마크는 잉크 면적 **32~40px²** 안에 든다(글자 한 자의 3배를 넘지 않는다).
- 폰트 코드포인트로 남는 것은 **문장 안의 부호**(`×`·`+`·`−`)뿐 — 그림은 전부 SVG.
- 얻는 것: 맥/윈도우/iPad 에서 같은 그림, 스킨 색 하나로 전부 따라옴, ⏸ 만 튀는 일이 구조적으로 불가능해짐.

**S3. 스킨 계약을 시험으로 못박는다** (`tests/`)
「스킨은 재질을 바꾸고 어휘와 자리는 바꾸지 않는다」(REQ-20260907-011-62x6 #1)가 **말로만 있고 기계가 안 센다.** 그래서 calm 이 `order:3` 으로 id 줄을 옮기고 아바타 원을 새로 만들었다. 시험 세 건으로 잠근다:
1. 스킨 10종에서 `.card` 의 자식 순서(`order` 계산값)가 같다.
2. 스킨 10종에서 `.card .id` 의 `getClientRects().length` 가 1 이다(한 줄).
3. 스킨 10종에서 같은 원소 집합이 존재한다(한 스킨만 있는 부품 금지).

### 판정할 것: 카드에서 `||` 를 없앴다. 그림이 아니라 **낱말**로 간다.

쉼 얼굴에는 손잡이가 아예 없고(id 줄은 라벨만), 손이 얹히면 **「중단하기」·
「이어 말하기」 두 낱말**이 나란히 선다. 첨부 j2(판 전체·쉼)에 `||` 는 한 개도
없다. 첨부 j4(카드·손 얹힘·5배)가 새 얼굴이다.

### 1. 그 손잡이가 실제로 무엇을 하는가 (코드 확인)

리드의 읽기 하나를 **뒤집는다**. 카드의 ⏸ 는 정책이 아니다.

| | 무엇 | 어디 | 얼굴 |
|---|---|---|---|
| `stopBtnHTML` (⏸) | **지금 도는 것을 끊는다** — `STOP_KIND` 의 worker·session·agent 셋. 「하던 일이 거기서 끝나고 사유가 문서에 남는다」 | 카드 + 문서 | 종전 글리프 |
| `wakeBtnHTML` (▶) | 안 붙어 있는 것을 **잇는다** | 카드 + 문서 | 종전 글리프 |
| `holdLockHTML` (「자동 이어받기 끄기」) | **정책** — `kind:"idle"`. 앞으로 못 맡게 한다 | **문서에만** | 이미 낱말 |

`deedBeltHTML` 은 `attached`(kind ≠ idle)일 때만 ⏸ 를 세운다. 즉 카드의 ⏸ 는
**실제로 무언가가 돌고 있을 때만** 서는 즉시 행위다. 정책은 REQ-20260830-042-62x6 가
이미 카드에서 걷어 문서의 낱말로 내려놓았다.

**그래도 반려는 옳다.** 뜻이 「정책」이 아니라 「즉시 행위」여도 `||` 는 여전히
재생기의 기호이고, 「이 요청이 지금 도는 것을 끊는다」와 아무 관계가 없다.

### 2. 카드의 문법 — 어느 줄이 라벨이고 어느 줄이 행위인가

id 줄(`.card .id`)의 원소는 다섯이다:

    점(livedot) · 식별자 · [벨트 ⏸/▶] · 경과 시각 · 「이어 말하기」

그리고 이 줄에는 **이미 규칙이 있었다**:

    .card:hover .elapsed{visibility:hidden}      쉼의 라벨이 비키고
    .card:hover .pickdoc{visibility:visible}     그 자리에 행위가 뜬다

**쉼 = 라벨, 손 얹힘 = 행위.** 그 줄의 행위(「이어 말하기」)는 **낱말**이고
**쉼에는 없다**. 벨트만 이 규칙 밖에 있었다 — 라벨만 있어야 할 줄 한가운데에
재생기 기호가 **상주**한 것이다. 자리를 새로 정할 것이 아니라 **이미 있는
규칙을 벨트에도 적용**하는 것이 답이었다.

- **전 스킨 검수 규칙 2**: 「한 줄에 성격이 다른 둘을 섞지 않는다 — 세는 것과
  누르는 것을 한 wrap 줄에 두면 접힘이 뜻을 갈라 놓는다. **섞어야 하면 묶음으로
  싸고, 접히면 묶음째 제 줄을 갖게 한다.**」
- **규칙 4**: 「카드 메타는 「누구·어디 / 무엇」 두 줄이고 같은 사실은 카드마다
  같은 줄에 선다 — **「한 줄」이 아니라 「제 줄」이 규율이다.**」
- **2절**: 「강조가 셋 이상이면 강조가 없는 것과 같다.」
- **카드 사실 줄**: 「줄이 버튼을 정당화하러 생기면 거꾸로 된 것이다.」

id 줄은 이 넷을 한꺼번에 어기고 있었다. 스킬이 부족했던 것이 아니라 **이 줄에
적용되지 않고 있었다.**

### 2. 여섯을 성격으로 갈랐다

| 원소 | 성격 | 언제 |
|---|---|---|
| 점(livedot) | **상태** — 무엇이 붙어 있나 | in-progress |
| 식별자 | **신원** | 늘 |
| 경과 시각 | **상태** — 얼마나 됐나 | 거의 늘 |
| 집힘 「대상」 | **상태** — 이 카드가 다음 말의 대상 | 판 전체에서 **한 장** |
| 벨트 ■/▶ | **행위** | 붙었거나 멈췄을 때 · 손 얹힘 |
| 「이어 말하기」 | **행위** | 손 얹힘 |

카드의 다른 줄: 제목=신원 · xref(Jira·계보)=신원 · mwho=신원(누구·어디) ·
mwhat=분류·양 · dep/stall/judge=사실 줄(정상이 아니다 / 할 일이 있다).
**행위를 맡은 줄은 카드에 없었다** — 그래서 라벨 줄이 떠안고 있었다.

### 3. 뿌리는 자리가 아니라 **폭**이었다

행위 둘이 **흐름에 서서** 벨트 27 + 시각 칸의 최소폭 52 = **79px** 를 늘
예약했다. 카드 안쪽 190px 의 **42%**, 식별자(98.6px)에 맞먹는 폭을 **쉼 얼굴에는
보이지도 않는 것들**이 물고 있었다. 그래서 줄이 접혔고, 접힌 빈 자리에 「대상」이
끼어들었고, 하나를 고치면 다른 데가 터졌다(084 · 108 · 064 · 011 · 021 · 009).

### 4. 배분 — 줄을 새로 만들지 않았다. 카드는 1px 도 안 커졌다

1. **집힘 「대상」 → 식별자 바로 뒤.** 코드 주석이 스스로 적어 둔 자리가
   「모서리가 아니라 **id 옆**」이었는데 마크업은 오른쪽 묶음(`margin-left:auto`)의
   첫 자식이라 **줄 한가운데에 매달려** 있었다 — 의도와 마크업이 갈라져 있었다.
   식별자 뒤로 옮기니 「이 카드(식별자) — 대상」으로 읽히고 왼끝이 정렬된다.
   크기도 11.5px·700 → **10px·600** 으로 한 급 내렸다(줄의 크기에 맞춘다;
   이웃이 `--faint` 400 이라 `--text` 600 이면 충분히 갈린다).
   손 얹힘에 감추던 규칙도 걷었다 — 손잡이가 더 이상 그 자리에 안 온다.
2. **「이어 말하기」 → 흐름 밖 묶음(`.idact`)** 으로. 시각 칸 안에 떠서 칸의
   폭을 안 넓힌다(규칙 2 의 「묶음으로 싸라」).
3. **벨트 ■/▶ → 점의 자리.** 리드의 ②가 맞았다 — 「돌고 있다」를 말하는 것이
   점이고, 그것을 멎게 하는 손이 줄 반대쪽 끝에 홀로 서 있으니 뜬금없다.
   쉼에는 점(상태), 손 얹히면 같은 자리에 ■(그 상태를 끝내는 손). 점을
   손잡이로 만든 것이 **아니다**(그러면 안 눌리는 얼굴까지 눌러 보게 된다) —
   시각↔손잡이가 이미 쓰던 **자리 교대**다. 상자는 13px 고정이라 교대해도
   줄이 안 밀리고, 예약은 **점 7 → 13px, +6px 뿐**이다.
4. **마크 ⏸ → ■.** `||` 는 재생기의 「잠시 멈춤」이라 `STOP_KIND` 셋(거기서
   끝난다 · 중단하라고 전한다 · 하던 일은 마치고 멈춘다)과 뜻이 다르다. 셋의
   공통은 「잠시」가 아니라 「멎게 한다」이고, 그 마크는 재생기에서도 이 제품의
   점 어휘에서도 **사각**이다. `×`(끊음)는 셋 중 둘이 「전하고 기다린다」라
   너무 단호해 접었다.

**결과 폭**: 13 + 98.6 + 52 + 8 = **171.6 < 190** — 한 줄에 선다.
접힘 문턱도 236 → **176** 으로 내렸다(흔한 카드 168.3 바로 위).

### 1. 왜 43건이 통과하는 동안 화면이 깨졌나

**픽스처가 한 세대 뒤처져 있었다.** 3차에서 `card.js` 는 벨트를 `.idact` 에서
점의 자리(`.idmark`)로 옮겼는데, `tests/test_id_realscale.py` 의 픽스처는 벨트를
옛 자리에 그대로 두었다. 그 파일의 첫 줄이 스스로 경고하던 바로 그 일이
그 파일 안에서 일어났다 — 「마크업이 화면과 어긋나면 이 시험은 화면이 아니라
**제 픽스처를 잰다**」. 그래서 43건은 아무도 그리지 않는 마크업을 재고 통과했다.

정적 계약 둘(`test_id_clearance` · `test_pick_state_look`)은 더 나빴다. 「행위
묶음은 흐름 밖에 떠 있어야 한다」를 못박고 있었는데, 그 규칙의 **까닭은 084 의
것**이었다: 흐름에 서면 칸이 낱말만큼 넓어져 **벨트와 시각 사이**에 빈 자리가
생긴다. 그런데 3차에서 벨트가 그 묶음을 떠났다 — 벌어질 사이가 없어졌는데
규칙만 남았고, 그 규칙이 「칸의 최소폭을 사람이 손으로 적어라」를 강제했다.
56 이라는 숫자가 어느 글꼴에서 틀렸는지는 아무도 재지 않았다.

### 2. 고친 것 — 숫자를 손으로 적는 일을 없앴다

**① 마크 자리는 채울 것이 있을 때만 선다** (`web/app/card.js`)
`.idmark` 를 점이나 벨트가 있을 때만 짓는다. 상자가 필요한 것은 **교대가
일어나는 카드**(쉼의 점 ↔ 손 얹힘의 ■)뿐이고, 그런 카드가 아닌 것이 화면의
대부분이다(open·review·done·cancelled 전부). 그 카드들에서 식별자가 줄머리에
서서 카드의 다른 줄과 같은 자를 쓴다.

**② 행위 묶음을 시각과 같은 격자 칸으로** (`web/css/board.css`)
`.idact` 에서 `position:absolute; right:0; max-width:100%; overflow:hidden` 을
걷었다. 묶음이 `.idnow` 의 흐름 안(같은 `grid-area:1/1`)에 서면 칸의 폭이
`max(시각, 낱말)` 로 **저절로** 선다 — 글꼴이 무엇이든 낱말이 제 폭을 갖고,
잘릴 것도 왼쪽 이웃(「대상」)으로 넘칠 것도 없다. 시각은 손 얹힘에
`visibility:hidden` 으로 비키지만 상자는 남으므로 **폭이 안 변한다**: 손을
얹어도 줄이 1px 도 안 흔들린다. 이 파일이 `.idnow` 주석에 이미 적어 둔
「둘은 같은 것을 다른 때에 말하므로 자리도 하나여야 한다」 그대로다.
그리고 **`min-width:56px` 을 함께 걷었다** — 그 숫자가 곧 이번 결함이다.

**③ 스트럿을 흐름에서 뺐다** (`web/css/board.css`)
폭 0 이면 자리를 안 먹는다고 여겼는데, flex 의 `gap` 은 폭이 아니라 **항목
사이**에 붙는다. calm 은 이 줄에 `gap:2px` 를 주므로 폭 0 스트럿 뒤에도 2px 이
생겨, calm 의 모든 카드에서 id 줄만 2px 더 들어갔다(실측 179건). `position:absolute`
로 흐름에서 빼고, 스트럿이 지던 줄 높이의 바닥은 `.card .id{min-height:var(--card-edge)}`
가 같은 자로 이어받는다.

**④ 죽은 예외를 걷었다** (`web/css/control.css`)
`.card .pickdoc{position:absolute}` 는 손잡이가 카드 모서리에 떠 있던 시절의
되돌림이다. 지금 손잡이는 칸 안 흐름에 서므로 그 예외는 겹판이 무엇에 얹히는지를
두 파일에 갈려 적히게 할 뿐이다. 자리는 board.css 한 곳이 말한다.

### ① 마크가 손 얹힘에 옆으로 뛰던 것

**뿌리**: 마크 상자(`.idmark`)는 13px 에 `justify-content:center` 인데, 그 안의
점(`.livedot`)이 줄에서 쓰던 `margin-right:6px` 를 그대로 들고 있었다. flex 의
가운데 맞춤은 **margin 을 포함한 바깥 상자**를 가운데에 두므로 점의 잉크는
상자 왼쪽 0..7(중심 3.5)에 섰고, 벨트는 `left:50%`+`translate(-50%)` 라 중심이
6.5 였다. 상자 시험은 벨트만 재고 있어서 이 어긋남을 한 번도 못 봤다.

**고친 것**: 잉크가 서는 **무대**를 상자 왼쪽 7px 로 못박고(`justify-content:
flex-start`), 벨트를 그 무대에 핀으로 꽂았다(`left:0;width:7px;height:13px`;
과녁 27px 은 양쪽으로 똑같이 넘친다). 무대를 상자 한가운데로 옮기지 않은 까닭은
