판단(부모 노트에 적은 대로): 그 commit 해시를 짚어 멈추는 쪽이 맞다. 다만 **누가 담았는지**를 가릴 신호가 지금 없다 — commit 의 author 는 사람·머신까지만 말하고 세션을 말하지 않아, 같은 컴퓨터의 두 세션이 같은 author 로 찍힌다. 그래서 이 요청의 몫은 둘이다: ① commit 에 세션을 남긴다(세션 바인딩에 그 sha 를 적는 쪽이 이력을 더럽히지 않는다) ② concurrent_gate 옆에 검사를 하나 세운다 — 담기는 코드 파일을 마지막으로 만진 commit 이 최근이고 내 세션의 것이 아니면, 그 해시·시각·메시지 한 줄을 적고 멈춘다. 빠져나가는 길은 종전과 같은 표(S9_ALLOW_CONCURRENT).

### 2026-09-15T17:10:45+09:00 response (agent: lead:claude-opus-5, by nicehugepark)

고친 자리 (bin/s9-guard · tests/test_recent_commit_gate.py, 아직 commit 전)

몫 둘을 다 세웠다.

① **누가 담았는지 가릴 신호.** commit 의 author 는 사람·머신까지만 말한다. 가르는 신호는 프로세스의 계보로 잡았다 — 세션이 건 커밋은 그 세션의 자손이라 세션 바인딩의 attach_pid 가 self_and_ancestors() 안에 든다(`my_binding()`). post-commit(`--after-commit`)이 그 sha 와 세션을 `state/commit-sessions.jsonl` 에 한 줄씩 덧붙인다 — trailer 로 이력에 박지 않아 commit 메시지는 그대로이고, 덧붙이기만 해서 같은 작업 트리의 여러 주체가 동시에 커밋해도 서로의 줄을 지우지 않는다. 500줄을 넘으면 뒤쪽만 남긴다(창이 15분이라 옛 줄은 쓸 데가 없다).

② **검사.** `recent_foreign_commits()` 가 담기는 **코드** 파일을 최근 15분(RECENT_COMMIT_SEC, FRESH_SEC 과 같은 폭) 안에 만진 commit 을 `git log` 한 번으로 찾아, 기록이 「다른 세션」이라고 말하면 해시·지난 시간·제목·누구를 적고 멈춘다. 기록이 **없는** commit(다른 컴퓨터에서 pull 로 온 것·훅 없이 만든 것)은 짚어 보여 주되 막지 않는다 — 그것까지 막으면 이 검사는 곧 손잡이로만 쓰이게 된다. 데이터 경로는 종전대로 뺐다.

**표는 하나다.** 두 검사(동시 작업 · 방금 담긴 파일)가 따로 표를 요구하면 환경변수가 하나뿐이라 아무도 못 지나간다. `concurrent_flags()` 를 세워 검사와 조회(`--concurrent`)가 같은 값을 보고, 표는 두 검사가 짚은 파일 전부를 덮는다. 종전 경우(둘째 검사가 안 설 때)의 표 값은 바뀌지 않는다 — test_concurrent_gate 가 그대로 통과한다.

고치기 전에 이 시험이 실패하는 자리: 옛 concurrent_gate 는 첫 두 줄이 `workers = live_workers(); if not workers: return` 이라, 작업자가 없는 자리(=사고 당시 상황, A 는 이미 끝났다)에서는 무엇도 보지 않았다.

시험: recent_commit_gate 18건 신규 통과(그중 하나는 이 저장소의 진짜 이력에서 방금 담긴 코드 파일을 찾는다 — 84881c9d9 로 실측). 계열 재실행 — concurrent_gate·concurrent_check·stdlib_only 59건, after_commit_sha·after_commit_red·commit_gate·guard_* ·s9_commit·commit_drift 67건, no_metaphors 포함 55건, 전부 통과.

한 곳 고쳐 적음: `_recent_commits_touching` 의 예외는 넓게 받는다(except Exception). 이력을 못 읽는 것이 커밋을 터뜨리는 이유가 되면 안 된다 — 이 파일의 다른 이력 조회(head_touches_wide)도 같다.
