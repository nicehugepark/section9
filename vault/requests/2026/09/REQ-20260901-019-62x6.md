### 무엇이 잘렸나 — 015 가 못 잡은 나머지 반

015 는 창의 **키**를 고쳤다(시작점과 최대 키가 한 자를 쓰게). 그 자는 지금도
맞다. 남아 있던 것은 **구르는 축**이다: 창이 통째로 굴렀다(`.dlgbox` 에
`overflow:auto`). 머리도 바닥도 본문과 같은 흐름에 실려 있어서, 내용이 최대
키를 넘는 순간 바닥 띠가 접힌 자리 아래로 밀려났다 — 그리고 「굴리면 나온다」를
말해 주는 것이 아무것도 없어서, 사람 눈에는 그냥 잘린 창이었다.

### 재현 (숫자로)

사용자 캡처에서 창 폭(432 CSS px)이 536 화면 px 로 찍혀 배율 1.24 — 즉 뷰포트
1531×684 CSS px. 그 크기로 세우니 그대로 났다(before-model-684.png):
창은 규격대로 660px 에서 끝나는데 `그만두기`·`다시 시작` 이 그 경계에 물려
반쯤 잘렸다.

### 고친 것 — 창은 세 띠다

`.dlgbox` 를 세로 flex 로 세우고 창 자체의 스크롤을 끊었다. 구르는 띠는 이름
으로 지목한다(`.dlgbody` · 치운 것 판의 `.tlist`), 나머지 직계 자식은 전부
붙박이(`.dlgbox>*{flex:0 0 auto}`) — 새 띠를 얹는 사람이 아무것도 안 적으면
「안 구르는 띠」로 굳는 쪽이 안전하다. `min-height:0` 이 실제로 스크롤을
만든다(없으면 flex 항목이 내용 키 밑으로 안 줄어 판이 다시 넘친다).

곁가지 둘:
- `placeHover` 가 위아래를 260·150 이라는 **어림수**로 판정하던 것을 잰 값으로
  바꿨다 — 폭에는 이미 하고 있던 일이다. 긴 쪽지가 아래로 새는 자리였다.
- 진단에 `?dlg=tidy[&dlgtab=trash]` 를 냈다. 치운 것 판은 `.dlgbox` 를 쓰면서
  제 목록 띠를 따로 두는 유일한 창인데 손이 없으면 열 수가 없었다.

### 전수 확인 (헤드리스 실측 — 제목에 숫자를 찍어 읽었다)

`fit=1` 은 바닥 띠의 아랫변이 판 안, 판의 아랫변이 뷰포트 안이라는 뜻이다.
`body` 는 본문 띠의 스크롤 여지, `seen` 은 고른 줄이 보이는 자리에 있나.

- 모델 1531×684 `fit=1 body=93 seen=1` · 560 `fit=1 body=194` · 440 `fit=1 body=293`
- 계정 684 `fit=1 body=197` · 560 `fit=1 body=298`
- 판정(첨부 3) 440 `fit=1` · 세션 440 `fit=1` · 고른 뒤(dlgpick=fable) 440 `fit=1 seen=1`
- 스킨 8종(cobalt·cork·field·glass·grid·slate·soft·terminal) 560 전부 `fit=1`
- 넉넉한 화면 1900×849 `fit=1 body=0` — 스크롤이 아예 안 생긴다(종전 모습 그대로)
