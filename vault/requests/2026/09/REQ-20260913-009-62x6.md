REQ-20260913-009-62x6 저장소 GitHub 연동 초안 검수 — 판정 넷.

① 자리: 적절. 로컬 사실(지금) → 관계 설정(GitHub) → 교환 행동(pull·push) 순서는 의존관계와 일치하고, "지금"/"주고받기" 사이에 이미 표 블록을 나누는 관행이 있어 새 블록 하나를 더 끼우는 것은 구조 발명이 아니다. 다만 연결 후 GitHub 절이 실제로 한 행으로 접혀야 "화면당 결정 하나"가 정상 상태에서 성립한다 — 그 축소가 핵심이다.

② 행 넷은 많다 — s9-design 1절 "선택지 3개 넘으면 기본값+접기"에 정면으로 해당. 대안 둘을 합쳐야 한다: (a) 「준비물」행을 없애고 그 정보를 잇기/만들기 버튼 각각의 `aria-disabled`+wmean(can.why)로 흡수한다 — 이 화면이 이미 pull/push에 쓰는 바로 그 규약이라 부품을 하나 더 안 만든다. 「외부 서비스 판 열기」는 그 wmean 옆 `.more`로. (b) 「새로 만들기」는 요청안대로 `+ 새로 만들기` 텍스트 버튼 뒤로 접는다(직장 맥락에서 기존 저장소 잇기가 압도적으로 흔한 경로). 기본 노출 2행(연결+잇기)로 줄고, 결정 비용·되돌리기(펼치기/접기) 둘 다 이득.

③ 행이 늘고 주는 것 자체는 결함이 아니다 — 더는 안 맞는 설정 행동을 치우는 것은 옳은 정보 설계다. 다만 한 번의 사용자 행동 뒤에 오는 이산적 전환이므로 폭 고정으로 자리를 영구 예약하지 말고(연결이 끝난 뒤 대부분의 화면 수명 동안 빈 자리만 남는다), 높이 트랜지션(150~200ms ease-out)으로 "방금 연결됐다 → 그래서 줄었다"는 인과를 보여준 뒤 접어라. 성공 문장(said)이 잠깐 보인 다음 접히는 순서가 원인을 읽게 한다. 아래 pull·push 표가 그 순간 위로 딸려 올라오는 것도 같은 트랜지션에 태운다.

④ 위반 소지 셋. (a) "연결됨" 상태를 초록 배지/필로 만들고 싶은 유혹 — 문장(wsay)으로만 말하고 색면 배지 금지를 지킨다(초안은 이미 이렇게 돼 있음, 유지). (b) private/public 선택을 세그먼트 pill로 만들면 금지 항목 정면 위반 — 기존 `.uf`/select 그대로. (c) 가장 위험한 지점은 연결→준비물→잇기→만들기가 "단계"로 읽혀 좌측에 번호 원+세로 선을 잇는 스테퍼 크롬을 얹고 싶어지는 것 — 이것이 사실상 "카드 좌측 세로 띠" 금지의 변주다. 스테퍼 없이 pull/push와 동일한 평평한 행으로 남겨야 한다. GitHub 로고/브랜드색 삽입도 같은 이유로 배제.

REQ-20260913-009-62x6 문구 검수 결과 — 수정 필요 4건, 나머지(private/public·push/pull·GITHUB_TOKEN·gh)는 원어 유지 정책 부합, 그대로.

**① 존댓말 층 이탈 (R1)**
- 전: 「gh 로 로그인하거나 외부 서비스 판에 GITHUB_TOKEN 을 저장하세요.」
- 후: 「gh 로 로그인하거나 외부 서비스 판에 GITHUB_TOKEN 을 저장하면 됩니다.」
- 이유: 화면 전체가 「…습니다」 층인데 이 문장만 해요체(「-세요」)로 이탈.

**② 행 이름 목적어 비대칭**
- 전: 「새로 만들기」
- 후: 「새 저장소 만들기」
- 이유: 짝인 「이미 있는 저장소 잇기」는 목적어(저장소)가 있는데 이쪽만 없음. 버튼 「잇기」「만들기」「끊기」 자체는 바로 위 행 이름·확인창 제목이 목적어를 이미 말해 주므로 홀로 서도 무방.

**③ 같은 개념, 다른 동사 (용어 일관성)**
- 전: 「GitHub 과 이어지지 않았습니다 — 이 컴퓨터 안에서만 기록합니다.」
- 후: 「GitHub 과 이어지지 않았습니다 — 지금은 이 컴퓨터에만 남습니다.」
- 이유: 끊기 확인창 설명은 같은 "로컬 전용" 개념을 「이 컴퓨터에 그대로 남고」로 말한다. "기록하다"는 주어·대상도 불분명 — "남다"로 통일.

**④ 어색한 결합**
- 전: 「다시 이으려면 같은 주소를 잇기에 넣으면 됩니다.」
- 후: 「다시 이으려면 같은 주소로 다시 이으면 됩니다.」
- 이유: "잇기"는 버튼 이름이지 담는 자리가 아니라 "~에 넣으면"과 어울리지 않음.

선택 사항: 「문서 이벤트마다 push 합니다」의 "이벤트"를 "문서가 바뀔 때마다"로 바꾸면 더 쉽지만, 필수 수정은 아님.
