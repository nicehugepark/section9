**판정할 것 하나: 버린 프로젝트가 휴지통 목록에 아예 안 뜬다 — 이건 화면이 아니라 서버 쪽이라 손대지 않았다.** 나머지는 다 고쳤고 실브라우저 두 엔진으로 눌러 확인했다.

### 1. 005 의 뿌리 — 무효화를 한 자리로 (`web/app/app.js`)
「문서가 바뀌었다」 신호 하나를 세웠다: `docsChanged()`. 프로젝트 목록을 먼저 받고(신선도를 지나서) 카탈로그를 받은 뒤, 레일만 바뀐 경우에 다시 그린다. 치우는 손(`tidySend`)은 이제 이 하나만 부른다 — 종전의 `refreshCatalog(true)` 직접 호출은 걷었다. 목록이 셋이 되는 날에도 고칠 자리는 이 함수 하나다.
실측: 프로젝트 문서를 휴지통으로 → 클라이언트 프로젝트 수 1→0 즉시, 되돌리기 → 0→1 즉시, Projects 레일 `PROJECT 1` 로 복귀.

### 2. 006 ② — 버린 그 자리에서 되돌린다 (`web/app/tidy.js` · `web/css/tidy.css`)
목록 띠 아래 한 줄: 「휴지통으로 보냈습니다 · 되돌리기 · 휴지통 보기 ×」. 새 자리를 만들지 않고 묶음 처리 띠(.tidybar)와 **같은 옷**을 입혔다 — 색면도 세로 띠도 없고 헤어라인과 잉크뿐이다. 보관 뒤·되돌린 뒤·완전히 지운 뒤에도 각각 한 문장이 선다(지운 뒤에는 되돌리는 손을 지어내지 않는다).
스스로 사라지지 않는다: 몇 초 뒤 접히는 줄은 그때 화면을 안 보던 사람에게는 없는 줄이고, 저절로 꺼지는 자리는 목록을 한 번 더 흔든다. 다음 치우기가 갈아 끼우고 × 가 걷는다. 목록이 15초마다 다시 그려져도 남는 것을 실측했다.

### 3. 006 문구 — 화면(web/) 만 (`bin/s9.py` 는 손대지 않았다)
확정 사전 여섯으로 통일: 보관 / 보관 해제 · 휴지통으로 · 되돌리기 · 완전히 지우기 · 휴지통 비우기. 「영구 삭제」·「전부 영구 삭제」·「영구 삭제하기」·「소거」는 화면에서 0건이 됐고, 코드 주석의 같은 낱말도 함께 고쳤다(읽은 말이 되쓰인다). 휴지통 탭은 「되돌리기」, 보관함 탭은 「보관 해제」로 갈라 한 낱말이 두 뜻을 지지 않게 했다. 판 부제는 「끝난 것은 보관함으로, 잘못 만든 것은 휴지통으로」. 확인 창은 되돌릴 자리를 이름으로 말한다: 「Docs 탭 위 「보관함 · 휴지통」에서 되돌릴 수 있습니다」. 벨트 툴팁의 반말(「…되돌린다」)도 존댓말로.
`tests/test_dialog_safe.py` CENSUS 의 「영구 삭제하기」 줄을 「완전히 지우기」로 갱신했다(라벨을 바꾸면 대장이 함께 가야 한다는 그 시험의 계약).

### 4. 고치지 않고 넘기는 것 — 별도 REQ 감
**휴지통 목록(`/api/trash`)이 버린 프로젝트 문서를 돌려주지 않는다.** 격리 vault 실측: 같은 자리에서 request 는 뜨고 project 는 안 뜬다(`doc_visible` 이 걸러낸다 — 문서가 `.trash` 로 가는 순간 프로젝트 등록부가 그 slug 를 모른다). 역할이 member 인 사용자는 `restore` 도 「권한 없음」으로 거절당했고, admin 이면 둘 다 된다. 즉 **버린 프로젝트는 멤버에게 보이지도 되돌려지지도 않는다.** 서버(`bin/s9.py`) 쪽이고 리드가 같은 파일을 고치는 중이라 손대지 않았다. 지금은 내가 세운 되돌리기 줄이 그 자리를 건지는 유일한 길이다(id 로 곧장 restore).
