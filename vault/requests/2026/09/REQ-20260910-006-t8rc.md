### 2026-09-10T16:26:52+09:00 response (agent: lead:claude-opus-5, by nicehugepark)

고친 곳 셋 (bin/s9.py, merge_doc 둘레).

1. 짝짓는 규칙을 `_doc_identity(meta)` 한 함수로 모았다 — `id` 가 있으면 그것, 없으면 `name`. 사용자 프로필에는 id 가 없어 병합기가 세 판을 보자마자 None 을 답했고, 그 길로 git 기본 3-way 가 machine_accounts 한 줄에서 갈렸다. 이제 name 이 세 판에서 같으면 받는다. vault 문서는 전수 확인 결과 하나도 빠짐없이 id 가 있어(휴지통 파일 하나 제외) 이 갈래는 실질적으로 users/*/profile.md 전용이다.

2. `_merge_machine_rows(o, t)` — machine_accounts 를 (machine, account) 로 짝짓는다. 대표는 `last` 가 새것인 쪽이되 `{**옛것, **새것}` 이라, 새 줄에 없는 항목(다른 컴퓨터가 모르는 `takes`)은 옛 줄의 값이 남는다. `first` 는 이른 쪽, `last`·`last_recv` 는 각각 새것인 쪽 — 받기 기록(recv-beat)은 `last` 를 고치지 않는 별도의 쓰기라 대표 줄에만 있다고 볼 수 없기 때문이다. 시각 비교는 문자열이 아니라 `_epoch()` 로 한다(시간대 표기가 다르면 문자열 비교가 갈린다). 덤으로, 이미 두 줄로 갈라져 들어온 프로필도 이 자리를 지나며 한 줄로 합쳐진다.

3. 프로필의 Notes 는 `### 시각` 헤더가 아니라 `- 시각 ...` 줄 목록이라, 헤더 단위 병합(`_merge_notes`)이 통째로 한 덩어리로 보고 ours 것만 남긴다 — 남의 컴퓨터가 적은 config 줄이 소리 없이 사라졌을 자리다. 양쪽 어디에도 헤더가 없을 때만 `_merge_lines`(줄 합집합·시각순)로 가른다. 문서 종류가 아니라 내용으로 가르는 조건이라 REQ 쪽 경로는 손대지 않았다.
