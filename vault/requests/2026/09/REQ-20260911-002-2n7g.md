## Original

REQ-20260910-053 을 맥에서 이어받아 실측한 결과. bin/s9.py cmd_shot 의 chrome 갈래는 후보를 (nt) ProgramFiles 계열 · /mnt/c/... · PATH 의 google-chrome/chromium/chromium-browser 에서만 찾는다. 맥에는 그 셋이 다 없어 「브라우저를 찾지 못했습니다. WSL이면 …」로 exit 3 이고, --engine chromium/webkit 은 _shot_webkit 이 「이 환경(macOS)에는 WebKit 경로가 없다」로 exit 3 이다. 규약(PROTOCOL 19조: 맥에서 Chrome 과 Safari 둘 다 본다)이 요구하는 검증을 하네스 도구가 맥에서 전혀 못 한다. 제안: cmd_shot 후보에 sys.platform == "darwin" 갈래를 더한다 — "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" · "/Applications/Chromium.app/Contents/MacOS/Chromium" · "/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" 와 ~/Applications 아래 같은 이름(os.path.expanduser). 종전 --headless --screenshot 경로가 그대로 통하므로 후보만 더하면 된다(REQ-20260910-015 의 chrome_path 맥 갈래와 같은 목록으로 한 곳에 모아 쓴다). Safari 는 safaridriver(-p 4445, W3C /session · /screenshot) 갈래를 --engine safari 로 두는 것이 다음 단계이나 이 요청의 범위는 Chrome 후보까지다. 시험: 맥 후보 경로가 os.path.exists 로 잡히면 candidates 에 드는지(모의 파일), 후보가 없을 때의 안내 문구에 「WSL이면」 대신 판별 문구가 서는지.
