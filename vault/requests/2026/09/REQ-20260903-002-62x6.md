## Original

실사고 2026-09-03: 계기가 07:26:46~08:19:30 의 세 갈래(api·ctl·dns) 동시 불통을 잡았고, 리드가 그것을 REQ-20260902-053(WSL 네트워크 죽음)의 재발로 보고했다. 사용자 정정: "방금 출근길이어서 네트웍이 끊긴건 정상이다."

즉 **오독이 났고, 오독의 원인은 계기에 있다.** 지금 세 갈래는 전부 바깥을 향한다:
- api = api.anthropic.com 전 구간
- ctl = 1.1.1.1 (이름 풀이만 건너뛴 대조군 — 여전히 바깥)
- dns = 이름 풀이 단독

셋 다 밖이라 「밖으로 못 나갔다」까지만 말하고, 그 사유가 **회선 자체가 없는 것**인지 **회선은 있는데 WSL 이 못 나가는 것**인지는 가르지 못한다. 사고 판정에서 이 둘은 정반대다 — 하나는 고칠 것이 없고 하나는 결함이다.

넣을 것: **국소 대조군 한 갈래**. 후보 —
① 기본 경로(default route)의 게이트웨이가 있는지·닿는지
② 링크 상태(operstate / carrier)
③ 호스트(윈도우) 쪽 한 자리 — WSL 게이트웨이 IP
바깥으로 한 발자국도 안 나가면서 「이 기계가 회선에 붙어 있나」를 답하는 것이면 된다.

판정 표가 이렇게 갈린다:
- 국소 죽음 + 바깥 죽음 = **회선이 없다** (이동 중·와이파이 끊김 — 고칠 것 없음)
- 국소 살아 있음 + 바깥 죽음 = **WSL/NAT 이 못 나간다** (REQ-20260902-053 의 그 병)

부수로: 이 갈래가 서면 지난 기록의 오독도 되짚을 수 있다.

### TDD — 국소 대조군 한 갈래

지금 세 갈래(api·ctl·dns)가 전부 바깥을 향해, 「밖으로 못 나갔다」까지만
말하고 사유(회선 없음 vs WSL 이 못 나감)를 못 가른다. 바깥으로 한 발자국도
안 나가는 갈래 `link` 를 더해 그 자리에서 갈리게 한다.

**판 규율을 지킨다** (DOC-20260903-004-62x6): 원시 `/proc` 읽기를 늘리지 않는다 —
`link_backend()` 라는 **문** 안에서 가르고, 문이 없는 판(맥·윈도우)에서는
「모른다」고 답한다. 모르는 것을 「붙어 있다」로 세면 대조군이 아니라 거짓말이
된다.

#### 정상
- [ ] L1. 리눅스에서 기본 경로와 링크 상태를 읽어 `ok` 를 판정한다.
- [ ] L2. 표본에 `net.link` 가 실리고, 어느 문으로 읽었는지(backend)가 함께 적힌다.

#### 판정 (이 요청의 핵심)
- [ ] L3. 바깥 셋이 다 죽고 **link 도 죽으면** → 「회선이 없다」(고칠 것 없음).
- [ ] L4. 바깥 셋이 다 죽었는데 **link 는 살았으면** → 「밖으로 못 나간다」(결함).
- [ ] L5. link 를 **모르는 판**이면 종전 문구 그대로 — 없는 근거로 판정하지 않는다.

#### 경계
- [ ] L6. 옛 표본(link 없음)을 읽어도 판정이 깨지지 않는다.
- [ ] L7. `/proc` 예산이 안 오른다 — 새 읽기는 문 안이다.
