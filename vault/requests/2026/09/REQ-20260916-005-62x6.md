## Notes

### 2026-09-16T08:52:25+09:00 tdd (agent: lead:claude-opus-5, by nicehugepark)

`s9-git-gate` (PreToolUse Bash 훅)에 검사 한 갈래를 더한다 — commit 의 훅 우회.

정상
- [ ] `git commit --no-verify -m x` 가 exit 2 로 거부되고, 사유에 s9-guard 가 무엇을 보는지와 대안이 실린다
- [ ] `git commit -n -m x` 도 같은 자리에서 거부된다
- [ ] `git add -A && git commit -m x` 는 그대로 지나간다 (기존 g2 회귀)

경계
- [ ] 짧은 옵션 묶음 `git commit -an -m x` 가 거부된다
- [ ] `git commit -m '-n 을 쓰지 마라'` 처럼 **글 안**의 `-n` 은 지나간다 (REQ-20260902-003-62x6 갈래)
- [ ] `git commit --no-edit --amend` 는 지나간다 (`--no-` 로 시작하는 다른 옵션을 `-n` 으로 읽지 않는다)
- [ ] `git -c core.hooksPath=/dev/null commit -m x` — 같은 우회의 다른 얼굴이라 함께 거부된다
- [ ] 저장소 밖(`cwd` 가 임시 디렉터리)의 `git commit --no-verify` 는 지나간다

실패/회귀
- [ ] `S9_GIT_OK=1 git commit --no-verify -m x` 는 의식적 우회로 지나간다 (기존 우회 규약과 같은 문)
- [ ] `bash -c "git commit --no-verify -m x"` 처럼 인터프리터가 받는 글자도 거부된다
- [ ] 비JSON 입력은 그대로 통과 (검사 고장이 모든 Bash 를 막지 않는다)
- [ ] 기존 파괴 명령 아홉 얼굴과 통과 목록이 그대로 선다 (tests/test_git_gate.py 전체)
