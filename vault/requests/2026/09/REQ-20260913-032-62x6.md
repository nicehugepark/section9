원인: 표시가 **기록이 아니라 보낸 순간의 DOM 에만** 있었다 — `sendChat`(web/app/restart.js)이 낙관 줄에 `→ REQ-…` 를 붙였는데, 곧이어 `refreshTermChat` 이 그 줄(.ln.pending)을 지우고 수신함 기록으로 다시 그린다. 다시 그리는 손인 `ccChatLine`(web/app/ccrender.js)은 줄에 실려 온 `req` 를 아예 보지 않아 `❯ 본문` 만 남았다. 언제 사라졌나 — 없어진 것이 아니라 **처음부터 오래 살지 못했다**: `ccChatLine` 은 2026-08-28 그 표시가 생긴 날부터 지금까지 한 번도 `req` 를 그리지 않았고(git log -L 로 확인), 보낸 직후에 함께 서던 `⎿ REQ-… 에 노트로 남았다` 한 줄만 다음 다시 그리기(탭 이동·새로 고침) 전까지 버텼다. 캡처의 21:22 줄도 수신함에 `req: REQ-20260913-014-62x6` 를 싣고 있는데 화면이 안 본 것이다.

고친 것 셋.
① bin/s9.py `/api/chat` POST → `chat_send(doc=…)`: 사람이 **눌러 고른** 문서를 수신함 줄에 `doc` 으로 적는다. `req`(이 말이 남은 문서)와 뜻이 달라 필드를 가른다 — 아티클 표기로 새 나간 말은 `req_id == picked` 가 아니므로 적지 않는다(가지 않은 자리를 가리키지 않는다).
② web/app/ccrender.js `ccChatMark`: 줄의 `doc`(없으면 `req`)을 보고 `→ <짧은 id> 에 이어 말함` 마크를 그린다. 옛 줄은 `req` 밖에 없어 새 요청인지 이어 붙인 것인지 가릴 수 없으므로 `에 기록됨` 이라고만 적는다 — 모르는 것을 단정하지 않는다. id 는 `data-tdoc` 링크라 눌러서 그 자리에서 미리보기가 열린다. 마크는 `white-space:nowrap` 한 덩어리라 좁아지면 통째로 다음 줄로 간다(WebKit 768 에서 「에 이어 / 말함」으로 갈리던 것을 보고 붙였다).
③ restart.js 의 낙관 줄도 **같은 함수**로 짓는다 — 두 손이 다른 모양을 지으면 echo 로 갈리는 순간 줄이 흔들린다.

검증: 임시 S9_ROOT 인스턴스를 9947 로 띄워(9909 는 건드리지 않았다) `/api/chat` 에 세 가지를 실제로 보냈다 — ⓐ doc 지목 ⓑ 지목 없는 요청 ⓒ 질문. 수신함 jsonl 이 각각 `req+doc` / `req` / 없음 으로 적혔고, 새로 연 화면(기록에서 다시 그린 길)에서 ⓐ `→ REQ-…-001 에 이어 말함` ⓑ `→ REQ-…-002 에 기록됨` ⓒ 마크 없음 으로 그려졌다. Chrome(Playwright chromium 1280)·WebKit(768) 둘 다 확인. 맥 Safari 는 실행하지 않았다. nowrap 을 붙인 뒤의 WebKit 재촬영은 Windows 쪽 Playwright 러너가 응답하지 않아 못 찍었다 — 붙인 규칙 자체는 CSS 한 줄이고 시험이 고정한다.

서버 재시작 필요 — bin/s9.py 를 고쳤다(`s9 serve --restart`). 재시작 전에 보낸 줄은 `doc` 이 없어 `에 기록됨` 으로 그려진다.
