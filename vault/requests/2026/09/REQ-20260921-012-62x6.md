### ① 표 — `[section9] identity = auto`
신원을 박을 때 `.git/config` 에 표를 함께 남깁니다. 표는 **값의 모양이 아니라 사실**을 적습니다 — 사다리가 프로필 메일을 골라 사람 것과 똑같이 생긴 값이 박혀도, 그것을 고른 것은 우리입니다.

### ② 되먹임 고리를 끊었습니다
`_git_identity()` 가 `.git/config` 에 그 표가 있으면 **그 파일의 user 절만** 건너뜁니다(전역은 그대로 읽습니다 — 사람이 정한 것입니다). 이 함수를 읽는 쪽(`_user_by_git_identity` · `user_name_from_src`)은 git 신원을 「이 사람이 누구인지」의 증거로 쓰는데, 그 값이 우리가 지어낸 것이면 증거가 아니라 메아리입니다. architect 와 security-engineer 가 부모 요청에서 **서로 모르는 채 같은 고리**를 짚었습니다.

### ③ 재료가 늘어난 순간 다시 잽니다
`ensure_identity(..., upgrade=True)` 는 우리가 박은 값이면 사다리를 다시 돌려 더 높은 칸이 나왔는지 봅니다. 사람이 손으로 정한 값은 `upgrade` 로도 덮지 않고, 같은 칸이 다시 나오면 아무것도 쓰지 않습니다(`.git/config` 의 mtime 만 흔들려 동시 작업 검사가 남의 것을 본 것처럼 구는 것을 막습니다). `s9 user add` · `s9 user attach` 가 그 자리에서 부릅니다.

### ④ 나가는 순간 한 번 알립니다
`sync_autoraise` 가 origin 을 보고 remote 로 올릴 때, 신원이 아직 임시값이면 한 줄 알립니다. **막지 않습니다**(product-owner 판정) — 되돌릴 수 없는 지점은 commit 이 아니라 push 이고, 이 줄이 그 직전입니다.
