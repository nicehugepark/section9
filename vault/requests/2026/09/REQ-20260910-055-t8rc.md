## Original

REQ-20260910-054 의 worktree 전체 테스트에서 갈라 세웠다 — 카탈로그 부재가 아닌 별개의 뿌리다.

실측 2026-09-10 (worktree state/worktrees/w-054-probe, 가지 wt/probe-054):
python3 tests/ instance_clean → 2건 실패.
  test_the_borrowed_branch_name_is_gone: 가지가 [main, wt/probe-054]
  test_the_history_has_no_documents_either: 이력에 users/e7test/profile.md 등 5건
본 저장소(main)에서는 15건 모두 통과한다.

뿌리: cmd_instance 의 `git clone --depth 1 file://ROOT` 는 베이스의 **현재
가지**를 가져온다(--depth 1 이 --single-branch 를 함의하므로 그 하나만). 베이스가
main 이면 clone 의 가지도 main 이고, 뒤의 `git branch -M main` 이 그것을 덮어써
사라진다 — 주석의 "옛 main 은 그때 사라진다" 가 그 전제다. 그런데 베이스가 main
이 아닌 가지에 서 있으면(worktree 는 언제나 wt/<이름> 이다) 그 가지는 -M 이
가져갈 이름이 아니라 **그대로 남고**, 그 가지의 첫 commit 에 vault/·users/ 가
통째로 들어 있어 계약 2("이력에도 없다")가 깨진다. 인스턴스를 만든 사람이 자기
저장소에서 남의 기억을 보게 되는 그 사고(REQ-20260908-039)가 되돌아온 것이다.

고치는 자리: bin/s9.py cmd_instance — `git branch -M main` 뒤에 main 이 아닌
로컬 가지를 전부 지운다(git branch --format=%(refname:short) → git branch -D).
worktree 만의 문제가 아니다: 기능 가지에 서서 init 하는 사람도 같은 자리를 만난다.

지금 못 고친 까닭: bin/s9.py 에 다른 작업자의 commit 안 한 변경 246줄이 있다
(REQ-20260910-009 계열 · tests/test_restart_transcript.py 동반). 동시 작업 규율상
덮지 않고 세워 둔다.
