### TDD 시나리오 — 머신별 마지막 받은 때

설계: 받은 때는 **등록부(users/<나>/profile.md 의 machine_accounts 줄)의 `last_recv`** 로 나간다.
새 파일을 만들지 않는 이유 — 같은 자리(`takes`, REQ-20260910-003)가 이미 「이 컴퓨터의 사실만
제 줄에 적어 내보낸다」는 규칙으로 서 있고, users/ 는 이미 미는 경로(SYNC_DATA_PATHS)다.
되먹임 차단: 한 번 적으면 MACHINE_RECV_BEAT_SEC(10분) 안에는 다시 적지 않는다. 두 자리에서
같은 문지기를 지난다 — ① 미는 회차(sync_run)에 얹혀 적고, ② 폴만 도는 조용한 컴퓨터는
문지기를 지날 때만 제가 한 번 민다.

- [ ] 정상 — 폴 성공(ok/none) 뒤 등록부의 이 컴퓨터 줄에 last_recv 가 적힌다
- [ ] 경계 — 10분 안의 두 번째 성공 폴은 다시 적지 않는다(폴이 곧 commit 이 되지 않는다)
- [ ] 정상 — 10분을 넘긴 성공 폴은 적고 스스로 한 번 민다(조용한 컴퓨터도 보인다)
- [ ] 정상 — 미는 회차(sync_run)가 돌면 그 회차에 얹혀 적힌다(따로 밀지 않는다)
- [ ] 실패 — 폴이 실패(net/diverged/dirty)하면 last_recv 를 갱신하지 않는다
- [ ] 경계 — 등록부에 그 컴퓨터 줄이 없으면 줄을 새로 만들지 않는다
- [ ] 정상 — machine_table 이 컴퓨터마다 last_recv 를 내고, 이 컴퓨터 줄은 로컬 실제값이 이긴다
- [ ] 경계 — 임계: 30분 넘으면 주의, 2시간 넘으면 사고, 적힌 적 없으면 아무 말도 하지 않는다
- [ ] 화면 — Settings 「컴퓨터·계정 이력」 표에 「마지막 받음」 칸이 서고, 임계를 넘은 줄은
      글자로 말한다(색면 하이라이트·좌측 띠 없음)
- [ ] CLI — `s9 sync --status` 가 다른 컴퓨터의 마지막 받음을 함께 낸다
- [ ] 회귀 — 비유 금지 검사(test_no_metaphors) 통과 · `s9 show` 가 오류 없이 끝난다
