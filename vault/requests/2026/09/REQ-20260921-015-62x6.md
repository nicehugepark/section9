고친 자리와 근거 (commit ab905c7b8)

무엇이었나 — bin/s9.py 의 `cmd_instance` 가 인스턴스를 만들 때 업스트림 카피에서 `git config user.name`·`user.email` 을 읽어 새 저장소의 로컬 설정에 그대로 박았습니다. 이 읽기는 전역·시스템까지 합친 값을 돌려주므로, 만든 사람이 제 컴퓨터에 정해 둔 실주소가 인스턴스 안으로 옮겨 갔습니다. 로컬 설정은 전역을 이기기 때문에, 그 디렉토리를 받은 사람의 commit 이 만든 사람의 이름·메일로 기록됩니다.

무엇으로 바꿨나 — 복사를 없애고 `ensure_identity`(bin/s9_firstrun.py) 한 자리를 부릅니다. 이 컴퓨터가 아는 신원이 있으면 아무것도 박지 않으니 각자의 자리에서 각자의 전역 설정이 쓰이고, 아무 데도 없을 때만 사다리(프로필 메일 → GitHub noreply → 임시값)가 고른 값을 그 저장소에만 둡니다. 「신원 부재로 merge·commit 이 거부되지 않게 한다」는 원래 목적은 사다리가 그대로 지킵니다.

무엇으로 확인했나 — tests/test_instance_init.py 에 M1·M2 를 더했습니다. 전역 신원이 있는 컴퓨터에서 만든 인스턴스의 .git/config 에 user.* 가 한 줄도 없고 업스트림의 이름·메일 문자열이 어디에도 없다는 것, 신원이 아무 데도 없는 컴퓨터에서는 사다리 값이 서고 그 값으로 commit 이 실제로 통과한다는 것을 잽니다. python3 tests/ instance_init → 4건 통과, instance_clean·firstrun·doctor_ident 61건 통과, no_metaphors·screen_lexicon 19건 통과. 전체 테스트는 commit 뒤 원격에서 돌고 있습니다(state/tests-async/ab905c7b8.log).

곁가지 하나 — M2 가 훅 안에서만 실패했습니다. 커밋 훅 안에서 도는 회차는 GIT_AUTHOR_*·GIT_INDEX_FILE 을 환경에 달고 오고, 그 환경 값이 `git -c user.name=…` 을 이깁니다. 시험이 물려받은 GIT_* 를 털게 했습니다.
