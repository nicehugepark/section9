### TDD 시나리오 — 탭과 화면이 어긋난다

원인 가설: `renderGraph()` 는 `graph` 캐시가 비면 `await fetch('/api/graph')` 로
멈췄다가 **깨어난 뒤 조건 없이** `#view` 를 덮는다. 그 사이에 탭이 바뀌면
알약과 판이 갈린다. 캐시는 15초 카탈로그 폴이 바뀔 때마다 비우므로(app.js
`if (changed){ ... graph = null; }`) 이 멈춤은 첫 진입만의 일이 아니다.

- [ ] S1 (정상) Graph 알약을 누르면 판이 그래프다: 헤더 알약 active 가 graph 이고
      `#view` 안에 `#gcanvas` 가 있다.
- [ ] S2 (정상) Board 알약을 누르면 판이 보드다: 알약 active 가 board 이고
      `#view` 안에 `.col`(보드 열)이 있고 `#gcanvas` 가 **없다**.
- [ ] S3 (경계·이 결함) `/api/graph` 응답이 늦는 동안 Graph → Board 로 옮기면,
      늦게 도착한 그래프가 보드 판을 덮지 않는다: 알약 board + `#gcanvas` 없음.
- [ ] S4 (경계·반대 방향) 응답이 늦는 동안 Board → Graph 로 옮기면 판에
      직전 보드가 남지 않는다: 알약 graph 이면 `#view` 에 보드 열이 없다.
- [ ] S5 (실패 경로) `/api/graph` 가 오류(500)여도 판이 다른 탭의 화면으로 남지
      않는다 — 화면이 사실을 말하고 알약과 갈리지 않는다.
- [ ] S6 (회귀) 15초 폴이 `graph` 캐시를 비운 뒤 탭을 옮겨도 S3 이 유지된다
      (첫 진입만의 결함이 아니라는 확인).
- [ ] S7 (회귀) 기존 알약 동기화(REQ-20260829-007-62x6, tests/test_tab_active_sync.py)가
