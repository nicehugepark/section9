넷의 판정을 모아 설계를 정했습니다.

### 넷이 같은 말을 한 것
- 묻지 않고 신원을 세웁니다 — 막지 않습니다. 문서 이벤트마다 commit 하는 제품에서 신원 부재는 곧 저장 불능입니다.
- `~/.gitconfig` 는 건드리지 않습니다. 폭발 반경이 이 저장소 밖이고, 도구가 말없이 고칠 자리가 아닙니다.
- 사람이 정해 둔 값은 덮지 않습니다(멱등).
- clone 경로도 같은 자리를 지나야 합니다 — 이것이 이 요청의 본체입니다.
- architect 와 security-engineer 가 서로 모르는 채 같은 되먹임 고리를 찾았습니다: section9 이 쓴 신원을 section9 이 사람의 증거로 다시 읽습니다(`user_name_from_src` · `_user_by_git_identity`). 표를 남겨 끊습니다.
- 만들지 않을 것: 신원 설정 화면·새 탭 · GitHub OAuth · 여러 걸음 마법사 · 과거 이력 재작성.

### 갈린 셋과 제 판정

**① 임시값의 모양 — security-engineer·architect 를 따릅니다.**
product-owner 는 `<계정>@local` 을 「임시임이 보이는 표」로 지키자고 했는데, security-engineer 가 그 값이 사내 로그인 이름을 원격 이력에 영구히 박는다는 것을 짚었고 되돌릴 길은 이력 재작성뿐입니다. architect 의 사다리를 채택합니다: 프로필 메일 → `<github>@users.noreply.github.com` → (대화가 불가능한 자리에서만) 임시값. 둘째 칸이 핵심입니다 — 비밀이 아니고 묻지 않아도 되는데 GitHub 이 실제로 그 계정에 이어 줍니다. product-owner 가 지키려던 「임시임이 보여야 한다」는 값의 모양이 아니라 `.git/config` 의 `[section9] identity = auto` 표로 만족시킵니다.

**② 첫 실행에서 메일을 묻는가 — 사다리가 둘을 화해시킵니다.**
프로필에 `emails` 나 `github` 가 있으면 묻지 않습니다(product-owner 의 요구). 아무것도 없을 때만 첫 실행에서 한 줄 묻되 Enter 로 건너뜁니다(ux-writer 의 문안). 이름을 세 번 묻는 꼴은 나지 않습니다 — 묻는 것은 메일 하나뿐입니다.

**③ push 를 막는가 — product-owner 를 따릅니다. 막지 않습니다.**
security-engineer 는 임시 신원이면 동기화를 켜지 않는 차단 층을 권했는데, 사다리를 넣고 나면 대부분의 사람은 애초에 GitHub 에 이어지는 주소를 갖습니다. 다만 security-engineer 가 짚은 위험(origin 이 생기면 그때까지 쌓인 것이 아무 확인 없이 나갑니다)은 실제이므로, 원격에 잇는 그 순간 한 번 알리고 「지금 정하기 / 그대로 가기」로 받습니다.

### 단계 (L 이라 갈랐습니다)
1. [S] 책임 가르기 — `ensure_identity` 를 `ensure_repo` 밖으로 꺼내 `s9 code` 가 언제나 부르게 합니다. 세 입구(배포판·clone·초대)가 한 자리를 지나게 됩니다. 숨은 함정이 하나 있습니다: 지금 `_ensure_identity` 의 `git config <키>` 는 로컬도 함께 읽어, `.git` 이 이미 있는 자리에서는 뜻이 달라집니다 — `--global`/`--local` 을 나눠 읽게 함께 고칩니다. (REQ-20260921-003-62x6)
2. [S] 사다리 얹기 — 프로필 메일 → noreply → 임시값. `IDENT_DEAD_MAIL` 을 공용 자리로 올려 투영하는 쪽과 진단하는 쪽이 같은 목록을 보게 합니다.
3. [S] 문구 — doctor 의 세 갈래를 ux-writer 문안으로 바꿉니다. 임시 신원은 오류(✗)가 아니라 알림(△)입니다.
4. [M] 승격 자리 — 등록·프로필 수정 뒤 재평가, doctor 의 고치기, 원격에 잇는 순간 1회 알림.

### 범위 밖에서 드러난 결함 둘 (파생으로 세웁니다)
- `s9 instance init` 이 업스트림의 `user.name`/`user.email` 을 새 인스턴스로 복사합니다 — A 가 만든 인스턴스를 B 가 받으면 B 의 commit 이 A 로 섭니다.
- 한 저장소를 둘이 쓰는 자리(공용 경로·worktree)에서 `.git/config` 는 전역을 이깁니다 — 제 전역을 올바로 맞춰 둔 사람의 commit 까지 먼저 박힌 남의 이름으로 나갑니다.
