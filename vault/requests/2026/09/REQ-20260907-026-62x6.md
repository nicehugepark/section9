### 결론

### 원천을 바로잡음 (지시와 다른 사실)

`harness/claude/gen_roster.py` 에는 **s9-design 항목이 없다.** 그 파일의 SKILLS 사전은 s9-protocol·tdd·browser-verify 등 12개만 담고, s9-design 은 `harness/claude/skills/s9-design/SKILL.md` **그 파일이 원천**이다(설치본 `~/.claude/skills/s9-design` 는 그 디렉터리를 가리키는 symlink). 그래서 표 절은 SKILL.md 에 직접 넣었고, `python3 harness/claude/gen_roster.py` 를 돌려 그것이 s9-design 을 덮거나 지우지 않음을 확인했다(정리 루프는 `s9-` 로 시작하지 않는 디렉터리만 지운다).

### 표 절 (여덟 규율)

① 열 머리는 mono·uppercase 규칙의 **예외** — 이 자리에 한글 라벨이 서고, mono 는 한글을 대체 글꼴로 떨어뜨려 같은 표에 얼굴이 두 벌이 된다(tech-writer 가 REQ-012 에서 짚은 자리). 확정값: 본문체 11px · 600 · `letter-spacing:.02em` · `--muted` · `text-transform:capitalize`. capitalize 를 고른 까닭은 **라벨 글자를 고치지 않고** 라틴(time→Time)과 한글(시각→시각)을 한 얼굴로 세울 수 있어서다. ② 정렬: 비교할 수는 오른쪽 + tabular-nums, 글·라벨·id·경로는 왼쪽, 날짜·시각은 왼쪽 + mono, 가운데 정렬 금지. ③ 열 순서: 폭이 고정된 열이 앞, 폭이 변하는 본문 열이 마지막. ④ 밀도 두 단계(보통 `8px 14px` · 촘촘 `4px 10px`, 세로는 4의 배수 — 홀수 px 은 비정수 배율에서 위아래가 갈린다). ⑤ 줄무늬와 헤어라인 중 하나만, 세로 구분선 없음. ⑥ 폭이 모자라면 접지 말고 가로 스크롤(`min-width`), 예외는 라벨-값 두 열짜리 정의 표. ⑦ 표 안의 손잡이는 글자 손잡이만, 행 전체를 과녁으로 만들지 않는다. ⑧ 연속 같은 값은 첫 행에만, 값은 지우지 말고 1px+clip 으로 가린다. 여기에 「표 위의 안내문은 상주하지 않는다」를 덧붙였다.

### audit 표에 적용한 것

- **중-1 (같은 값만 반복되는 열)**: 종류·남긴 사람·세션 세 열에 연속 값 접기. `once(col,key,html)` 가 앞 행과 같으면 `<span class="dup">` 로 감싸고, CSS 는 `display:none` 이 아니라 1px + `clip-path:inset(50%)` 로 가린다 — 화면낭독기와 복사는 값을 그대로 갖는다. 시각(행마다 바뀜)과 내용(이 표의 본문)은 접지 않는다.
- **열 순서**를 `시각·종류·남긴 사람·세션·내용` 으로 바꿨다. 고치기 전에는 내용 열이 가운데서 남는 폭을 다 가져가, 짧은 행에서 왼쪽 끝과 오른쪽 끝이 600px 넘게 떨어져 있었다(첨부 ①). 로그 화면의 관례(시각·등급·출처·메시지)와도 같다.
- **남는 폭은 마지막 본문 열이 갖는다**(`th:last-child,td:last-child{width:100%}`). 이것 없이 접기만 했더니 접힌 열 셋이 폭만 차지해 되레 나빠졌다 — 첫 캡처에서 잡아 고쳤다.
- **중-2 (안내문 상주)**: `<div class="cap">` → `<details class="cap">`, 기본 닫힘. **문장은 한 글자도 바꾸지 않았다**(REQ-018 몫). 접힘의 이름 `이 화면은?` 은 REQ-012 designer 보고가 제안한 말을 그대로 썼다 — ux-writer 확정 필요.
- 열 머리 얼굴 적용(mono·uppercase·`--faint` 제거), 셀 여백 `7px`→`8px`(4의 눈금), 시각 열 `--faint`→`--muted` + tabular-nums, 세션 열 `nowrap`(좁아진 열에서 기계 문자열이 두 줄로 끊겼다 — 첫 수정 캡처에서 잡음), grid 스킨은 줄무늬를 쓰므로 헤어라인 0.

### 대안 비교 (왜 이 선택인가)

- 같은 값: **(A) 연속 값 접기** vs (B) 값이 하나뿐인 열을 통째로 접고 표 밖에 한 번 적기. B 는 필터가 값을 묶은 경우에만 참이고, 필터를 풀면 열이 다시 나타나 표의 모양이 바뀐다(같은 화면이 두 구조를 갖는다). A 는 어떤 필터에서도 같은 구조라 골랐다. B 도 절에 남겨 두었다(조건: 그 값을 표 밖 한 곳에 적을 때만).
- 안내문: **(A) `<details>` 접힘** vs (B) 한 줄로 줄여 상주. B 는 문장을 고치는 일이라 REQ-018 과 충돌하고, 줄여도 판을 열 때마다 읽히지 않는 줄이 남는다. A 는 되돌리기가 한 줄(`open` 속성)이라 판정 비용도 낮다.
- 열 머리: **(A) capitalize + 본문체** vs (B) 라벨을 한글로 바꾸며 얼굴도 함께 교체. B 가 최종 모습이지만 라벨 교체는 translator 의 자리라, 얼굴만 먼저 한글이 설 수 있게 해 두었다.

### translator 인계 (REQ-012 tech-writer 묶음 A)

라벨 글자는 그대로 두었다: `time`·`type`·`by`·`session`·`event`. 옮길 것 — TIME → 시각 / BY → 남긴 사람 / TYPE → 종류 / SESSION → 세션 / EVENT → 내용. 얼굴은 이미 한글 기준이라 글자만 바꾸면 되고, `capitalize` 는 한글에 아무 일도 하지 않으므로 CSS 를 다시 손댈 필요가 없다. `web/app/audit.js` 의 `<thead>` 한 줄이 전부다.

### `.metatbl` 판정 (코드는 남의 자리)

표 절이 문서 뷰어의 메타 표에도 닿는다 — 두 곳이다. ① **라벨 얼굴**: `.metatbl td:first-child` 가 mono 10px + uppercase + `letter-spacing:.08em` + `--faint` 인데, 그 라벨은 한글이 서는 자리라 audit 열 머리와 **같은 결함**이다(얼굴 두 벌 + 읽어야 하는 글자에 `--faint`). 같은 확정값(본문체 11px·600·`--muted`)으로 옮겨야 한다. ② **폭이 모자랄 때**: 이미 옳다 — `tablet.css` 가 900px 아래에서 라벨을 값 위로 쌓는데(`tr{display:block}`), 그것이 절 ⑥ 의 「두 열짜리 정의 표는 표가 아니라 목록」 예외와 정확히 같다. 고칠 것은 ① 뿐이고, docs.css 의 그 블록은 D1, docs.js 는 frontend-developer 의 자리라 손대지 않았다.

### 검증

`python3 tests/ audit_table` 9/9 · `audit_wiring` · `doc_table` · `terminal_table` · `no_metaphors` 통과. 실브라우저 캡처는 ledger·grid·glass·soft 4스킨 1440 과 ledger 768. 안내문을 펼친 얼굴은 `s9 shot` 이 클릭을 못 하므로 `open` 속성을 잠깐 넣어 찍고 되돌렸다(첨부 ⑤, 되돌린 것은 grep 으로 확인). **미검증**: 행 hover 틴트(규칙을 바꾸지 않았다)와 summary hover 밑줄 — 실포인터 캡처는 하지 않았다. Safari(WebKit) 미검증 — `details`·`clip-path`·`tabular-nums` 는 WebKit 이 오래 지원한 것들이지만 이 화면에서 눈으로 보지는 않았다.
