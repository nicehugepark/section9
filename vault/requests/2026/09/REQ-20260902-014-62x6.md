이제 멀티 프로젝트에 대한 준비는 됐는데 동시에 여러 사용자가 실시간에 가까운 요청 동기화에 대해서 준비를 해야한다. 
우선 시 되어야 하는건, 여러 요청이 있더라도 자신의 요청이 자신의 머신에서 실행이 되는 것이다. 
요청 문서를 실시간으로 공유한다고 하게 되면 남의 요청 문서가 in-progress 상태로 나한테 pull/fetch가 되었을 때 내 머신에서도 같은 요청에 대해서 중복 실행이 될 수 있어서 방지해야한다.
그리고 요청을 처리하면서 이 시스템이나 llm 모델이 스스로 생성하는 요청이 있는데 이를 위해서 요청 문서에 현재 사용하는 사용자의 id 와 에이전트 정보까지 작성이 되어야 한다. 그래야 순수 사람이 요청을 한건지, 에이전트가 요청을 한건지, 에이전트가 누구의 요청을 처리하다 파생한 요청인지를 알 수 있다. 그러면 현재 내 머신의 세션에서는 나의 요청과 내 요청으로 인해 파생된 에이전트 요청만 처리하고 다른 사람의 요청은 손대지 않을 수 있게 된다. 하지만 이럴 경우 요청을 남에게 할당할 수 없게 되는데, 요청의 생성자 항목과 요청 담당자 항목을 만들고, 담당자는 변경할 수 있도록 하는 기능도 있어야 할 것 같다.
그리고 무엇보다 이 요청들이 거의 실시간에 가깝게 그리고 안전하게 충돌 없이 공유가 되도록 해야하는데 이 부분은 방법을 찾아야한다. 깃헙 main 브랜치 하나에서 하는 것을 처음엔 생각했었는데 프로젝트별로 브랜치가 생성이 되는 방법이라거나, 프로젝트-사용자 브랜치를 사용한다거나.. 어떤 식으로든 실시간으로 그리고 지저분하지 않게 충돌이 되지 않게 성능이 떨어지지 않게 하는 방법을 찾아야한다.
현재 문서는 모든 문서를 하나의 디렉토리에 저장하고 조회 시 필터를 사용하는데 애초에 vault 하위에서 프로젝트별로 혹은 프로젝트/사용자별로 문서를 만들고 통합해서 보여주는 방식은 어떨지..
브레인스토밍 단계의 아이디어일 뿐이다. 방향성을 제시한것이 아니라. 
그리고 observer 계정 혹은 계정 타입을 둬서 요청을 생성하거나 수정하거나 하지는 않고 오로지 read only만 되면서 모든 프로젝트 혹은 프로젝트별 상태 관찰이나 이력,지식 검색만 할 수 있는 기능도 있어야 할 것 같다.
