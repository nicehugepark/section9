[지금 구조]
쓰는 자리는 하나다: `do_user_config_set`(bin/s9.py:22661). CLI(`s9 user config`, 22916)도 대시보드
POST `/api/user/config`(bin/s9.py:36513)도 이 함수 하나를 지나고, 여기서 viewer 차단·키 정규식·
audit(profile.md Notes) 이 함께 선다. 저장 파일은 둘로 갈리지만(`users/<id>/config/settings.json`=git 추적 ·
`local.json`=비추적) 가르는 판정은 `_local_only_key`(367) 한 곳이고 `pref_*` 는 그 목록에 없으니
**전부 추적 파일**로 간다. 읽는 자리도 하나다: `user_config`(389) 가 settings 위에 local 을 겹쳐 준다.
주입은 Claude 의 UserPromptSubmit 훅 `bin/s9-audit-prompt` 뿐이다 — 모든 분기가 지나는 `emit()`(720)이
`turn_prefs()`(671)를 부르고, 그것이 `s9 user current`(세션 바인딩 → 사람)로 주체를 정한 뒤
`s9 user config <그 사람>` 을 매 턴 새로 읽어(캐시 없음, test_pref_injection R2) `◈ …` 한 문장으로 만든다.
없으면 「없음 — 기본 말투로」를 명시 주입한다(REQ-20260824-016). 화면은 web/app/userform.js 가 `pref_`
접두로 걸러 표를 세우고 새 키에 접두를 붙이며(710), 빈 값은 서버가 삭제로 읽는다. 시험은
tests/test_pref_injection.py(모든 턴 경로)·test_audit_prompt.py(P1~P3)·test_viewer_gate.py·
test_observe_scope.py·test_local_only_config.py 가 있다. 요약: **저장·읽기의 단일 경로는 잘 서 있고,
갈라진 것은 「주입」과 「내용의 경계」다.**

5. 주제 칸은 label 이 아니라 **값**이므로 `.metatbl td:first-child` 의 mono·uppercase·
   letter-spacing 을 이 표에서만 벗긴다: 본문체 12px/600 · `letter-spacing:.02em` ·
   `color:var(--muted)`(표 절 1 의 확정값). metatbl 전역은 건드리지 않는다.
6. 빈 상태를 **표 자리로** 올리고 두 줄 「…습니다」로: 「아직 정해 둔 선호가
   없습니다. / 아래에 주제와 내용을 적으면 다음 대화부터 그대로 따릅니다 — 예: 주제
   `말투`, 내용 `짧게 답하고 칭찬은 빼 주세요`.」
7. 저장 손버릇을 통일한다. **권장: 칸을 떠날 때 즉시 저장 + `.secmsg` 한 줄**
   (시간대·대화 기록이 이미 그렇게 한다). 대안: 「선호 저장」 버튼 유지. 즉시 저장을
   고르는 근거 — 한 판에 저장 모형이 둘이면 어느 칸이 어느 쪽인지 화면이 말하지
   못하고, 이 값은 다시 적으면 되돌아오므로 파괴적이지 않다. 버튼을 남긴다면 세
   버튼(설정 저장·선호 저장·값 저장)이 무엇을 각각 담는지 화면이 말해야 한다.
8. 「그 밖의 값」은 `<details>` 로 접고(기본 닫힘) 이름을 「기계가 적어 둔 값 N개」로
   — 사람이 적는 지시와 기계의 장부를 눈으로 가른다. 「개인화 설정」 절은 이름을
   내용으로 좁히고(digest 분량), 「임의 키」 칸에 `pref_` 를 치면 「개인 선호로
   갑니다」를 말하거나 그 칸에서 막는다(문은 하나).

**접근성**: 값 입력에 이름이 없다(`<label for>`·`aria-label` 모두 없음) — 화면낭독기가

### 개인 선호(pref_*) 기능 점검 결과

격리 루트(S9_ROOT=임시)에서 실제로 돌려 쟀다. 라이브 nicehugepark 의 pref 둘은 읽기만 했고 그대로다.
**저장·주입의 본줄기는 작동한다.** 결함 6건 — 데이터 유실 1, 상한 없음 1, 나머지는 조용한 실패·발견성.

### 잰 것 (무엇을 어떻게 재서 무엇이 나왔나)

- 저장/한글 키: `s9 user config alice pref_말투 '존댓말로 짧게'`, `'pref_응답 형식'` → 둘 다 exit 0, settings.json 에 그대로. 내부 공백 있는 한글 키도 통과.
- 아주 긴 값: 5000자·8000자 저장 → exit 0, 잘림 없이 전량 저장(상한 없음).
- 줄바꿈 값: `$'첫 줄\n둘째 줄\n셋째 줄'` → settings.json 에 `'첫 줄\n둘째 줄\n셋째 줄'` 로 보존.
- 같은 키 덮어쓰기: pref_말투 를 '반말로' 로 재설정 → 조회가 '반말로'. 정상.
- 빈 값 = 삭제: `pref_말투 ''` → 키가 사라짐(`['pref_긴값','pref_다줄','pref_응답 형식']`). 정상.
- 키 검증: `pref_a!b` → `invalid config key` exit 1. 64자 초과 키 → 거부 exit 1. 미등록 사용자 → `not registered` exit 1. 정상.
- 주입(직접 호출): `prefs_context(env,'alice')` → `◈ 이 사용자의 개인 설정(응답 말투·작업 방식에 반영하라): …` 생성. pref 없는 bob → `◈ 개인 설정: 없음 — 기본 말투·방식으로 응답하라`.
- 주입(훅 전체 실행): UserPromptSubmit JSON 을 `bin/s9-audit-prompt` 에 물려 실행 → additionalContext 안에 `◈ 이 사용자의 개인 설정…: 말투: 아주 짧게.` 실측. 실제로 들어간다.
- 그 사람의 것만: `s9 user switch bob` 뒤 훅 실행 → bob 의 값만 실림. alice 의 값은 안 실림. 전환이 따라간다.
- 순서 안정성: 키 5개(a·b·가·긴값·말투)로 3회 반복 → 매번 `['a','b','가','긴값','말투']` 동일(`sorted()` 기반). 안정.

### 결함

**D1 [중·데이터 유실] 줄바꿈이 든 pref 값이 Settings 를 여는 것만으로 한 줄로 뭉개진다.**
CLI 는 줄바꿈을 받아 저장하고 훅도 줄바꿈째 주입하는데, 화면의 행은 `<input>`(web/app/userform.js:138)이라 브라우저가 값에서 줄바꿈을 지운다. 저장 버튼은 `val !== String(cfg[k] ?? "")` 일 때만 POST 하는데(userform.js:706-707) 줄바꿈이 지워진 값은 저장값과 다르므로 **아무것도 안 고쳐도 POST 가 나가** 원본을 덮어쓴다.
재현: ① `s9 user config <나> pref_다줄 $'첫 줄\n둘째 줄'` ② Settings ▸ 내 계정 ▸ 맨 아래 개인 선호 ③ 아무것도 고치지 말고 「선호 저장」 ④ `s9 user config <나> pref_다줄` → `첫 줄둘째 줄`.

**D2 [중] pref 값에 길이 상한이 없다 — 저장에도 주입에도.**
8000자 값을 넣으면 매 턴 프롬프트에 8000자가 그대로 실린다(실측: 훅 출력의 90%가 pref 본문). 자름도, 경고도, 화면 안내도 없다. 붙여넣기 사고 한 번이 모든 턴의 컨텍스트를 먹는다.
재현: `s9 user config alice pref_긴값 "$(python3 -c "print('나'*8000)")"` → 훅 실행 → additionalContext 에 8000자 전량.

**D3 [하] `prefs_context(env, "")` 가 IndexError 로 터진다.**
bin/s9-audit-prompt:552 `name = (who or "").split()[0].strip()` — 빈 문자열 가드(`if not name`)가 인덱싱 **뒤**에 있다. 지금은 호출부 `turn_prefs()`(:688-690)가 `if who` 와 `except Exception: return ""` 으로 감싸 안 터지지만, 그 except 가 장애를 「pref 없음」으로 삼켜 조용한 실패로 만든다.
재현: `prefs_context(dict(os.environ), "")` 직접 호출.

**D4 [하] 현재 사용자가 미등록이면 주입이 통째로 사라진다.**
`s9 user config <미등록>` 이 비-0 → `prefs_context` 가 `""` 반환. pref 도 안 실리고, REQ-20260824-016 이 세운 「부재도 명시 지시로」(= `개인 설정: 없음 — 기본 말투로 돌아가라`)도 안 나간다. 계약이 이 갈래에서만 깨진다.
재현: `prefs_context(env, "nobody")` → `''`.

**D5 [하] `pref_` 접두 없는 키를 CLI 가 말없이 받는다.**
`s9 user config alice 취향 '아무거나'` → exit 0, 「alice: 취향 = 아무거나」, settings.json 에 저장, 화면의 「그 밖의 값」에도 표시. 그런데 주입은 영영 안 된다. 사람은 저장됐다고 본다. 화면은 자동으로 `pref_` 를 붙여 주므로(userform.js:710) 이 갈래는 CLI 에만 있다 — 주인이 CLI 로 쓰다 「안 먹는다」고 느낄 자리.

**D6 [하·발견성] 개인 선호 표가 가장 안 보이는 자리에 있다.**
내 계정 화면의 **맨 아래**(캡처 실측 y≈2380 / 전체 약 2600px), 프로필·컴퓨터 이력·개인화 설정·시간대·대화 기록·시크릿·바깥 폴더를 **일곱 판 지나서야** 나온다. 왼쪽 목록에는 제 항목이 없고 「내 계정 — 프로필·개인화」로만 적혀 있어 이름조차 안 보인다. 주인이 「잘 사용하지 않았다」고 한 기능이 놓인 자리가 이렇다.
