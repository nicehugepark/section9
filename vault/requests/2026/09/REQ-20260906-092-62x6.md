### 태블릿 문제 목록 (분석)

실측: Windows Chrome headless, 1024x768(가로)·768x1024(세로), skin=calm/tone=system(다크).
캡처로 본 것은 Board·Docs·Projects·Terminal 넷. Graph·Audit·Stream·Settings 는 캡처
예산이 모자라 CSS 로만 봤다(아래 T7·T8 은 그래서 규칙 근거만 있고 그림 근거가 없다).

### T0. 반응형 규칙을 놓는 자리가 잘못 알려져 있다 (구조)
`web/index.html` 의 css 목록에서 responsive.css 는 **여섯 번째**다 — actions·skins·
density·calm·tidy·overlay 가 그 **뒤**에 온다. "responsive 가 맨 뒤라 덮는다"는 전제는
사실이 아니고, 게다가 스킨 규칙은 `[data-skin="calm"] .col` 처럼 특이도가 한 급 높아
`.col` 한 줄로는 애초에 못 덮는다. → 폭 규칙은 ① 컴포넌트가 읽는 변수(--vpad·--docsh
같은)를 바꾸거나 ② 스킨과 같은 특이도로 쓰거나 ③ 의사요소로 얹는다. 순서에 기대지 않는다.

### T1. 헤더가 세로를 23% 먹는다 — 모든 탭
가로 1024x768 에서 헤더 175px(전체의 23%). 세로 768x1024 에서는 `.hrow2` 의 필터가
두 줄로 접혀 215px. hrow2 의 select 가 자연폭이라(프로젝트 select 만 230px) 768 폭에서
한 줄에 못 들어간다. → ≤1180 에서 select·검색칸에 max-width 를 물려 한 줄을 지킨다.

### T2. 문서 본문이 12자마다 끊긴다 — Docs, 세로 768
`.doclist{width:330px}` + `.viewer{--vpad:34px}` → 768 폭에서 본문에 남는 폭 366px.
그 안 `.metatbl td:first-child{width:150px;white-space:nowrap}` 이 라벨에 150px 을
가져가 값 칸이 185px 로 눌린다: SUMMARY·GOAL 이 한 줄에 열두 자씩 끊기고 doclink
`REQ-20260906-091-62x6` 이 토큰 한가운데서 잘린다. → ≤1180 목록 폭 축소, ≤900 에서
--vpad 축소 + metatbl 라벨을 값 **위로** 쌓아 값에 폭을 다 준다.

### T3. 터치 대상이 44x44 에 못 미친다 — 헤더·Docs 목록 (전 폭)
탭 단추 36px · 계기줄 `.stat` 34px · 타입바 `.tb` 24px · hrow2 체크박스 13px ·
`+ N개 더 보기` 15px. 손끝(약 9mm)으로는 옆 것을 누른다. → 칠(보이는 모양)은 그대로
두고 **과녁만** 넓힌다: `::after` 를 절대 위치로 얹거나 안여백만 키운다(s9-design
「칠은 과녁이 아니다」). 카드 벨트의 27px 글리프는 REQ-20260830-043-62x6 으로 확정된 값이라
건드리지 않는다.

### T4. 스크롤하면 문서 머리가 헤더 뒤로 사라진다 — Docs (폭 무관, 태블릿에서 더 아픔)
`header{position:sticky;top:0;z-index:10}` 와 `.viewer .dhead{position:sticky;top:0;
z-index:5}` 가 같은 문턱을 다툰다 — 헤더가 이긴다. 문서를 내리면 제목·전이 단추 띠가
통째로 헤더 뒤에 깔려 안 보인다(≤900 은 REQ-20260830-046-62x6 이 이미 `position:static`
으로 붙기를 포기해 둔 자리다). → 헤더 실측 높이를 `--hh` 로 내보내고 dhead 의 문턱을
그 값으로 둔다. 데스크탑 폭은 이번에 건드리지 않는다(회귀 금지) — 같은 결함이 거기에도
있다는 사실은 여기 남긴다.

### T5. Stream 의 대화 영역이 화면 밖으로 넘친다 — Stream, 세로 768
`.term{max-height:calc(100vh - 150px)}` 의 150px 은 헤더 높이를 손으로 적은 값이다.
실제 헤더가 175~215px 인 태블릿에서는 영역이 화면 아래로 25~65px 삐져나가, 페이지
스크롤과 안쪽 스크롤이 겹친다. 옆 목록(.doclist)은 JS 실측(--docsh)을 쓰는데 이쪽만
상수다. → 같은 `--hh` 로 갈아탄다.

### T6. Board 가로 스크롤에 단서가 없다 — Board
열 최소폭이 base 210px, calm 224px, grid 212px 이라 다섯 열이면 1050~1120px 다.
1024 가로에서 마지막 열이 잘리고, 태블릿은 오버레이 스크롤바라 "옆으로 밀 수 있다"는
표시가 아예 안 보인다(세로 768 폭에서는 세 열만 보인다). → 열 최소폭을 태블릿 폭에서
낮춰 잘리는 열을 줄인다. 스크롤 자체는 설계된 동작이라 없애지 않는다.

### T7. Audit 표가 스크롤하지 않고 눌린다 — Audit (CSS 근거만)
`.audit .tblwrap{overflow-x:auto}` 인데 `.audit table{width:100%}` 라 표가 넘치는 대신
칸이 눌린다 — overflow 가 걸릴 일이 없다. → 태블릿 폭에서 표에 min-width 를 주어
가로 스크롤이 실제로 서게 한다.

### T8. Graph 여백 레일 (CSS 근거만)
`.gsplit` 은 1180 이하에서 이미 1열로 내려간다. 캔버스는 width:100% 라 폭은 따라오지만
높이는 확인하지 못했다 — 남은 점검이다.

### 손대지 않은 것
