### 목적을 다시 세웠다 — 건수가 아니라 시간·부하

사용자 정정: "테스트 건수를 단순히 줄이는게 목적이 아니다. 본질은 테스트가 너무 오래걸리고 시스템에 부하를 준다는 사실을 해결하려는 것이다. … 동시 요청 작업 처리 시 같은 테스트를 스위트라는 명목으로 중복, 중첩 실행되는것을 방지하려고 하는거다."

그래서 두 겹으로 막았다 (`tests/__main__.py`).

**① 선택별 green 기록** — 패턴 묶음마다 마지막 green 의 **나무 지문**(HEAD + 미커밋 파일의 mtime·크기)을 `state/tests-green/<선택해시>.json` 에 적는다. 지문이 같으면 돌 이유가 없다. 전체 green 스탬프(`--changed`)의 조카뻘인데, 그쪽은 「전체」에만 서고 이쪽은 **어떤 선택에도** 선다.

**② 단일비행** — 같은 선택이 이미 돌고 있으면 두 번째는 **새로 돌리지 않고 기다렸다가 그 결과를 받는다**(`state/jobs/tests-<선택>.lock`, flock). 기다림이 끝나면 ①을 다시 보고, 앞 실행이 방금 통과시켰으면 그대로 쓴다.

실측:
| | |
|---|---|
| `tests/ uid` 1회차 | 4.0초 (실제로 돈다) |
| 같은 것 2회차 | **0.08초** (기록 재사용) |
| 같은 것을 둘이 동시에 | 두 번째가 2.1초 기다렸다가 **앞 실행의 결과를 받는다** |

**고친 것 하나 — 실측이 잡았다.** 처음에는 `--no-reuse` 가 잠금까지 건너뛰게 짰다. 그랬더니 둘이 나란히 도는 것을 눈으로 봤다. **잠금은 언제나, 재사용만 고를 수 있게** 로 고쳤다 — `--no-reuse` 는 "기록을 믿지 말고 다시 돌라"이지 "남과 겹쳐 돌아도 된다"가 아니다.

안쪽 실행(`S9_TESTS_NESTED=1`)은 둘 다 지나친다 — 바깥이 이미 문을 지났고, 여기서 또 잠그면 자기 자신을 기다린다.
없는 판(`fcntl` 없는 윈도우)에서는 잠그지 않고 그냥 돈다 — 겹침을 막는 것이 목적이지 그 판에서 못 돌게 하는 것이 목적이 아니다.

### 항목 줄이기 (009 몫) 는 3,215 → 1,532

assert 는 하나도 안 버리고 클래스당 한 항목으로 접었다. 접다가 두 번 배웠다 — 클래스 경계를 넘으면 setUpClass 속성이 어긋나고, `setUp` 이 있는 클래스는 접으면 상태가 새어 없던 실패가 난다. 그래서 **읽기만 하는 계약 시험**만 접는다.

### 아직 안 끝난 것

접은 결과의 전체 스위트 검증이 도는 중이다. 그 와중에 내가 다른 시험을 동시에 돌려 `test_port_pool` 에서 포트 충돌 에러가 하나 났다 — **이 요청이 막으려는 바로 그 현상**이라, 우연히 증거가 됐다. 검증은 조용한 상태에서 다시 받는다.
