### 용어 판정 — 휴지통 새 낱말 (tech-writer)

**반려 한 자리: 「N건 정리하기」. 나머지 전부 유지.**

| 낱말 | 판정 | 근거 |
|---|---|---|
| 거르개 셋 「전부 / 화면에서 버린 것 / 명령으로 버린 것」 | 우리 말 · 유지 | 이 축은 남의 도구 이름이 아니라 「사람이 어디에 있었나」다. 화면 쪽도 명령 쪽도 같은 do_rm 을 부르니 `rm` 은 둘을 가르지 못한다 — 2조의 문(칠 명령이 있는가)을 통과할 이름이 애초에 없다. 그러므로 우리 말이 맞다. |
| 축 이름 「명령」 | 유지 | 규약 2조가 스스로 「칠 명령」이라 쓴다 — 이 하네스의 확립어다. 「CLI」는 영어 약자라 금지(s9-design 설명 규율 ②), 「터미널」은 이 제품에서 이미 대시보드 터미널 탭·터미널 뷰의 이름이라 겹친다(같은 것에 이름은 하나, 다른 것에 같은 이름도 하나). 「화면에서 / 명령으로」의 조사가 어긋나 보이는 것은 한쪽이 자리, 한쪽이 수단이기 때문이고 우리말은 그렇게 쓴다 — 억지로 맞추지 마라. |
| 행 표시 「화면에서 버림 / 명령으로 버림」 | 유지 | 행 표시는 문장이 아니라 표의 값이라 명사형이 맞고, 같은 줄의 「30일 넘김」과 한 꼴이다. R2 의 명사형 금지는 확인 창의 **실행 버튼** 자리를 가리킨다. 안 적힌 옛 문서가 아무 말도 안 하는 것도 맞다 — 모르는 것에 이름을 붙이면 그 이름이 거짓이 된다. |
| **「N건 정리하기」** | **금지 → 「N건 완전히 지우기」** | 셋째 사전이다: 한 판 바닥에 같은 일의 이름이 「정리하기」·「휴지통 비우기」·(행마다)「완전히 지우기」 셋이 선다. 더 나쁜 것은 이 손잡이가 여는 확인 창의 실행 버튼이 이미 「완전히 지우기」라는 점 — 시작하는 이름과 하는 이름이 다르다. 「정리」는 되돌릴 수 없는 일을 부드럽게 말해 R2(버튼은 결과를 말한다)의 반대쪽 결함이고, 조각 이름(tidy.js)이 화면으로 샌 말이다. 수명을 넘긴 것만 집는다는 사실은 바닥 문장과 행의 「30일 넘김」이 이미 말하므로 손잡이가 다시 말할 필요가 없다. 바꾸면 확정 사전은 여섯 그대로다(수 하나가 앞에 붙을 뿐). |
| 바닥 문장 「30일을 넘긴 것도 저절로 사라지지 않습니다 — 지우는 것은 사람이 누릅니다.」 | 유지 | 존댓말 한 층·사용자 말·비유 없음. 날수를 코드가 아니라 설정에서 받아 쓰므로 설정이 바뀌면 문장이 따라간다. 지키지 않을 약속을 적지 않는다는 뜻에서 수명이 꺼지면 이 줄이 서지 않는 것도 맞다. |
| `trashed` · `trashed_by` · `trashed_how` (값 `screen`/`cli`) | 그대로 | 문서 프론트매터 키 — 2조 ⑤. 값은 화면에 날것으로 나오지 않고 TIDY_HOW 가 옮긴다. **다만**: 문서 뷰어 메타 표에 이 값이 그대로 뜨는 날이 오면 라벨은 TIDY_HOW 와 **같은 사전**을 써라(화면에서 버림 / 명령으로 버림). 같은 사실에 사전이 둘이면 그때 갈린다. |
| `trash_keep_days` | 그대로 | 사람이 `s9 user config trash_keep_days 30` 으로 직접 치는 글자 — `ui_skin` 과 같은 자리다. |

### 물음 3 — Settings 에 세운다면 그 칸의 이름
**「휴지통 넘김 기준」 · 단위 칸 「일」 · 설명 한 줄 「이 날수를 넘긴 것에 「넘김」이 붙습니다 — 저절로 지워지지는 않습니다.」**
값(`trash_keep_days`)은 그대로 두고 이름과 설명만 우리 말이다(skin/tone 표와 같은 규율).
금지 둘: ①「보관 기간」— 보관·보관 해제·보관함은 archive 의 확정어라 휴지통 쪽에 쓰면 두 사전이 겹친다. ②「자동 삭제 기간」·「수명」— 저절로 지우지 않으므로 거짓이다. 행 표시가 「30일 넘김」이니 설정도 「넘김」으로 한 이름을 쓴다.
