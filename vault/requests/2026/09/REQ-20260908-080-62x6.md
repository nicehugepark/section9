### ① 상위 이름 — 후보 넷을 견줌

- **외부 시스템 연동** — 반려. 목록에 이미 「시스템」 항목이 있어 두 줄이 붙어 읽힌다(「시스템」과 「외부 시스템…」). 8자에 동사까지 붙어 목록에서 혼자 길다.
- **바깥 도구 연결** — 반려. 「바깥」은 그 자리에서 지은 말이고(조어 금지), 「도구」는 Notion·Slack 을 담기에 좁다. 「연결」은 ④ 로 막힌다.
- **연동** — 반려. 2자로 결은 맞으나 무엇과의 연동인지가 없어, 바로 위 「저장소」(GitHub 과 주고받기)와 뜻이 겹쳐 보인다.
- **다른 서비스와 연결** — 반려. 목록 라벨이 아니라 문장이다. 조사가 붙은 라벨은 목록의 다른 이름과 결이 다르다.
- **외부 서비스** — 채택. 5자 명사구로 「사용자 관리」·「저장소」와 같은 결이고, 「시스템」 항목과 글자가 겹치지 않는다. Jira·Notion·Slack 모두 「서비스」로 담기며(Notion 도 Connections, Atlassian 도 Apps 로 서비스 단위를 쓴다), 「저장소」는 이 제품이 코드를 두는 곳이라 뜻이 갈린다. 「외부 서비스 연동」은 국내 SaaS 의 확립된 연어라 조어가 아니고, 목록에서는 뒤 두 글자를 덜어 명사구로 세운다.

### ② 부제 한 줄

들어 있는 서비스 이름을 원어로 가운뎃점으로 잇는다 — 서비스가 하나면 `Jira`, 둘이면 `Jira · Notion`. 준비 정도는 서비스가 하나일 때만 `Jira · 준비 3/4` 로 뒤에 붙인다(둘 이상이면 이름만 세우고 준비 정도는 각 절이 말한다). **「선택 사항」은 넣지 않는다** — 고르는 데 아무 정보도 보태지 않고, 다른 항목 부제와 층이 다르다.

### ③ 절 제목

`Jira` — 원어 한 낱말. 화면 계층이 「외부 서비스 → Jira」이므로 절 제목이 곧 서비스 이름이다.

### ④ 연동 vs 연결 — 같은 것에 이름 하나

화면에서 **「연결」은 이미 두 자리에 쓰이고 있다**: 네트워크 연결(「서버에 연결할 수 없습니다」 — settings.js:22, dialog.js:100 외 다수)과 계정 이어붙이기(「다른 이름의 기존 계정에 연결하려면 s9 user attach」 — settings.js:119). 여기에 세 번째 뜻을 얹으면 한 낱말이 세 가지를 가리킨다.

가르는 선 한 줄: **연결 = 이 제품 안의 둘을 잇는 것**(브라우저↔서버, OS 계정↔s9 계정) · **연동 = 바깥 서비스와 주고받는 것**(Jira·Notion). 따라서 이 화면의 동사는 전부 「연동」이다 — 버튼은 「연동하기」, 푸는 것은 「연동 해제」(「연결 끊기」 반려). 반대로 서버·계정 자리에 「연동」을 쓰지 않는다.

### translator 인계 — 옮길 것 / 그대로 둘 것

- 그대로: Jira · Notion · Slack · issue · project key · webhook · API token · URL
- 옮길 것: integration → 연동 · connect(외부 서비스) → 연동하기 · disconnect → 연동 해제 · optional → (부제에서는 쓰지 않음)

### 적용 지점

- web/app/settings.js SECTIONS: `["jira", "Jira 연동", jiraNavSub()]` → 상위 항목 `["integrations", "외부 서비스", …]` 아래로 Jira 를 넣는다(키 이름은 화면에 안 나오므로 개발자 판단)
- 같은 파일 jiraNavSub(): 부제를 ② 규칙으로
- 그 화면 안의 절 제목·버튼 문구: ③④ 규칙으로
