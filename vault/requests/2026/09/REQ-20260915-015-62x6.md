## Original

현재 대시보드가 실행 중인 저장소의 경로를 정확하게 표시할 필요가 있을 것 같다. 한 머신에서도 여러개의 section9이 실행될 수 있다는 사실을 알게됐네. 용도에 따라서 여러개의 section9을 실행한다면 각 대시보드가 어떤 저장소를 기준으로 실행됐는지 알 수 있어야 하고, 저장소 주소를 클릭하면 탐색기나 터미널이 해당 위치로 실행이 되던가 해야하고, stop 하는 방법도 표시 되는게 좋을 것 같다.

■ 왜 이 꼴인가
1. 긴 Windows 경로는 `overflow-wrap:anywhere` 로 끊는다 — `break-word` 는 최소 폭을 줄이지 못해 표가 통째로 넓어진다. 경로는 기계 문자열이라 낱말 지키기(keep-all)의 예외이고, 사람이 읽는 한 줄 설명(.svnote)에는 keep-all 을 준다(전 스킨 검수 규칙 3).
2. 읽는 것(경로)과 누르는 것(손잡이)은 한 줄에 섞지 않고 제 줄을 갖는다(규칙 2). 좁은 폭은 tablet.css 가 이미 `.metatbl tr{display:block}` 으로 라벨을 값 위에 쌓고, 손잡이 띠는 `.acts.dacts` 의 flex-wrap 으로 접힌다.
3. 색면·세로 띠 없음. 구분은 `.metatbl` 의 hairline 뿐이고, 위계는 글꼴(mono 경로 / 본문체 설명)과 잉크 급(--text / --muted)이 만든다. 세로 여백은 4·8 만 써 비정수 배율에서 위아래가 갈리지 않는다.
4. 표 절 7(셀에 버튼 더미 금지)에 걸리지 않는다 — `.metatbl` 은 비교하는 표가 아니라 라벨-값 목록이고, 손잡이는 행마다 되풀이되지 않는 이 두 행의 것이다. 과녁은 control.css 의 `.acts button.deed:not(.ico)` 가 `--ctl-md` 로 이미 잡는다.

쉼 · 경로 못 받음(손잡이 aria-disabled) · 누르는 중(400ms 넘으면 「여는 중…」) · 못 엶(`.svtell` 한 줄 + 붙여넣을 명령 복사 버튼) · 복사됨/복사 실패(2초) · 긴 경로(anywhere 줄바꿈) · 좁은 폭(라벨 위로 쌓임).

■ 안 고른 길
