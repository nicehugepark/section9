### TDD 시나리오 — 서버의 쓰기 경계

정상
- [ ] N1 대시보드 꼴 POST(Origin=http://127.0.0.1:<port>, Sec-Fetch-Site: same-origin)가 경계를 지난다
- [ ] N2 헤더가 둘 다 없는 POST(같은 컴퓨터의 CLI·시험)가 지난다 — 기존 시험을 깨지 않는다
- [ ] N3 루프백 바인드 서버의 GET 은 그대로다

경계
- [ ] B1 Host 가 localhost:<port> 이고 Origin 이 http://localhost:<port> 면 지난다
- [ ] B2 Sec-Fetch-Site: none + 우리 Origin -> 지난다 (주소를 직접 친 자리)
- [ ] B3 --host 0.0.0.0 + --open-write -> POST 가 경계를 지난다
- [ ] B4 guard_argv/_guard_spawn_child 가 --open-write 를 물려준다 (되살린 서버의 경계가 같다)

실패
- [ ] F1 Origin: http://evil.example.com -> 403 (남의 페이지)
- [ ] F2 Origin: http://127.0.0.1:<다른 포트> -> 403 (같은 루프백의 남의 서버)
- [ ] F3 Sec-Fetch-Site: cross-site (Origin 없음) -> 403
- [ ] F4 Origin: null -> 403
- [ ] F5 --host 0.0.0.0 (기본) -> POST 403, GET 200
- [ ] F6 /api/chat 로 온 남의 페이지 요청이 수신함에 한 줄도 넣지 못한다

회귀
