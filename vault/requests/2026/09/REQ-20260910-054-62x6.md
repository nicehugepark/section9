### 뿌리와 고친 자리

재현(이 컴퓨터, probe worktree): `git worktree add` 로 만든 사본에는 index/ 가
아예 없고, 거기서 `python3 tests/ short_ref` 를 돌리면 len(refs)==0 →
ZeroDivisionError 를 포함해 4건이 실패한다. 본 저장소에서는 같은 파일이 통과한다.

뿌리는 요청 문서가 짚은 그대로이되 한 겹 더 있었다 — **git 훅이 이미 색인을
다시 만드는데, 만드는 자리가 본 저장소다.** `.git/hooks/post-checkout` 은
`S9_ROOT="$MAIN"` 을 못박고 `s9 index rebuild` 를 부른다. 본 저장소에서 checkout
할 때는 MAIN==TOP 이라 맞지만, worktree 를 만들 때는 TOP(새 사본)이 아니라
MAIN 의 색인을 다시 만든다. 새 사본은 계속 빈 채로 남는다.

고친 자리는 `tests/__main__.py` 의 `ensure_catalog()` 하나다(러너 시작 지점,
샤드는 물려받으니 바깥 실행 한 번). 카탈로그가 **없고** vault/ 에 문서가 있을
때만 `s9 index rebuild` 를 한 번 부른다. 요청 문서의 길 1(만든다)을 택했고,
길 2(빈 카탈로그면 skip)를 버린 이유도 그대로다 — 있는 카탈로그에는 손대지
않으므로 진짜로 깨진 색인은 여전히 실패로 드러난다.

훅(post-checkout)을 고치지 않은 까닭: 훅은 만들 때 한 번뿐이라 이미 있는
worktree 와 훅이 설치되기 전의 clone 을 못 덮는다. 러너 쪽 한 곳이면 세 경우가
같은 길로 해결되고, 판정 자리도 하나로 남는다.
