## Original

주인 질문 2026-09-08 13:01: 「사용자는 실제로 설치할 때 s9-install, s9 code 이거 두개만 실행하지 않나? 이 상황에서 사용자가 추가되는 경우 기본 프로젝트에 붙는것맞지?」

리드 실측(임시 자리에서 그 흐름 그대로): **안 붙는다.**
- `s9-install` 은 `s9 init` 을 부르지만 사용자를 등록하지 않는다.
- 등록된 사용자가 없으므로 `ensure_default_project` 가 아무 일도 하지 않는다(REQ-20260908-027 에서 그렇게 고쳤다 — init 이 신원을 지어내면 안 되므로).
- 그 상태로 요청을 접수하면 `user: someone` 만 있고 **`project:` 자체가 없다**. `s9 project ls` 는 「프로젝트 없음」.

즉 REQ-20260908-022 가 세운 기본 프로젝트는 **사람이 `s9 user add` 를 치는 판에서만** 선다. 주인이 말한 실제 설치 흐름(install → code)에서는 서지 않는다.

풀 자리를 정해야 한다. 후보 셋:
① `s9 code` — 주인이 실제로 치는 문이다. 사용자·기본 프로젝트를 여기서 보장한다.
② SessionStart 훅 — 세션마다 도는 자리.
③ `s9 user add` 가 첫 사용자일 때 프로젝트를 만든다.

**제약(REQ-20260908-027 에서 값을 치른 것)**: 시험이 쓰는 경로에서 사람이나 프로젝트를 만들면 픽스처가 오염된다. 어느 후보든 **그 경로를 어떤 시험이 쓰는지 먼저 세고** 골라야 한다.
