### 2026-09-08T22:04:00+09:00 subagent (agent: sub:ux-writer, by nicehugepark)

ux-writer 문구 시안 (designer 판정 위에 얹음). 원칙: Jira·issue·key·push/pull/both 는 원어, 나머지는 우리 말. 상태를 비유로 말하지 않음. 에러는 무엇이 안 됐나+왜+다음.

[1] 문서 metatbl 행 라벨 (한 낱말)
  Jira
  - 근거: 라벨은 값이 무엇인지를 한 낱말로 가리키면 된다. 「이슈」는 어느 도구의 이슈인지 안 보이고, 「연동」은 값(키·상태·시각)과 안 맞는다. 같은 표의 다른 행 라벨과 길이도 맞는다.

[2] 그 행 값의 문장 꼴
  a. 정상       : MP1-7 · To Do · 3분 전 동기화
                  (키 · Jira 상태 원문 · 마지막 동기화. 시각은 사람 단위 상대시간, 1분 미만이면 「방금 동기화」)
  b. pending=create: 이슈를 만드는 중 — 30초 안에 키가 붙습니다
  b'. pending=push : 바뀐 내용을 Jira 로 보내는 중 — 30초 안에
  c. last_error(create): 이슈를 만들지 못했습니다 — <서버 문장>
  c'. last_error(push) : Jira 로 보내지 못했습니다 — <서버 문장>
     (서버 문장은 원문 그대로 뒤에 붙인다. 자동 재시도가 있으면 뒤에 「 · 30초 뒤 다시 시도합니다」를 덧붙이고, 없으면 붙이지 않는다 — 없는 재시도를 약속하지 않는다.)

[3] 어긋남(≠) 툴팁 한 문장
  여기는 review, Jira 는 In Progress 입니다 — 다음 동기화 때 방향 설정대로 맞춥니다.
  - 우리 상태 값(review)과 Jira 상태 원문(In Progress)을 옮기지 않고 그대로 넣는다. 어느 쪽이 틀렸다고 말하지 않는다.

[4] 카드 링크 title 속성 한 문장
  Jira 에서 MP1-7 열기 (새 창)
  - 어긋남이면: Jira 에서 MP1-7 열기 (새 창) — 상태가 서로 다릅니다

[5] Projects 정보 패널 세 항목 라벨
  - Jira 주소   (placeholder: https://<회사>.atlassian.net)
  - project key (placeholder: MP1)   ← Jira 화면에서 같은 이름으로 다시 만나는 고유 이름이라 원어
  - 동기화 방향
  빈 상태 한 줄:
  연결된 Jira 가 없습니다 — 주소와 project key 를 넣으면 이 프로젝트의 요청이 이슈로 올라갑니다.

[6] 방향 select 옵션 글자 (값은 push/pull/both 그대로 앞에)
  push · 여기 → Jira
  pull · Jira → 여기
  both · 양쪽

[용어 사전 갱신분]
  Jira / issue / project key / push / pull / both : 원어 고정. 「지라」·「이슈키」·「밀기/당기기」 금지.
  Jira 상태(To Do·In Progress…) : 원문 그대로 표시, 우리 상태 값으로 옮기지 않는다.
  동기화 : 이 제품의 말. 「싱크」 금지.
  「동기화 방향」 : 이 개념의 표시어 하나로 고정(「연동 방향」·「전송 방향」 금지).

[한계]
  자동 재시도 유무와 동기화 주기(30초)는 구현에 맞춰 숫자를 바꿔야 한다 — 문구가 약속하는 시간과 실제가 다르면 [2]b·[2]c 를 먼저 고친다.

### 2026-09-08T22:04:06+09:00 subagent (agent: sub:translator, by nicehugepark)

Jira 표시 문구 6건 번역 (원문 → 옮김 → 검산). 존댓말 한 층, 비유·의인화 없음, Jira·issue·key·push·pull·site·상태값(review·In Progress)은 원어 유지.

① 카드 링크 title
  원문: 이 요청은 Jira 이슈 MP1-7 과 짝지어져 있다 — 새 창에서 연다
  옮김: Jira 이슈 MP1-7 과 연결되어 있습니다. 새 창에서 열립니다.
  검산: 어느 이슈인지 + 누르면 무슨 일이 나는지 둘 다 남음. 「짝지어져」는 화면 어휘로는 낯설어 「연결」로 — 이 화면의 기존 낱말과 같은 계열.

② 상태 어긋남 툴팁
  원문: 우리 상태는 review 인데 Jira 는 In Progress 다 — 다음 동기화 때 맞춘다
  옮김: 여기서는 review 인데 Jira 에서는 In Progress 입니다. 다음 동기화 때 맞춥니다.
  검산: 어긋난 두 값 + 저절로 풀린다는 사실 유지. 「우리」는 화면에서 주어가 모호해 「여기서는」으로.

③ 이슈 생성 중
  원문: 이슈를 만드는 중 — 워처가 30초 안에 만든다, 실패하면 여기 까닭이 선다
  옮김: Jira 이슈를 만드는 중입니다. 30초 안에 만들어지고, 안 되면 여기에 까닭이 뜹니다.
  검산: 기다릴 시간 + 실패 시 볼 자리 유지. 「워처」는 내부 부품 이름이라 뺌(R5) — 사람이 할 일이 없다는 뜻은 「만들어지고」의 피동으로 남음.

④ pending push
  원문: Jira 로 상태를 보내는 중
  옮김: Jira 로 상태를 보내는 중입니다.
  검산: 그대로. push 는 방향 이름(⑥)으로만 화면에 서고, 이 자리에서는 「보내는 중」이 무슨 일인지를 말함.

⑤ Projects 패널 빈 상태 (두 줄 — 무엇이 없나 / 무엇을 하면 되나)
  원문: 이 프로젝트는 아직 Jira 와 연동하지 않았다 — 연동하려면 site 와 project key 를 적는다
  옮김: 아직 Jira 와 연결한 프로젝트가 없습니다. / site 주소와 project key 를 적으면 연결됩니다.
  검산: 없다는 사실 + 다음 행동 유지. 「연동」은 업계어라 「연결」로 통일(①·②와 한 낱말).

⑥ 방향 셋
  push: 이곳의 상태를 Jira 로 보냅니다.
  pull: Jira 의 상태를 이곳으로 가져옵니다.
  both: 양쪽으로 주고받습니다. 문서가 기준이라, 검사를 지난 변경만 들어옵니다.
  검산: 화살표 방향 셋이 갈림. 「문서가 진실이다(source of truth)」는 직역이라 「문서가 기준이라」로 — 밖에서 들어오는 것이 걸러진다는 뜻이 그대로 섬.

어휘 근거: Jira·issue·key·site·push·pull 은 사용자가 Jira 화면에서 같은 글자로 다시 만나는 이름이라 원어(규약 2조). review·In Progress 는 양쪽 시스템의 상태값이라 그대로. 「동기화」·「연결」·「프로젝트」는 우리 말 자리. 새 낱말은 하나도 짓지 않았고, 「연결」 하나로 ①②⑤를 묶어 같은 개념에 이름이 둘이 되지 않게 했습니다.
