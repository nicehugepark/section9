## Original

REQ-20260907-057 재작업 중 격리했다 — 준비 신호 변경과 무관하다(변경 전 파일로도 같은 실패, 2회 실측).

증상: `python3 tests/ project_tab` 에서 2건 실패.
  - `하나뿐인 프로젝트를 열지 않고 고르라고 한다`
    empty = "문서를 찾을 수 없습니다: PRJ-20260823-001 — 삭제되었거나 목록이 오래되었습니다."
  - `우측에 프로젝트 문서 판이 안 섰다`

읽은 데까지의 사실:
  - 프로젝트 줄 자체는 선다(/api/projects 는 vault/projects/*.md 를 읽는다).
  - 그 행을 열면 loadDoc → GET /api/doc?id=PRJ-20260823-001 이 404 다(docs.js:405).
  - 서버의 `locate()` 는 ① catalog 의 path ② 파일 이름이 `<id>.md` 인지로 찾는다.
    프로젝트 문서의 파일 이름은 slug(`section9.md`)라 ②는 못 찾는다 — 즉 이 문서를
    여는 길은 **catalog 에 PRJ 행이 있을 때뿐**이다. catalog 에 없거나 path 가 낡으면 404.
  - 이 실행 자리(worktree)에는 index/catalog.jsonl 이 없어 서버가 새로 짓는다 —
    그 재생성이 project 문서를 담는지 확인이 필요하다.

다음 사람이 할 일: ① 서버를 띄워 /api/catalog 에 PRJ 행이 있는지 본다.
② 없으면 catalog 재생성이 vault/projects 를 담게 고친다(근원). 있으면 doc_visible 쪽을 본다.
③ 파일 이름이 slug 인 문서를 id 로 못 찾는 것 자체가 fallback 의 구멍이니 함께 판단한다.
