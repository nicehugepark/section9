## Original

REQ-20260915-021 을 고치다 남은 갈래. `s9 commit` 은 ROOT(본 저장소) 기준으로 담을 것을 세므로 요청 전용 worktree 안에서 부르면 담을 것이 없다고 답한다. 그래서 worktree 작업자는 plain git commit 을 쓸 수밖에 없고, 공유 index 를 피해 담는 길(임시 index·sync 잠금)을 쓰지 못한다.

## Notes

### 2026-09-15T14:59:16+09:00 tdd (by nicehugepark)

`s9 commit` 이 지금 서 있는 working tree 에서 담는다 — ROOT(데이터의 자리)와
working tree(코드의 자리)를 가른다.

- [ ] 정상: worktree 안에서 `s9 commit -m … -- <경로>` 가 그 worktree 의 HEAD 대비
      변경을 담아 그 worktree 의 branch 에 commit 한다 (본 저장소의 HEAD 는 안 움직인다).
- [ ] 정상: 본 저장소 안에서 부르면 종전 그대로 본 저장소에 commit 한다 (회귀).
- [ ] 정상: worktree 에서 담은 뒤 그 worktree 의 index 가 새 HEAD 에 맞춰진다
      (`git diff --cached` 에 역방향이 남지 않는다).
- [ ] 경계: 상대 경로·절대 경로 둘 다 그 worktree 기준으로 풀린다.
- [ ] 경계: S9_ROOT(데이터의 자리)는 그대로 본 저장소를 가리킨다 — 훅에 넘기는
      S9_ROOT 도 ROOT 이지 worktree 가 아니다.
- [ ] 경계: 잠금·표식(state/.sync.lock · s9-commit-in-progress)은 ROOT 에 그대로 둔다
      — 저장소가 하나이므로 창도 하나다.
- [ ] 실패: 같은 저장소가 아닌 자리(다른 저장소·저장소 밖)에서 부르면 옮기지 않고
      ROOT 에서 담는다 — 남의 저장소를 건드리지 않는다.
- [ ] 회귀: tests/test_s9_commit.py 의 계약 여덟(C1~C8)이 그대로 통과한다.
