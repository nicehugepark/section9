### 고친 자리 (commit a10c11cb4)

`tests/__main__.py` 에 `_machine_root(repo)` 를 세우고 `RUN_LOCKS` 를 그 자리로 옮겼다.
바꾼 것은 **한 줄의 뜻**이다: 실행 잠금은 checkout 이 아니라 컴퓨터의 것이다.

읽고 나서 좁혔다는 것이 이 요청의 요지다. 처음에는 「러너가 겹침을 안 막는다」고
보았는데, 막는 장치(`hold_run_lock`, 같은 선택이면 최대 30분 대기)는 이미 있었다.
없던 것은 **두 회차가 같은 파일을 잠그는 것**뿐이었다 — worktree 의 REPO 는 그
worktree 라 잠금 경로가 갈렸다. 그래서 고침은 새 장치가 아니라 경로 한 줄이다.

경계를 좁게 잡았다: `s9 worktree` 가 두는 모양(`<본>/state/worktrees/<이름>`)일 때만
본 저장소로 올라가고, 다른 자리에 둔 worktree 는 종전대로 제 잠금을 쓴다. git 에
묻지 않는다 — import 때 도는 자리라, 쓰지도 않을 git 호출이 시험을 깼던
REQ-20260916-002-2n7g 를 되풀이하지 않는다.

통과 기록(REUSE_DIR)은 tree 마다 그대로 두었다. 잠금은 「지금 이 컴퓨터가 바쁜가」를
묻고 기록은 「이 내용이 통과했나」를 묻는다 — 뒤엣것은 tree 마다 다르다.

**안 한 것**: 30분을 기다리고도 앞 회차가 안 끝나면 지금도 그냥 실행한다. 4분짜리
회차 둘이 30분을 넘길 일은 없어 이번 사고와는 무관하고, 한 번에 한 가지만 바꾼다.
