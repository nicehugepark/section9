## Original

REQ-20260916-011-2n7g 의 검증을 리드가 맥 Safari 로 대신 하면서 두 항목만 못 쟀다.

증상: safaridriver 로 `#fold-f` 를 눌러 거르개를 편 뒤 `[name=f-user]` 에 값을 넣으려 하면, 다음 호출에서 그 element 가 이미 없다(「f-user 없음」). 같은 자리에서 세 번 났다. 머리글이 폴링으로 주기적으로 다시 그려지기 때문으로 보인다 — 펴는 동작 자체가 비동기라 한 스크립트 안에서 펴고 값을 넣을 수도 없다(펼친 직후에도 select 가 아직 없다).

못 잰 두 항목:
① 거르개를 걸고 접으면 손잡이 줄이 그 조건을 그대로 읽는가 (단위 시험 folded_handle_tells_what_is_on 은 통과한다 — 못 잰 것은 실화면이다)
② 그래프의 되돌리기로 조건을 풀면 손잡이 줄에서도 그 조건이 사라지는가

재는 법의 후보 셋:
ⓐ 값을 넣는 대신 **실제 포인터로 select 를 열어 항목을 고른다**(맥 Safari 는 Allow JavaScript from Apple Events 가 켜져 있으면 select 를 펼쳐 읽을 수 있다 — browser-verify 스킬).
ⓑ 다시 그리기를 잠깐 세우는 길이 있으면 그것을 쓴다(폴링 간격·정지 손잡이).
ⓒ 조건을 주소(해시·쿼리)로 실을 수 있으면 그 길로 넣고 화면만 읽는다.

ⓒ 가 있으면 가장 싸다 — 먼저 그것부터 본다.

### 못 잰 것이 아니라 내가 잘못 물었다 (실제 맥 Safari 26.4, 400x900)

후보 셋(ⓐ 포인터로 select 열기 · ⓑ 다시 그리기 세우기 · ⓒ 주소로 싣기)을 보기 전에
원인부터 다시 봤다. **다시 그려져서가 아니었다** — 내가 `[name=f-user]` 로 찾았는데
그 select 의 식별자는 `id` 다(`web/index.html:174` 의 `<select id="f-user">`). 그래서
세 번 다 「없다」가 나왔고, 나는 그것을 머리글이 다시 그려진 탓으로 읽었다. 내 오독이다.

`#f-user` 로 물으니 한 번에 잡혔고 두 항목 다 그 자리에서 쟀다.

**① 접힌 손잡이 줄이 켜진 조건을 읽는다 — 통과.**
`#f-user` 를 `nicehugepark` 으로 두고 거르개를 접으니 손잡이 줄이
「거르개 사용자 nicehugepark」 이었다(접힘 상태 aria-expanded=false).

**② 그래프의 되돌리기로 풀면 손잡이 줄에서도 사라진다 — 통과.**
검색어를 없는 말로 두어 관계도를 비우니 「검색·필터 지우기」 손잡이가 떴다. 그것을
실제 포인터로 누르자 `#q` 와 `#f-user` 가 함께 비고, 손잡이 줄이 「거르개」로 돌아왔다.
누르기 전 「거르개 사용자 nicehugepark」 → 누른 뒤 「거르개」.

재는 법은 ⓐⓑⓒ 어느 것도 필요 없었다 — 셀렉터 하나였다. 그 사실을 남긴다: 다음에
같은 증상(「있는데 없다고 나온다」)을 만나면 **다시 그리기를 의심하기 전에 무엇으로
찾고 있는지부터 본다.**
