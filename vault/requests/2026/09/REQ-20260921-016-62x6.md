## Original

security-engineer 가 REQ-20260921-004-62x6 의 위험 판정에서 찾았습니다(2026-09-21): .git/config 는 그 저장소에 하나뿐이고 git 은 저장소 로컬을 전역보다 앞세웁니다. 공용 경로(/srv/section9 같은 자리)에 A 의 신원이 먼저 박히면, 제 ~/.gitconfig 를 올바로 설정해 둔 B 의 commit 까지 A 의 이름·이메일로 나갑니다. 그 이메일이 GitHub 에 등록된 실주소면 GitHub 이 A 의 계정으로 귀속합니다 — 임시값보다 이쪽이 더 나쁩니다. git worktree 도 extensions.worktreeConfig 를 켜지 않는 한 .git/config 를 본체와 공유하므로, 요청별 worktree 에서 도는 백그라운드 작업자가 본체의 신원을 물려받습니다.

권고(architect·security-engineer): 설정 파일에 쓰지 말고 commit 마다 -c user.name=… -c user.email= 로 넘기는 쪽을 검토할 것. bin/s9.py 에 이미 그 모양의 자리가 있습니다.
