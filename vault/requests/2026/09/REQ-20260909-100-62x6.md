### 2026-09-09T18:21:07+09:00 response (agent: lead:claude-opus-5, by nicehugepark)

주인의 세 번째 증상(18:20) — 「심지어 헤더 앵커도 풀리기도 한다」. 스크롤한 화면에 열 머리가 하나도 없다.

리드가 소스에서 본 것: web/app/card.js 의 fitBoard() 가 `--board-top` 을 `getBoundingClientRect().top + window.scrollY`(문서 기준 오프셋)로 잡는데, board.css 는 그것을 `max-height:calc(100vh - --board-top - --board-foot)`(창 기준)로 쓴다. 두 기준이 다르므로 문서 스크롤이 0 일 때만 맞는 식이다. 문서가 스크롤되면 판이 창 안에서 일찍 끝나고, 판째 위로 밀려나면 그 안의 sticky 머리도 함께 화면 밖으로 나간다 — sticky 의 기준은 판의 스크롤 상자인데 그 상자가 떠나기 때문이다.

이 요청은 이제 셋이다: ① 손 얹은 카드 윗변이 붙은 머리에 덮인다 ② 헤더 아래 테두리 색 ③ 문서가 스크롤되면 열 머리가 통째로 풀린다. ③ 이 가장 크다 — 093 이 세운 계약이 그 자리에서 무너진다. designer 에 중계했고 ③ 을 먼저 하게 했다.

### 2026-09-09T18:26:37+09:00 tdd (agent: sub:designer, by nicehugepark)

실측으로 확정한 것 (chromium, 1600x900, DPR2, 스킨 10종). 주인의 스킨은 soft 가 아니라 **calm** 이다(user config ui_skin=calm).

붙은 머리 아랫변과 첫 카드 윗변의 거리(쉼 → 손 얹음):
  calm 0 → **-2** (카드가 머리 상자 **안으로** 2px 들어간다) · cork 2 → **0** · soft 2 → 1
  glass 8 → 8 · ledger/terminal/grid/slate/cobalt/field 0 → 0 (뜨지 않고 테두리·그림자도 없다)
calm 은 손을 얹으면 translateY(-2px) 로 뜨고 윗변에 1px 호박색 테두리가 생기는데, 그 2px 가
머리(z-index:2, 배경 --bg 불투명) 아래로 들어가 **윗변이 통째로 사라진다** — 둥근 모서리가
위로 말려 올라가다 평평하게 잘린다(캡처로 확인). 주인이 본 그림 그대로다.

### 갈래

### 정상
- [ ] N1 어느 스킨에서도 첫 카드에 손을 얹었을 때 카드 윗변(테두리·그림자)이 붙은 머리 상자와 겹치지 않는다 — 머리 아랫변과 hover 카드 윗변의 거리 ≥ 0
- [ ] N2 판을 세로로 스크롤해 머리 밑을 지나가는 카드는 **여전히 머리 뒤로 가려진다** (z-index 역전 없음: 머리 z-index > 카드)
- [ ] N3 붙은 머리의 아래 선은 그 스킨의 선 토큰(--hairline/--border)에서 온다 — 값을 손으로 적은 색이 없다

### 경계
- [ ] B1 뜨지 않는 스킨(ledger·terminal·grid·slate·cobalt·field)은 머리와 첫 카드 사이 여유가 0 그대로다 — 장부 스킨에 없던 틈을 만들지 않는다
- [ ] B2 여유는 4의 배수 px 이다 (배율 불변 — 홀수 px 은 125/150% 에서 위아래가 다르게 반올림된다)
- [ ] B3 촘촘(compact) 밀도에서도 N1 이 성립한다

### 실패
- [ ] F1 문서가 스크롤되어도 열 머리가 남는다 — 판의 높이가 **잰 값이 아니라 배치**에서 와서, 판 탭에서 문서가 넘칠 일이 없다 (`--board-top` 이 문서 오프셋인데 CSS 는 창 기준으로 써 어긋나던 자리)
- [ ] F2 판 탭을 떠나면 그 배치 고정이 풀린다 (다른 탭의 세로 스크롤을 막지 않는다)
- [ ] F3 창을 낮춰 판이 최소 높이에 걸리면 문서 스크롤을 허용한다 — 판이 0 으로 눌리지 않는다
