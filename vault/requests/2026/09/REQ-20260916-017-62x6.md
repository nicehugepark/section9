### 설계 문서 — DOC-20260916-003-62x6 「s9.py 를 가르는 bind 설계」

#### ① 고른 방법 — `bind(globals())` 로 이름공간을 주입하고 s9.py 로 재수출

**한 줄 이유: 이 저장소가 이미 그렇게 하고 있다.** `bin/s9_commit.py`(651줄)가
`_S9 = {}` 에 `bind(g)` 로 s9.py 의 globals 를 받아 `_S9["ROOT"]` ·
`_S9["_sync_lock_take"](30)` 으로 쓴다 — 그 파일 머리말이 이유까지 적어 두었다
(「정의를 두 벌로 두지 않는다」).

**제가 더 잰 것 둘이 이 선택을 고정했습니다** (리드 실측 위에 얹습니다):
- `bin/s9.py` 를 `SourceFileLoader`/`spec_from_file_location` 으로 올리는 **시험 파일 350개**.
  그 시험들은 올린 모듈의 globals 를 직접 부릅니다 — `s9.now_iso()` · `s9.chat_send(...)` ·
  `self.m.STALLED_WIN`. → **s9.py 의 globals 가 이 저장소의 공개 API 입니다.**
- `ROOT` 는 s9.py:44 에서 **import 때 한 번만** 정해집니다(재대입·`global ROOT` 없음).
  시험은 `S9_ROOT` 를 바꿔 **모듈을 다시 올리는 것**으로 격리합니다. → 자식 모듈을
  `sys.modules` 에 캐시하면 옛 ROOT 가 남아 격리가 조용히 무너집니다.

**기각한 대안** — 인자 주입(A): 호출부 전부 수정, 시험 350개가 인자 없이 부르므로
그 자리에서 깨집니다. 전역을 쥔 객체(B): (A)의 비용에 더해 없던 개념을 하나 더
들여옵니다. `sys.path` + 평범한 import(C): 같은 파일이 두 이름으로 앉아 **ROOT 가 두 벌**이
됩니다 — 기존 세 모듈이 하나도 이 길을 안 쓰는 것이 이미 답입니다.

**계약 셋**: C1 자식은 s9.py 를 import 하지 않는다(dict 하나만 받는다 → import 단방향,
순환 불가) · C2 s9.py 가 `EXPORTS` 를 제 globals 로 되받는다(호출부·시험 한 줄도 안 고침) ·
C3 싣는 자리 한 곳, 캐시는 s9.py 의 globals 에(다시 올리면 새것).
