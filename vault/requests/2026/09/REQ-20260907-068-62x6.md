주인 물음 2026-09-07 19:48: 「클로드 계정 정보가 어디로 사라졌지?」 (캡처 첨부)

## 실측
- 사용자 캡처: 헤더에 `nicehugepark @ DESKTOP-TEHV1KR WSL [admin]` 만 있고 그 위의 `claude01.pfe@… · 5h … · wk … · fable …` 줄이 없다.
- 리드가 같은 시각 새로 찍은 화면(1200px·700px 둘): 그 줄이 **있다**. 좁은 폭에서도 두 줄로 접혀 둘 다 보인다 — 잘림이 아니다.
- 서버 `/api/claude/usage`: 세 번 200·70ms. 그런데 리드의 첫 probe 한 번은 **000**(연결 끊김) — WSL 중계의 간헐 리셋(DOC-20260903-001)이다.

## 원인 — `web/app/usage.js:145-149`
```js
const d = await loadSupply("usage", …, {prio: 1, tries: 1, quiet: true});
if (!d || (!d.ok && !d.stale)){
  el.textContent = ""; usageLast = null; …; return;
}
```
**한 번(`tries: 1`) 실패하면 칩을 비운다.** 마지막으로 받아 둔 값(`usageLast`)까지 버린다. 다음 폴(60초)에 성공하면 돌아오지만, 리셋이 이어지면 계속 빈 칸이다. 주석은 「빈 칩에 키보드가 멈추면 정거장이 된다」로 비우기를 정당화하는데, 그것은 tabindex 를 빼서 풀 일이지 **글자를 지울 이유가 아니다.**

이것은 REQ-20260828-039 가 `whoami` 에서 고친 것과 같은 모양이다 — 「빈 자리는 아무 문제 없음으로 읽힌다. 조용히 물러나지 않는다」. 그때 usage 는 남겨졌다.

## 고칠 방향
1. 실패해도 `usageLast` 가 있으면 **그 값을 ⏳ 표시로 남긴다**(서버가 stale 을 줄 때 이미 쓰는 표시 — 새 어휘 아님).
2. 받은 적이 없으면 「사용량을 받지 못했습니다」 한 줄 — whoami 의 「⚠ 내 계정을 받지 못했습니다」와 같은 결.
3. tabindex 처리는 그대로(빈 칸일 때만 뺀다는 뜻은 남는다 — 이제 빈 칸이 안 생긴다).
