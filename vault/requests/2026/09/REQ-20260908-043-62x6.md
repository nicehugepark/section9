### ① 인스턴스는 이력 없는 첫 commit 으로 선다 (`cmd_instance`, `bin/s9.py:20064` 언저리)

clone 직후, `.gitignore` 를 쓰기 전에 데이터 경로를 index 와 working tree 양쪽에서 뗀다. 지금의 `git checkout -q -B main` 을 orphan 으로 바꾸는 것이 핵심이다.

    git checkout -q --orphan main
    git rm -r -q --cached --ignore-unmatch vault users projects .s9-sync
    (shutil.rmtree 로 vault/ users/ projects/ 를 working tree 에서도 지운다)

그 뒤는 지금 순서 그대로 — `.gitignore` 쓰기 → `bin/s9 init`(빈 뼈대 생성) → `.s9-sync` → `git add -A` → commit. 결과는 **commit 1개, 문서 0건**이고 이력에도 남의 문서가 없다.

`projects/` 를 지우는 것에 주의가 필요하다: 그 안에 `section9/CONTEXT.md`·assets 가 있어 남겨 두면 이 저장소의 프로젝트가 새 인스턴스에 그대로 선다. 인스턴스의 프로젝트는 첫 사용자가 등록될 때 서는 것이 맞다.

### ② 업그레이드 경로를 merge 에서 코드 경로 checkout 으로 바꾼다

①로 이력이 갈라지므로 지금 init 이 찍는 안내문의 `git merge upstream/main` 은 더 이상 성립하지 않는다 — 이력이 이어지지 않을 뿐 아니라, merge 가 성공하면 지운 문서 1390건이 되살아난다. 대신 코드 경로만 받는다.

    git fetch upstream
    git checkout upstream/main -- bin web harness docs tests README.md CLAUDE.md pyproject.toml .github
    git commit -m "upstream 코드 갱신"

`s9 instance upgrade` 로 감싸고, init 이 마지막에 찍는 안내문도 이 줄로 바꾼다. docs/08 에도 같은 절을 적는다(docs/ 도 이 세션 범위 밖이다).

### ③ INSTANCE_TRACK_GITIGNORE 에 빠진 세 줄을 넣는다 (`bin/s9.py:20018`)

    streams/
    users/*/streams/
    users/*/config/local.json

ignore 목록의 원천이 업스트림 `.gitignore` 와 이 상수 둘로 갈려 있어 또 어긋날 자리다. 업스트림 `.gitignore` 에서 데이터 track 관련 줄만 바꿔 만들거나, 최소한 두 목록이 어긋나면 시험이 걸리게 한다(TDD 시나리오 ③).

### 적용 뒤에 할 일

1. 지금의 `~/section9-test` 와 GitHub 사설 저장소 `section9-test` 는 문서 1390건을 담고 있으니 지우고 다시 만든다 — 파일만 지워도 git 이력에 남는다. 저장소를 지우는 것은 주인의 결정이라 여기서 하지 않았다.
2. 다른 WSL 머신에서 clone → `bin/s9-install` → `bin/s9 code` 를 실제로 해 본다. 이 세션에는 그 머신이 없어 못 했다.
