정상
- N1 전체 id 지목 → 그 문서, 앞머리는 본문에서 떼어낸다
- N2 세 자리 번호만(`#057`) → 진행 중 요청에서 찾는다. **이게 '편하게' 의 실체다**
- N3 지목이 없으면 지금과 완전히 같다 (새 REQ 생성)
- N4 붙이면 문서에 남고 새 문서는 생기지 않는다
- N5 화면이 집어 준 것(doc 필드)이 앞머리 표기보다 우선 — 눌러 고른 것이 타이핑보다 확실하다

경계
- B1 없는 문서: 지목하지 않고 이유를 말한다. **본문을 잃지 않는다**
- B2 끝난 요청은 번호로 안 잡힌다 — 완료까지 뒤지면 번호가 겹친다
- B3 지목만 있고 할 말이 없으면 평소대로 둔다
- B4 끝난 문서에 붙이면 그 사실을 알린다 — 조용히 묻히면 안 된다

실패
- 모호한 지목(2건 이상)은 집지 않는다. **잘못 집어 남의 문서에 붙이는 것이
  못 찾는 것보다 나쁘다** — locate 가 모호한 id 를 거부하는 것과 같은 규율
- 못 읽었으면 세션 로그에 남긴다: 조용히 새 요청이 생기면 사용자는 알 길이 없다

### 2026-08-27T22:09:41+09:00 response (by nicehugepark)

**지금부터 이렇게 쓰면 된다.**

    >064 이것도 같이 해줘        전체 id 로 지목
    #057 이것도 같이 해줘        세 자리 번호만 — 진행 중 요청에서 찾는다

`>` · `→` · `#` 셋 다 받는다. 새 요청 문서를 만들지 않고 그 문서의 노트로 들어가고,
그 줄을 받은 세션은 그 id 로 상태를 관리한다.

**안 하는 것**
- 못 찾거나 두 건 이상과 맞으면 **지목하지 않는다.** 잘못 집어 남의 문서에
  붙이는 것이 못 찾는 것보다 나쁘다 — 모호한 id 를 거부하는 `locate` 와 같은
  규율이다. 이때 본문은 그대로 살아 새 요청이 된다(말을 잃지 않는다).
- 왜 안 붙었는지는 세션 로그에 남는다. 조용히 새 요청이 생기면 사용자는 알 길이
  없다.
- 번호 지목은 **끝난 요청을 뒤지지 않는다.** 완료 323건까지 뒤지면 번호가 겹친다.
- 끝난 문서에 붙으면 "이미 done 이다"를 돌려준다 — 조용히 묻히면 안 된다.

**남은 몫(디자이너)**: 카드를 눌러 대상을 집어 두는 화면. `/api/chat` 의 `doc`
필드가 이미 열려 있고, 그것이 앞머리 표기보다 **우선**한다 — 눌러 고른 것이
타이핑보다 확실하기 때문이다.

### 2026-08-28T00:15:22+09:00 designer (by nicehugepark)

**집는 손을 만들었습니다.** 새 어휘는 만들지 않고, 이미 있는 "지목" 어휘(에이전트에게 보낼 때 입력창 위에 서는 그 줄)를 그대로 씁니다.

**집기.** 카드에 얹으면 오른쪽 위에 `→ 이어 말하기` 손잡이가 나옵니다. 상시로 붙이지 않은 이유는 카드 90장에 버튼이 늘 붙으면 제목보다 버튼이 먼저 읽히기 때문입니다. 키보드로 카드에 닿아도 나옵니다. 읽고 있는 문서 뷰어에서도 같은 버튼으로 집습니다 — 읽는 자리가 곧 집는 자리입니다.

**보임.** 집으면 터미널로 넘어가고 입력창 바로 위에 이렇게 섭니다:

    → REQ-20260827-072-62x6 「구간에 메모 달기」 에 남깁니다        × 해제

제목을 낫표로 감싼 이유는, 제목 자체가 동사로 끝나는 문서가 있어서입니다("문서에 이어 말하기") — 따옴표가 없으면 뒤 조사와 엉켜 한 문장으로 읽힙니다. 목록으로 돌아가도 집힌 카드에 표시가 남습니다(잉크 테두리 + 손잡이 반전).

**풀기.** `× 해제` 하나입니다. 그 버튼은 지금 서 있는 것이 에이전트 지목이든 문서 지목이든 그것을 풉니다.

**없을 때.** 줄 자체가 없습니다. 전송 본문에도 `doc` 를 붙이지 않습니다 — 지금과 완전히 같습니다.

**에이전트 지목과는 양립하지 않게** 했습니다. 메시지는 에이전트에게 가거나 문서 노트로 들어가지 둘 다일 수 없습니다. 하나를 집으면 다른 쪽이 풀립니다.

**이미 끝난 요청**은 집는 순간에 말합니다 — `· 이미 done — 다시 열리지는 않는다`. 보내고 나서 알려 주면 되돌릴 수 없기 때문입니다. 보낸 뒤 확인 줄도 말을 가릅니다: 새 요청이면 "…로 기록됨", 집어 보낸 것이면 "…에 노트로 남았다". 같은 문장으로 뭉뚱그리면 새 요청이 하나 더 생긴 줄 압니다.

검증: 진단 파라미터 `?pick=<문서id>` 로 집힌 상태를 세워 보드(집힌 카드)와 터미널(입력창 위 줄)을 헤드리스에서 직접 봤습니다.
