사용자 판단: 이 WSL 에서 systemd 로 돌릴 것이 없으니 systemd 자체를 끈다(채팅 지시). 저장소 확인 결과 section9 는 systemd 에 의존하지 않는다(bin/core 전체에 systemctl 호출 없음). docker/containerd/snapd 만 systemd 아래 있었고 docker 는 /etc/init.d/docker 가 있어 'sudo service docker start' 로 뜬다.

조치: /etc/wsl.conf 의 [boot] systemd=true → false. 루트 권한이 필요해 리드가 직접 쓸 수 없어 사용자에게 한 줄로 넘긴다. 반영은 Windows 에서 'wsl --shutdown' 후 재접속.

**왜 그 메시지가 떴나**

부트 로그를 보면 이렇습니다.

```
00:46:15  systemd-tmpfiles-setup.service 시작
00:46:25  WSL: /sbin/init failed to start within 10000ms
00:46:35  WSL: Timed out waiting for user session for uid=1000
00:47:29  systemd-tmpfiles-setup.service 완료   ← 73초
00:47:29  systemd-logind 시작
```

`systemd-tmpfiles-setup` 이 73초(직전 부트는 46초) 동안 `sysinit.target` 을 붙잡고, 그 뒤에 오는 `systemd-logind` 가 그만큼 늦게 뜹니다. WSL 은 사용자 세션을 10초만 기다리다 포기하고 그 메시지를 냅니다. 그래서 `/run/user/1000` 도 없고 `systemctl --user` 도 "Failed to connect to bus" 가 납니다.

**끄기 전에 확인한 것**

- section9 은 systemd 를 쓰지 않습니다 (`bin/`, `core/` 전체에 `systemctl` 호출 0건).
- systemd 아래 있던 건 docker·containerd·snapd 뿐입니다. docker 는 `/etc/init.d/docker` 가 있어 `sudo service docker start` 로 뜹니다. snap 앱은 못 씁니다.

**적용 (루트가 필요해 직접 못 씁니다)**

`/etc/wsl.conf` 가 root 소유이고 sudo 가 비밀번호를 요구해서 제가 쓸 수 없습니다. 이 줄을 프롬프트에 붙여넣어 주세요.

```
! sudo sed -i 's/^systemd=true/systemd=false/' /etc/wsl.conf && cat /etc/wsl.conf
```

그다음 Windows PowerShell 에서 `wsl --shutdown` 하고 다시 여시면 반영됩니다 — 이때 지금 세션은 끊깁니다.

되돌리려면 같은 자리를 `systemd=true` 로 바꾸면 됩니다.

한 가지 덧붙입니다: systemd 를 끄면 메시지는 사라지지만 `systemd-tmpfiles` 가 왜 73초씩 걸렸는지는 미규명으로 남습니다. 다른 배포판이나 나중에 systemd 를 다시 켤 때 같은 자리에서 걸릴 수 있으니, 별건으로 남겨둘지는 말씀 주시면 문서로 올리겠습니다.
