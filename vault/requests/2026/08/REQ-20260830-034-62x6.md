### 2026-08-30T19:10:46+09:00 designer (by nicehugepark)

### 다섯 스킨의 밀도 — 죽어 있던 게 아니라 **남의 숫자로 덮여 있었다**

### ① 먼저 바로잡을 전제

REQ 는 "calm 과 같은 사고가 다섯에 남아 있다"고 봤는데, 재 보니 **사고의 방향이
반대**다. `index.html` 의 실린 순서는 `skins.css`(103행) → `density.css`(104행) →
`calm.css`(105행)다. calm 은 density 뒤라 skin 이 이겼고(손잡이가 죽었다), 이 다섯은
density 앞이라 **compact 가 이겼다**. 즉 손잡이는 살아 있었다 — 대신 켜는 순간
ledger 의 숫자가 그 스킨의 언어를 지웠다. 실측 증거:

    grid  density=compact  →  main 여백이 0 이 아니라 10px 12px 로 그려졌다
    field density=compact  →  판 여백 26px/57.6px 가 10px 12px 로, 가장자리의 지면이 사라졌다

grid 의 풀블리드와 field 의 가장자리 지면은 그 스킨의 **정체성**이지 여백 취향이
아니다. 밀도를 켰다고 스킨이 바뀌면 두 축이 독립이라는 말이 거짓이 된다.
고치는 방법은 calm 때와 똑같다 — 짝(특이도 0,3,0)은 **순서와 무관하게** 이기므로
두 방향의 사고를 한 번에 막는다.

### ② 실측 — 같은 로드 안에서 before/after

보드는 살아 있는 데이터라 3분 뒤에 다시 재면 카드 글이 달라져 있다(cork normal 이
227.1 → 211.1 로 혼자 움직였다). 그래서 파일을 두 번 바꿔 재는 방식을 버리고,
**같은 DOM 에서 짝 규칙만 CSSOM 에서 걷어내** 짝 없던 시절을 그 자리에서 재현했다
(`web/verify-density.html`, 기존 `verify-*.html` 과 같은 문법). 카드 높이는 보드 전체
14장의 중앙값, 장수는 REQ-032 와 같은 660px 칸 환산이다.

| 스킨 | normal | compact(짝 없음) | **compact(짝)** | normal→compact | 660px 칸 장수 |
|---|---|---|---|---|---|
| cork | 227.1px | 186.1px | **188.1px** | −17.2% | 2.20 → **2.59** |
| grid | 203.6px | 187.1px | **185.1px** | −9.1% | 2.45 → **2.69** |
| slate | 211.3px | 187.1px | **189.1px** | −10.5% | 2.38 → **2.65** |
| field | 216.1px | 187.1px | **187.1px** | −13.4% | 2.34 → **2.67** |
| terminal | 215.1px | 201.6px | **185.6px** | −13.7% | 2.36 → **2.70** |

짝이 되찾아 준 것(같은 로드 비교):

- **grid** — 판 여백 `10px 12px` → **0**(풀블리드 회복), 컬럼 폭 281.6 → 286.6px,
  카드는 오히려 2px 더 낮다. 잃은 것 없이 정체성만 돌아왔다.
- **field** — 판 여백 `10px 12px` → **`14px clamp(12px,2.4vw,32px)`**. 카드 높이는
  1px 도 안 바뀌고(187.1 그대로) 가장자리로 필드가 다시 보인다. compact 의 몫은
  세로가 이미 다 가져갔다는 뜻이라, 가로를 도로 준 대가가 0 이다.
- **terminal** — body 12px → **11.5px**. normal 이 이미 12.5px 라 generic 12px 는
  0.5px 밖에 못 줄였다. 스킨의 눈금으로 한 칸 더 내려 카드가 201.6 → **185.6px**
  (−7.9%) — 다섯 중 짝이 가장 크게 일한 자리다.
- **cork·slate** — 카드가 2px **높아졌다**. 일부러다: 라운드 8px 모서리 안쪽으로
  좌우 10px 밑을 파면 글자가 곡선에 닿아 보인다(각진 ledger 의 10px 를 그대로
  쓸 수 없는 이유). 좌우는 10~11px 에서 멈추고 줄인 몫은 세로가 가져갔다 —
  normal 대비로는 여전히 −17.2% / −10.5% 다.
