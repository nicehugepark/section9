### 4. 세 갈래 각각, 앞으로 무엇이 어긋나는가

**A. `approve` / `deny` (사용자 안) — 반대**
- 없는 상태 이름을 발명한다. 소문자 영문 동사는 이 화면에서 곧 상태 식별자의 서체다. 사용자가 `s9 status <id> approve` 를 치게 되고, 그런 전이는 없다. 화면이 CLI 에 존재하지 않는 동사를 가르치는 셈.
- 그 어긋남을 메우려 `s9 approve` alias 를 만들고 싶어진다 → 상태 전이의 쓰기 경로가 둘이 된다. 이 저장소가 세 번 반복해 배운 그 실패("판정이 두 벌이면 한 벌만 고쳐진다").
- 화면은 영어인데 History·통지·워커 프롬프트는 계속 "승인:"·"반려됐다" 다. **지금은 화면과 History 가 같은 말인데 그게 깨진다.** 승인을 누르고 History 를 읽는 사람이 매핑을 손으로 한다.
- 결정적으로, **문제를 못 고친다.** 다른 버튼은 여전히 `→ done`(목적지 명사)이고 이것만 `approve`(행위 동사)다. 언어만 맞췄지 문법은 그대로 둘이다. 사용자가 다음 판정에서 같은 위화감을 다시 말할 확률이 높다 — 이미 서체로 한 번 고쳤는데(2차) 또 물어본 것이 그 증거다.

**B. 전부 상태 이름 (`→ done` · `→ in-progress`)**
- 일관성·번역 비용·CLI 대응은 최상. 진지한 후보다.
- 대신 **`→ in-progress` 가 반려라는 사실이 버튼에서 사라진다.** 사유 필수 · 워커 재스폰 · 담당 세션 통지가 달린 가장 무거운 간선이 "그냥 뒤로 옮기기"로 보인다. 위험한 버튼을 중립적으로 그리는 것은 오조작을 부른다(지금은 창이 막아 주지만, 누르기 전에 예측이 안 되는 건 여전히 나쁘다).
- `done` 으로 가는 길이 둘인데(`in-progress→done` = 일이 끝남, `review→done` = 사람이 승인함) 라벨이 같아지면 **서버가 다르게 취급하는 두 간선이 화면에서 구별 불가**가 된다. 게이트 면제가 붙은 쪽이 어느 쪽인지 화면이 못 말한다.
- 6개월 뒤 "승인 버튼이 어디 갔냐"로 되돌아온다.

**C. 현행 유지**
- `RVLABEL` 이 화면 상수라 상태머신이 바뀌면 조용히 뒤처진다(이미 반대 방향으로 한 번 터졌다).
- 위 §2 의 `승인:` 이중 소유가 그대로 남는다.
- 사용자의 위화감이 해소되지 않는다 — 그게 이 대화의 출발점이다.

### 5. 권고와 반증 조건

**권고: 문법을 하나로 통일한다. 모든 버튼이 목적지 상태를 보이고, 판정 간선만 그 앞에 행위 한 낱말이 더 붙는다.**

```
review 문서:     ✓ 승인 → done        ↺ 반려 → in-progress
그 밖의 문서:            → blocked            → cancelled            → done
```

- 모델을 그대로 그린다: 판정은 전이의 부분집합이고, 부분집합에 이름표가 하나 더 붙는다. 새 개념 없음.
- "왜 여기만 다르지"에 답한다 — 이제 다르지 않다. 더 붙었을 뿐이다.

**창 머리(cap)** — 지금 넷 다 `판정` 인데, 3차에서 세운 원칙("review 에서 나가는 것만 판정")과 어긋난다. `in-progress → done` 창이 스스로를 `판정` 이라 부르면서 버튼은 `상태 옮기기` 라고 한다.

| 창 | before | after |
|---|---|---|
| 승인 · 반려 | `판정` | `판정` |
| 그 밖의 이동 · 취소 | `판정` | **`상태 옮기기`** |

**창 안 문장** — 지금 것이 옳다. 한 곳만:

    before  「판정 창 세 가지」 을(를) 승인해 done 상태로 넘깁니다
    after   「판정 창 세 가지」를 승인해 done 상태로 넘깁니다

### 1. 칸 이름 — `timezone` 을 유지하고, 한국어는 설명 줄에

### 2. 목록에 무엇을 적나 — **IANA 이름 + 지금 시각**, 오프셋 없음, 한국어 병기 없음

한 행에 둘만 둔다.

```
Asia/Seoul                              지금 17:02
America/New_York                        지금 04:02
Pacific/Honolulu                   지금 어제 22:02
```

**왜 IANA 이름 그대로인가.** 그게 저장되는 값이고, `s9 user config` 출력·`S9_TZ`·에러 메시지에서 다시 만날 글자다. 1번과 같은 이유 — 번역하면 대조가 끊긴다.

**왜 시각인가.** 이것이 유일한 검증 신호다. 실증 하나: `Etc/GMT+9` 는 POSIX 규약 탓에 **UTC−9** 다. 지금 `Asia/Seoul` 이 17:02 일 때 `Etc/GMT+9` 는 **어제 23:02** 다. 이름만 보면 한국인은 백이면 백 이걸 고른다. 시각을 옆에 두면 고르기 전에 틀린 것이 보인다. 이름이 거짓말할 수 있는 자리에서 시각은 거짓말하지 못한다.

**왜 오프셋(`+09:00`)을 빼나.** 자기 오프셋을 외우는 사람은 드물고, 외워도 `+05:45`·`+12:45` 앞에서 무너진다. 무엇보다 오프셋은 **대조할 대상이 없다** — 사용자 손목시계에 `+09:00` 이 적혀 있지 않다. 시각은 적혀 있다. 오프셋은 화면에서 빼되 **검색어로는 받는다**(3번).

**왜 한국어 도시명을 병기하지 않나.** 498개 중 한국인이 이름을 아는 것은 30개 남짓이다. 나머지는 번역표가 없어 `Africa/Ouagadougou` 처럼 영문만 남는다 — **목록의 절반만 한국어인 화면은 미완성으로 읽힌다.** 그리고 IANA 이름은 이미 도시명이다: `America/New_York` 을 못 읽는 사용자는 없다. 한국어는 **보이는 자리가 아니라 쳐 넣는 자리**에 둔다(3번). 그러면 "서울"을 쳐서 `Asia/Seoul` 을 찾는 길은 열리면서, 목록은 균질하게 남는다.

**날짜가 다르면 `어제`/`내일` 을 붙인다.** `04:02` 만 있으면 오늘 새벽인지 어제인지 알 수 없다. 이 표기가 없으면 시각을 보여 주는 의미가 반감된다.

**시계는 째깍이지 않는다.** 분 단위(`HH:MM`)로, 목록이 열릴 때와 검색어가 바뀔 때 다시 계산하고, 열려 있는 동안 30초마다 갱신한다(초 단위 갱신은 s9-design 5절의 "장식적 모션"이다). 화면이 안 보일 때는 멈춘다.

### 처음에 무엇이 보이나

498개를 임의로 잘라 "더 보기"를 다는 대신, **위로 끌어올리고 나머지를 그대로 이어 붙인다.** 잘린 목록은 "왜 내 도시가 없지"를 만들고, 이어 붙인 목록은 스크롤로 끝까지 간다.

```
지금 쓰는 곳
  ✓ Asia/Seoul                          지금 17:02
    설정 안 함 — 이 컴퓨터의 시간대를 따릅니다
전체
    Africa/Abidjan                       지금 08:02
    …448개, 알파벳순
```

- 절 제목 둘만. 셋째("최근 고른 곳")는 만들지 마라 — 저장할 데가 없고, 타임존은 자주 바꾸는 값이 아니다.
- **`Etc/*` 35개와 이름 홑개 15개는 기본 목록에서 뺀다.** `etc/`·`gmt`·`utc` 를 직접 쳤을 때만 나온다. 부호가 뒤집힌 함정을 기본으로 노출할 이유가 없다.
- **`Factory` 와 `localtime` 은 어떤 검색어로도 내보내지 마라.** 시간대가 아니라 파일 시스템 부산물이다.
- 현재 값 표시는 `✓` 와 `선택됨` 텍스트를 함께 — 색만으로 구분하지 않는다(s9-design 7절).

**별칭표는 보이지 않는 검색 키워드다.** 항목 하나에 `["서울","seoul","한국","korea","kst"]` 식으로 단다. 보이지 않기 때문에 **불완전해도 결함이 아니다** — 별칭이 없으면 영문으로 치면 되고, 화면은 여전히 균질하다. 이것이 2번에서 한국어 병기를 뺀 대가를 여기서 치르는 방식이다.

별칭표 최소 범위(이 정도면 실사용 99%): 한국·일본·중국·대만·홍콩·싱가포르·인도·베트남·태국·인도네시아·필리핀·호주·뉴질랜드·미국 주요 4개 zone·캐나다·영국·프랑스·독일·네덜란드·스페인·이탈리아·스위스·스웨덴·폴란드·튀르키예·러시아(모스크바)·UAE·사우디·이스라엘·이집트·남아공·브라질·아르헨티나·멕시코. 대략 50~60줄.

> `kst` 를 계산으로 얻으려 하지 마라. `Intl.DateTimeFormat(…,{timeZoneName:'short'})` 는 미주·유럽 zone 에는 `EST` 를 주지만 아시아 zone 에는 `GMT+9` 를 준다 — 약어 검색은 **계산으로는 반쪽만 된다.** 이 제품이 자기 기록에 `KST` 를 찍고 있으므로(`◈ 현재 시각 … KST`) 사용자가 `kst` 를 칠 확률은 높다. 별칭표에 손으로 넣어라.

**안 맞춘다 (분명히 못 박는다)**

- **오타 교정 없음.** `seuol` 은 안 맞는다. 퍼지 매칭을 넣지 마라 — 시간대는 잘못 골라도 티가 안 나는 값이라, 어림짐작이 정답처럼 보이는 것이 오타보다 위험하다.
- **국가 코드 없음.** `KR`·`US` 는 안 받는다. 두 글자는 잡음이 너무 많다(`kr` 가 지명 안에서 걸린다). 나라는 **이름**으로 친다.
- **부호 없는 숫자는 오프셋이 아니다.** `9` 만 치면 오프셋 검색을 하지 않는다 — 지명 부분일치만. `+9` 나 `-9` 여야 오프셋이다.
- **행정구역·지명 없음.** `강남`·`판교`·`경기도` 는 안 맞는다.
- **시각으로는 못 찾는다.** `17:02` 를 쳐도 그 시각인 zone 을 찾아 주지 않는다. 시각은 확인용이지 검색어가 아니다.

### 4. 아무것도 안 맞을 때 · 값이 비었을 때

### 빈 결과 (두 줄)

```
맞는 곳이 없습니다
도시 이름으로 찾아보세요 — 서울 · seoul · new york · +9
```

- 사용자가 친 글자를 문장에 넣지 않는다. `'{입력}' 과` 는 조사가 갈리고(`seoul 과`? `+9 와`?), 이미 검색창에 그 글자가 그대로 보인다. 반복은 잡음이다.
- 비난하지 않는다. "잘못 입력했습니다"·"유효하지 않은" 금지.
- 둘째 줄이 **다음 행동**이다 — 예시 넷은 3번에서 실제로 되는 것만 골랐다.
- **"이대로 저장" 같은 탈출구를 만들지 마라.** 목록에 없는 이름을 저장하면 지금과 똑같은 조용한 폴백으로 돌아간다. 이 컨트롤은 목록에 있는 것만 저장한다.
- 찾는 도시가 정말 없을 때(작은 도시): 목록 아래 붙박이 한 줄로 둔다 — `찾는 도시가 없으면 시각이 같은 가까운 큰 도시를 고르세요.` 빈 결과 화면이 아니라 **상시 힌트**여야 한다. 빈 결과일 때만 나오면 이미 늦다.

### 값이 비었을 때 — 화면이 말해 줘야 한다

**그렇다. 반드시.** 지금은 `placeholder="Asia/Seoul"` 인데, 이건 **거짓말에 가깝다** — 흐린 글씨로 `Asia/Seoul` 이 보이면 서울로 설정된 것처럼 읽히고, 실제로는 시스템 로컬로 물러서 있다. 우연히 둘이 같아 아무도 눈치채지 못했을 뿐, 해외에서 열면 화면이 틀린 말을 한 셈이 된다.

닫힌 칸 표시:

```
설정 안 함        이 컴퓨터의 시간대를 따릅니다
```

그리고 이것은 **목록의 정식 항목이기도 하다** — 설정한 사람이 되돌아갈 길이 있어야 한다(s9-design 4절).

> **designer/구현에 주는 제약:** 물러서는 대상은 *브라우저*가 아니라 **`s9` 서버가 도는 컴퓨터**다(`bin/s9:10547`, `astimezone()` 기본). 브라우저의 `Intl.DateTimeFormat().resolvedOptions().timeZone` 을 가져와 `설정 안 함 (Asia/Seoul)` 처럼 적으면 원격 접속 시 틀린 말이 된다. **`/api/whoami` 가 서버의 실제 해석 값을 실어 주기 전까지는 이름을 적지 마라.** 실어 줄 수 있게 되면 `설정 안 함 — 이 컴퓨터의 시간대 (Asia/Seoul) 를 따릅니다` 로 늘린다.

### 5. 고른 뒤 — 즉시 저장

**저장 버튼 없음. 고르는 즉시 저장한다.**

1. 같은 판의 `기록 남기기` 스위치와 `디스플레이` 의 skin/tone/density 가 이미 즉시 저장이다(`web/index.html:9632` 주석에 그 판단이 적혀 있다). **같은 판에서 어떤 것은 즉시, 어떤 것은 버튼이면 사람은 규칙을 외울 수 없고 "골랐는데 왜 안 되지"가 생긴다.**
2. 하나만 고르는 컨트롤에는 "작성 중" 상태가 없다. 고른 순간 의도가 완결된다 — 지킬 중간 상태가 없으니 확인 단계도 필요 없다.
3. 되돌리는 비용이 0 이다. 다시 고르면 끝. 파괴적 행동이 아니므로 확인 창을 두지 않는다(s9-design 4절).

### 저장 알림 (`.secmsg` 패턴 재사용)

```
저장하는 중…
저장했습니다 — 이제 Asia/Seoul 기준입니다. 지금 17:02.
```

`설정 안 함` 을 골랐을 때:
```
저장했습니다 — 이 컴퓨터의 시간대를 따릅니다.
```

실패:
```
✕ 저장하지 못했습니다 — {서버 사유}
```

> **조사 함정:** `Asia/Seoul 로` 는 로마자 뒤라 `로/으로` 가 갈린다(`Asia/Kolkata 로`? `Etc/GMT 으로`?). 그래서 **`기준입니다` 로 명사를 끼워 조사를 흡수한다** — 판정 창이 `→ done` 을 `done 상태로 옮깁니다` 로 고친 것과 같은 수법(REQ-20260828-007-62x6). 이름 뒤에 직접 조사를 붙이는 문장을 쓰지 마라.

> **실패 시 화면을 되돌려라.** 저장이 실패했는데 칸에 새 값이 남아 있으면 화면이 거짓말한다. 실패하면 표시를 이전 값으로 되돌리고 알림만 남긴다.

### 바뀐 것을 그 자리에서 확인할 방법

**그 자리에서 진실을 말할 수 있는 것은 이 칸의 시계 하나뿐이다.** 조사한 결과:

| 시각이 나오는 곳 | 설정을 바로 따라오나 |
|---|---|
| **이 칸의 `지금 17:02`** | **예 — 클라이언트가 계산** |
| 훅이 주입하는 `◈ 현재 시각` | 화면에 안 보임. 다음 턴에나 |
| Stream/터미널의 타임스탬프 | **아니오.** `TZ = display_tz()` 가 **서버 기동 시 1회** 계산된다(`bin/s9:10549`) — 서버를 다시 띄워야 따라온다 |
| 카드의 상대 시각(`2분 전`) | 시간대와 무관 |

그러니 문구가 **"화면 시각이 따라갑니다"** 라고 넓게 약속하면 거짓이 된다. 알림은 **자기가 증명할 수 있는 것만** 말한다 — `지금 17:02` 까지다.

> **designer/리드에게:** `display_tz()` 를 요청마다 해석하도록 고치면(캐시 무효화 한 줄) 대화 기록 시각도 F5 만으로 따라온다. **이건 별건 REQ 로 떼는 게 맞다** — 여기서 문구로 덮지 마라. `서버를 다시 시작하면 반영됩니다` 같은 문장은 결함에 자막을 단 것이고, s9-design 1절이 금하는 "설명으로 구조 문제를 덮는" 짓이다. 고치기 전까지는 알림을 위의 두 줄로 유지하고 아무 약속도 더하지 않는다.

### 6. 키보드

| 자리 | 동작 | 화면에 보이는 문구 |
|---|---|---|
| 닫힌 칸 | `Enter` `Space` `↓` → 열림 | — |
| 열린 직후 | 검색란 포커스, 전체 목록, **현재 값에 커서** | placeholder: `도시 이름 (예: 서울 · seoul · +9)` |
| 타자 중 | 좁혀지고 **첫 행으로 커서 이동** | 목록 아래: `Enter 로 고르기 · Esc 로 닫기` |
| `↑` `↓` | 커서 이동, 목록 끝에서 멈춤(순환 금지) | 위와 같음 |
| `Home` `End` | 처음/끝 행 | 표기하지 않음(보편 관례) |
| `Enter` | 고르고 → 저장 → 닫힘 | 저장 알림으로 이어짐 |
| `Esc` | **아무것도 저장하지 않고** 닫힘, 값 그대로 | — |
| `Tab` | **고르지 않고** 닫히고 다음 칸으로 | — |

- **`Tab` 이 커서에 놓인 항목을 고르게 만들지 마라.** 콤보박스에서 가장 흔한 결함이고, 시간대는 잘못 저장돼도 즉시 티가 안 나서 피해가 오래간다. 확정은 `Enter` 하나뿐이다.
- 힌트는 한 줄로 족하다 — 규칙이 둘이고 둘 다 짧다. `↑↓` 는 목록의 `aria-label` 이 말한다(아래). 판정 창이 힌트를 두 줄로 쪼갠 것은 낱말이 길어 좁은 폭에서 끊겼기 때문이고, 여기는 그렇지 않다.
- 목록 안에서 `↑↓` 는 페이지 스크롤을 가져가야 한다(`preventDefault`), 커서 항목은 항상 보이게 스크롤.

### designer 에게 넘기는 구현 함정 (문구 아닌 것들, 전부 실제로 확인함)

1. **`web/index.html:9619` 의 `설정 저장` 버튼에서 `timezone` 을 빼라.** 안 빼면 렌더 시점의 낡은 값을 방금 저장한 값 위에 덮어쓴다. `digest_budget` 만 남긴다.
2. **`Etc/*` 35개는 기본 목록에서 감춰라.** `Etc/GMT+9` = UTC−9 다(지금 어제 23:02). 이름과 뜻이 반대인 항목을 기본 노출할 이유가 없다.
3. **`Factory`·`localtime` 은 어떤 경로로도 내보내지 마라.** 시간대가 아니다.
4. **목록의 출처를 정하라.** 서버 `zoneinfo` 는 498개, 브라우저 `Intl.supportedValuesOf('timeZone')` 은 별칭·`Etc/*` 를 빼고 그보다 적다. 둘이 다르면 "화면에 없는데 저장은 되는 이름"이 생긴다. **서버가 목록을 주는 쪽**을 권한다 — 저장 검증(`zoneinfo.ZoneInfo(name)`)과 같은 출처여야 한다.
5. **`bin/s9:10549` 의 `TZ = display_tz()` 는 서버 기동 시 1회다.** 대화 기록 시각이 설정을 바로 못 따라온다 — 별건 REQ 감. 문구로 덮지 마라(5번 참조).
6. **`display_tz()` 는 `resolve_user()`, 즉 서버를 띄운 사람의 설정을 본다.** admin 이 남의 계정을 편집(`isAdminEdit`)해도 서버 표시 시각은 안 바뀐다. 이 판에 그 사실을 적을 필요는 없지만, "왜 안 바뀌지"가 오면 여기다.
7. 시계 갱신은 30초 주기, `document.hidden` 이면 정지, 판이 닫히면 타이머 정리(s9-design live follow 규약).

관련 파일: `/home/sjpark1/section9/web/index.html` (9524~9530, 9619), `/home/sjpark1/section9/bin/s9` (10539~10555). **아무 파일도 고치지 않았고 `s9 note` 도 남기지 않았다.**
