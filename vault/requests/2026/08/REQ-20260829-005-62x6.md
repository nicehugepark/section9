## Original

main 체크아웃에서 git status 가 "fatal: this operation must be run in a work tree" 로 거부됐다. .git/config 의 core.bare 가 true 로 뒤집혀 있었고, 되돌려도 1분 안에 다시 뒤집혔다. 파일은 멀쩡해서 커밋하려는 순간에야 드러난다. REQ-20260829-004 의 doctor 확장 작업 중 커밋이 막혀 발견.

## Notes

### 2026-08-29T01:14:53+09:00 response (by nicehugepark)

원인 — git 이 훅에 넘기는 GIT_DIR 이 자식에게 그대로 샌다.

경로(실측으로 전 구간 확인):
1) s9 serve 감시 틱이 주인 떠난 worktree를 자동 보존한다 — state/worktrees/w-827-012-62x6-* 에서 git commit (ps 로 pid 583 의 자식임을 확인).
2) git 이 pre-commit 훅에 GIT_DIR=<repo>/.git/worktrees/<이름> 을 넘긴다.
3) 훅(s9-guard)의 staged_tests_gate 가 python3 tests/ 를 띄운다.
4) 그 테스트가 임시 리포에 git init 을 부른다(tests/test_streams_untracked.py 의 git 헬퍼).
5) GIT_DIR 이 '-C <임시경로>' 를 이겨 그 worktree 자리를 다시 init 하고, 작업 트리가 없다고 판단해 **공용 .git/config 에 core.bare=true** 를 박는다.

격리 재현(임시 리포):
  GIT_DIR=<repo>/.git/worktrees/wt1 git -C <다른경로> init -q  →  core.bare false → true
그 뒤 본 체크아웃의 git status 는 'fatal: this operation must be run in a work tree'.

왜 안 보였나 — 파일은 멀쩡하고, 되돌려도 1분 뒤 자동 보존 커밋이 다시 밟는다. 커밋하려는 순간에야 드러난다. 손으로 tests 를 돌리면 GIT_DIR 이 없어 재현되지 않는다(내가 처음 그렇게 확인하고 무혐의 판정했다가, 훅 환경 차이를 보고 다시 잡았다).

조치 셋:
- bin/s9-install: 훅 템플릿이 두 rev-parse 뒤 'unset GIT_DIR GIT_WORK_TREE GIT_COMMON_DIR GIT_PREFIX' 한다. 문 앞에서 벗기므로 worktree의 옛 사본에도 효과가 있다. GIT_INDEX_FILE 은 남긴다 — 가드가 '지금 담기는 것'을 보려면 필요하고(부분 커밋은 임시 인덱스), 파괴적인 것은 GIT_DIR 쪽이다.
- bin/s9-guard: clean_git_env() 로 자식 테스트에 GIT_* 를 벗겨 넘긴다.
- tests/test_streams_untracked.py: git 헬퍼도 같은 스크럽(방어 이중화).
- 증상 감지: s9 doctor 의 저장소 점검이 core.bare=true 를 critical 로 지목한다(REQ-004).

시험: tests/test_hook_git_env.py — 스크럽 계약 넷 + 실제 뒤집힘 재현 둘(벗기면 안 뒤집힌다까지). 6/6 통과.
