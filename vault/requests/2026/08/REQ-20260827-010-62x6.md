### 직접 본 것

세 장을 찍었다(`state/shots/010-rework-1.png` · `010-rework-2.png` · `010-tall.png`).

- `#stream` 만 열면 오른쪽은 안내문뿐이다 — 세션을 골라야 본문이 나온다.
- 세션을 골라 1440×900 으로 찍으면 **본문이 위아래로 잘려 있다.** 첫 줄이 글자 중간에서 시작한다.
- 같은 화면을 1200×2600 으로 찍으면 **본문이 통째로 다 나온다.** 즉 내용이 잘려 저장된 게 아니라 **열자마자 맨 아래로 내려가 있어서** 앞부분이 안 보이는 것이다.

### 원인 — 끝난 세션이 `live` 로 표시된다

캡처에 그대로 찍혀 있다: `session 9a2bd342-… · 21 events · ● live ☑ follow`.

그 세션은 **어제 22:14 에 끝났다.** 바인딩을 열어 보면 명시적으로 적혀 있다:

    state/sessions/DESKTOP-TEHV1KR__9a2bd342.json
      "ended": "1"

그런데 스트림 API 는 `live: true` 를 준다. `bin/s9` 의 `resolve_stream_path()` 가 **"바인딩이 있고 transcript 파일이 디스크에 남아 있으면 살아있다"** 로 판정하기 때문이다:

    tp = b.get("transcript_path", "")
    if tp and os.path.exists(tp):
        return tp, True  # 라이브 원본 우선

`ended` 도, 마지막 활동 시각도 보지 않는다. **한 번이라도 돌았고 파일이 남아 있으면 영원히 live 다.**

그 결과가 화면에서 둘로 나타난다:

1. `term.scrollTop = d.live ? term.scrollHeight : 0` — 열자마자 맨 아래로 뛴다. 그래서 **본문 앞부분이 안 보인다.** (`web/index.html`)
2. `follow` 체크박스가 켜진 채 **2.5초 폴링이 영원히 돈다.** 죽은 세션이라 새 이벤트는 0 이지만, 화면은 "지금 살아 있고 따라가는 중"이라고 계속 말한다.

`live` 가 올바로 `false` 였다면 같은 줄이 `term.scrollTop = 0` 이 되어 **본문 첫 줄부터 보인다.** 반려 사유의 앞 절반("본문이 다 보이지도 않고")이 이것 하나로 풀린다.

### 고치는 자리 — `bin/s9` (이 세션 봉투 밖)

이 저장소에는 이미 같은 판정을 제대로 하는 장치가 있다. `chat_target()` 이 쓰는 그대로다:

    if b.get("ended") or not chat_live(b): continue

제안: `resolve_stream_path()` 의 그 분기를 아래로 바꾼다.

    tp = b.get("transcript_path", "")
    if tp and os.path.isfile(tp) and not b.get("ended") and chat_live(b):
        return tp, True          # 진짜로 도는 세션만 live
    if tp and os.path.isfile(tp):
        return tp, False         # 파일은 읽되 live 라고 말하지 않는다

계약 테스트 자리도 정해 둔다: `ended` 가 박힌 바인딩에 대해 `stream_events()` 가 `live=False` 를 주는가 · 그래도 이벤트는 그대로 오는가.
