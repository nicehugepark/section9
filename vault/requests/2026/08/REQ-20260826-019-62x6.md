### 3. 미답 표시

ADR 결정 3 그대로 **파생**으로 읽는다. 판정 함수는 `isAnswered(r, body)` 하나다:

- 뷰어는 본문을 들고 있으니 원본(`answer`/`response` 라벨 노트)에서 **직접** 읽는다. 정규식은 s9 의 `_answered()` 와 같은 것(`^### \S+ (?:answer|response)\b`)이고, V7 이 그 이음매를 붙잡는다 — 실제 `s9 note --label answer` 가 만든 본문을 index.html 에서 뽑아낸 정규식으로 다시 매치한다. 여기가 어긋나면 답을 달아도 화면은 영원히 미답이다.
- 목록은 본문이 없으니 카탈로그 `answered` 를 쓴다.

**3상이다: 답함 · 미답 · 모름.** 카탈로그에 `answered` 필드가 없는 경우(구 카탈로그, rebuild 전)를 미답이라 단정하지 않는다 — 그러면 답이 붙은 문서를 목록은 미답, 뷰어는 답함으로 읽어 같은 화면에서 두 진실이 생긴다. 이 타입이 없애려던 상태가 정확히 그것이다.

### 2. 수리 제안 (bin/ — 봉투 밖, 적용하지 않음)

`bin/s9` 의 `chat_audit()` 에서 비-request 분기가 지금은 이렇다:

```python
if _chat_classifier(t) != "request":
    subprocess.run([me, "log", f"chat: {first[:60]}"], ...)

```

제안: 로그만 남기고 끝내지 말고 **질문이면 프롬프트 훅과 같은 기준으로 QST 를 만든다.** 판정 함수는 이미 로드한 그 모듈에 있다 — `_chat_classifier` 를 잡을 때 `mod.is_durable_question` 도 함께 잡아 두면 새 의존이 없다.

```python
cls = _chat_classifier(t)
if cls != "request":
    subprocess.run([me, "log", f"chat: {first[:60]}"], ...)
    if cls == "question" and _chat_durable(t):        # 훅과 같은 자
        title = first[:QUESTION_TITLE_MAX] + ("…" if len(first) > QUESTION_TITLE_MAX else "")
        out = subprocess.run([me, "new", "question", "--title", title,
                              "--tag", "auto-audit", "--user", sender or "dashboard"],
                             input=t, capture_output=True, text=True, env=env, timeout=15)
        # 채팅은 Stop 훅이 없다 — 답 부착 경로는 아래 주의 참고
    return None
```

**주의 두 가지.**

1. **답 부착 경로가 프롬프트 턴과 다르다.** 프롬프트 경로는 `bind last_qst` → Stop 훅이 답을 붙인다. 채팅은 서버가 만들고 답하는 주체는 수신 세션이라 Stop 훅이 이 QST 를 모른다. 그대로 두면 **채팅 질문이 전부 미답으로 쌓인다.** 수신함 줄(`inbox-<sid8>.jsonl`)에 `req` 를 싣듯 `qst` 를 함께 실어 보내고, 세션 훅이 그 값을 `last_qst` 로 바인딩하면 기존 Stop 훅 경로가 그대로 재사용된다 — 새 부착 로직이 필요 없다.
2. **`--user sender`** 를 넘겨야 한다(채팅 REQ 와 같은 규칙). 안 넘기면 서버 계정으로 기록된다.

### 3. 과거 154건 소급 이관 — 판단이 필요해 확인 포인트로 올린다

자동으로 하지 않았다. 결정이 갈리는 지점이 둘 있다.

- **원문이 잘려 있다.** 세션 로그의 `question:`/`chat:` 줄은 앞 60자뿐이다. 원문 전체와 그때의 답은 `streams/*.jsonl`(44개 세션, 132MB)에 있으므로 **복구는 가능하지만 도구가 필요하다**(`s9 backfill-questions` 류). 그건 `bin/` 이다.
- **잘린 질문 + 미답으로 154장을 만들면 잡음이다.** 답이 실제로는 있었는데(리드가 답했다) 문서로만 없는 것이라, 전부 미답으로 세우면 미답 목록의 신호가 죽는다. 이 타입의 값어치가 미답 목록에 있으므로 그건 자해다.

그래서 두 안 중 하나를 골라 달라 — (A) 도구를 만들어 streams 에서 원문·답까지 복구해 제대로 이관, (B) 소급은 포기하고 오늘부터 쌓이는 것만 관리. 둘 다 `bin/` 작업이라 이 세션이 정할 수 없다.

### 화면에서 고친 것 (web/ — 봉투 안)

반려를 계기로 화면에 실제 결함이 하나 드러났다. **총량만 보이고 "그중 몇 장이 답이 없나"가 안 보였다.** 이 타입을 만든 이유가 미답을 드러내는 것인데, 타입바는 `QUESTION 2` 라고만 말했다.

- 타입바의 question 항목에 미답 수를 병기한다 — `QUESTION 2 미답 1`. 총량은 회색으로 물러나 있고 미답만 타입색 잉크로 선다(면·띠 아님, 글자색과 무게만). **0이면 붙이지 않는다** — 없는 신호가 자리를 차지하면 있는 신호가 안 읽힌다.
- 처음엔 `2 미답 1` 로 숫자를 붙여 놨다가 `2`와 `1`이 한 덩어리로 읽혀 단어를 앞으로 옮겼다(`미답 1`). 숫자 사이에 글자가 들어가야 경계가 생긴다.

**구현 중 실제 버그 하나를 잡았다.** `isAnswered(r)` 가 타입을 보지 않아, 카탈로그가 비질문 행에도 실어 보내는 `answered: ""` 를 `!!""` = `false` 로 읽었다 — 그대로 세면 **요청 269건이 전부 미답으로 집계된다.** 판정 함수 첫 줄에 타입 가드를 넣고 V12 로 고정했다.
