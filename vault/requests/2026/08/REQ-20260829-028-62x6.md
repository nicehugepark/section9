### 낡은 자리에 앉히지 않는다 — 스폰 자리 판정 설계 (구현 지시서)

읽기 전용으로 스폰 경로 전체를 읽고 확정했다. `bin/s9` 는 손대지 않았다.

### 0. 먼저: 읽으면서 발견한 두 가지 (설계의 전제가 된다)

**(가) 지금 자동 커밋 하나가 30초마다 무한히 실패하고 있다.**
`state/auto_resume/spawn.log` 가 16:51부터 `WT-AUTOCOMMIT w-827-012-62x6-1787929230` 를
30초 간격으로 계속 찍는다. 그 워크트리는 `AD f` · `M bin/s9-install` ·
`M tests/test_commit_gate.py` 로 여전히 dirty 다. 원인은 `_worktree_autocommit`
(bin/s9:13205)이 `git commit` 을 `capture_output=True` 로 삼키고 반환코드를 안 보기
때문이다 — pre-commit 게이트(`bin/s9-guard`)가 거부하면 아무 소리 없이 실패하고,
sweep 이 다음 틱에 또 부른다. **실패가 안 보이는 자동 커밋은 장치가 아니라 거짓말이다.**
이것이 ③의 판단 근거 중 가장 무거운 실측이다.

**(나) 한 문서가 워크트리를 넷까지 만들었다.**
`state/worktree_owners/` 에 `w-829-011-62x6-` 이 타임스탬프만 다른 채 넷,
`w-829-015-62x6-` 이 둘 있다. `worker_worktree_name()`(13139)이 매 스폰마다
`int(time.time())` 을 붙이므로 재스폰이 곧 새 워크트리다. 아홉까지 늘어난 것은
`worktree_sweep` 이 게을러서가 아니라 **스폰이 무제한으로 만들기 때문**이다.

### ② 판정 규칙

#### 핵심 통찰 하나: 워크트리가 놓치는 것은 **코드뿐이다**

`worker_workspace` 는 `S9_ROOT` 를 본 저장소로 못박는다(13165). 그래서
`vault/`·`state/`·`index/`·`users/` 의 미커밋은 워크트리 기준선과 **아무 상관이 없다** —
워커는 그것들을 본 저장소에서 읽는다. 지금 미커밋 101건 중 상당수가 그쪽이다.
"저장소가 dirty 면 거부" 가 부작용이 큰 이유가 여기 있다: 그 판정은 이 저장소에서
사실상 상수 `True` 라 무인 작업자가 영영 안 뜬다. **코드만 세면 판정이 다시 살아난다.**

#### 새 상수 (13054 `WORKTREE_MIN_AGE` 옆)

```python
DATA_PREFIXES  = ("vault/", "state/", "index/", "users/", ".git/")
SPINE          = ("bin/s9", "web/index.html")   # 이 저장소가 통째로 기대는 두 파일
LIVE_VERIFY    = ("web/",)                      # 9909 서버·tests 의 ../web 상대경로
WORKTREE_MAX        = 6         # 이보다 쌓이면 새로 만들지 않는다
WORKTREE_STALE_SEC  = 24*3600   # 주인 죽고 이만큼 지나면 사람 앞에 올린다
AUTOCOMMIT_MAX_TRIES = 3
LEASE_HOME          = os.path.join(ROOT, "state", "file_leases")
LEASE_WAIT_MAX_SEC  = 1800      # 기다림의 천장 — 넘으면 겹쳐도 띄운다
```

#### 새 함수 (의사코드)

```python
def code_dirty_paths():
    """워크트리 기준선이 놓치는 것 — 미커밋 **코드**만.
    데이터는 S9_ROOT 로 본 저장소를 함께 쓰므로 기준선과 무관하다.
    그것까지 세면 이 저장소는 늘 더럽고 판정은 상수가 된다."""
    return [p for p in _dirty_paths() if not p.startswith(DATA_PREFIXES)]


def declared_scope(doc_id):
    """이 요청이 만질 코드 파일 — **문서가 이름을 댄 것만**. 없으면 None(모름).
    추측하지 않는다: 모르면 모른다고 하고, 그때는 보수적으로 본 저장소를 고른다.
    틀리는 방향이 비대칭이다 — 본 저장소로 잘못 보내면 보이는 충돌 하나이고,
    워크트리로 잘못 보내면 오늘처럼 다섯 시간이 조용히 사라진다."""
    meta, body = read_doc(find_path(doc_id))
    text = " ".join([meta.get("title",""), meta.get("summary",""),
                     meta.get("goal",""), body])
    got = set()
    for m in re.finditer(r"(?<![\w/.-])((?:bin|web|tests|harness|docs)/"
                         r"[A-Za-z0-9_./-]+)", text):
        rel = m.group(1).rstrip(".,)`'\"")
        if os.path.isfile(os.path.join(ROOT, rel)):
            got.add(rel)
    return got or None


def workspace_decision(doc_id, cfg):
    """워크트리냐 본 저장소냐 — 판정은 여기 한 곳에만 있다.
    반환 {"kind","reason","scope","blocking"}"""
    if not cfg.get("worker_worktree"):        return M("off")
    if len(worktree_list()) >= WORKTREE_MAX:  return M("worktree-pile")
    if _doc_live_worktree(doc_id):            return M("worktree-exists")

    scope = declared_scope(doc_id)
    if scope and any(p.startswith(LIVE_VERIFY) for p in scope):
        return M("live-verify")     # 살아있는 서버가 못 보고, tests 가 ../web 를 읽는다
    if scope and any(p == "bin/s9" or p.startswith("bin/s9-") for p in scope):
        return M("self-edit")       # 샌드박스가 자기 도구를 자른다

    dirty = code_dirty_paths()
    if not dirty:                       return W("fresh")
    if set(dirty) & set(SPINE):         return M("dirty-spine", dirty)
    if scope is None:                   return M("dirty-unknown", dirty)
    if set(scope) & set(dirty):         return M("dirty-overlap", scope & dirty)
    return W("fresh-outside")
```

**`dirty-spine` 이 오늘의 사고를 정면으로 막는 줄이다.** `bin/s9` 나
`web/index.html` 이 미커밋이면, 무엇을 하든 워크트리는 낡은 자리다 — 시험이
`HERE/../bin/s9` 를 읽고 화면 검증이 9909 를 보기 때문에 스코프가 겹치지 않아도
검증이 거짓말을 한다. 지금 둘 다 dirty 다 → **오늘 뜨는 모든 워커는 본 저장소로 간다.**
이것이 의도한 결과다. 그리고 이 규칙은 좋은 압력을 만든다: **커밋하면 병렬 격리가
돌아온다.** 워크트리를 되찾는 값이 커밋이라는 것이 화면에 보인다(⑥ V6).

#### 본 저장소에서 여럿이 돌 때의 방벽 — 스폰 시점 파일 리스

워크트리를 안 쓰기로 하면 격리가 사라진다. 대체물 없이는 이 설계가 성립하지 않는다.
본 저장소에 이미 있는 것부터 세어 보면 방벽이 셋이다:

1. `snapshot_dirty()`(1610) — 30초마다 모든 미커밋 파일을 내용주소로 뜬다.
   덮어써도 원본이 `state/snapshots/` 에 있다. **복구는 된다.**
2. `bin/s9-guard concurrent_gate`(121) — 워커가 도는 중 900초 안에 만져진 파일을
   담으려는 커밋을 막는다. **반쪽 커밋은 안 난다.**
3. 봉투의 충돌 규율 문단(4596) — 이건 규율이지 장치가 아니다.

빠진 것은 **예방(같은 파일에 두 손이 동시에 붙는 것 자체)** 이다. 그것을 리스로 세운다.

```python
### state/file_leases/<safe(doc_id)>.json
### {"doc": ..., "pid": 0, "paths": [...], "since": ts, "reason": "spawn"}

def lease_take(doc_id, paths): ...          # 스폰 직전, pid 는 Popen 뒤에 채운다
def lease_release(doc_id): ...              # 워커 종료·문서 in-progress 이탈 시
def lease_conflict(doc_id, scope):
    """다른 문서가 잡고 있는 겹침 → [(path, holder_doc)]. 주인 pid 가 죽었으면
    그 리스는 없는 것으로 본다 — 죽은 손이 파일을 영원히 잡으면 교착이다."""
```

`_spawn_worker` 안, **`_auto_caps_ok` 앞**에 대기 판정을 넣는다:

```python
dec = workspace_decision(doc_id, cfg)
wait = None
if dec["kind"] == "main":
    inflight = [p for p in _worker_spawn_targets() if _worker_alive(p)]
    if len(inflight) >= int(cfg.get("auto_resume_max_inflight", 2)):
        wait = ("inflight", f"무인 작업자 {len(inflight)}이 이미 돌고 있다")
    elif dec["scope"]:
        hit = lease_conflict(doc_id, dec["scope"])
        if hit:
            wait = ("held", f"{hit[0][1]} 가 {hit[0][0]} 를 잡고 있다")
```

세 가지를 짚어 둔다:

- **거부가 아니라 대기다.** rework 워처가 30초마다 다시 부르므로 앞 작업자가 끝나면
  저절로 뜬다. 거부는 오늘의 병("멈춘 것이 계속 멈춰 있다")을 되살리지만 대기는 아니다.
- **기다림에 천장이 있다.** `LEASE_WAIT_MAX_SEC`(30분)를 넘기면 겹쳐도 띄우고 그
  사실을 크게 남긴다. 천장 없는 큐는 교착의 다른 이름이다.
- **스코프를 모르면(`None`) 붙잡지도 붙잡히지도 않는다.** 모르는 것으로 남을 막으면
  워커 하나가 전부를 세운다.
- 리스를 잡았으면 봉투(4596 else 가지)에 한 줄 더 준다:
  `[네 차례] 이 라운드에 네가 받은 코드 파일은 <paths> 다. 그 밖의 코드 파일은 만지지 마라 —
  다른 작업자가 잡고 있다.` 리스가 스케줄러 안에만 있으면 워커는 그것을 모른다.

### ③ 자동 커밋 — 쓰지 않는다

"스폰 전 스냅샷 커밋"은 기준선을 신선하게 만드는 가장 직접적인 수단이고,
그래서 진지하게 검토했다. **기각한다.** 근거 넷:

1. **이미 있는 자동 커밋이 지금 이 순간 조용히 실패 중이다.** (0-가) `_worktree_autocommit`
   은 자기 워크트리 안, 자기 파일만 담는 **가장 안전한 형태**의 자동 커밋인데도 게이트에
   막혀 30초마다 무한 반복하고 아무도 모른다. 그보다 훨씬 위험한 형태(본 저장소, 남의
   파일 포함)를 그 위에 얹는 것은 순서가 틀렸다. **먼저 고칠 것은 실패를 보이게 하는 일이다.**
2. **남의 진행 중 편집을 삼킨다.** 지금 22개 파일 2,702줄이 여러 주체의 손에 동시에
   있다. `git add -A` 는 "내 변경"이 아니라 "그 파일의 지금 상태"를 담는다 —
   2026-08-26 21:42 사고가 정확히 그것이었고, `s9-guard concurrent_gate` 는 그 사고를
   막으려고 존재한다. 스폰 경로의 자동 커밋은 그 게이트를 `S9_ALLOW_CONCURRENT` 로
   지나야만 가능하다. **분류기가 막은 일을 다른 문으로 통과시키는 것**이고,
   이 저장소가 이미 규율로 세운 '게이트에 옆문 내지 않기' 를 스스로 어긴다.
3. **되돌릴 수 없는 쪽을 자동화하는 셈이다.** 자리 선택은 틀려도 다음 스폰에 고쳐지고
   비용이 0이다. 커밋은 이력에 남고, 22개 파일을 뭉친 무의미한 커밋은 나중에 워크트리
   병합이 잘못됐을 때 되돌릴 지점을 없앤다.
4. **필요가 없다.** 기준선이 낡았다는 문제의 답은 두 가지다 — 기준선을 올리거나
   (커밋), 낡은 기준선을 안 쓰거나(본 저장소). 둘째가 공짜고 안전하다.

**대신 이렇게 한다:**

- (a) `_worktree_autocommit`(13205)을 **고친다** — 이건 유지한다. 워커 자기 가지,
  자기 파일이라 남을 삼키지 않고, 없으면 워커의 일이 사라진다(REQ-20260828-025-62x6).
  다만 `r = subprocess.run(...)` 의 반환코드와 stderr 를 읽고, 실패를 owner json 의
  `autocommit_tries`/`autocommit_error` 에 적고, `AUTOCOMMIT_MAX_TRIES` 회 실패하면
  그만두고 `s9 loose` 에 줄을 올린다.
- (b) 사람이 부르는 커밋은 손잡이로 준다: `s9 worktree add --commit-first` 또는
  `s9 spawn --commit-first`. **사람이 누르는 커밋은 괜찮다. 사람이 없을 때 나는 커밋이 문제다.**
- (c) 화면·CLI 가 "지금 워크트리를 못 쓰는 이유는 미커밋 `bin/s9`·`web/index.html`
  입니다" 를 말한다(⑥ V6). 커밋을 강제하지 말고 **이득을 보여서 유도한다.**

### ④ 워크트리를 거두는 규칙

원칙은 그대로다 — **남길 것이 있으면 지우지 않는다.** 바뀌는 것은 "지우지 않는다"가
"조용히 쌓인다"와 동의어이던 부분이다.

- **R1 문서당 하나.** `worker_workspace` 는 만들기 전에 `state/worktree_owners/` 에서
  같은 `doc` 을 찾는다.
  - 주인 pid 가 살아 있으면 → 애초에 스폰하지 않는다(겹쳐 띄우기 금지, 상류에서 막는다).
  - 죽었고 clean·not-ahead → 그 자리를 거두고 새로 만든다(잃을 것이 없다).
  - 죽었고 dirty 거나 ahead → **둘째를 만들지 않는다.** `worktree-exists` 로 본 저장소를
    고르고, 그 워크트리는 `s9 loose` 에 "합칠 것이 남았다" 로 올린다.
  오늘 `w-829-011` 이 넷이 된 것은 이 규칙 하나가 없어서다.
- **R2 총량 천장.** `worktree_list()` 가 `WORKTREE_MAX`(6) 이상이면 새 워크트리를 만들지
  않고 본 저장소로 간다(`worktree-pile`). 쌓임 자체가 신호다 — 신호를 무시하고 더
  쌓지 않는다.
- **R3 묵은 것은 지우지 말고 올린다.** sweep 에서 주인이 죽고 `WORKTREE_STALE_SEC`(24h)
  를 넘겼는데 dirty/ahead 인 워크트리는 `undelivered_requests()`(7242)에 이미 뜬다.
  거기에 **경과 시간**을 붙이고, 그 REQ 문서에 `--label worktree` 노트를 **한 번만**
  남긴다(중복 방지 표식을 owner json 에). 사람이 볼 자리는 문서다. 지우는 것은 사람이
  `s9 worktree merge` 또는 `rm` 으로 한다.
- **R4 자동커밋 포기.** (③-a) 3회 실패하면 재시도를 멈추고 `s9 loose` 에
  "자동 보존 실패 — 손으로 커밋해야 한다 (사유: …)" 로 올린다. 지금은 무한 루프라
  로그가 진짜 신호를 덮는다.
- **R5 성공 경로에서 즉시 거둔다.** `worktree_merge`(13170)는 이미 합치고 거둔다.
  더해서, 문서가 `done`/`blocked` 로 가고 그 가지가 이미 main 에 있으면(ahead==0,
  clean) sweep 이 `WORKTREE_MIN_AGE` 를 기다리지 않고 거둔다.

### ⑦ 기각한 대안

- **A. dirty 면 스폰 거부.** 기각. 이 저장소에서 미커밋은 상시라 무인 작업자가 영영
  안 뜨고, 그건 오늘의 병("멈춘 것이 계속 멈춰 있다")을 되살린다. 사용자가 명시적으로
  경고한 갈래다. — **채택한 것**: 거부가 아니라 **자리 바꾸기**(본 저장소), 그리고
  겹칠 때만 **천장 있는 대기**.
- **B. 스폰 전 본 저장소 스냅샷 커밋.** 기각. ③에 근거 넷. 요약하면 남의 편집을 삼키고,
  `s9-guard` 에 옆문을 내야 하며, 이미 있는 자동 커밋이 지금 조용히 실패 중이다.
- **C. `git stash` 로 잠깐 치우고 워크트리를 만든다.** 기각. 살아 있는 에이전트 셋이
  파일을 쥔 채로 stash 하면 그들의 다음 저장이 stash 뒤의 트리에 얹혀 뒤섞인다.
  이 저장소의 봉투가 `git stash` 를 금지하는 이유가 그것인데, 도구가 그걸 하면 규율이
  거짓말이 된다.
- **D. 워크트리를 만든 뒤 본 저장소의 미커밋 diff 를 이식한다.** 기각하되 **2단계로 남긴다.**
  이론상 신선함과 격리를 둘 다 얻는다. 그러나 지금 그대로 하면 워커의 가지가 **남의
  미완성 작업을 자기 기반으로 갖게 되고**, `s9 worktree merge` 가 그것을 워커의 산출물인
  양 본 저장소에 되돌려 넣는다 — 원저자가 그 사이에 더 고쳤다면 **고치는 것이 아니라
  지우는 일**이 된다. DOC-20260829-001-62x6 이 지목한 그 실패를 한 층 아래로 옮길 뿐이다.
  안전한 형태가 있긴 하다: **스코프에 해당하는 파일만** 이식하고, 워커가 그것을
  `기준선 이식` 이라는 **별도 첫 커밋**으로 못박게 하는 것. 그러면 병합이 이식분과
  작업분을 구분해 재생하고, 원본이 바뀌었으면 조용한 되돌림 대신 충돌이 뜬다.
  1단계(라우팅)가 돌고 나서, 워크트리를 다시 넓게 쓸 필요가 생기면 그때 만든다.
- **E. 워크트리를 아예 버린다.** 기각. `git add`/`checkout` 이 남의 작업을 삼키는 사고를
  막는 유일한 **구조적** 방벽이고(REQ-20260828-011-62x6, 네 번의 실사고), 깨끗한 기준선에서는
  대가가 0이다. 버리면 저장소가 커밋된 좋은 상태일 때조차 격리를 못 쓴다.
- **F. 워커의 파일 접근을 봉투로 제한해 충돌을 막는다.** 기각. `--allowedTools` 는
  도구 단위지 경로 단위가 아니고, 봉투는 "경계가 아니다"(4568 주석의 자백). 리스는
