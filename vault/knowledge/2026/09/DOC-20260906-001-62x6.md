## Original

증상: `ssh -N -L 9919:127.0.0.1:9909 jade` 가 붙어 있고 ss 는 127.0.0.1:9919·[::1]:9919 LISTEN 을 보이는데, WSL 안의 curl 도 윈도우 브라우저도 「연결 거절(ERR_SOCKET_NOT_CONNECTED)」. 윈도우 netstat 에는 그 포트가 아예 없다.

실측(2026-09-06, DESKTOP-TEHV1KR / WSL2 VirtioProxy, 이 저장소 세션 11b47d38):
- A `-4 -L 127.0.0.1:25909:127.0.0.1:9909` → WSL 200 · 윈도우 curl.exe 200
- B `-L 9929:127.0.0.1:9909` (사용자와 같은 꼴) → 000, 26초까지 계속 거절
- C `-4 -L 127.0.0.1:9929:…` (같은 포트) → 200 — 포트 대역이 아니라 **바인드 꼴**이 원인
- D 25909 를 윈도우 쪽에서 → 200

결론: 바인드 주소를 생략하면 ssh 가 [::1] 과 127.0.0.1 둘 다 잡는데, VirtioProxy 중계는 그 조합을 공개하지 않는다(DOC-20260903-001 「윈도우 중계가 우리 포트를 가로챈다」의 이웃 현상). 처방은 한 줄 — `-4` 와 `127.0.0.1:` 을 명시한다:
    ~/section9/bin/s9 secret run -- sh -c "{{secret:jade}} -4 -N -L 127.0.0.1:9919:127.0.0.1:9909"
그 뒤 브라우저 http://127.0.0.1:9919 . (s9 secret run 은 자식의 출력을 끝까지 모아 두므로 -N 터널은 조용한 것이 정상이다.)
