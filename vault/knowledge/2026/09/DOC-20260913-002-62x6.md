## 결론 (REQ-20260913-015-62x6)

1. **Claude Design 은 두 길이다.** ① `design` 스킬 = 아트보드(`*.dc.html`) 여러 장을 한 캔버스에 올려 Artifact 로 내는 화면·흐름 설계. 에이전트가 짓고, 내보낸 PNG/PDF 를 `s9 note <REQ> --attach` 로 요청에 붙이는 데까지가 자동이다. ② DesignSync 도구 = claude.ai/design 프로젝트 읽기·쓰기(list_projects → create_project → list_files → finalize_plan → write_files). 호출마다 권한 프롬프트가 뜨므로 사람 승인이 있는 리드만 한다. 미리보기 HTML 첫 줄 `<!-- @dsCard group="…" -->` 이 디자인 시스템 카드가 된다.
2. **디자인 시스템 미리보기는 원천(CSS)에서 생성한다** — `bin/s9-design-export` 가 tokens.css 의 `:root{}`·`[data-theme="carbon"]` 블록과 부품 규칙(선택자 이름으로 원본에서 꺼냄)으로 카드 4장을 낸다. 값을 손으로 적지 않으니 토큰이 바뀌어도 다시 실행하면 따라온다. 못 찾은 선택자는 stderr 경고(조용한 실패 금지), 같은 입력이면 바이트 동일.
3. **시험 예산 기준선(tests/BUDGET.json, 66/66) 아래서 새 시험 파일은 소스를 한 번만 읽을 수 있다.** 값 대조(tokens.css 1회)는 새 파일에, 「원천에 그 절이 있는가」 류의 글자 계약은 이미 세어진 파일(test_ux_agents.py — 같은 세 역할을 다루는 곳)에 항목으로 더한다. 기준선을 올리지 않는다.
4. **`s9 shot` 의 chrome 엔진은 Windows 쪽에서 뜨므로 WSL 의 `file:///home/...` 을 못 읽는다** — 12KB 짜리 빈 캡처가 나온다. `python3 -m http.server <빈 포트>` 로 그 디렉터리를 잠깐 띄우고 `http://localhost:<포트>/x.html` 로 찍는다(9909 는 대시보드라 쓰지 않는다).
5. **여러 에이전트가 한 index 를 쓸 때는 `git commit --only <내 경로>`** — 남이 stage 한 파일은 그대로 두고 내 경로만 담긴다. s9-guard 의 동시 작업 검사는 `bin/s9-guard --concurrent <경로>` 로 미리 보고, 표(S9_ALLOW_CONCURRENT)는 `git diff --cached` 를 읽은 뒤에만 붙인다. index.lock 이 있으면 지우지 말고 기다린다(다른 커밋의 pre-commit 훅이 시험을 돌리는 동안 잠긴다 — 실측 4분).
