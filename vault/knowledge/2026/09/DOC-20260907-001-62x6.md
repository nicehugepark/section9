## Original

## 사고
2026-09-07 10:35, bin/s9.py 에 REQ-098(cmd_shot)과 REQ-094(cmd_secret)의 변경이 함께 있었다. 098 만 먼저 담으려고 `git diff -U0` 을 hunk 단위로 갈라 `git apply --cached --unidiff-zero` 로 index 에 넣고 commit 했다(fc3011a). 문맥이 0줄이라 `def cmd_shot` 과 docstring 첫 줄, `--engine` 인자 줄이 한 줄씩 어긋나 담겼고 HEAD 의 s9.py 는 SyntaxError 였다. 작업 트리는 멀쩡해 시험은 통과했다 — 깨진 것은 commit 뿐이라 알아채기 어렵다. 다음 commit 이 작업 트리 전체를 담아 되돌렸다.

## 규칙
- 한 파일에 두 요청의 변경이 섞이면 **hunk 로 가르지 않는다.** 순서를 정해 먼저 끝난 쪽을 통째로 commit 하거나, 두 요청을 한 commit 에 담고 메시지에 둘을 적는다.
- 정말 갈라야 하면 `-U3` 이상의 문맥으로 hunk 를 고르고, commit 직후 `git show HEAD:<파일> | python3 -c 'import ast,sys; ast.parse(sys.stdin.read())'` 로 HEAD 의 구문을 확인한다 — 작업 트리가 아니라 HEAD 를.
- 같은 파일을 위임과 리드가 동시에 고치는 상황 자체를 피한다: 위임 지시문에 파일 범위를 적고, 리드는 그 파일을 위임이 끝난 뒤에 만진다(PROTOCOL 19조 동시 편집).
