## Original

## 판정

`bin/s9.py` 를 가르는 방법은 **`bind(globals())` — 이름공간 주입과 재수출**이다.
새로 고른 것이 아니라 **이 저장소가 이미 쓰고 있는 것**이다: `bin/s9_commit.py`
(651줄)가 `_S9 = {}` 에 `bind(g)` 로 s9.py 의 globals 를 통째로 받아
`_S9["ROOT"]` · `_S9["_sync_lock_take"](30)` 으로 쓴다. 그 파일의 머리말이
이유까지 적어 두었다 — 「잠금과 표식의 정의를 두 벌로 두지 않는다」.

## 맥락 — 실측 (리드 2026-09-16, REQ-20260916-007/-017)

| | |
|---|---|
| `bin/s9.py` | **41,564줄** · top-level def/class 1,228개 |
| 최근 7일 commit | **126~133회** — 다음 파일의 5.7배 |
| 오늘 하루 commit | **28회** |
| 동기화 계열 함수 | **77개**, 줄 범위 **863~34393**, 2,281줄 (한 덩이가 아니라 흩어져 있다) |
| 밖에서 불리는 것 | **27개** (`_sync_git` 8곳 · `sync_mode` 6곳 · `_sync_log` 4곳) |
| 동기화가 밖에서 끌어 쓰는 것 | **37개** = 공용 20 + 거의 전용 17(304줄) |
| 그 공용 20개 중 혼자 서는 것 | **6개**뿐 (`die`·`now_iso`·`current_machine`·`_iso_epoch`·`_notice_epoch`·`_notice_sig`) |
| 전역·남의 함수에 기대는 것 | **14개** (`chat_send` 57줄+ROOT+함수 5개, `chat_target` 50줄+함수 5개 …) |

여기에 이 설계가 더 재서 얻은 두 가지 — **이것이 방법을 고르게 한 값이다**:

| | |
|---|---|
| `bin/s9.py` 를 `SourceFileLoader`/`spec_from_file_location` 으로 올리는 시험 파일 | **350개** |
| `ROOT` 의 성질 | s9.py:44 에서 **import 때 한 번만** 정해진다 (`S9_ROOT` 또는 경로). 재대입·`global ROOT` 없음 |

시험은 그렇게 올린 모듈의 globals 를 직접 부른다 — `s9.now_iso()` ·
`s9.chat_send(...)` · `self.m.heartbeat_path(rid)` · `self.m.STALLED_WIN`.
그리고 환경변수 `S9_ROOT` 를 바꿔 **모듈을 다시 올리는 것**으로 시험끼리 격리한다.

**그래서 제약이 둘 고정된다.**
- **P1 — `bin/s9.py` 의 globals 가 이 저장소의 공개 API 다.** 옮긴 이름이 거기서
  사라지면 시험 350개와 저장소 안 호출부가 함께 깨진다.
- **P2 — 모듈 상태는 다시 올릴 때마다 새것이어야 한다.** 옮긴 자식이 `sys.modules`
  에 캐시되면 옛 `ROOT` 가 남아, 시험의 격리가 조용히 무너진다.

## 대안과 기각 이유

**(A) 인자 주입 — 함수 시그니처에 `root`·`state` 를 더한다.**
기각. 호출부를 전부 고쳐야 한다. `now_iso()` 하나가 저장소 전역에 흩어져 있고
시험 350개가 인자 없이 부른다(P1 위반). 옮기는 diff 에 호출부 수정 수천 줄이
얹혀 리뷰가 불가능해지고, 같은 창에 들어오는 하루 28회의 commit 과 전부 충돌한다.

**(B) 전역을 쥔 객체 하나(`Ctx`)를 지나가게 한다.**
기각. (A)와 같은 호출부 비용에 더해, 그 객체를 누가 만들고 어디까지 들고 다니는가가
새 설계 문제로 남는다. s9.py 에 지금 그런 객체가 없으므로 **없던 개념을 하나 더
들여오는 것**이고, 「의존성은 비용」 원칙에 걸린다. ROOT 가 상수라(실측) 객체로
감쌀 이유도 약하다.

**(C) `sys.path.insert` + 평범한 `import s9_helpers`.**
기각. s9.py 는 스크립트로도 돌고 시험은 파일 경로로 올린다 — 같은 파일이
`sys.modules` 에 두 이름으로 앉아 **ROOT 가 두 벌**이 된다(P2 위반). `S9_ROOT` 를
바꿔 다시 올리는 격리가 첫 시험부터 깨진다. 저장소의 기존 세 모듈
(`s9_commit`·`s9_env`·`s9_firstrun`)이 **하나도** 이 길을 쓰지 않는 것이 이미 답이다.

**(D) 가르지 않는다.** — 아래 「하지 않을 것」에서 따로 잰다.

**채택 = bind.** 호출부를 **한 줄도 고치지 않고**, `sys.path` 를 건드리지 않으며,
import 방향이 `s9.py → 자식` 단방향이라 순환이 생길 수 없다. 자식은 s9.py 를
import 하지 않고 dict 하나를 받을 뿐이다.

## 계약 셋 (이 설계의 전부)

- **C1 — 자식은 s9.py 를 import 하지 않는다.** `_S9 = {}` 와 `def bind(g): _S9.update(g)`
  만 둔다. 전역도 남의 함수도 `_S9["…"]` 로 꺼내 쓴다. 이것이 순환을 없애는 자리다 —
  「엉켜 있다」가 bind 아래에서는 비용이 아니게 된다.
- **C2 — s9.py 는 옮긴 이름을 제 globals 로 되받는다.** 자식이 `EXPORTS` 를 선언하고
  s9.py 가 `for n in mod.EXPORTS: globals()[n] = getattr(mod, n)`. P1 이 지켜진다.
- **C3 — 싣는 자리는 한 곳, 캐시는 s9.py 의 globals 에.** `commit_module()` 이 이미
  `globals()["_COMMIT_MODULE"]` 에 캐시한다 — s9.py 를 다시 올리면 globals 도 새것이라
  캐시도 새것이다. P2 가 지켜진다. `sys.modules` 에 캐시하면 안 된다.

이 셋을 지키는 회귀 시험 하나를 첫 조각에 함께 둔다: 옮긴 이름이 s9.py 의 globals 에
있고 자식의 것과 **같은 객체**인가 · 자식 소스에 `import s9` 가 없는가.

## 첫 조각 — `bin/s9_ctx.py` (S, 예산 15분)

물음은 「혼자 서고 · 값이 있고 · 다음 조각의 순환을 실제로 없애는 것」이었다.

**첫 조각은 「공용 6개를 내보내는 것」이 아니다.** 리드가 이미 실측으로 그 길을
닫았다 — 6개를 옮겨도 14개가 남아 순환이 그대로다. **첫 조각은 bind 장치 자체이고,
6개는 그 장치를 실증하는 짐이다.**

- 새 파일 `bin/s9_ctx.py`: `_S9`·`bind`·`EXPORTS` + 혼자 서는 6개
  (`die`·`now_iso`·`current_machine`·`_iso_epoch`·`_notice_epoch`·`_notice_sig`).
- `bin/s9.py`: 싣기 한 곳(`_side_module(name)` — `commit_module()` 의 모양 그대로)과
  재수출 한 줄. 그 6개의 본문은 지운다.
- 시험 1개: C1·C2·C3.

**이 조각의 값은 6개가 옮겨진 것이 아니라, 나머지 71개가 옮겨질 수 있게 된 것이다.**
`chat_send` 가 ROOT 와 함수 5개에 기대도, 그 다섯이 `_S9` 안에 있으면 그대로 옮겨진다.
리드가 막혔다고 본 자리(「14개가 엉켜 있어 못 옮긴다」)는 **옮기기로는 막혔지만
bind 로는 막히지 않는다** — 엉킴을 풀지 않고 통째로 지나가게 하기 때문이다.

## 순서와 크기

| # | 무엇 | 크기 | 왜 이 자리 |
|---|---|---|---|
| 1 | `s9_ctx.py` — bind 장치 + 혼자 서는 6개 + 계약 시험 | **S** | 장치가 먼저다. 코드는 적게 옮겨 장치만 실증한다 |
| 2 | 동기화 전용 17개(304줄) → `s9_sync.py` | **S** | 다섯 곳 미만에서만 쓰여 재수출 부담이 가장 작다. **bind 아래에서 「엉킨 것」이 실제로 옮겨지는가**를 여기서 판정한다 |
| 3 | 동기화 77개 중 밖에서 안 불리는 50개 → `s9_sync.py` | **M** | 밖에서 안 부르니 재수출도 거의 필요 없다 |
| 4 | 밖에서 불리는 27개 → `s9_sync.py` + 재수출 | **M** | 가장 위험한 자리(`_sync_git` 8곳 · `sync_mode` 6곳). 마지막에 둔다 |

**조각 2 뒤에 멈춰 다시 잰다.** 3·4 를 할지는 그때 판정한다 — 아래 「하지 않을 것」 5번.

**옮기는 조각은 하루에 하나만, 그날 그 파일의 다른 작업을 세우지 않는다.**
오늘 s9.py 에 commit 28회가 들어갔다. 함수가 통째로 사라진 자리에 남이 고친 hunk 가
오면 `s9 commit --hunks` 로도 가를 수 없다. 옮기기는 `s9 commit -m '…' -- bin/s9.py
bin/s9_sync.py` 한 번으로 담는다.

전체 시험은 각 조각의 **마지막에 한 번**, 원격에서(규약 18조).

## 하지 않을 것

1. **`sys.path` 를 건드리지 않는다.** 시험 350개가 파일 경로로 올린다.
2. **호출부를 고치지 않는다.** 재수출이 있는 한 `s9.now_iso()` 는 그대로 돈다.
   호출부 정리를 옮기기에 섞으면 diff 가 리뷰 불가능해지고 충돌 면적이 그만큼 넓어진다.
3. **공용 14개의 엉킴을 풀지 않는다.** bind 아래에서 엉킴은 비용이 아니다.
   `chat_send` 를 「ROOT 를 인자로 받게」 고치는 일에는 값이 없다 — 그것은 (A)를
   조각 단위로 되살리는 것이다.
4. **1,228개 def 를 전부 가르는 계획을 세우지 않는다.** 이 설계가 답하는 것은
   동기화 77개까지다. 나머지는 이 장치가 조각 2 에서 증명된 뒤 각각 요청으로 선다.
5. **조각 3·4 는 지금 승인하지 않는다 — 가르지 않았을 때의 비용을 재 보면 그렇다.**
   - **가르지 않는 비용**: 오늘 commit 28회 · 7일 133회. 여럿이 한 파일을 고쳐
     동시 편집 검사에 걸리고, `--hunks` 우회가 **규약 19조에 문장으로 박혔다**.
     우회가 규약이 되었다는 것은 구조가 진 자리다.
   - **그런데 가르는 것이 그 비용을 줄이는가**: 동기화 2,281줄은 41,564줄의 **5.5%** 다.
     충돌을 만드는 것은 줄 수가 아니라 **같은 시간에 같은 파일을 고치는 사람 수**이고,
     5.5% 를 떼어 낸다고 28회가 눈에 띄게 줄 이유가 없다. **한 번의 가르기로는 안 준다.**
   - 그러므로 이 설계의 값은 「s9.py 를 작게 만드는 것」이 아니라 **「가를 수 있는
     구조를 하나 세우는 것」**이다. 조각 1·2 는 그 구조를 세우고 실증하므로 값이 넘는다.
     조각 3·4 는 **부피를 옮기는 일**이라, 조각 2 뒤에 s9.py commit 충돌 횟수를 다시
     세어 줄었을 때만 한다. 안 줄었으면 **하지 않는다** — 아픈 것과 고쳐야 하는 것은
     다르고, 4만 줄이 아픈 것은 사실이나 옮기는 것이 약이라는 증거는 아직 없다.

## 결과 예상

- **선다**: s9.py 의 globals 를 공개 API 로 보존한 채 코드를 밖으로 내보내는 길 하나.
  이후 어떤 구간이든 같은 세 계약으로 뗄 수 있다.
- **안 선다**: s9.py 의 줄 수가 의미 있게 줄지 않는다(조각 4까지 다 해도 5.5%).
  동시 편집 충돌이 줄어든다는 보장도 없다 — 그것은 조각 2 뒤에 실측으로 판정한다.
- **위험**: 재수출이 빠진 이름 하나가 시험 350개 중 어디선가 깨진다.
  C2 를 지키는 시험이 그것을 첫 조각에서 막는다.
