## Original

실증 2026-09-07 (REQ-20260907-076~079). 주인 지시: 화면 시험은 실제 맥 Safari 에서도 실행한다. 맥에는 ssh 로 못 붙고 Remote Control 로 부른다.

## 길
맥 세션(Claude Code)에 `SendMessage` 로 대상 REQ·URL·볼 것·예산을 적어 보낸다. 맥에 section9 체크아웃이 있으면 **이 머신을 망에 열 필요가 없다** — 맥이 pull 해 제 대시보드를 열면 된다. 그래서 순서가 정해진다: **commit·push 가 먼저다.** 맥이 보는 것은 push 된 코드다.

## 돌아오는 것
캡처는 `vault/requests/<연>/<월>/assets/<REQ>/` 에 두면 `s9 sync` 로 이쪽에 온다. 맥의 파일 경로를 그대로 받으면 안 된다 — 이 머신에는 없다. 회신 요지는 그쪽에서 `--label subagent` 로 남긴다.

## 맥이 무엇까지 잴 수 있는지는 그 맥의 Safari 설정이 정한다
Safari ▸ 설정 ▸ 고급 ▸ 개발자용의 「Allow Remote Automation」·「Allow JavaScript from Apple Events」가 **켜져 있으면** safaridriver 로 누르는 것까지 되고 계산값도 읽힌다 (2026-09-07 21:56 확인: POST /session·/url·/execute/sync, innerWidth 1440x922, DOM 값; 새 창은 800x600 이라 /window/rect 로 맞춘다). **꺼져 있으면** safaridriver 도, 값 읽기도 안 된다. 그러면 **눌러야 보이는 것**(select 를 펼쳐 읽기)과 **계산값**은 맥에서 못 잰다. 2026-09-07 첫 왕복에서 넷 중 하나(프로젝트 필터의 option 문구)가 정확히 그 이유로 미검증이었다. 이런 항목은 「맥에서 못 잰 항목」으로 적고 WebKit 이나 사람이 본다 — **없는 검증을 했다고 적는 것이 못 한 것보다 나쁘다.**

## 보낼 때는 push 한 sha 를 준다
아직 안 민 sha 를 적어 보내면 맥은 그 객체를 모른다 — 그쪽은 origin 최신으로 재고, 무엇을 잰 것인지 어긋난다(2026-09-07 실제로 그렇게 어긋났다: 리드가 로컬 sync commit 을 적어 보냈고 맥은 origin 최신으로 쟀다). `git push` 뒤에 `git rev-parse --short origin/main` 을 적는다.

## 왜 WebKit 캡처로 끝내지 않는가
같은 엔진 계열이어도 맥의 Safari 는 글꼴·스크롤·입력·확대가 따로 논다. 다만 2026-09-07 1440 폭 첫 검증에서는 갈리는 것이 없었다(글꼴 잘림·헤더 겹침·가로 스크롤 없음) — 그것도 사실로 적어 둔다. 없다는 것을 아는 것과 안 본 것은 다르다.
