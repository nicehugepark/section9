## Original

## 문제
압축을 푼 자리(코드만, .git 없음)를 팀 저장소의 main 으로 맞춰야 한다. `git clone` 은 빈 디렉토리를 요구하고, `git checkout -B main origin/main` 은 미추적 파일(배포판 코드)이 원격의 추적 파일과 겹쳐 「would be overwritten」로 서며 `-f` 가 필요하다 — 그 `-f` 와 `reset --hard` 는 bin/s9-git-gate 가 작업 트리를 되돌리는 명령으로 막는 꼴이다(실사고 REQ-20260901-004 의 규율).

## 길 (bin/s9_firstrun.py join_repo, git 2.43 실측)
    git init -q -b main            # 없을 때만
    git remote add origin <url>
    git fetch -q origin
    git read-tree -u --reset refs/remotes/origin/main   # index + 작업 트리를 원격 tree 로 — 겹치는 미추적 파일은 덮이고(코드는 원격 판이 이긴다), 원격에 없는 미추적 파일은 남는다
    git update-ref refs/heads/main refs/remotes/origin/main
    git symbolic-ref HEAD refs/heads/main
    git config branch.main.remote origin ; git config branch.main.merge refs/heads/main   # fetch 는 clone 과 달리 upstream 을 잡아 주지 않는다

`read-tree -u --reset` 은 `reset --hard` 의 plumbing 이라 **덮는 힘은 같다** — 그래서 규율은 명령이 아니라 조건으로 지킨다: vault/·users/ 아래 파일이 하나라도 있으면(빈 디렉토리 제외) 거부하고, origin 이 이미 있으면 같은 URL 만 멱등으로 지나간다. 되돌림은 이번에 만든 .git 을 지우거나(없던 자리) 이번에 더한 origin 만 제거한다.

## 시험에서
로컬 bare(`git init --bare`)를 GitHub 삼으면 네트워크 없이 fetch/push 전부를 실증할 수 있다(tests/test_join.py). 첫 인스턴스는 tests/unpacked.py 의 release_shape(작업 트리를 export-ignore 규칙으로 복사)로 세운다 — `git archive HEAD` 는 commit 전 코드를 모른다.
