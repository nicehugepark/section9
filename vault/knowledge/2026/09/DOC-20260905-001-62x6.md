### ③ 크기별 처리 시간 예산 (제안 — 숫자는 오늘 실측에서 역산)

| | S | M | L |
|---|---|---|---|
| 접수→commit 상한 | **15분** (최선 5/기대 10/최악 15) | 60분 (최선 30/기대 45/최악 90) | 4시간 (최선 2/기대 3/최악 5), 파생 REQ 로 쪼개 각 M 이하 |
| 착수 | 접수 즉시 — 선행 REQ 의 전체 실행을 기다리지 않는다(표적 시험은 간섭 없음) | 즉시 | 즉시, parent 만 열고 파생은 순차 |
| 위임 | **없음** — 리드 직접(규약 7 직접 처리 하한선 ①) | 1명 | 병렬 N |
| 문구 판정 소집 | **0** — 기존 사전 낱말(테스트·건·전체)만 쓰면 tech-writer 판정 없이 진행; 새 낱말이 설 때만 tech-writer 1명 | 넷 소집 1회, stalled 는 3분에 끊고 designer 가 판정 | 넷 소집, 라운드 ≤2 |
| 새 시험 상한 | **≤3건**(정상 1·경계 1·회귀 1), 이웃 동반 실행 없음 | ≤10건, 이웃은 같은 디렉토리 파일만 | 상한 없음, 파일당 실행 ≤30초 |
| 캡처 | **≤2장**(바뀐 얼굴 1·대표 스킨 1) | ≤4장 | ≤8장 |
| 전체 스위트 | **0회** — 표적 파일 + commit 전 스모크(≤30초) 1회 | 1회(commit 직전, 배경) — 붉으면 그 파일만 단독 | ≤2회(중간·최종) |
| 서버 재시작 | 0 (화면 파일만이면 F5) | ≤1 | ≤2 |
| 범위 확장 | **금지** — 추가 요구는 `--parent` 파생 REQ 로 받고 현 REQ 는 먼저 commit | 파생 REQ | 파생 REQ |

006 에 이 예산을 대입하면: 대기 12→0, 소집 7→0, 2차 요구 22→별도 REQ, 시험 9→1, 재시작 2→0 → **약 10분**. 예산 초과는 게이트가 막기보다 **초과 사실을 노트로 남기고 리드가 왜 넘었는지 한 줄 적는** 방식이 낫다 — 게이트 하나 더는 또 하나의 대기다.
