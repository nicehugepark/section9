## 한 줄 결론

동기화 구조는 바꾸지 않는다(main 하나·문서 1개=파일 1개·git 이 전송층). 바꾸는 것은 셋이다 — ① 실행 귀속의 뿌리를 「만든 머신」에서 **「담당자 + 문서에 적힌 리스」** 로 옮기고 판정을 한 함수에 모은다 ② 동기화의 **쓰기 모델**을 고친다(전송 비동기·의미 병합·수신 폴링·실패 표면화) ③ 자율 실행을 여는 것은 전부 **로컬**에 두고, 공유 리포에서 실행 권위를 갖는 텍스트는 admin 게이트 뒤로 보낸다. observer 는 이미 있는 `viewer` 역할에 이빨을 붙이는 일이다.

역할 에이전트 10명(deep-diver·architect·staff-engineer·backend-developer·devops-engineer·security-engineer·database-administrator·product-owner·white-hacker·project-manager)의 개별 보고 원문은 `projects/section9/assets/014-sync-design/` 에 있다. 아래는 리드가 합치고 판정한 것이다.

## 1. 확인된 사실 (열 보고가 코드·재현으로 일치한 것)

- **가드가 세 곳·세 기준.** 무인 스폰 `_spawn_worker`(bin/s9:7247)는 문서를 **만든 머신** 기준, `s9 next`(11002)는 user 기준, 훅이 매 프롬프트 최우선으로 주입하는 `reopened/stalled/blocked/approvals` 목록(10444·s9-audit-prompt:726-767)은 **필터가 없다.** 남의 반려 REQ 가 pull 되면 내 리드 세션이 워처보다 먼저 "지금 이어서 작업하라"를 받는다 — 사용자가 걱정한 경로가 실재한다(deep-diver 격리 재현 exit 0).
- **역방향도 뚫린다.** `machine` 은 생성 뒤 갱신되지 않아, 남이 `s9 claim` 으로 이어받아도 만든 머신의 워처가 그 클레임을 "죽은 세션"으로 보고(생존 신호 pid·transcript 가 로컬 사실) 중복 스폰한다(repro_reassign, Popen 2회). "남에게 할당"이 곧 사고인 구조.
- **바인딩 공유가 섞인다.** `state/sessions` 는 track 되는데, 남의 바인딩의 `attach_pid` 가 내 머신의 산 pid 와 겹치면 `chat_target`·`rework_claimed` 에서 살아나고(실리포 159건 중 131건 pid 보유), `update_active_reqs`·`_release_binding_claim` 은 남의 바인딩 파일을 고쳐 써 push 한다 — docs/08 의 "같은 파일을 쓸 일 없음"과 모순. 절대경로·pid 가 커밋된다.
- **같은 문서 동시 편집은 3/3 충돌.** note+전이·note+set·note+note 전부(devops·architect 각각 격리 재현). 원인은 모든 쓰기가 갈아엎는 `updated:` 한 줄과 한 줄 JSON 목록 필드. 충돌 시 `sync_run` 은 abort 후 60초 백오프·로그만 남기고 **영구 정지** — 복구 명령도 화면 표시도 없다.
- **수신 경로가 없다.** pull 은 내가 문서 이벤트를 낼 때만 돈다. 쓰지 않는 머신(관찰자)은 남의 변경을 영원히 못 받는다. non-fast-forward push 거부를 네트워크 장애로 분류해 60초 침묵한다.
- **viewer 는 이름뿐.** `ROLES` 에 있으나 판정에 쓰는 코드 0줄. `s9 user role <me> admin` 도 CLI 에서 무검사(자기 승격). `/api/status`·`/api/chat`·`/api/stop`·`/api/session/restart` 에 역할·소유 검사 없음.
- **자율 실행 스위치가 공유 파일에 산다.** `users/<u>/config/settings.json`(auto_resume_apply·auto_resume_gh·s9code_args·worker_worktree)이 track 된다 → push 권한자가 남의 머신 워커 권한을 켤 수 있다. `projects/*/agents/*.md` 는 워커 프롬프트 서두에 1500자 그대로 주입되고 `.claude/agents` 로 미러되는데 s9-guard·CODEOWNERS 보호 밖이다. 반려 노트 `safe_note`(7464)는 제목과 달리 `<<`/`>>` 치환이 빠져 방벽 탈출 주입이 가능하다. branch protection 은 `enforce_admins=false`.
- **디렉토리·ID·인덱스는 문제가 아니다.** git 충돌은 파일 단위라 디렉토리 분할은 충돌 면적을 바꾸지 않고, 조회는 카탈로그가 하며(`find_path`·`link_audit` 은 id 기준), ID 는 머신 지문 접미로 이미 전역 유일(docs/08 "한계 1"은 낡음). index rebuild 894건 0.27s, 6,465건 1.0s.
- **브리핑 정정.** streams/ 는 track 되지 않는다(.gitignore + SYNC_DATA_PATHS 제외). docs/08 표가 낡았다.

## 2. 결정 (권고안) — 사용자가 뒤집을 수 있는 항목은 §4 에

**축 1+2 · 실행 귀속과 담당자 — 한 기능의 앞뒤다.**
- `user` = **현재 담당자**(변경 가능)로 재정의한다. 근거: `next_pickup`·`_spawn_worker` owner·`doc_visible`·`--user` 필터가 이미 전부 그 뜻으로 읽는다 — 새 `assignee` 를 두면 네 자리를 다 고쳐야 하고 하나만 빠져도 그 자리로 샌다(backend). 별칭 `--assignee` 를 둔다.
- 생성 시 확정·불변 필드 넷을 더한다: `creator`(사람 계정), `origin`(human|agent|derived), `origin_actor`(lead:<model>·worker:<reason>·sub:<role>), `origin_req`(어느 REQ 를 처리하다 만들었나). "누구의 요청을 처리하다"는 `origin_req` 문서의 `user` 로 답한다(따로 두면 재할당 때 낡는다). `parent/derived_from` 은 나중에 바뀌는 계보, `origin_req` 는 생성 행위의 출처 — 중복이 아니다. 사람 입구는 훅·채팅·화면 폼 셋뿐이라 그 셋만 `--origin human` 을 붙이고 나머지는 `cmd_new` 한 곳이 `--parent`/`S9_JOB_REQ`/`S9_SESSION`/`S9_AUTO_RESUME` 로 판정한다.
- 판정은 순수 함수 하나 `exec_verdict(meta, local, want)` → allow/code. 순서: 종결→viewer→담당자≠나→상태→리스(신선하면 같은 머신·같은 세션 renew / 같은 머신·다른 세션은 로컬 생존 신호로 / **다른 머신은 벽시계만**)→free. 이 함수를 `_spawn_worker`·`rework_claimed`·`_claim_req`·`update_active_reqs`·`next_pickup`·훅 목록 4곳·드래그 통지·`trigger_dependents` 가 쓴다. `do_transition` 은 게이트하지 않는다(전이는 판정이지 실행이 아니다).
- 리스는 **문서 frontmatter** 에 둔다(`lease: {user, machine, session, since, renewed}`). 바인딩이 아닌 이유: 바인딩은 머신별 파일이라 두 머신이 **둘 다 성공**한다. 문서의 같은 줄을 두 머신이 쓰면 rebase 충돌 → `git push` 의 non-fast-forward 가 곧 원자적 비교-교환(CAS)이다. 획득 `lease_acquire` = pull → 판정 → 기록 → push 확인. **스폰은 비관**(push 성공 전 Popen 금지), 사람의 claim 은 네트워크 실패 시만 경고 후 허용. 하트비트는 새 시계 없이 담당 머신의 문서 쓰기(`HEARTBEAT_WRITE_CMDS`)가 `renewed` 를 갱신, TTL 은 기존 `CLAIM_GRACE` 1800초.
- 이것이 사용자 원문의 "자기 요청은 자기 머신에서"를 충족하되 낱말을 바꾼다: 기준은 머신이 아니라 **담당자 + 처음 집은 머신(리스)**이다. 머신 기준은 두 대를 쓰는 순간 깨지고 할당을 막는다 — 사용자 자신이 원문에서 그 모순("남에게 할당할 수 없게 된다")을 발견했다.
- 재할당 `s9 assign <id> <user>` 단일 경로(CLI·대시보드 공용 `do_assign`): 담당자 갱신 + lease 삭제 + History 한 줄. 권한은 생성자·현 담당자·admin·프로젝트 maintainer 이상, viewer 는 담당 불가. 옛 담당 머신은 다음 틱에 not-mine 을 받아 워커를 세우고 훅이 "담당이 바뀌었다"를 주입한다. 파생 REQ 의 담당자 기본값은 원 요청의 담당자(자식은 기본으로 따라가지 않는다).
- 마이그레이션은 **파일 이동·일괄 rewrite 0건**: 읽기 규칙 한 곳(`creator or user`, origin 미상은 빈 값 — 지어내지 않는다). 846 문서 일괄 재기록은 sync 충돌 면적만 늘린다.

**축 3 · 동기화 — 구조는 그대로, 쓰기 모델을 수리한다.** (DOC-20260826-002 가 단일 main·이벤트 즉시·허브 없음을 이미 확정했고, 열 보고 중 브랜치·디렉토리 분할을 권한 것은 없다.)
- **전송 비동기.** 문서 이벤트는 로컬 커밋(<0.3s)만 하고 반환. push·pull 은 serve 의 전송 루프가 맡는다(2초 디바운스 commit·in-flight push 1·묶음). 거부(non-ff)는 즉시 fetch→rebase→push 재시도(지터, 최대 5회), 네트워크·타임아웃만 60초 백오프. 리스 획득만 동기 왕복이다.
- **수신 폴링.** serve 가 활성 세션 있을 때 10초·유휴 60초 fetch + ff 병합 + index 갱신. 전이 직전 그 문서에 한해 fetch 1회. 화면의 pull 손잡이와 sync_run 의 pull 을 한 함수로.
- **의미 병합 드라이버.** `.gitattributes vault/**/*.md merge=s9doc`(s9-install 이 git hook 과 같은 방식으로 등록). 규칙: `updated`=max, 목록(agents·contributions·relates·tags·blocked_by·members)=합집합, Notes·History=타임스탬프 헤더 단위 합집합·시각순, `status` 가 양쪽 다르면 **늦은 쪽(LWW)** + History 양쪽 보존 + `s9 doctor` 「이중 전이」 표시. 선행: 한 줄 JSON 목록을 항목당 한 줄로. 되면 `children`·`updated` 를 파생으로 바꿔 부모 파일 쓰기를 없앤다.
- **자가 치유·표면화.** 전송 시작 시 `.git/rebase-merge` 잔재 abort, 타임아웃 분기에도 abort. git 판·digest 첫 줄·훅 주입에 "마지막 보냄/받음·대기 n건·diverged", `s9 sync resolve <id> --take mine|theirs`, `s9 sync --stats`(sync.jsonl 로 p50/p95·거부율).
- **state/sessions track 해제.** 다른 머신이 필요한 것은 "누가 무엇을 맡았나"뿐이고 그것은 문서 리스로 간다. 바인딩 공유가 주는 것(인수인계 열람)보다 해(유령 클레임·남의 파일 쓰기·절대경로·pid 노출)가 크다. `approvals_seen.json` 도 함께.
- **지연 목표.** 이벤트→로컬 커밋 0.3s, origin 도착 p95 15s(5인)/30s(20인), 남의 화면 p95 40s. 초 단위는 git 전송층으로 불가 — 필요해지면 GitHub webhook→serve 알림이 다음 단계.
- **배치·ID·인덱스.** 디렉토리 분할 기각(파티션 키 `project` 는 가변, sparse-checkout 요구는 프로젝트별 인스턴스 리포로). ID 유지 + 지문 고정(local.json)·등록부(machines.json)·pull 후 충돌 검지. 증분 카탈로그는 3천 문서 전에.

**축 4 · observer = viewer 강제.** 새 역할을 만들지 않는다. 강제 자리는 문서 쓰기의 단일 경계 `write_doc`(bin/s9:421, 36 호출부) 한 곳 + 문서 쓰기가 아닌 조작(chat/wake/stop/restart) 은 POST 진입부 한 곳. 읽기는 프로젝트 멤버십(project role viewer) 기본, 전체 관찰은 admin 이 `until` 붙여 예외 부여. 훅 자동 기록(REQ/QST/SES)도 viewer 세션에서는 만들지 않는다. 층별 실패 가정: 로컬 인가는 자기신고라 인증이 아니다 → observer 에게는 인스턴스 리포 **read 권한만** → doctor 가 GitHub 권한과 profile role 불일치를 경고. 화면 낱말(「관찰자」)은 ux-writer·tech-writer 판정.

**보안 — 결정과 무관하게 즉시.** ① 자율 실행 설정(auto_resume*·s9code_args·worker_worktree)을 `local.json` 으로 옮겨 track 에서 뺀다 ② `projects/**/agents/**`·`users/*/skills|agents`·`users/*/profile.md` role 을 s9-guard PROTECTED + CODEOWNERS 에, `enforce_admins=true` ③ `safe_note` 에 `_safe_title` 과 같은 델리미터 치환, 문서 유래 텍스트에 출처 봉투 ④ `s9 user role` CLI 에 admin 검사. 원칙: **실행·권한을 여는 것은 전부 admin 게이트, 데이터는 실시간 공유, 코드는 절대 자동 동기화 대상이 아니다.**

## 3. 기각한 것과 이유

- 프로젝트별 브랜치 / 프로젝트-사용자 브랜치: 충돌을 없애지 않고 병합 시점으로 **미룬다**. 통합 조회·observer 를 위해 결국 병합 브랜치가 필요하고 그 주기만큼 "거의 실시간"이 깨진다. 통합자는 SPOF.
- vault 디렉토리 분할: 파일 단위 충돌에 효과 0, `project` 변경 = git mv + assets 동반 이동 + rename/modify 충돌, 경로와 필드의 이중 진실.
- 이벤트 소싱(append-only 저널)으로 저장: 문서 1개=파일 1개=진실 원칙 위반, 읽는 곳 36+ 전부가 파생 뷰로. 그 **병합 의미론**만 드라이버에 채택.
- 허브 서버(단일 원천)·GitHub Actions 통합자: 오프라인·로컬 파일 원칙 위반, 과금·지연.
- 사용자 접미 ID: 한 사람 두 머신에서 충돌 — 발번 단위는 머신이 맞다.
