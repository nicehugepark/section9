# 내 프로젝트 선택 UX 설계 — REQ-20260823-067 (designer 최종 보고 원문)

독자: 이 설계를 구현할 frontend-developer와 승인할 사용자. `web/index.html`의 헤더 필터(#f-user/#f-project/#f-tag/#f-type), #me(localStorage `s9me`), #proj-info 구조를 안다고 전제한다. 읽고 나서 할 일: 권고안 승인 후 구현 REQ로 진행.

**결론(권고안): 별도 화면을 만들지 않는다. '나' = 기존 #me를 그대로 쓰고, 필터 툴바에 "내 것만" 토글 하나를 추가한다. 토글이 켜지면 (1) 문서 필터가 내가 active 멤버인 프로젝트들로 좁혀지고, (2) #f-project 드롭다운도 그 범위로 스코핑되며, (3) #proj-info 자리에 "MY PROJECTS" 레저 스트립(내 프로젝트 행 목록: 제목·role·직무·만료)이 나타나 행 클릭 한 번으로 단일 프로젝트로 파고들 수 있다.** Board/Graph/Docs가 모두 `filtered()` 한 지점을 공유하므로 세 뷰에 동시에 적용된다.

검증 근거: 설계 전 `s9 serve`를 기동해 실브라우저 렌더(1440×900 스크린샷)로 현재 헤더 2행 구조·#me 셀렉트·보드 레이아웃을 확인했고, `/api/projects` 실페이로드(members에 user/role/position/since/until/active 존재)와 `/api/users`를 확인했다. 코드 산출물이 없으므로 신규 UI의 브라우저 검증은 구현 단계 몫이다.

## 1. 설계 질문에 대한 답

### Q1. '나'는 기존 #me인가, 별도 개념인가 → **#me 재사용**

- #me는 이미 "행동 주체"로서 localStorage(`s9me`)에 영속하고, user config(ui_skin 등) 동기화 축이며, 값이 `/api/projects`의 `members[].user`와 같은 이름 공간이다. 별도의 "뷰어" 개념을 만들면 사용자가 정체성을 두 번 선언해야 하고 두 값이 어긋나는 상태가 생긴다 — 최소 개념 원칙 위반.
- 한계 인정: #me의 현재 의미는 "기록 주체"다. 이 기능이 "보기 주체" 의미를 추가하므로, #me의 title 문구를 "작업 주체이자 '내 프로젝트' 판정 기준"으로 보강한다(문구는 ux-writer 몫이나 방향은 여기서 확정).
- me 미지정 상태는 "나 없음"이므로 토글을 비활성화한다(3절 상태 표 참조).

### Q2. #f-project와의 관계 → **직교하는 스코프 토글 + 드롭다운 스코핑**

- "내 것만"은 **필터 값이 아니라 필터의 범위(scope)**다. #f-project(어느 프로젝트?)와 직교시킨다: 토글 ON + project:all = 내 프로젝트 전체 합집합, 토글 ON + 특정 slug = 그 프로젝트 하나.
- 토글 ON이면 #f-project 옵션 목록 자체를 내 프로젝트로 좁히고 첫 옵션 라벨을 `project: mine(N)`으로 바꾼다. 현재 선택된 slug가 내 프로젝트가 아니면 선택을 해제(all로 복귀)한다 — 조용한 빈 결과보다 명시적 리셋이 낫다.
- 랜딩 화면·별도 스위처는 채택하지 않는다(2절 옵션 C 기각 사유).

### Q3. 0개·1개·다수 상태 → 3절 상태 표에 전부 명세.

### Q4. role·position·until·active 표기 → **레저 스트립 행 + #proj-info 내 행 마커**

- 스트립 행: 제목(본문체 600) + `(slug)` + role·position(mono, muted) + `~until`(임박 시 amber 글자색). **배경 배지·pill 금지 — 전부 글자색과 케이스로.**
- active=false(만료 멤버십)는 "내 프로젝트"에서 제외하되, 존재 사실은 빈 상태/스트립 꼬리 문구로 고지한다.
- 단일 프로젝트 선택 시 기존 #proj-info 멤버 테이블에서 내 행에 mono `· ME` 마커를 붙인다(행 배경색 금지).

## 2. 옵션 비교

| | A. 토글만 | **B. 토글 + MY PROJECTS 스트립 (권고)** | C. 랜딩/스위처 화면 |
|---|---|---|---|
| 개요 | .chk "내 것만" 하나. 필터 스코프만 좁힘 | A + 토글 ON일 때 내 프로젝트 레저 행 목록 표시, 행 클릭=단일 선택 | 진입 시 프로젝트 선택 화면을 먼저 거침 |
| 클릭 비용 | 1 (범위 전환) | 1 (범위) + 1 (개별 프로젝트) | 매 진입마다 +1, 전체 뷰 복귀 비용 발생 |
| Q4(role 등) 답 | 못 함 — 드롭다운 option은 스타일 불가, 텍스트 꼬리표뿐 | 스트립이 role/position/until의 자연스러운 지면 | 선택 화면에서 가능하나 이후엔 사라짐 |
| 다수 프로젝트 | 합집합 뷰는 되지만 구성이 안 보임 | 합집합 뷰 + 구성 목록 + 개별 진입 동시 제공 | 단일 선택 강제 — 합집합 뷰 상실 |
| 기존 구조 충돌 | 없음 | 없음 (#proj-info와 같은 자리, 배타 표시) | 계기판 진입 흐름 파괴, `?project=` 공유 URL·해시 라우팅과 충돌 |
| 리스크 | 기능이 숨어 발견성 낮음 | 화면 요소 +1 (단, 토글 ON일 때만) | 구현·상태 관리 대폭 증가 |

- **A 기각 사유**: 최소 비용이지만 Q4를 답하지 못하고, "내 프로젝트가 뭐가 있더라"를 확인할 지면이 없다.
- **C 기각 사유**: 이 대시보드는 전체 현황 계기판이 기본값이다. 랜딩은 매 진입에 선택을 강제하고, 뒤로가기/해시 라우팅/공유 URL 모델을 전부 재설계하게 만든다. 얻는 것(첫 화면 집중)은 B의 스트립이 화면 안에서 제공한다.
- **B 채택**: 랜딩의 장점(목록에서 고른다)을 기존 화면 문법(레저 행) 안으로 흡수. 되돌리기는 토글 해제 1클릭.

### 3.3 스타일 지침 (기존 토큰만)

- **토글**: 기존 `.chk` 문법 그대로(네이티브 checkbox + 라벨 "내 것만"). #f-project 바로 앞 배치 — 스코핑 대상과 인접. 새 컴포넌트 발명 없음.
- **스트립 `#my-projects`**: `border: 1px solid var(--border)`, 배경 `var(--panel)`, 라운드 0·그림자 0. 헤더 행 라벨 `MY PROJECTS · @SJPARK1` = `var(--mono)` 10px uppercase letter-spacing .08em `var(--muted)`. 행 구분은 `border-bottom: 1px solid var(--hairline)` — 카드가 아니라 장부 행.
- **행 내부**: 제목 본문체 13px 600 `var(--text)` / `(slug)` mono 11px `var(--faint)` / role·position mono 11px uppercase `var(--muted)` / until mono 11px. hover = 배경 틴트만(움직임·그림자 없음). 선택 행 = `inset 2px` 잉크색(`var(--text)`) 좌측 바 — 상태색 아닌 잉크이므로 "좌측 컬러 바 금지"에 저촉되지 않는 활성 위치 신호.
- **#proj-info 내 행 마커**: 이름 셀 `@nicehugepark` 뒤 mono 10px `· ME`(`var(--muted)`), 이름만 600. 행 배경색 금지.
- **접근성**: 행은 `<button>`(전폭) — Tab 순회 가능, `:focus-visible`에 `outline: 1px solid var(--text); outline-offset: -1px`. 토글은 네이티브 체크박스라 키보드·스크린리더 기본 지원. muted(#5c6470)/panel(#fff) 대비 약 5.9:1로 11px mono에 충분, faint는 보조 정보에만.
- **다크/skin**: 색은 전부 토큰 참조이므로 tone 전환 자동 대응. `soft` skin에서는 기존 override(스택 필터) 흐름에 토글이 .fgroup의 한 행으로 자연 편입 — 별도 override 불필요 예상, 구현 시 확인.

## 4. 구현 요점 (코드 없음 — 구현 REQ에서 수행)

- **API**: 신규 없음. `/api/projects`(이미 `refreshProjects()`로 catalog와 함께 폴링) + `/api/users` + catalog 재사용. mine 판정 = `projects[].members`에 `user === me && active`.
- **상태**: 전역 `mineOnly` + localStorage `s9mine`. me와 독립 저장하되 me 빈 값이면 무시. `onMeChanged()`에서 mine 집합 재계산 + `graph = null`(그래프 재빌드) + `render()`.
- **필터 결합**: `filtered()`의 project 조건 앞단에 mine 가드 한 줄 개념(`mineOnly`면 `r.project ∈ mineSlugs`). Board/Docs/Graph가 자동으로 같은 범위를 공유. `fillProjects()`가 `mineOnly` 시 옵션을 mine으로 스코핑하고 첫 옵션 라벨 교체, 현재 선택이 범위 밖이면 all로 리셋.
- **렌더**: `renderProjectInfo()` 옆에 `renderMyStrip()` 신설. 표시 규칙 — 토글 ON이면 스트립, 단일 slug 확정(선택 or mine 1개)이면 #proj-info 병행, 둘 다 board/docs/graph 탭에서만(기존 `render()`의 proj-info 조건과 동일 지점).
- **밀도·리셋**: 스트립 8행 제한 + 더 보기, 필터 변경 시 제한 리셋(기존 규칙). 토글 변경도 필터 변경으로 취급해 목록 제한·count 갱신.
- **URL**: 해시에 넣지 않는다(기존 필터들과 동일). 공유는 기존 `?project=slug` 유지 — mine은 기기 로컬 정체성이라 공유 의미가 없음을 명시적 결정으로 남긴다.
- **검증(구현 시)**: browser-verify 규약대로 `s9 shot`으로 토글 OFF/ON, 0·1·다수, me 미지정, 다크 tone, 좁은 폭(hrow2 wrap 여부) 각 상태 스크린샷 필수.

## 한계
