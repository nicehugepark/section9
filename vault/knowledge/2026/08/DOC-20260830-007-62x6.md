## Original

## 사실 (실측 2026-08-30 22:00, REQ-20260830-047)

대화형 Claude Code 세션의 프로세스에 시그널로 SIGINT 를 1회 보내면, 턴 취소('Request interrupted')가 아니라 **프로세스 종료**가 일어날 수 있다. busy(도구 실행 직후·다음 응답 대기) 상태에서 실측 재현: 트랜스크립트에 중단 마커 없이 스트림이 침묵했고, 사용자의 로컬 터미널 세션과 대시보드 터미널 뷰가 함께 끊겼다.

## 이유

CC 는 Ctrl+C 를 raw 모드 키 입력으로 받아 '한 번 더 누르면 종료' 이중 확인을 처리한다. 커널 시그널로 배달된 SIGINT 는 그 키 입력 경로를 지나지 않으므로, 안전한 발사 창을 외부에서 식별할 수 없다. '가드(busy 판정·claude pid 확인·신선도·쿨다운) 전부 통과 시 SIGINT 1회 = 안전'(REQ-20260825-008)은 거짓으로 판명.

## 규칙

- 대화형 세션에 대한 중단 지시는 수신함(kind=interrupt) 한 길로만 — Monitor 큐잉이 도구 경계마다 실어 주므로 바쁜 턴에도 닿는다.
- 프로세스 kill 이 정당한 대상은 그 요청만 실행하는 전용 headless 백그라운드 작업자(worker_stop, 스폰 마커 pid)뿐.
- 회귀 검사: tests/test_interrupt.py S4 — SIGINT 를 보내는 kill 호출이 소스에 돌아오면 실패한다.
- 2차 피해 사슬 주의: 세션이 종료되면 _session_proc_alive 가 false 가 되어, 몇 분 뒤 wake/재작업 워커가 그 세션 id 를 --resume 으로 가져간다(619e6b59 실측) — 종료된 원인 규명 없이 resume 가로채기를 해석하지 마라.
