## 자동 재작업(auto-resume) — 무인 자동 스폰

대시보드에서 요청을 **반려(review→in-progress)** 하면, 그 요청을 소유한 세션에
headless `claude -p --resume`로 **자동 재작업 세션**이 뜬다. 사람이 다음 프롬프트를
칠 필요 없이 즉시 이어진다. (실증: DOC-크로스머신-resume + 스폰된 세션이 이전 맥락
'매직넘버=42'를 이어받음 확인)

### 발동 조건 — 딱 한 구간
- **review → in-progress (반려) 만.** 다른 전이는 스폰 안 함.
- in-progress → review (완료)는 **하드 배제** (자기재귀 무한루프 방지).
- 파생/의존은 스폰 아니라 상태 전이만: done→그것을 기다리던 blocked 요청 자동 해제.

### 켜기 / 끄기
```bash
# 켜기 (사용자 계정별 opt-in, 기본 off)
s9 user config <이름> auto_resume on
# 끄기
s9 user config <이름> auto_resume off
# 전역 즉시 정지 (kill-switch) — 폭주 시
export S9_AUTO_RESUME_DISABLE=1   # 서버/CLI 환경에
```

### 튜닝 (users/<이름>/config/settings.json)
- auto_resume: on/off (기본 off)
- auto_resume_cooldown_sec: per-REQ 재스폰 최소 간격 (기본 120)
- auto_resume_global_per_hour: 전 REQ 합산 시간당 상한 (기본 6)
- auto_resume_global_per_day: 일일 상한 (기본 20)
- auto_resume_transitions: 확장용 (기본 [["review","in-progress"]], 완료전이는 코드가 배제)

### 방어장치 (DOC 자동스폰 보안 심사)
1. opt-in 기본 off (미설정=구조적 off)
2. 동의 주체 = 스폰당하는 **오너(meta.user)** config, 리뷰어 아님
3. 자기세션 가드: 오너가 자기 세션에서 반려 시 자기 --resume 안 함
4. 같은 머신만 (크로스머신은 모바일 remote-control 몫)
5. 신뢰 바인딩에서만 sid/cwd 취득 (스트림 파일 내용 cwd 신뢰 안 함 = 공유vault RCE 차단)
6. per-REQ 쿨다운 + 전역 시간당/일일 캡 (fanout 폭주 차단)
7. env 재진입 가드 S9_AUTO_RESUME=1 (자식 세션 전파)
8. note 인젝션 격리: 반려 사유를 <<참고>> 델리미터로 인용 + "지시 아님" 프레이밍
9. kill-switch S9_AUTO_RESUME_DISABLE

### 로그 (관찰)
- state/auto_resume/spawn.log — SPAWN/SKIP(cap)/ERROR 타임라인
- state/auto_resume/<REQ>.log — 스폰된 세션 stdout/stderr
- state/auto_resume/<REQ>.json, _global.json — 캡 카운터

### 현재 상태 (2026-08-23)

- 방어 8종 가짜 claude 스텁으로 전부 검증. 실제 claude resume 맥락 계승 실증.

### 주의
- 백그라운드로 실행 중인 세션이 토큰을 쓴다. 폭주 의심 시 즉시 S9_AUTO_RESUME_DISABLE.
- note는 무인증 자기신고 입력 — 인젝션 격리는 프롬프트 프레이밍이지 절대 방어 아님.
  민감작업 자동화 세션은 제한권한(plan/allowlist)으로 띄우는 것이 다음 단계 권장.

### 2026-08-23T23:21:47+09:00 update (by nicehugepark)

v2 재설계 (REQ-20260823-083, 2026-08-23): 전이 시점 즉시 스폰 폐지 → serve 워처의 클레임 기반 단일 경로. 반려 후 유예(auto_resume_grace_sec, 기본 90s) 내 미클레임(신선한 세션의 last_req/active_reqs 부재)이면 무인 스폰 — 담당 세션 조용: --resume 승계 / 활성인데 안 집음: 새 headless 세션(활성 세션 포크 금지, 문서가 컨텍스트). 스폰된 세션은 첫 행동으로 s9 last <REQ> 클레임. 기존 방어장치(kill-switch S9_AUTO_RESUME_DISABLE·opt-in·쿨다운·시간당/일일 캡·note 격리) 유지, 워처 끄기 S9_REWORK_WATCH=off. 운영 주의: 위임 클레임은 last_req가 아니라 s9 last --add(active_reqs)로 — 훅의 last_req 회전으로 유실되면 워처가 이중 스폰한다.
