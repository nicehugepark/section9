## Original

머신을 옮기면 Claude Code 설정을 잃는다. 통째로 미러해 두었다가 새 머신에서 덮으면
편하다. 그런데 그 통 안에 `permissions` 가 함께 들어 있다 — 그것 하나 때문에 통째
미러는 성립하지 않는다.

## 검사는 두 겹이다

    ① 막힌 명령을 실행하지 못한다
    ② 그 막힘을 푸는 설정 변경도 하지 못한다

검사를 검사로 만드는 것은 ②다. ①만 있으면 스스로 열고 지나가면 그만이다.

통째 미러는 **②를 우회하는 길을 새로 낸다.** 이 머신에서 vault 에 쓰는 것은 막히지
않는다 → 동기화된다 → 저 머신이 그 파일로 `settings.json` 을 덮는다. **이 머신에서
막힌 것이 저 머신에서 열린다.** 누가 그럴 의도가 없어도 구조가 그렇다. 우회는 의도가
아니라 경로의 성질이다.

## 리포가 공개라는 두 번째 이유

REQ-20260827-036 이후 이 리포는 공개다. `permissions` 가 vault 에 실려 흐르면
"어느 머신이 어떤 명령을 사람 확인 없이 실행하는가"가 공개 기록이 된다. 그건 설정이
아니라 **공격 표면 지도**다.

그래서 "미러는 하되 적용만 수동으로"는 부족하다. 적용 시점을 늦춰도 **싣는 순간**
지도는 이미 공개된다. 막아야 할 곳은 적용이 아니라 **적재**다.

## 세 층으로 가른다

    자동 복원   model · theme · remoteControlAtStartup · agentPushNotifEnabled
                env(키 허용목록에 든 것만)
                → 리포로 흐른다. 새 머신에서 무엇이 달라지는지 보여주고 덮는다.

    수동 반출   permissions
                → 리포에 싣지 않는다. 파일 하나로 뽑아 사람이 손으로 옮기고,
                  적용할 때 "이 명령들이 확인 없이 실행됩니다"를 읽고 승인한다.

    안 옮김     자격증명·토큰
                → REQ-20260827-035 자리 (users/<이름>/secrets · external_secrets_path)

## env 도 통째로는 안 된다

`env` 에는 API 키가 흔히 들어앉는다. 값을 그대로 실으면 시크릿 차단을 우회하는
셈이다. 키 이름 **허용목록**에 든 것만 옮기고, 목록의 기본값은 비어 있다 — 새로
넣는 것은 사람이 이름을 적어 넣는 행위여야 한다.

## hooks 는 옮기지 않는다

`s9-install` 이 재생성한다. 훅 경로에는 이 워크스페이스의 절대경로가 박히므로
옮기면 오히려 깨진다 — 다른 머신에서 존재하지 않는 경로를 가리키는 훅은 조용히
아무것도 하지 않고, 화면에는 아무 경고도 안 뜬다(REQ-20260827-032 에서 겪은 자리).

## 판단 기준 한 줄

설정을 옮길 때 물어야 할 것은 "복원하면 편한가"가 아니라
**"이 값이 저 머신에서 무엇을 열어 주는가"** 다.

    아무것도 열지 않는다  → 자동으로 옮긴다
    능력을 연다           → 사람이 눈으로 보고 누른다
    그 자체가 비밀이다    → 리포에 싣지 않는다
