# 외부 스케줄러 비의존 (systemd·cron 금지)

**규칙**: section9 는 systemd(user) 유닛도 cron 항목도 만들지 않는다. 주기 실행·감시가
필요하면 **자기 감시**로 푼다 — `s9 serve` 가 감시자를 분리 기동(setsid + double-fork)해
사용자 세션과 무관하게 살아남고, 감시자까지 사라지는 경우(WSL 재시작)는 이미 설치된
SessionStart 훅이 멱등하게 다시 세운다. 재기동에는 백오프를 둔다.

**근거**: 사용자가 명시적으로 배제했고("그런건 없기를 바라는데"), 이 셸에서는 systemd
user 버스 연결조차 안 된다. 무엇보다 "의존성 0"이 이 제품의 설치 계약이다 — 외부
스케줄러를 쓰는 순간 설치가 OS·배포판·권한 상태에 묶인다.

**적용 범위**: 감시·복구·주기 작업 전부. 새 주기 작업이 필요하면 serve 안의 데몬 스레드
또는 훅 경로에 붙인다. 예외를 두려면 이 문서를 먼저 개정하라.

**현행 상태** (2026-08-26 확인): 코드 전체에 crontab/systemctl 호출 0건.
`bin/s9-doctor` 의 "systemd" 문자열은 부모 프로세스 판정용이지 사용이 아니다.
