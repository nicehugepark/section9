## 결정 (REQ-20260831-013, 5인 검토 종합)

사용자 문제 제기: 선행 REQ 가 review 판정 전인데 연관 후행이 먼저 구현·판정되는 상황 — 선행 반려 시 후행 연쇄 반려 위험.

### 기각된 두 안 (5인 전원 일치)
- A안 전이 잠금: 잠글 키(판정 의존 간선)가 저장 구조에 없다 — 043↔012 는 간선 자체가 없었다(staff 실측). parent 는 우산-자식이라 자식 먼저 판정이 정상(오탐). 잠그면 끝난 작업이 in-progress 에 갇혀 스톨·워처·클레임이 오판. 판정자 1인 체제에서 잠금 비용(반나절~무기한 정체, PM 추정)이 사후 수습 실비용(오늘 수십 분)을 압도.
- B안 자동 승인: 후행 성공 ≠ 선행 정답 — 049 성공은 048 을 승인이 아니라 판정 대상 소멸로 만들었다(정확한 반례). 사람 판정만 goal/TDD 검사를 면제받는 구조(judge=True)와 충돌하고, 반려율 41.7%(8월 321건 실측, PM)에서 사람 판정 생략은 정보 손실.

### 채택 — 판정층 정렬 4규칙 (실행은 낙관 병렬 그대로)
1. 대체는 선언·즉시 철회: 후행이 선행의 판정 대상(같은 화면·산출물)을 대체하면 선행을 review 에 방치하지 않고 즉시 철회한다(REQ-20260831-014 선례 표준화). 전부 대체면 후행 확인 포인트에 "이 판정이 REQ-xxx 를 함께 닫습니다"를 명시하고 사람의 한 번 판정으로 묶어 닫는다 — 자동 승인이 아니라 판정 단위의 병합(사람은 최종 화면을 실제로 본다). 부분 대체면 확인 포인트를 개정해 재상신.
2. 낡음 배지 (경고-only): review 문서의 파생/동일 표면이 다른 REQ 에서 움직이면 카드에 "판정 대상이 바뀌는 중" 표시. 판정 큐는 review_family(읽기 파생, 연결 성분)로 선행 우선 정렬 — 저장 구조 무변경.
3. 반려 전파는 판단 과제: 선행 반려 시 후행 자동 반려 금지(TDD 초기화·작업자 예산을 다 씀·무관 사유 파괴). 재작업 작업자의 프롬프트 템플릿에 후행 목록과 "반려 사유가 후행에 닿는지 판정해 필요하면 되돌려라"를 주입 — 전파 주체는 기계가 아니라 재작업 에이전트.
4. 같은 부위 재작업은 relates --why 필수(REQ-20260827-030 재확인) — 043↔012 링크 누락이 실측 공백이었다.

### 격상 경로 (지금은 아님)
배지 도입 후에도 역순 판정 사고가 실측되면 judge 경로에 확인 대화상자(soft gate)를 얹는다. 전이 잠금은 그때도 아니다. supersedes 영속 필드(backend 안)는 note 어휘+derived_from 수확으로 흡수하고, 1단계에서 필요가 실증되면 재론.
