## Original

## 결론(권고)
도입 찬성 — 단, '완전 자유 구조'가 아니라 **최소 규약 + 자유**로.

## 문제 인식 (요청 취지)
현재 체계는 요청 문서(REQ)와 상태 관리 중심이라 '작업 기록'은 남지만 '작업 재료'를 둘 곳이 없다. 실제 프로젝트에는 스펙/계약/회의록/데이터 샘플/외부 API 문서 같은 에셋이 생기고, LLM이 프로젝트 배경을 매 세션 빠르게 파악하려면 읽을 위치가 고정돼야 한다.

## 권고 설계 (1단계)
- 디렉토리: section9/projects/<slug>/
  - CONTEXT.md — 프로젝트 배경·용어·핵심 링크의 단일 진입점. LLM 컨텍스트 주입 대상(요약 상한 적용). 이것 하나만 '필수 규약'.
  - assets/ — 외부 파일 보관(자유 구조). 인덱싱·검색 확장 대상.
  - 그 외 하위 구조는 참여자 자유(커스텀 운영 허용) — 규약은 위 2개뿐.
- CLI: s9 project add 시 스캐폴드 자동 생성, 기존 프로젝트는 s9 project scaffold <slug>.
- 검색: s9 search --body 인덱스에 CONTEXT.md 포함(1단계), assets/ 텍스트 파일은 2단계.
- 훅: 프롬프트가 특정 프로젝트로 확정되면 audit 컨텍스트에 'CONTEXT.md 경로 + 첫 N줄 요약' 주입(토큰 상한 필수 — 전체 주입 금지).

## 왜 '완전 자유'가 아닌가
'각자 커스텀 구조' ↔ 'LLM이 빠르게 찾는다'는 상충한다. 진입점(CONTEXT.md)이 없으면 LLM이 매 세션 디렉토리를 탐색해야 하고, 그 비용이 도입 취지를 상쇄한다. 규약을 2개(진입점·에셋 폴더)로 최소화하면 자유와 검색성이 양립한다.

## 위험과 대응
1. git 용량: 대형 바이너리가 vault git에 실리면 클론·동기화가 무거워짐 → assets/에 크기 지침(예: 10MB+는 링크 또는 git-lfs 결정 필요), .gitattributes 검토는 도입 시 별도 결정.
2. 접근 격리 정합: REQ-20260824-017의 가시성 규칙과 동일하게 — 에셋 열람도 프로젝트 멤버(+admin)만. 대시보드에서 서빙한다면 같은 필터 필수.
3. 기존 프로젝트 문서(vault/projects/<slug>.md)와 역할 혼동 → 명확 분리: 문서=메타·멤버·이력(시스템 관리), projects/<slug>/=재료·컨텍스트(사람·LLM 소비).
4. 컨텍스트 비대화: CONTEXT.md 무제한 주입은 매 턴 토큰 낭비 → 주입은 상한(예: 40줄)과 '자세한 건 경로 참조' 방식.

## 도입 단계
1단계: 스캐폴드 + CONTEXT.md 인덱싱 + 훅 경로 안내 (S)
2단계: 대시보드 프로젝트 패널 에셋 목록·열람(가시성 필터), assets/ 전문 검색 (M)
3단계: 세션 시작 시 활성 프로젝트 CONTEXT 자동 주입(요약 상한) (S)

### 개정 v2 (2026-08-24 재검토 — id/slug·인덱스 논점 보강)
### 디렉토리 키: slug 채택 (id 아님) — 근거
- vault의 프로젝트 문서 파일명이 이미 slug(vault/projects/<slug>.md)라 파일시스템 관례가 일치하고, 사람이 셸에서 탐색할 때 projects/webshop/이 projects/PRJ-20260823-001/보다 읽힌다.
- PRJ id는 불변 식별자로 '조회·검색'에서 병행 해석한다: load_project(ref)가 id/slug 양쪽을 이미 해석하므로, CLI·API는 어느 쪽을 받아도 같은 디렉토리에 도달하게 구현한다(s9 project assets PRJ-.. == s9 project assets webshop).
- 전제: slug는 생성 후 불변(현재 변경 기능 없음). 훗날 slug 변경을 도입하면 '문서 파일명 + 에셋 디렉토리 동시 마이그레이션'을 그 기능의 필수 절차로 명시한다.
### 프로젝트 인덱스 정합 (재검토에서 확인된 현재 결함 포함)
- 현재 결함: 카탈로그의 PRJ 행에 slug 필드가 없어 slug 검색이 프로젝트 문서 자체를 못 찾는다 → 1단계에 앞서 즉시 수정 대상(REQ-20260824-024): catalog_row에 slug 포함 + CLI/웹 검색 hay에 slug 추가.
- 에셋 검색: 디렉토리는 slug지만 검색 질의는 id/slug 모두 허용 — 질의가 PRJ id면 slug로 정규화 후 projects/<slug>/ 스코프 검색. CONTEXT.md는 s9 search --body 대상에 포함(1단계), assets/ 텍스트는 2단계.
- 그래프/대시보드: 프로젝트 문서 행이 이미 카탈로그에 있으므로 에셋 존재 여부 배지(있음/개수)만 2단계에서 추가 검토.
