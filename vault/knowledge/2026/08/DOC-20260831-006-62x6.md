## Original

증상: s9 project add 를 같은 날 두 번 하면 두 PRJ 문서가 같은 id 를 받는다 (테스트 실측: demo·cliproj 둘 다 PRJ-20260831-001-62x6).

원인: next_id 는 os.walk 로 '파일명'을 PREFIX-YYYYMMDD-NNN 패턴에 매칭해 순번을 정하는데, 프로젝트 문서는 vault/projects/<slug>.md 로 저장돼 매칭 0건 → seq 항상 0 → 항상 -001.

해법: 파일명이 id 가 아닌 문서 유형은 frontmatter 의 id 를 스캔해 발번한다 (_next_project_id — .trash 포함해 지워진 번호 재발급도 방지, next_id 와 동일 규칙). 회귀 가드: tests/test_project_api.py test_01 (같은 날 생성 프로젝트 간 id 상이 단언).

일반 교훈: 발번기를 재사용할 때는 '무엇을 스캔해 순번을 얻는가'가 저장 규약(파일명 vs frontmatter)과 일치하는지 먼저 확인하라.
