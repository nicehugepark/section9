## Original

## 규칙

section9 에서 `claude` 백그라운드 작업자를 띄우는 코드는 `bin/s9` 의 `_spawn_worker(doc_id, meta, prompt, reason, allow_resume=False)` **하나뿐**이다. 호출자는 프롬프트만 만든다.

## 왜

2026-08-26 이전에는 세 갈래였다 — `_spawn_rework`(반려 재작업), `_spawn_followup`(승인 메모 후속), 그리고 새로 필요해진 항목 재개. 세 곳이 각자 갖고 있던 것:

- 방어장치: 오너 `auto_resume` 옵트인 / 같은 머신 / 쿨다운·일일캡(`_auto_caps_ok`)
- 권한 범위: `--allowedTools Read Glob Grep Bash(s9:*)`, 적용 모드면 `--permission-mode acceptEdits` + tests allowlist
- pid 마킹(`_auto_mark_pid`) — 대시보드가 "이 워커가 아직 살아 있나"를 판정하는 유일한 근거
- 실행 중인 세션 포크 금지 규칙 (REQ-20260823-081)

이 넷 중 하나라도 한 곳에서만 고쳐지면 **다른 경로가 조용히 규칙 밖으로 나간다.** 실제로 pid 마킹은 REQ-20260825-086 에서 뒤늦게 추가되며 경로마다 따로 붙여야 했고, 새 경로가 생길 때마다 누락 검사 테스트(L12)를 유지해야 했다.

## 불변식과 그 검사

`tests/test_live_signal.py` L12:
- `wp = subprocess.Popen(argv,` 가 소스에 **정확히 1회** 등장한다 (경로가 갈라지면 실패)
- `_auto_mark_pid(doc_id, wp)` 가 정확히 1회 등장한다

"스폰 지점 수 == pid 기록 수" 였던 이전 불변식보다 강하다 — 경로가 하나면 누락될 경로가 없다.

## 새 스폰 요구가 생기면

새 Popen 을 쓰지 마라. `_spawn_worker` 에 `reason` 을 하나 더 넘기고, 프롬프트만 호출자에서 만들어라. `allow_resume=True` 는 담당 세션이 조용할 때만 `--resume` 으로 컨텍스트를 승계한다(실행 중인 세션은 절대 포크하지 않는다).

로그 토큰 `SPAWN(resume)` / `SPAWN(fresh)` 는 그대로 둔다 — 운영 중 grep 과 기존 테스트가 이 형태를 읽는다. 사유는 뒤에 `reason=<...>` 로 덧붙인다.
