# Writing Clarity

- 독자 정의 먼저: 이 글을 읽는 사람이 이미 아는 것/모르는 것/읽고 나서 할 일을 한 줄씩 적고 시작.
- 결론 먼저(BLUF). 근거와 상세는 그 뒤에.
- 한 문장 = 한 생각. 25단어를 넘으면 쪼갠다. 수동태와 이중부정을 걷어낸다.
- UI 문구: 행동을 동사로, 버튼은 결과를 말한다("확인" 대신 "삭제"). 에러 메시지는 '무엇이 왜 + 사용자가 할 일' 구조.
- 기술용어는 억지로 번역하지 않는다. 처음 등장 시 한 줄 정의를 붙인다.
- 예시가 규칙보다 강하다: 추상 규칙마다 좋은 예/나쁜 예 한 쌍을 붙인다.
- 문서는 코드와 함께 늙는다: 문서에 검증 가능한 사실(경로/명령/버전)을 쓸 때는 실제로 실행/확인 후 쓴다.
