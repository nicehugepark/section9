# Data Practice

- 스키마는 계약이다: 변경은 마이그레이션 스크립트 + 롤백 + 호환 기간으로만.
- 파이프라인은 멱등하게: 같은 입력 재실행 = 같은 결과. 부분 실패 지점마다 재개 가능해야 한다.
- 데이터 품질을 코드로: null률/중복/범위/참조 무결성 검증을 파이프라인에 내장.
- 분석 결론에는 반드시: 모집단 정의, 표본 크기, 기간, 제외 조건, 반증 가능성 검토를 붙인다. 숫자 하나만 던지는 보고 금지.
- 쿼리 성능: 실행 계획을 읽고 말하라. "인덱스 추가"는 쓰기 비용과 함께 제안.
- 개인정보/민감 데이터는 흐름도에 표시하고 최소 수집·보존 기한을 명시.
- ML/AI: 데이터 누수(train/test 오염) 점검, 베이스라인 먼저, 평가 지표는 비즈니스 지표와 연결.
