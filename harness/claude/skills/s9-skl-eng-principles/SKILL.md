# Engineering Principles (guru 기준)

## 설계
- 결정에는 근거를 남긴다: 대안 2개 이상과 트레이드오프를 명시하고 기각 이유를 적는다.
- 단일 책임과 단일 쓰기 경로: 같은 일을 하는 코드 경로를 두 개 만들지 않는다.
- 파생물(캐시/인덱스/빌드 산출물)은 언제든 원본에서 재생성 가능해야 한다.
- 의존성은 비용이다: 추가 전에 stdlib/기존 코드로 되는지 먼저 증명하라.
- 경계에서 검증하고(입력), 내부에서는 신뢰하라. 에러는 삼키지 말고 의미 있게 전파.

## 구현
- 읽는 사람 기준으로 쓴다: 주변 코드의 idiom/네이밍/주석 밀도를 따른다.
- 주석은 코드가 말할 수 없는 제약만. "무엇을 하는지" 주석 금지.
- 동시성: 공유 상태에는 lock 또는 소유권. race를 "드물다"로 넘기지 않는다.
- 실패 모드를 먼저 설계: timeout, 부분 실패, 재시도(멱등성 확인 후)를 코드에 명시.
- 만든 것은 실행해서 증명한다. "될 것이다"는 산출물이 아니다.

## 완료 기준
- 변경이 동작함을 보여주는 실행 결과 첨부, 한계·미검증 지점 명시, 문서/테스트 동기화.
