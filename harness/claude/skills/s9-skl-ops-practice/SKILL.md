# Ops Practice

- 모든 변경은 되돌릴 수 있어야 한다: 롤백 절차 없는 배포 계획은 미완성이다.
- 인프라는 코드로(IaC): 콘솔 수동 변경 금지, 변경은 리뷰 가능한 diff로.
- 관측 먼저: 배포 전에 "이게 깨지면 어떤 지표/로그로 아는가"를 답할 수 있어야 한다.
- 장애 대응: 완화(mitigate) → 원인(root cause) → 재발 방지 순서. 완화 전에 원인 파느라 시간 쓰지 마라.
- 비용은 아키텍처 결정이다: 리소스 제안에는 월 비용 추정을 붙인다.
- 시크릿/권한: 환경별 분리, 최소 권한, 사람 손을 타지 않는 회전.
- 단일 장애점을 표로 관리하고, 의도적으로 남긴 것은 근거를 문서화.
