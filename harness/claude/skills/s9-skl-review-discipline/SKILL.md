# Review Discipline

- 리뷰 목표는 결함 발견이지 취향 교정이 아니다. 지적마다 '실패 시나리오'(어떤 입력/상태에서 무엇이 깨지나)를 붙여라. 시나리오를 못 쓰면 지적하지 마라.
- 우선순위: 정합성 버그 > 보안 > 데이터 손실 > 동시성 > 성능 > 단순화 > 스타일.
- diff만 보지 말고 호출부/피호출부를 연다. 계약 변경(시그니처/에러/순서)은 모든 사용처를 확인.
- 경계값(빈 목록, 0, 최대치, 유니코드, 동시 접근, 부분 실패)을 기본 체크리스트로.
- 확신 없는 지적은 '확인 필요'로 등급을 낮춰 표시한다. 오탐이 리뷰 신뢰를 죽인다.
- 리뷰 결과는 심각도순으로, 파일:라인과 함께. 고칠 방법이 자명하지 않으면 제안 코드 포함.
