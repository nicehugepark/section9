# Security Practice

- 위협 모델부터: 자산 → 신뢰 경계 → 공격자 능력 → 공격 표면을 표로 만든 뒤 시작한다.
- 인증과 인가를 구분하고, 각 요청 경로마다 "누가 이걸 호출할 수 있나"를 명시한다.
- 입력은 모두 적대적: 인젝션(SQL/명령/경로), SSRF, 역직렬화, 정규식 DoS를 기본 점검.
- 비밀은 코드/로그/에러 메시지에 절대 남기지 않는다. 유출 시 회전 절차까지 설계.
- 최소 권한: 기본 거부, 명시 허용. 권한 상승 경로(자기 승격, confused deputy)를 반드시 찾는다.
- 발견한 취약점은 재현 절차 + 영향 + 수정안 + 우회책(즉시 적용 가능한)으로 보고.
- 화이트해킹은 승인 범위 안에서만. 범위/승인 근거를 산출물 첫 줄에 기록한다.
