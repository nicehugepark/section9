# section9 Design System — "instrument panel"

대시보드는 단일 파일(web/index.html), 외부 CDN 금지(오프라인), 의존성 0.

## 이 문서 하나가 기준이다

2026-08-25 사용자 판정으로 `ux-craft`를 여기에 흡수했다 — **둘로 나눌 이유가 없다**.
앞부분(1~8)은 어느 화면에나 통하는 완성도 기준(**Apple HIG**의 명료함·존중·깊이와
**토스류 국내 제품**의 한 화면 한 결정·군더더기 제거·실패까지 설계된 문구), 뒷부분은
이 대시보드의 구체적인 시각 언어·토큰·컴포넌트·반려 이력이다. 충돌하면 **뒤(이 제품의
결정)가 이긴다** — 사용자 반려로 확정된 금지가 일반 권장보다 우선한다.

새 규칙을 적을 자리: 특정 값(색·px·셀렉터)·이 대시보드 컴포넌트·반려로 확정된 금지는
"디자인 언어" 이후 절에, 다른 화면에도 그대로 참인 판단 기준은 1~8절에 적는다.

## 완성도 기준 (모든 화면 공통)

## 1. 한 화면 한 결정

- 화면마다 **사용자가 내려야 할 결정 하나**를 정하고, 그 결정을 돕지 않는 요소는 뺀다.
- 선택지가 3개를 넘으면 기본값을 정해 제시하고 나머지는 접는다. "고르게 하지 말고
  정해주고 바꿀 수 있게 한다."
- 설명이 필요하면 화면을 고칠 신호다. 툴팁·안내문으로 구조 문제를 덮지 않는다.

## 2. 위계는 크기·간격·굵기로, 색은 신호로만

- 정보 위계는 타이포 스케일과 여백으로 만든다. 색은 상태·경고·강조 **신호**일 때만.
- 강조가 셋 이상이면 강조가 없는 것과 같다. 한 화면의 주 강조는 하나.
- 간격은 리듬이다: 4/8 배수 같은 고정 스케일을 쓰고 임의 값(13px, 17px)을 섞지 않는다.
- 간격은 상자가 아니라 **잉크 사이**로 잰다 (REQ-20260830-043). 눈이 재는 것은
  보이는 흰 자리다 — 글리프가 제 상자 안에 여백(과녁 27px 안의 그림 11px)을 가지면
  상자를 붙여도 틈이 뜬다. 그만큼 되돌려 한 줄의 다른 틈과 같은 눈금에 맞추되,
  이 당김은 **모든 얼굴에서** 검산한다(아래 3절 — hover 원의 왼끝은 잉크가 아니라
  원 가장자리가 기준이라, 쉼만 보고 당기면 hover 가 이웃 글자를 파고든다).

## 3. 상태를 전부 디자인한다

빈 상태 · 로딩 · 부분 로딩 · 에러 · 권한 없음 · 오프라인 · 극단(0개/1개/1만 개).
- **부품의 얼굴도 전부다** (REQ-20260830-043 2차 반려의 교훈): 쉼 · hover · 포커스 ·
  눌림 · busy · disabled — 컨트롤 하나에도 얼굴이 여섯이다. 정적 캡처에는 쉼만
  나오므로 **그린 적 없는 얼굴은 검증되지 않은 얼굴**이다. hover 가 반전·확대·칠로
  나타나는 컨트롤은 그 얼굴이 이웃(글자·줄 위 요소)을 침범하지 않는지까지가 설계다.
  배경을 통째로 반전하는 스킨 위에서는 currentColor 피드백이 배경과 같은 색으로
  사라질 수 있다 — 반전 맥락마다 검산한다.
- **빈 상태**는 안내가 아니라 다음 행동을 주는 자리다(버튼 하나 + 한 줄).
- **로딩**은 진행을 보여준다. 정적 문구는 멈춘 것처럼 읽힌다 — 경과·단계·스켈레톤 중
  하나는 반드시.
- **에러**는 무엇이 왜 실패했고 지금 무엇을 하면 되는지 한 문장씩.

## 4. 인터랙션 비용을 센다

- 목표까지의 **탭 수·시선 이동·되돌리기 가능성**을 세어 대안과 비교한다.
- 파괴적 행동은 확인 대신 **되돌리기**를 준다(삭제 후 "실행 취소" 5초). 확인 창은
  되돌릴 수 없을 때만.
- 입력은 최소로: 자동 채움, 붙여넣기 허용, 형식 강요 금지(전화번호 하이픈 등은 받아서
  정규화한다).

## 5. 움직임은 인과를 설명할 때만

- 애니메이션은 **어디서 와서 어디로 갔는지**를 설명하는 용도. 장식적 모션 금지.
- 지속시간 120~240ms, 감속(ease-out) 기본. 반복 애니메이션은 대기 상태에서만.
- `prefers-reduced-motion`을 반드시 존중한다.
- 레이아웃이 흔들리는 모션은 결함이다(폭 고정·자리 예약).

## 6. 문구 (ux-writer 필수)

- **사용자 언어로**: 시스템 용어(트랜스크립트·인덱스·디스패치)를 그대로 쓰지 않는다.
- 버튼은 **동사+목적**("변경 사항 저장"), 모호한 확인/취소 단독 사용 금지.
- 에러는 비난하지 않는다: "잘못 입력했습니다" → "이메일 형식이 아니에요. 예: a@b.com".
- 숫자·단위·시간은 사람 기준으로("2분 전", "1.2MB", "약 30초 남음").
- 모순 표현 금지("필수 권장"), 겹말 금지, 과장 금지.
- **남의 도구 이름은 번역하지 않는다** (REQ-20260902-002 사용자 지적): pull·push·
  commit·worktree·rebase 처럼 사용자가 GitHub·터미널·다른 도구에서 **같은 글자로
  다시 만나는** 고유 기능 이름은 버튼 낱말이어도 원어로 선다. 「받기」·「올리기」·
  「따로 떼어 놓고 일하기」는 반려된 옮김이다 — 화면에서 배운 말이 밖에서 안 통하면
  사람은 두 개의 사전을 들고 다녀야 한다. 이 제품이 **스스로 지은** 상태어
  (done·in-progress)와 남의 도구 이름을 같은 자로 재지 마라.
- **조어 금지 — 새 낱말을 짓지 말고 있는 말을 쓴다** (REQ-20260830-039 「맡은 손」 반려).
  시금석 넷: ① 실재하는 사물을 가리키는가(「창」= 실제 터미널 창 — 통과) ② 국어에
  이미 있는 연어인가(「일손」·「손길」— 사전에 있다, 통과) ③ 그 자리에서 지은
  합성어인가(「맡은 손」— 억지) ④ 묶는 이름(상위어·역할명)을 은유로 지었는가(억지).
  한 줄 규칙: **은유는 낱개의 구체물을 부를 때만, 묶는 이름은 일상 직무어로**
  (담당·진행 같은 확립 업계어 — Jira·Notion·두레이 등 10개 서비스 교차 확인 완료).
  확립 업계어를 순우리말로 되돌려 옮기는 것도 기계 직역과 같은 결함이다(Jira
  「할당 해제됨」이 거부당한 그 패턴). 같은 개념에 두 번째 이름을 만들지 않는다 —
  화면의 기존 용어 사전이 우선한다.

## 7. 접근성은 기본 사양

- 대비: 본문 4.5:1, 큰 텍스트 3:1 이상. 색만으로 상태를 구분하지 않는다(모양·문구 병행).
- 키보드만으로 전 경로 도달 가능 + 포커스 링 가시. 터치 타깃 최소 44×44.
- 이미지·아이콘 버튼에 이름(alt/aria-label). 동적 영역은 상태 변화를 알린다.
- **칠은 과녁이 아니다** (REQ-20260830-043 2차로 확정): 손이 닿는 상자(과녁)와
  시각 피드백(칠·링)은 다른 층이다. 과녁은 절대 줄이지 않되, 칠은 상자 안에
  더 작게 가둘 수 있다(`background-clip:content-box` 류). 시각을 맞추려고 과녁을
  깎는 것도, 과녁 크기대로 칠해 이웃 글자를 덮는 것도 결함이다. 포커스 링도
  칠과 같은 층이다 — 상자 밖으로 번지면 음수 offset 으로 칠 둘레에 두른다.

## 8. 검증 없이는 완료가 아니다

- 화면 작업은 **실제 브라우저로 확인**한다(`browser-verify` 스킬 · `s9 shot`).
- 상태별 스크린샷(빈/로딩/에러/극단)을 남기고, 흔들림·잘림·대비를 눈으로 확인한다.
- 이 저장소의 대시보드를 만질 때는 **`s9-design`의 디자인 언어가 우선**한다 — 이
  스킬은 그 위의 완성도 기준이지, 시각 언어를 덮어쓰지 않는다.

## 디자인 언어 (2026-08-23 사용자 지시로 확정)

**전형적인 AI-생성 대시보드 문법을 금지한다**: 둥근 카드, 좌측 컬러 바,
파스텔 배경 pill 배지, 인디고/퍼플 액센트, 부유하는 그림자, 세그먼트 pill 탭 — 전부 금지.

대신 계기판/장부(ledger) 스타일:
- **라운드 0, 그림자 0.** 구획은 오직 1px 보더(굵은 `--border`, 얇은 `--hairline`)로.
- **면이 아니라 선으로 나눈다**: Board 컬럼은 회색 웰 대신 hairline 세로 구분,
  카드는 박스가 아니라 리스트 행(border-bottom), hover는 배경 틴트만(움직임 없음).
- **타이포가 곧 UI**: 메타데이터(id/시각/카운트/라벨)는 전부 `var(--mono)` 10~11px
  uppercase + letter-spacing. 제목은 본문체 600. 색보다 크기/굵기/케이스로 위계.
- **색은 기능 신호만**: 상태/타입 색은 7px 사각 점(.cdot)과 글자색으로만 쓴다.
  배경색 배지 금지. 장식적 액센트 색 없음 — 인터랙션 강조는 `--text`(잉크색)
  언더라인/inset 바.
- 탭 = 텍스트 + 활성 밑줄 2px. 사용자 표시 = `@이름` (mono, ::before로 @).
- 헤더는 2행 고정 구조: 1행 브랜드+탭 / 2행 툴바(.hrow2 — .fgroup 필터 좌,
  .pgroup 환경설정 우, .pdiv 구분선). 컨트롤을 1행에 우겨넣어 wrap시키지 말 것.
- "더 보기" = `+ N개 더 보기` 텍스트 버튼(mono, 밑줄 hover).

## 토큰

- 라이트: bg #fafaf8(종이톤) / panel #fff / border #d8d8d3 / hairline #e9e9e5 /
  text #141518 / muted #5c6470 / faint #9096a0. accent = text (잉크).
- 다크(prefers-color-scheme): bg #111214 / panel #17181b / border #33353a /
  text #e8e8e4. 상태색은 다크에서 밝기 보정본 재정의.
- 상태색: open #1d4ed8 / in-progress #b45309 / blocked #b91c1c / review #6d28d9 /
  done #047857 / cancelled·draft #868c96 / published #0f766e.
  타입색: request #1d4ed8 / knowledge #0f766e / session #92400e. (JS 하드코딩
  상수 TCOLOR_RAW·KC도 이 값과 동기화할 것)
- 컴포넌트는 토큰만 참조 — 다크 대응은 토큰 블록에서만.

## 터미널 뷰 (.term)

테마 무관 항상 다크 #101418. 역할색: user 노랑 #fbbf24 / assistant #e2e8f0 /
tool #a5b4fc / result #94a3b8 / thinking #64748b. agent 이벤트 = opacity .7 +
좌측 1px 보더. REQ 문서 내 스트림 섹션도 동일 컴포넌트 재사용.

## 디스플레이 설정 (헤더 ⚙ 패널)

skin/tone/density 컨트롤은 헤더 툴바에 늘어놓지 않는다 — me + ⚙ 버튼만 두고,
⚙ 클릭 시 Settings 패널(#settings)에서 조정한다(esc/바깥클릭 닫힘).
저장 우선순위: **me(등록 사용자)의 user config(ui_skin/ui_tone/ui_density)
> localStorage > 기본**. me가 있으면 변경 시 `/api/user/config`로 저장되어
기기 간 동기화된다. me 변경 시 그 사용자 설정을 즉시 적용(onMeChanged).

## 테마 = 2축: skin(디자인 언어) × tone(색)

- **tone** (data-theme): system(OS 추종, 기본)/paper/carbon/phosphor — 토큰 세트 교체.
  새 tone = 토큰 블록 하나. 컴포넌트 CSS는 절대 색을 직접 쓰지 않는다.
  localStorage `s9theme`. 다크 판정은 isDarkTheme(). 그래프 캔버스 배경은
  getComputedStyle의 --bg.
- **skin** (data-skin): 형태·밀도·컴포넌트 문법 자체의 전환. localStorage `s9skin`.
  - **최상위 원칙 (2026-08-23 2차 반려로 확정): skin = 시스템 정체성(계기판·장부·
    프로페셔널 도구) 안의 재질/분위기/셸 변주. 장르 코스튬 금지.** 다른 물건
    (신문·네온사인·도면 등)의 겉모습을 입히는 스킨은 "시스템과 어울리지 않는다"로
    반려된다 — newspaper/neon/blueprint 3종이 이 사유로 제거됨(같은 날 추가분).
    통과 기준은 glass처럼 "같은 도구를 다른 재질로 만든 것"인가이다. 동시에
    "비슷한 변형 금지"도 유효 — 재질/분위기/셸 중 최소 한 축이 뚜렷이 달라야 한다.
  - **썸네일 테스트 (2026-08-23 3차 반려로 추가 확정): 구분감은 썸네일 수준에서
    즉시 보여야 한다.** 같은 데이터의 Board 스크린샷을 ~300px 폭으로 축소해 나란히
    놓았을 때 서로(그리고 기존 스킨들과) 즉시 구분되지 않으면 탈락. 미묘한
    헤어라인·질감·단차 변주는 실패 — instrument(머신드 계기판)/archive(장부
    아카이브) 2종이 "죄다 똑같은 디자인" 사유로 제거됨(같은 날 추가분).
    새 스킨은 [배경 분위기 / 모양 언어(라운드·보더) / 깊이(그림자·블러·부조) /
    셸 구조 / 타이포 스케일] 중 **최소 2~3축을 과감하게** 바꿔야 한다.
  - `ledger` (기본): 이 문서의 "디자인 언어" 섹션 규칙 그대로 (상단 탭 셸).
  - `soft`: **좌측 고정 사이드바 앱 셸**(세로 탭, 스택 필터) + 라운드 카드/그림자/pill.

### 화면에 보이는 이름과 설명 (REQ-20260907-032 으로 확정 · 원천 = `web/app/format.js` UI_DIMS)

**값은 불변, 이름과 설명만 고친다.** 값(`ledger`·`paper`·`compact` …)은 사람이
`s9 user config ui_skin ledger` 로 **직접 치는 글자**라 화면의 용어와 같아야 한다
(REQ-20260907-012 판정). 고칠 수 있는 것은 뒤의 한글 이름과 한 줄 설명뿐이다.

**쓰는 법 셋.** ① 설명은 **「고르면 무엇이 보이나」**만 적는다 — 설계 의도·구현 방식이
아니라 눈에 들어오는 것(바탕색·모양·떠 있나·글꼴). ② **업계 은어·영어 약자·값 이름의
음차 금지** — SaaS·뉴트럴·웜 그레이·인버스·앱 셸·플랫 패널·레이어·블러·CRT, 그리고
「슬레이트」·「카본」·「그래파이트」·「코르크」처럼 값을 그대로 음차한 이름은 고르는 데
아무 정보도 보태지 않는다(2026-09-07 주인 지적: 「SaaS 블루라는 게 도대체 무슨 뜻이지」).
③ **한 줄에서 서로 갈려야 한다** — 두 스킨을 같은 문장으로 가리킬 수 있으면 실패다.
갈리기 어려운 세 묶음이 시금석이다: 선·표·고정폭(ledger/grid/terminal) · 떠 있는
카드(calm/soft/cork) · 색 바탕(slate/field/cobalt). tone 은 **밝다/어둡다 + 바탕의
색기 + 강조색** 셋을 반드시 말한다. 길이는 **48칸**(한글 2칸·라틴 1칸)까지 — 넘으면 닫힌 선택 상자에서 설명이 잘린다.

| 축 | 값 | 이름 | 설명 |
|---|---|---|---|

## 카드 사실 줄 (REQ-20260830-040 반려로 확정)

카드 위 글자 줄은 **「정상이 아니다」 또는 「당신이 할 일이 있다」를 말할 때만**
선다: 중단 · 멈춤(+고친 것 있음) · 선행 대기 · 오래 걸림(서버 STALLED_WIN 이상).
정상 진행의 서술(진행 중·맡은 창·손길 따위)은 줄 자격이 없다 — 컬럼 이름과
점(livedot)이 이미 한 말이다. 지금 무엇이 붙어 있는가는 점이, 신원·경과·잡
이름은 툴팁이 말한다. 축마다 한 줄, 카드 최대 두 줄(관계 축 + 진행 축; 진행 축
사다리: 중단 > 멈춤 > 오래 걸림). 잡 조각은 이긴 줄의 꼬리(`· 테스트 4분째`),
이긴 줄이 없으면 툴팁. ▶/⏸ 글리프는 사실 줄이 아니라 푸터 id 줄에 산다.
줄이 버튼을 정당화하러 생기면 거꾸로 된 것이다.
▶/⏸ 는 **상태 배타**다(REQ-20260830-042 반려로 확정): 붙어 있으면(⏸ 중단하기)
하나, 안 붙어 있으면(▶ 이어가기) 하나 — 재생기 글리프는 "한 축의 두 방향,
하나만 참"을 그림으로 약속하므로 둘이 나란히 서는 순간 모순으로 읽힌다.
행위(지금 도는 것을 끊는 「중단하기」)와 정책(앞으로 못 맡게 하는 「중단해
두기」)은 같은 글리프를 쓰지 않는다 — 정책은 문서 화면의 낱말 버튼으로.

## 점(livedot)의 일곱 얼굴 (REQ-20260831-005/012/016 로 확정 · 025 로 앰버 폐지)

어휘는 두 축이다 — **모양 = 무엇이 붙어 있나 · 채움 = 문서에 기록이 나가나.**
원(도는 것)과 사각(멎은 것)이 모양을, 채움·링·줄이 채움의 정도를 말한다.
새 상태가 필요하면 이 두 축 안에서 조합하라 — 축 밖의 새 색·새 모양 금지.

| 상태 | 마크 | 잉크 | 움직임 |
|---|---|---|---|
| 직접 작업 중 (기록도 나감) | ● 채운 원 | `--dot-live` 초록 | 맥박 1.6s |
| 일하는 중 · 기록은 아직 | ◎ 링+심 | 초록 (새 색 금지 — 초록의 한 얼굴) | 맥박 2.6s |
| 살아는 있으나 아직 안 맡음 (만든 창만 살아 있음 · 무인 작업이 막 떴음) | ○ 속 빈 링 | 초록 | 없음 |
| 멈춤 | ▫ 속 빈 사각 | `--c-inprogress` | 없음 |
| 맡았던 작업이 죽음 | ▪ 채운 사각 | `--c-blocked` | 없음 |
| 사람이 중단해 둠 | ⊟ 줄 그은 사각 | `--muted` | 없음 |
| 모름 | ○ 작은 링 (scale .78) | `--muted` | 없음 |

**배율 불변** (REQ-20260831-019/022): 화면은 Windows 배율 125/150%·레티나 200%·
브라우저 줌 어디서나 **같은 모양**이어야 한다 — "배율마다 달라 보인다"는 감수할
일이 아니라 설계 결함이다. 정밀 기하(마크·글리프·테두리·대칭)는 비정수 배율에서
반올림이 갈릴 자리를 만들지 마라: 홀수 px 치수·소수 px 테두리·반화소 좌표가
용의자다. 검증은 1·1.25·1.5 세 배율 캡처를 눈으로 — browser-verify 「배율은
정수만이 아니다」 절이 방법이다.

**좌표는 3층이다** (`web/css/actions.css`): ① 무대(`.livedot` 7px 상자·중심·
정렬 — 어느 얼굴도 못 건드린다) ② 맥박(`::after` 동심 1px 링, `top/left:50%`
+`translate` — `margin:auto` 는 상자가 부모보다 커지는 순간 가운데를 포기한다,
box-shadow 맥박 금지: 속 빈 마크에서 색면으로 배어 나온다) ③ 마크(잉크
`color` + 채움). 얼굴 규칙이 상자·자리·정렬을 만지는 순간 종류별 좌표가 갈린다.
글리프 SVG 는 **viewBox 한 칸 = 한 화소**(`.gly` 11px ↔ `viewBox 0 0 11 11`),
좌표는 정수 — 어긋나면 획이 반 화소에 걸려 번진다. 함정 상세는
DOC-20260831-003, 회귀는 `tests/test_wake_handle.py` TheMarkSharesOneStage 3건,
검증 자는 `web/verify-livedot.html`(일곱 얼굴이 실선 두 줄을 반씩 물어야 한다 — 기동 중과 만든 창은 한 얼굴(○)을 쓰고 툴팁 문장이 가른다).
툴팁 문장은 「누가 / 언제까지 움직였나 / 문서는 어떤가」 한 틀 — 기계어(세션·
프로세스·신호) 금지, ◎ 는 서버 `stall_why` 를 그대로 쓴다(문장 두 벌 금지).

## 표(테이블) — 열·정렬·밀도의 규율 (REQ-20260907-026 으로 신설)

목록이 두 열을 넘으면 카드가 아니라 표다. 표에서 눈이 하는 일은 **행을 따라가고 열을
비교하는 것**이라, 카드의 규칙(위계·간격)만으로는 판단이 서지 않았다 — 이 절이 그
빈 곳이다(REQ-20260907-012 검수 ③-6).

1. **열 머리는 mono·uppercase 규칙의 예외다.** 「메타데이터는 전부 mono 10~11px
   uppercase」(디자인 언어 절)는 ASCII 라벨을 전제로 적은 규칙이다. 열 머리에는 한글
   라벨(시각·남긴 사람)이 서는데, mono 를 주면 한글이 대체 글꼴로 떨어져 라틴 라벨과
   글자 폭·높이가 어긋나고(같은 표에 얼굴이 두 벌이 된다), uppercase 는 한글에 아무
   일도 하지 않으며 `letter-spacing:.1em` 은 음절 사이를 벌려 낱글자로 흩어 놓는다.
   **확정값**: 본문체 · 11px · 600 · `letter-spacing:.02em` ·
   `color:var(--muted)` · `text-transform:capitalize`(라틴은 첫 글자만 크게, 한글은
   그대로 — 라벨 글자를 고치지 않고 두 문자를 한 얼굴로 세운다) · 아래 경계는
   `--border` 1px. `--faint` 는 열 머리에 쓰지 않는다(읽어야 하는 글자다).
2. **정렬은 값의 성격이 정한다.** 비교할 수(개수·크기·금액)는 **오른쪽**이고
   `font-variant-numeric:tabular-nums` 로 자릿수를 세로로 맞춘다. 글·라벨·id·경로는
   **왼쪽**. 날짜·시각은 크기를 비교하지 않는 순서 값이라 왼쪽이되 mono 로 자리를
   맞춘다. 머리의 정렬은 그 열 값의 정렬과 같다 — 값이 오른쪽인데 머리가 왼쪽이면
   한 열이 둘로 보인다. 가운데 정렬은 쓰지 않는다(양끝이 어긋나 열이 서지 않는다).
3. **열 순서: 폭이 고정된 열이 앞, 폭이 변하는 본문 열이 마지막.** 시각·종류·사람·
   출처처럼 길이가 정해진 열을 왼쪽에 모으고, 길이가 제각각인 본문(사건 내용·제목)을
   마지막에 둔다. 본문 열을 가운데 두면 그 열이 남는 폭을 다 가져가, 짧은 값이 든 행에
   빈 자리가 수백 px 생기고 눈이 행의 오른쪽 끝을 잃는다(2026-09-07 Audit 실측).
4. **밀도는 두 단계뿐이다.** 보통 = 셀 여백 `8px 14px`(행 34px 안팎), 촘촘
   (`data-density="compact"`) = `4px 10px`(행 25px 안팎). 세로 여백은 4의 배수만
   쓴다 — 홀수 px 은 비정수 배율에서 위와 아래가 다르게 반올림된다(「배율 불변」 절).
   행 높이는 고정하지 말고 여백으로 정한다(두 줄로 접히는 셀이 잘리지 않게).
5. **줄무늬와 헤어라인 중 하나만.** 기본은 헤어라인(`--hairline` 1px 아래 경계)이고
   줄무늬는 없다. 줄무늬(지브라)를 쓰는 스킨은 그 스킨에서 헤어라인을 0 으로 내린다 —
   둘이 겹치면 한 행이 두 겹 상자로 읽힌다. 세로 구분선은 쓰지 않는다(열은 정렬이
   가른다). hover 는 배경 틴트 한 겹, 움직임 없음.
6. **폭이 모자라면 접지 말고 가로로 스크롤한다.** 열이 셋 이상인 표는
   `overflow-x:auto` 상자에 담고 표에 `min-width` 를 준다 — 셀이 눌려 한글이 음절마다
   끊기는 것보다 가로 스크롤이 낫다(REQ-20260906-092). **예외는 라벨-값 두 열짜리
   정의 표**다(`.metatbl`): 그것은 표가 아니라 목록이라, 좁은 폭에서 라벨을 값 위로
   쌓는다(`tr{display:block}`). 가르는 물음 한 줄: **열끼리 비교하는가**(비교하면 표 —
   가로로 스크롤) **한 값을 읽기만 하는가**(읽기만 하면 목록 — 위아래로 쌓는다).
   열 머리를 고정하려면 그 상자가 세로 스크롤까지 맡아야 한다 — `overflow-x:auto` 는
   세로도 함께 스크롤 상자로 만들어, 그 안의 `position:sticky` 는 페이지 스크롤에
   반응하지 않는다. 페이지가 세로를 맡는 표는 머리 고정을 포기하고 행 상한 + 「더
   보기」로 한 화면 안에 둔다(아래 밀도 절).
7. **표 안의 손잡이는 글자 손잡이다.** 셀 안에서는 doclink(점선 밑줄)와 글자 버튼만
   쓴다 — 색면 버튼이나 아이콘 버튼 줄을 셀에 넣지 않는다(행마다 반복되면 표가 도구
   막대의 더미가 된다). 행 전체를 누르게 만들지 않는다(hover 틴트는 읽기 보조지 과녁이
   아니다). 한 행에 손잡이가 둘 이상 필요하면 그것은 표가 아니라 목록 행(카드)으로
   만들 자리다.
8. **연속한 같은 값은 첫 행에만 적는다.** 한 열에 같은 값이 이어지면 둘째 행부터 눈에서
   뺀다(장부의 관행) — 열 머리는 그대로 서 있어 그 열이 무엇인지는 남는다. **값은
   지우지 말고 가린다**: 1px 상자 + `clip-path:inset(50%)` 로 접어 화면낭독기와 복사가
   값을 그대로 갖게 한다(`display:none`·`visibility:hidden` 은 값을 잃는다). 필터가 그
   열의 값을 하나로 묶어 버린 경우라면 열째 접는 것도 답이지만, 그때는 그 값을 표 밖
   한 곳에 한 번 적어야 한다.

**표 위의 안내문은 상주하지 않는다.** 표를 설명해야 한다면 화면을 고칠 신호다(1절).
그래도 남겨야 하는 배경 설명은 `<details>` 로 접어 기본을 닫아 둔다 — 판을 열 때마다
보이는 문장은 두 번째부터 읽히지 않고 자리만 차지한다.

이 절이 재는 대상은 Audit 표(`.audit`)와 문서 뷰어의 메타 표(`.metatbl`)다.

## 전 스킨 검수에서 세운 규칙 (REQ-20260907-011, 2026-09-07)

designer·ux-writer·tech-writer 셋이 8탭 × 9스킨을 검수해 낸 규칙이다. 파생 요청
021~026·017·018·019 가 이 규칙으로 고쳐졌고, 이후의 화면 작업은 이것을 잣대로 본다.

### 구조·시각 (designer)
1. **스킨은 재질을 바꾸고 어휘와 자리는 바꾸지 않는다** — 같은 뜻의 원소(사람 이름·
   경과·더 보기)는 전 스킨에서 같은 부품·같은 자리로 서고, 스킨은 색·면·깊이·모서리만
   달리한다. (soft 의 색면 배지가 이 규칙으로 걷혔다, REQ-023)
2. **한 줄에 성격이 다른 둘을 섞지 않는다** — 세는 것과 누르는 것을 한 wrap 줄에 두면
   접힘이 뜻을 갈라 놓는다. 섞어야 하면 묶음으로 싸고, 접히면 묶음째 제 줄을 갖게
   한다. `margin-left:auto` 는 접히지 않는 줄에만 쓴다. (타입 띠 REQ-013 · 프로젝트 레일
   머리 REQ-024)
3. **한글은 낱말이 끊기지 않게 접는다** — 사람이 읽는 제목·라벨은 `word-break:keep-all`
   이 기본이고 기계 문자열(id·경로)만 예외다. (REQ-021)
4. **칩은 한 종류** — 한 카드·한 줄에 테두리 칩과 맨 글자와 태그가 함께 서면 셋이 다른
   뜻으로 읽힌다. 테두리는 세는 것에만. 카드 메타는 「누구·어디 / 무엇」 두 줄이고 같은
   사실은 카드마다 같은 줄에 선다 — 「한 줄」이 아니라 「제 줄」이 규율이다. (REQ-022)
5. **`--faint` 는 글자에 쓰지 않는다** — 읽어야 하는 보조 글자는 `--muted`, `--faint` 는
   선·자리 표시에만.

### 문구 (ux-writer)
R1. 화면의 모든 문장은 「…습니다」 한 층이다. 툴팁도 문장이면 존댓말이다 — 「…한다」는
    코드 주석의 어휘이지 화면의 어휘가 아니다. (REQ-017)
R2. 확인 창의 실행 버튼은 「…하기」로 결과를 말한다(지우기·보내기·바꾸기). 명사형
    (「영구 삭제」)과 조사 종결(「휴지통으로」)은 반려한다.
R3. 부사·조사만으로 된 버튼을 두지 않는다 — 「다시」·「전부」는 목적어를 데리고 선다
    (「다시 받기」·「이 목록 전부 고르기」). 파괴적으로 읽히는 버튼은 도착지를 말한다
    (「삭제」→「휴지통으로」, REQ-019).
R4. 크기·개수·시간은 사람이 한 번에 세는 단위로: 1MB 이상은 MB, 글자 수는 「자」,
    1분 미만은 「방금」. 라틴 축약(8m 36s)은 모노 칩에만. (REQ-018)
R5. 파일 경로·glob·내부 식별자는 화면 문장에 쓰지 않는다. 필요하면 툴팁으로 내리고
    문장에는 그것이 무엇인지를 쓴다.
R6. 툴팁은 한 문장이다. 두 문장이 필요하면 그것은 빈 상태·안내 줄이 할 말이다. 빈
    상태는 두 줄 — 무엇이 없는가 / 무엇을 하면 되는가 또는 왜 비었는가 — 이고 없는
    행동을 버튼으로 지어내지 않는다. (REQ-019)
R7. 부호는 한 벌 — 늘고 줄어드는 짝은 `+` 와 `−`(U+2212), 닫기·해제는 `×`, 전각 `＋` 는
    쓰지 않는다(두 칸이라 mono 버튼의 왼끝이 어긋난다). (REQ-017)

### 용어 (tech-writer) — 규약 2조 ⑤ 와 용어표 DOC-20260906-002 를 본다
문서 키·CLI 옵션 이름은 화면에서도 그 글자 그대로, 그 밖의 표시어는 우리 말로.

## Claude Design 연동 (REQ-20260913-015, 주인 지시 2026-09-13)

주인의 말: 「클로드 디자인의 경우에도 자동으로 연동이 되게 해서 문서와 아티팩트 생성도
할 수 있도록 해야한다」. 길은 둘이고, 어디까지 자동인지는 정직하게 가른다 — 캔버스·첨부·
미리보기는 에이전트가, claude.ai/design 으로 올리는 것은 사람 승인이 있는 리드가.

- **화면·흐름 설계는 `design` 스킬로 Claude Design 캔버스를 짓는다.** designer 가 기본이고
  frontend-developer·ux-writer 도 같은 길이다. Skill 도구로 `design` 을 로드하면 절차가
  보인다 — 아트보드(`*.dc.html`)마다 화면 하나, 대안은 아트보드를 나란히, `canvas.json` 이
  배치, Artifact 로 낸다. 짓기 전에 이 문서의 토큰·부품 값을 그대로 옮긴다(`design` 스킬
  0단계: 기존 앱을 화소 단위로 맞춘다 — 4/8px 격자로 반올림하지 않는다).
- **내보낸 그림(PNG/PDF)·문서는 요청에 첨부한다**: `s9 note <REQ> '무엇을 찍은 그림인지
  한 줄' --attach <파일>`. 캔버스 링크는 그 노트 본문에 적는다. png 에는 글자가 없어 나중에
  찾을 실마리는 그 한 줄뿐이다(규약 4조). `projects/<slug>/assets/` 에 직접 두지 않는다.
- **디자인 시스템(토큰·부품)이 바뀌면 미리보기를 다시 만든다**: `bin/s9-design-export` 가
  `web/css/tokens.css` 와 부품 규칙(web/css 의 실제 선택자)에서 `harness/claude/design-system/`
