## Original

section9 은 문서에 「누가」를 적습니다 — 요청을 세운 사람, 승인한 사람, 반려한 사람. 그래서 이 컴퓨터의 계정이 section9 의 이름 하나에 이어져 있어야 합니다. 첫 실행이 「◌ 이 컴퓨터의 계정(…)은 section9 에 등록돼 있지 않다. 이름(Enter=…):」 하고 물었을 때 답했다면 이미 끝난 일입니다. 여기서는 그것을 확인하고, 안 됐으면 등록하고, 첫 사람에게 필요한 admin 역할까지 올립니다.

### 확인 — 우상단 한 줄

대시보드 우상단에 **이름 @ 컴퓨터 [역할]** 이 보이면 등록된 것입니다. 대신 「⚠ 미등록 계정 <계정> @ <컴퓨터> — 터미널에서 s9 user add <계정> 로 등록하세요」가 보이면 아직입니다 — 아래로 갑니다.

### 등록 — 세 경우

명령은 풀어 놓은 디렉토리(예: `~/section9`) 안에서 실행합니다. Windows 는 `bin/s9` 자리에 `bin\s9` 를 씁니다.

| 경우 | 명령 | 결과 |
| --- | --- | --- |
| 이 저장소를 처음 쓰는 사람 | `bin/s9 user add <이름>` | 출력 `user registered: <이름>  (users/<이름>/)` — 새 이름으로 등록됩니다 |
| 저장소에 이미 있는 이름(두 번째 컴퓨터 · 팀 합류) | `bin/s9 user attach <이름>` | 새로 만들지 않고 이 컴퓨터를 그 이름에 잇습니다 |
| 첫 실행의 물음에 Enter 로 답했음 | 할 일 없음 | OS 계정 이름으로 이미 등록돼 있습니다 |

이름은 문서에 그대로 남는 표기입니다 — 팀에서 부르는 이름으로 정하십시오. 같은 사람이 두 이름으로 등록되지 않게, 두 번째 컴퓨터에서는 `add` 가 아니라 `attach` 입니다.

### 첫 사람은 admin

이 저장소의 첫 사람은 admin 이어야 Settings 의 사용자 관리와 저장소 pull · push 가 열립니다. 등록 뒤 한 줄:

```
bin/s9 user role <이름> admin        # 출력: <이름>: role = admin
```

### 따라 해 보기

1. 대시보드 우상단을 봅니다 — 이름이 서 있으면 3번으로.
2. 터미널에서 위 표의 명령으로 등록하고, `bin/s9 user role <이름> admin` 을 실행합니다.
3. 브라우저에서 대시보드를 새로고침(F5)합니다. 우상단에 **이름 @ 컴퓨터 [admin]** 이 섭니다. 이제 승인 · 반려 · 저장소 판이 이 이름으로 기록됩니다.

### 끝내기

다 됐으면 이 카드를 끝내십시오 — 카드를 눌러 문서를 열고 **→ in-progress** → **상태 옮기기**, 이어서 **→ done** → **상태 옮기기**. 카드가 DONE 열로 갑니다(안내 1의 「끝내기」와 같습니다).
