## Original

지금 보고 있는 화면은 대시보드의 **Board** 탭입니다. 여기 놓인 카드 한 장이 요청 하나입니다 — 터미널에서 Claude Code 에게 일을 시키면 그 말이 카드가 되어 이 보드에 섭니다. 이 안내 일곱 편도 요청입니다. 첫 실행이 기본 프로젝트 `general` 에 세워 두었고, 읽고 끝내는 것이 곧 이 보드를 다루는 첫 연습입니다.

### 열 — 카드가 어느 열에 있는지가 곧 상태입니다

| 열 머리 | 뜻 | 누가 옮기나 |
| --- | --- | --- |
| OPEN | 접수 — 요청이 생긴 자리 | 터미널에서 일을 시킨 순간 저절로 |
| IN-PROGRESS | 진행 — 일하는 중 | 타치코마(리드)가 착수하면 |
| BLOCKED | 대기 — 사람의 손이나 다른 요청의 완료를 기다림. 대기 사유가 카드에 그대로 보입니다 | 타치코마 |
| REVIEW | 확인 대기 — 사람의 판정을 기다림 | 타치코마가 올리고, 사람이 승인·반려로 내립니다(안내 5) |
| DONE | 완료 | 승인하면 |
| CANCELLED | 취소 — 하지 않기로 한 요청. 기록은 남습니다 | 사람 |

OPEN · IN-PROGRESS · REVIEW · DONE 넷은 늘 보이고, BLOCKED · CANCELLED 는 그 상태의 카드가 있을 때만 나타납니다. 열 머리의 숫자가 그 열의 건수입니다. 넘치면 「+ N개 더 보기」가 붙습니다.

### 카드 한 장에 보이는 것

제목 · 담당 · 만든이 · 크기(S/M/L) · TDD n/n(그 작업이 스스로 정한 검증 시나리오 중 통과한 수) · #태그 · REQ 번호 · 그 상태에 머문 시간. IN-PROGRESS 카드 왼쪽의 점은 「지금 실제로 실행 중인가」를 말합니다 — 점의 모양 일곱 가지는 가이드 3장 「카드 위의 실시간 신호 읽기」에 있습니다(대시보드 Settings 목록 맨 아래의 가이드 링크, `http://127.0.0.1:9909/guide.html`).

### 따라 해 보기

1. 브라우저에서 대시보드를 엽니다 — `http://127.0.0.1:9909`(첫 실행 출력의 「대시보드 기동: …」 줄에 적힌 주소). 서버가 꺼져 있으면 풀어 놓은 디렉토리에서 `bin/s9 code`(Windows 는 `bin\s9 code`)를 실행하면 다시 뜹니다.
2. 상단 탭에서 **Board** 를 누릅니다. OPEN 열에 「안내 1」부터 「안내 7」까지 일곱 장이 있습니다.
3. 「안내 1 — 이 보드 읽는 법」 카드를 누릅니다. 문서가 열립니다 — 원문(Original) · 작업 기록(Notes) · 상태 이력(History) 이 한 문서에 다 있습니다. 지금 읽는 글이 그 Original 입니다.
4. 문서 위쪽의 버튼 줄을 봅니다. 「→ in-progress」 「→ blocked」 「→ cancelled」 셋이 이 문서를 옮길 수 있는 곳이고, 「이어 말하기」는 안내 4에서 씁니다.

### 끝내기 — 이 카드를 DONE 열로

다 읽었으면 이 카드를 끝내십시오. OPEN 카드는 바로 DONE 으로 가지 않고 IN-PROGRESS 를 한 번 지납니다 — 「일을 하지 않고 닫는 길」을 화면에 두지 않기 때문입니다.

1. 문서 위쪽의 **→ in-progress** 를 누르고, 뜨는 창 「상태 옮기기」에서 메모는 비워 둔 채 **상태 옮기기** 를 누릅니다.
2. 같은 자리에 **→ done** 이 생깁니다. 누르고 다시 **상태 옮기기**.
3. Board 로 돌아오면 이 카드가 DONE 열에 있습니다.

카드를 드래그해 IN-PROGRESS 열에, 다시 DONE 열에 놓아도 같은 일입니다 — 드래그하는 동안 놓을 수 있는 열만 점선으로 표시됩니다. 「승인」 버튼은 REVIEW 카드에만 있습니다 — 그 연습은 안내 5에서 합니다.
