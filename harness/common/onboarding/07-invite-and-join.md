## Original

동료를 부르는 일은 둘로 나뉩니다. **초대하는 사람**은 Projects 탭에서 이메일 주소를 적어 초대장을 보내고, **초대받은 사람**은 초대장에 실린 명령 한 줄로 팀 저장소에 합류합니다. 앞서 GitHub 저장소가 이어져 있어야 합니다(안내 6) — 합류 명령에 저장소 주소가 들어가기 때문입니다. 혼자 쓸 생각이면 읽어만 두고 카드를 끝내도 됩니다.

### 초대하는 사람 — Projects 탭 「+ 초대하기」

준비물 둘. ① 메일을 보내려면 Settings › **외부 서비스** › **이메일 보내기** 표(SMTP 주소 · 보내는 주소가 있어야 보냅니다). 없어도 초대 창은 열립니다 — 본문을 복사해 직접 전달합니다. ② private 저장소면 GitHub › Settings › Collaborators 에서 그 사람을 먼저 추가합니다 — 초대는 section9 프로젝트의 멤버로 넣을 뿐, GitHub 의 권한을 대신 주지 않습니다.

1. 상단 탭 **Projects** → 왼쪽 목록에서 프로젝트를 고릅니다(처음이면 `general`). 오른쪽 정보 패널의 멤버 표 아래 **+ 초대하기** 를 누릅니다 — 곁에 「아직 계정이 없는 사람은 이메일로 초대합니다.」가 붙어 있습니다. 이미 등록된 사람은 표의 **+ 추가** 로 넣습니다.
2. 창 「<slug> 에 초대합니다」에서 **이메일** · **권한**(기본 `contributor`) · **직무(선택)** 을 적고 **미리 보기** 를 누릅니다. 아래에 **이메일 본문** 과 **합류 명령** 두 줄(「Linux · macOS — 터미널」 · 「Windows — PowerShell」, 각각 **복사**), 그리고 **본문 복사** 가 섭니다. 미리 보기는 아무것도 기록하지 않습니다.
3. **보내기** — 「<주소> 주소로 초대 이메일을 보냈습니다.」가 서고 멤버 표에 그 이메일이 고른 권한으로 들어갑니다. SMTP 준비물이 없으면 **보내기** 가 잠겨 있습니다 — **본문 복사** 로 메신저에 붙여 보내되, 그때는 풀어 놓은 디렉토리에서 `bin/s9 project invite <slug> --to <이메일> --print`(Windows 는 `bin\s9 …`)로 초대를 기록합니다(본문을 찍으면서 멤버 표에 넣습니다).

GitHub 을 아직 잇지 않았으면 창이 「먼저 Settings › 저장소에서 GitHub 을 이어 주세요 — 합류 명령에 저장소 주소가 들어갑니다.」라고 말하고 보내지 않습니다. 초대는 maintainer 이상이 합니다.

### 초대받은 사람 — 명령 한 줄로 합류

초대 메일에 이 한 줄이 실려 옵니다. 주소와 slug 는 초대한 쪽의 것입니다 — 손으로 고치지 마십시오.

```
bin/s9 code --join <주소> --project <slug>          # Linux · macOS · WSL
bin\s9 code --join <주소> --project <slug>          # Windows
```

1. 준비물: git · Python 3 · Claude Code, 그리고 이 컴퓨터의 git 이 그 저장소에 닿는 것(`ssh -T git@github.com`).
2. 릴리스 파일을 받아 **새 디렉토리**에 풉니다. `bin/s9 code` 는 아직 치지 않습니다 — 그냥 치면 혼자 쓰는 저장소가 서고, 그 자리에서는 합류가 「이 자리에 이미 문서가 있다」로 거절됩니다.
3. 풀어 놓은 디렉토리에서 메일의 명령을 그대로 칩니다. 첫 실행이 저장소를 받고(「◌ 팀 저장소에 합류했다 — origin <주소> 의 main 을 받았다(문서·사람·프로젝트 포함)」), 훅 · 스킬을 설치하고, 이름을 묻습니다 — 물음 뒤의 「이미 있는 이름: …」에 내 이름이 있으면 그것을, 처음이면 Enter 또는 원하는 이름을 칩니다.
4. 「◌ 프로젝트 <slug> 에 참여했다 — 요청·문서가 그 프로젝트에 붙는다」가 찍히고 Claude Code 가 열립니다. 브라우저의 Board 에 팀이 이미 만든 카드가 보이고, 상단 **프로젝트** 필터에 `<slug>` 가 있습니다.

확인(풀어 놓은 디렉토리에서):

```
bin/s9 project member <slug> ls      # 내 이름이 contributor 로 있습니다
bin/s9 sync --status                 # 모드: remote  (commit→pull→push)
```

### 하지 말 것

- 이미 쓰던 section9 디렉토리 안에서 `--join` 을 치지 마십시오 — 팀마다 새 디렉토리에 풉니다.
- 합류한 뒤 `git remote` 를 바꾸지 마십시오 — 문서가 오가는 길입니다. 바꿀 일이 있으면 안내 6의 끊기 · 잇기로 합니다.
- 같은 사람이 두 이름으로 등록되지 않게 — 이 컴퓨터 git 의 `user.email` 을 팀에서 쓰는 주소로 맞춰 두면(`git config --global user.email <주소>`) 첫 실행이 묻지 않고 그 이름에 잇습니다. 이미 두 이름이 됐다면 `bin/s9 user attach <원래 이름>`.

### 끝내기

초대를 보냈거나 합류했으면(또는 혼자 쓰기로 했으면) 이 카드를 끝내십시오 — 카드를 눌러 문서를 열고 **→ in-progress** → **상태 옮기기**, 이어서 **→ done** → **상태 옮기기**. 카드가 DONE 열로 갑니다(안내 1의 「끝내기」와 같습니다).
